# 威胁角色（Actors）

建议档。角色是**能采取的动作集合**，不是公司名。  
对照五层：协议 / 实现 / 部署 / 经济 / 密码。

| ID | 角色 | 能做（事实级能力，须点名对象） | 不能被写成 |
|---|---|---|---|
| A1 | 资金权利人 | 用规范允许的签授权一笔花费 / 迁钥 | 「签过消息 = 已控制资金」（不变量 258） |
| A2 | 本高度 proposer | 写本块交易列表（若抄 ABCI：Prepare） | 「签了头 = 自己排过序」（不变量 27） |
| A3 | 验证者（投票） | 对同一 `(height, round, type)` 签一张票 | 「两张签 = 已 slash」（不变量 21） |
| A4 | 拜占庭验证者 ≤ ⅓（BFT 模型） | 停活性、双签、注入非法提案 | 「⅓ 已是不确定法定人数」——不要抄数字当默认 |
| A5 | 应用（ABCI） | CheckTx / Prepare / Process / Finalize / Commit / 快照四门 | 「回了 AppHash = 本头已交差」（不变量 147） |
| A6 | 引擎（CometBFT 对照） | 锁、提案、计票、交 Misbehavior、落盘输出 | 「引擎交证据 = 应用已罚」（不变量 21） |
| A7 | P2P 对等节点 | 宣布 / 交付 / 拒收 / 变异块 | 「宣布 = 已收到」（不变量 36） |
| A8 | 快照发送者 | 提供 Snapshot + chunk；除轻验 AppHash 外可伪造 | 「Metadata 对上 = 已从创世重放」（不变量 38） |
| A9 | RPC / 钱包 UI | 显示余额、绿勾、付款 URI | 「RPC 绿勾 = 验证」（settlement-copy） |
| A10 | 治理 / 升级操作员 | 改参数、换二进制 | 「治理通过 = 实现已能吃」（不变量 58） |
| A11 | 轻客户端用户 | 跳过中间高度（若提供） | 「新委员会自己的 2/3 = 已验证」（不变量 20） |
| A12 | 局域网 / 代理 | 仅当打开 UPnP / SOCKS | 「默认全节点已暴露这类对手」（不变量 53、54） |

v1 **必须写进产品句的对手**：A1 自己、A3/A4、A7、A9。  
v1 **可以不提供的能力**（从而缩小对手面）：A8 快照同步、A11 轻客户端、A12 自动打洞。

禁止把「测试通过」或「官网没有事故」写成 A4 不存在。

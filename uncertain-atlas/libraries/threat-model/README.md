对手与假设，不是功能列表。

## 对手 → 层 → 第一版必须写下的句子

| # | 对手 | 主打哪层 | 用户侧失败 | 看守（建议） |
|---|---|---|---|---|
| 1 | 假 RPC / 钓鱼签字 | 用户 + 部署 | 以为到了或签了错域 | 默认全节点路径；域分离；文案不把 RPC 当验证 |
| 2 | 验签炸弹 | 部署 / 经济 | 节点倒、池停 | 配额；见 unbounded-verify |
| 3 | < 阈值拜占庭验证者 | 协议 | 停或（规则错时）裂 | 相交 + 锁；V(h) 唯一 |
| 4 | 长时间分区 | 协议 + 部署 | 两边各「到了」或全停 | 产品先选：停 vs 概率重组 |
| 5 | 断电 / 时钟 / 磁盘 | 实现 + 部署 | 半块状态、矛盾票 | 原子高度；WAL；杀进程测试 |
| 6 | 收集公钥等量子 | 密码学 | 旧账户被伪签 | 算法敏捷；冷账户出口；账本空行要测 |
| 7 | 升级钥 / 社会工程 | 治理 | 供给或桥被改 | 钥不能静默改供给；时锁 |
| 8 | 状态填盘 | 经济 + 协议 | 全节点门槛被抬到机房 | 字段白名单或占用不等式；见 L2.6 |
| 9 | 多数客户端同一实现洞 | 实现 + 部署 | 用户跟错根仍看见绿勾 | 第二实现比根；见 CVE-2021-39137 |

## 不自动覆盖

- 用户把助记词发给钓鱼网站。协议应不假装能救。  
- 「主网还在跑」不等于五层都成立。  
- 测试绿了只覆盖已写句子。

## 跨系统「到了」错认（目的 A）

见 [`../../tracks/lifecycle/README.md`](../../tracks/lifecycle/README.md)。  
商家按错列的绿勾发货，是威胁 1 与最终性文案的合谋，不是签名公式问题。

## 第一版结算机最怕（建议）

1. 假最终性文案导致商家放货。  
2. 无上限验签。  
3. 非规范编码分裂客户端。  
4. 升级后门。  
5. 冷账户无法迁移。  
6. 实现上限变成未写明共识（BIP 50 类）。

## 后量子特有

量子对手不自动获得验证者席位。他获得的是**伪造旧算法授权**的能力。  
BFT 的 2/3 算术仍在；被污染的是票与用户 tx 的字节。  
因此：用户签与投票签要分开记账（工程账本第 1–2 行）。

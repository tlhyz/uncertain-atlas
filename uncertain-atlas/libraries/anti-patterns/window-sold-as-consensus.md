# 反模式：把对等窗写成已经改了共识

**标识：** `window-sold-as-consensus`
**等级：** 重要
**相关模式：** [`name-the-history-window`](../design-patterns/name-the-history-window.md)
**相关课文：** [L5.3](../../courses/level-05-ethereum/L05-M03-multi-client.md)
**相关不变量：** 207、23、25、195

## 错误句

「对等节点宣布了历史窗，所以共识已经删了历史。」「线上收据没有布隆，所以共识收据已经改了。」「握手去掉总难度，所以已经能判断同步完没完。」「换了线协议版本，所以已经硬分叉。」「EIP-7642 就是不变量 23 / 25 / 195。」

## 为什么错

官方页写：本页改 `eth` 对等协议，让节点宣布自己还服务的历史块范围；握手去掉合并后不再用的总难度；线上收据去掉布隆。历史过期工作组说客户端**可以**在约定后丢掉合并前历史——看见本页不是已经共识删历史。最早块字段**技术上不是**历史过期所必须；没有它，客户端只能去要历史、失败时猜「大概没了」。收端必须重算布隆才能完整核收据哈希。线协议现在偏离共识收据编码。本页**不改 EVM 共识**、**不要求硬分叉**；旧客户端可以继续用旧线版本，多版本可以共存。

看见对等节点宣布历史窗不是已经改了共识历史；线上收据没有布隆不是已经改了共识收据编码；握手去掉总难度不是已经能判断同步完没完；换线协议版本不是已经硬分叉；EIP-7642 不是不变量 23 也不是 25 也不是 195。

## 正确替代

[`name-the-history-window`](../design-patterns/name-the-history-window.md)。需要 blob 侧车服务窗时用[不变量 23](../invariants/README.md)。需要跳过具名规则时用[不变量 25](../invariants/README.md)。需要状态历史哈希时用[不变量 195](../invariants/README.md)。

## 会在哪炸

把对等窗当成共识已经删历史，会把「线上看不见」写成「协议规定必须没有」。把线上收据当成共识收据，会漏掉收端必须重算布隆。把去掉总难度当成已经能判断同步完没完，会把分叉标识已经能做的事写成总难度已经做了。把换线版本当成硬分叉，会把可选共存写成必须升级。把本页写成 23 / 25 / 195，会把侧车窗、跳过验证、状态历史哈希混进对等历史窗。

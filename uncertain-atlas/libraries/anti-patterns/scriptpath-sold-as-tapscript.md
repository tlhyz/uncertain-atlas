# 反模式：把走脚本路径写成已经是 tapscript 语义

## 一句话

把 341 的脚本路径写成已经按 342 跑，或把遇见成功操作码写成已经执行完、已经安全升级。

## 看起来像什么

- 「走了脚本路径，新脚本语义已经在跑。」
- 「有成功操作码，整段已经执行完。」
- 「成功操作码就是已经升级。」
- 「旧多重签在 Taproot 里还能用 / 已经变成成功操作码。」
- 「342 就是 341。」

## 为什么错

[BIP-342](https://github.com/bitcoin/bips/blob/master/bip-0342.mediawiki) 写明：本页是 341 底下那一套初始脚本语义，只在隔离见证、taproot 花费、脚本路径、并且叶子版本标成 tapscript 时适用。遇见成功操作码是整段无条件过，不是已经执行完。软分叉还没定义就用，官方写成会丢钱。旧多重签操作码禁用，故意不改成成功操作码。

## 正确分法

1. 先点名问的是 341 结构还是本页语义。
2. 再点名叶子版本是不是 tapscript 这一档。
3. 再问成功操作码是无条件过，还是已经执行完。
4. 最后才问旧多重签和 MINIMALIF 在本页是哪一盏灯。

## 和相邻坑的差别

- 和 [`keypath-sold-as-tree.md`](keypath-sold-as-tree.md) 不同：那一条把钥匙路径写成已经揭开脚本树。
- 和 [`hash-sold-as-redeem.md`](hash-sold-as-redeem.md) 不同：那一条是付给哈希写成已经揭开赎回。
- 和 [`valid-sold-as-der.md`](valid-sold-as-der.md) 不同：那一条是 ECDSA 验过写成已经是严格 DER。

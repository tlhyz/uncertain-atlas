# 反模式：把扩展公钥写成已经能花

## 一句话

把 `xpub` 写成已经能花，或把能从它推出的子公钥写成已经是地址、已经有 UTXO。

## 看起来像什么

- 「给对方 xpub，他就能花。」
- 「HD 钱包导出了，地址已经在链上。」
- 「能推出子钥，就是已经能收款。」
- 「硬化只是编号，公钥路径也能走。」

## 为什么错

[BIP-32](https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki) 把扩展公钥写成去势对象：能看、能推未硬化子孙公钥，不能签字。硬化下标从公钥父节点必须失败。链节点标识和地址同源，但不建议写成地址，钱包也不必接受打到这颗节点的付款。看见扩展公钥不是已经能花，也不是已经有 UTXO。

## 正确分法

1. 先点名扩展密钥种类。
2. 再点名硬化分界。
3. 再问这是树节点还是收款地址。
4. 最后才问有没有花费能力和有没有 UTXO。

## 和相邻坑的差别

- 和 [`bech32m-sold-as-bech32.md`](bech32m-sold-as-bech32.md) 不同：那一条把后继校验写成已经是旧方案；本条把扩展公钥写成已经能花。
- 和 [`address-sold-as-utxo.md`](address-sold-as-utxo.md) 不同：那一条把地址写成已经有输出；本条还没编到地址。
- 和 [`psbt-sold-as-broadcast.md`](psbt-sold-as-broadcast.md) 不同：那一条把未完成交易对象写成已经能广播。

# 反模式：把净计量写成已经是瞬时存储

**标识：** `net-meter-sold-as-transient`
**等级：** 重要
**相关模式：** [`name-the-net-meter`](../design-patterns/name-the-net-meter.md)
**相关课文：** [L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)
**相关不变量：** 225、159、223、169

## 错误句

「净计量了，所以已经是瞬时存储。」「只看当前值和新值就够了。」「同帧再写更便宜，所以转账津贴里已经能改槽。」「EIP-2200 就是 EIP-1153 / 不变量 159 / EIP-3529 / EIP-2929。」

## 为什么错

官方页写：给存储写入做净计量，计价用原来值、当前值和退款计数。当前值等于新值是空操作。原来值等于当前值才是这一上下文第一次改这个槽；否则槽已经脏了。剩余气小于等于转账津贴时，写存储让当前帧以气不够失败。1283 原定义会带来一种新的重入危险；低剩余气时不许写存储，就能挡住，且不拆原意。本页大体做到瞬时存储想做的事，但不必引入脏图或另一套存储结构。和当时旧表比，本页不会更贵。规范没有把净计量写成已经是瞬时存储，也没有把本页写成 3529 或 2929，也没有把本页写成已经能在津贴帧里改槽。

看见净计量不是已经是瞬时存储；看见原来值 / 当前值 / 新值不是已经只有当前值；看见津贴帧里写存储会停不是已经能在转账津贴里改槽；EIP-2200 不是 EIP-1153 也不是不变量 159，也不是 EIP-3529。

## 正确替代

[`name-the-net-meter`](../design-patterns/name-the-net-meter.md)。需要瞬时存储时用[不变量 159](../invariants/README.md)。需要退款削减时用[不变量 223](../invariants/README.md)。需要冷热访问时用[不变量 169](../invariants/README.md)。

## 会在哪炸

把三本账当成临时库房，会把「同帧再写便宜」写成「已经不进持久店」。把 2200 当成 3529，会把三值计价听成已经削薄退款。把同帧便宜当成津贴帧能写，会把 1706 那道禁写听成已经能改槽。

# 反模式：看见同一套钥就当成已经是同一条 P2SH 地址 / 看见只共享门限和主公钥就当成已经够了 / 看见未压缩钥就当成已经是本页

**层次**：应用 / 失败模式。  
**分类**：事实（对象）+ 推断（事故）。  
**来源**：[BIP-67](https://github.com/bitcoin/bips/blob/master/bip-0067.mediawiki)。  
**例**：[同一套钥 ≠ 已经是同一条 P2SH 地址](../../tracks/implementation/worked-example-sorted-vs-one-address.md)。

## 塌法

1. 看见同一套钥 / 同一门限，就当成已经是同一条赎回脚本，或当成已经是同一条 P2SH 地址。
2. 看见只共享了门限和参与者主公钥，就当成已经够了，或当成已经不必采用本页排序。
3. 看见还没采用本页，就当成已经必须为每个地址另存一份状态。
4. 看见未压缩钥，就当成已经是本页，或当成已经可以自动压成压缩形式。
5. 看见一条 P2SH 地址，就当成已经能当网络规则，或当成部分合规也不会长出别人认不出的地址。

## 为什么会出事

官方写：赎回脚本并不要求公钥按某一种顺序或某一种编码；同一套钥、同一门限可以长出多条标准赎回，各有一条地址。采用本页之后，只要共享门限和主公钥，各钱包才会长出同一批地址。未压缩钥不兼容，兼容实现不应当自动压缩；本页不能写成网络规则，那样会硬分叉。

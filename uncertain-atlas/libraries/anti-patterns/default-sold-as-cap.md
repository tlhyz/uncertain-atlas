# 反模式：把客户端默认气限写成已经是协议帽

**标识：** `default-sold-as-cap`
**等级：** 重要
**相关模式：** [`name-the-default-gas`](../design-patterns/name-the-default-gas.md)
**相关课文：** [L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)
**相关不变量：** 211、203、202、96

## 错误句

「各家默认气限改成同一档，所以协议已经写死块气帽。」「绑到一次硬分叉发布，所以共识已经改了。」「默认配置齐了，所以已经是单笔气帽。」「EIP-7935 就是不变量 203 / 202 / 96。」

## 为什么错

官方页写：建议在一次硬分叉发布时，各家执行层客户端把默认配置里生成的气限改到同一档。本页是 Informational。改的是默认配置，不是协议写死的块气帽。各家配置格式不同。过去默认不好齐，所以建议绑到一次硬分叉发布。官方写更高气限不该弄坏已有合约，并且要和单笔气帽的日程对齐。规范没有把默认配置写成已经是协议帽，也没有把绑到硬分叉写成已经改了共识，也没有把默认齐了写成已经是单笔气帽。

看见客户端默认气限不是已经是协议帽；看见绑到硬分叉发布不是已经改了共识；看见默认配置齐了不是已经是单笔气帽；EIP-7935 不是不变量 203 也不是 202 也不是 96。

## 正确替代

[`name-the-default-gas`](../design-patterns/name-the-default-gas.md)。需要单笔气帽时用[不变量 203](../invariants/README.md)。需要编码硬帽时用[不变量 202](../invariants/README.md)。需要通道尺寸时用[不变量 96](../invariants/README.md)。

## 会在哪炸

把默认配置当成协议帽，会把说明书听成法律。把绑到硬分叉当成共识已改，会把发版日听成硬分叉规则。把默认齐了当成单笔气帽，会把出厂值和协议单笔帽混成一句。把本页写成 203 / 202 / 96，会把单笔帽、编码帽、通道尺寸混进默认配置。

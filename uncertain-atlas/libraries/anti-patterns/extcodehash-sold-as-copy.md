# 反模式：把代码哈希指令写成已经看见代码

**标识：** `extcodehash-sold-as-copy`
**等级：** 重要
**相关模式：** [`name-the-extcodehash`](../design-patterns/name-the-extcodehash.md)
**相关课文：** [L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)、[L2.2](../../courses/level-02-state/L02-M02-account.md)
**相关不变量：** 221、180、162、220

## 错误句

「多了一条代码哈希指令，所以已经看见对方代码。」「返回 0，所以这个账户已经是没代码。」「返回空数据哈希，所以这个地址已经不存在。」「EIP-1052 就是 EIP-161 / 不变量 180 / 不变量 162。」

## 为什么错

官方页写：给 EVM 加一条返回某账户代码哈希的指令。许多合约要检查字节码，但不一定需要字节码本身；现行整份拷在只要哈希时很贵。账户不存在或按 161 是空，推 0。账户没有代码，推空数据的哈希。本页把「没代码的账户」和「不存在的账户」分开，和状态树表示一致。规范没有把本页写成已经拷出代码，也没有把返回 0 写成已经是没代码，也没有把空数据哈希写成已经不存在，也没有把本页写成 161 或 3607。

看见代码哈希指令不是已经看见代码本身；看见返回 0 不是已经是没代码的账户；看见空数据哈希不是已经是账户不存在；EIP-1052 不是 EIP-161 也不是不变量 180，也不是不变量 162。

## 正确替代

[`name-the-extcodehash`](../design-patterns/name-the-extcodehash.md)。需要空 / 不存在 / 死时用[不变量 180](../invariants/README.md)。需要发送者代码哈希时用[不变量 162](../invariants/README.md)。

## 会在哪炸

把读哈希当成已经开箱，会把「报指纹」写成「已经看过货」。把 0 当成没代码，会把不存在和空户听成同一盏灯。把空数据哈希当成不存在，会把「有账户、没代码」听成货位已经拆掉。

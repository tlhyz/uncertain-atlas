# 反模式：把数前导零写成已经更便宜的 ZK

**标识：** `clz-sold-as-zk`
**等级：** 重要
**相关模式：** [`name-the-clz`](../design-patterns/name-the-clz.md)
**相关课文：** [L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)
**相关不变量：** 208、206、199、204

## 错误句

「有了数前导零，所以零知识证明已经更便宜。」「动机写了后量子签名，所以已经有后量子签。」「能用它表达最低位，所以已经有数尾零。」「EIP-7939 就是不变量 206 / 199 / 204。」

## 为什么错

官方页写：加入一条新操作码，弹出一个值，压回前导零个数；输入为零则压回字宽。动机把更便宜的计算、更便宜的零知识证明、更短的字节码，以及后量子签名方案，写成加它的理由。官方更想先加数前导零，不先加数尾零：最低位可以再表达，反过来不行。这是以前没有的新操作码。规范没有把看见本页写成证明已经便宜，也没有把动机点名后量子写成签名已经换完，也没有把能表达最低位写成已经有数尾零。

看见数前导零操作码不是已经更便宜的 ZK 证明；动机写了后量子签不是已经有后量子签名；能用它表达最低位不是已经有数尾零；EIP-7939 不是不变量 206 也不是 199 也不是 204。

## 正确替代

[`name-the-clz`](../design-patterns/name-the-clz.md)。需要模幂输入帽时用[不变量 206](../invariants/README.md)。需要曲线算术预编译时用[不变量 199](../invariants/README.md)。需要 P256 验签时用[不变量 204](../invariants/README.md)。

## 会在哪炸

把一条栈操作当成证明系统已经便宜，会把「官方预期」写成「已经测过」。把动机里的后量子举例当成签名已经换完，会把积木写成方案。把能表达最低位当成已经有数尾零，会把一条操作码写成两条。把本页写成 206 / 199 / 204，会把输入帽、配对预编译、验签混进数前导零。

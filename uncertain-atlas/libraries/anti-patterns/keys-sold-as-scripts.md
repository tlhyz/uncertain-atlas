# 反模式：把密钥备份写成已经知道该看哪种脚本

## 一句话

把只拿回私钥或助记词写成钱包已经知道该产出哪种输出脚本，或把看见描述符写成已经是地址。

## 看起来像什么

- 「助记词恢复了，地址种类已经齐。」
- 「有 xpub 就能导出收款脚本。」
- 「描述符就是地址。」
- 「给扩展钥换一套版本字节，脚本类型已经焊上了。」

## 为什么错

[BIP-380](https://github.com/bitcoin/bips/blob/master/bip-0380.mediawiki) 写明：只拿私钥，恢复后的钱包无法知道该产出哪几种输出脚本和地址。脚本类型和派生路径必须显式写出。给扩展钥换版本字节来表示脚本类型是越层。看见描述符不是已经是地址，也不是已经有 UTXO。

## 正确分法

1. 先点名密钥材料。
2. 再点名脚本类型是否显式。
3. 再问这是描述符还是收款地址。
4. 最后才问链上有没有输出。

## 和相邻坑的差别

- 和 [`mnemonic-sold-as-seed.md`](mnemonic-sold-as-seed.md) 不同：那一条把看见词写成已经是种子；本条是种子齐了仍不知道脚本。
- 和 [`xpub-sold-as-spendable.md`](xpub-sold-as-spendable.md) 不同：那一条把扩展公钥写成已经能花。
- 和 [`address-sold-as-utxo.md`](address-sold-as-utxo.md) 不同：那一条把地址写成已经有输出。

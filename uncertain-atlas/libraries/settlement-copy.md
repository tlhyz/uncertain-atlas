# 「不确定」结算文案纪律

目的 B：产品句子不得比协议对象更硬。  
建议，不是已选型。对照：`tracks/lifecycle/`、L10.3、威胁模型第 1 条。

## 允许的句型（须填空后才能用）

1. 「高度 / 检查点 / 确认数 **X** 上，我们承认意图 T；所依据的协议对象是 **Y**。」  
2. 「若 **Y** 被推翻（重组 / 未 finalized / 日蚀），我们的放货规则是 **Z**。」  
3. 「用户从 RPC 看到的余额 **不是** 验证。」  
4. 「失败但已包含的交易：nonce/费按规范 **……**，收款 **未到**。」

Y 必须来自 `tracks/finality/` 已有行，或一条新的、写进规范的对象。禁止发明「链上绿勾」。

## 禁止的句型

- 「已经到了 / 不可逆 / 最终确认」而未写 Y。  
- 「后量子所以更安全」（密码层换算法 ≠ 最终性）。  
- 「BFT 所以秒到」（未写 commit 对象与假设）。  
- 「测试通过所以不会双花」。  
- 「和某某链一样快/一样最终」。

## 后量子附加

可以说：「用户签名算法标识为 **A**；迁移状态为 **S**。」S 来自 `tracks/post-quantum/migration.md`。  
在账本未测之前，禁止：「后量子主网已完成。」

## 与决策列的关系

文案选定 Y，仍不等于共识算法已定。可以先规定「产品只使用一种 Y」，再在 L10.1 记录里选实现 Y 的引擎。

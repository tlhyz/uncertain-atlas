# 模式：把付款 URI 三件事说成三个名字

**层次**：生命周期 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-321](https://github.com/bitcoin/bips/blob/master/bip-0321.mediawiki)。  
**例**：[付款 URI ≠ 已经授权](../../tracks/lifecycle/worked-example-uri-vs-authorized.md)。

## 三个名字

1. **用户授权：** 没有批，不得按这条 URI 行事。不是已经付了。
2. **路径与查询：** 路径可以空，只要查询里至少有一条指示。不是已经没有指示。
3. **必选参数与回执：** 不认识的必选参数让整条非法。回执不是已经确认。

## 为什么要分开叫

官方把「点链接就能付」写成一条 URI，同时又写没有用户授权不得行事，并且路径空不等于没有指示。把它们叫成一个「已经付了」，会把远程取单、地址串和部分签名包一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果接受付款链接，先数清问的是用户批没批、指示写在路径还是查询，还是已经付了，再决定要不要同一次发布。

# 模式：并行必须先点名访问集

**问题：** 产品把「UTXO 所以能并行」写成已经解释了冲突。用户把谓词通过听成脚本已跑，或把只读重叠听成必须串行，或把并行听成已经不需要顺序 L。  
**方案：** 每个并行句先点名问的是谓词、脚本、只读重叠、写集相交，还是顺序副作用。访问列表必须先写出读写键，再谈并行还是拓扑序。  
**适用：** Fuel 式 UTXO / `contractID` 访问集、任何「声明依赖再并行」的结算文案。  
**优点：** 用户能指出并行放开的是读还是写，合法性仍按哪一条 L。  
**缺点：** 句子变长；不能再用「也是声明锁」交差。  
**项目：** Fuel 规范 Transaction Validity：预检 → 谓词 → 脚本 → 后检；写不相交可并行（含只读重叠）；写相交必须拓扑序。  
**常见 bug：** 谓词写成脚本；只读重叠写成必须串行；并行写成没有 L；访问集写成账户锁或 STM。  
**不确定：** 第一版不要把短槽 + 声明调度当默认。若对照，必须点名访问集主键。见 [工作实例](../../tracks/parallelism/worked-example-utxo-access-list.md)。

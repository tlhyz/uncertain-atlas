# 先给数前导零操作码起名（name-the-clz）

> 类型：design pattern  
> 对读：不变量 208；C212；反模式 [`../anti-patterns/clz-sold-as-zk.md`](../anti-patterns/clz-sold-as-zk.md)；[`../../tracks/implementation/worked-example-clz-vs-zk.md`](../../tracks/implementation/worked-example-clz-vs-zk.md)。

设计或讲解「加了一条数前导零」时，先分开四个名字：

1. **数前导零** — 栈上一条新操作码，不是已经更便宜的 ZK 证明。
2. **动机里的后量子** — 官方举例它能当积木，不是已经有后量子签名。
3. **能表达最低位** — 官方更想先加这一条的理由，不是已经有数尾零。
4. **7939** — 新操作码，不是模幂输入帽，也不是验签预编译。

四句对照：

- 看见的是栈上数前导零，还是证明已经便宜？
- 看见的是动机点名后量子，还是签名已经换完？
- 看见的是能再表达最低位，还是已经有数尾零？
- 这是 7939，还是已经是 206 / 199 / 204？

不要和模幂输入帽（不变量 206）、预编译算术≠已验 BLS（不变量 199）、P256 验签≠已验 k1（不变量 204）糊成「EVM 更强了」一句。

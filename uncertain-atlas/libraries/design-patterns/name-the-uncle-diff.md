# 模式：把含叔块的难度说成一个名字

**层次**：共识 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[EIP-100](https://eips.ethereum.org/EIPS/eip-100)。  
**例**：[含叔块的难度 ≠ 已经数清叔块](../../tracks/consensus/worked-example-uncle-diff-vs-header.md)。

## 三个名字

1. **含叔块的目标：** 平均出块把叔块算进去；不是已经没有炸弹，也不是已经改了奖励。
2. **只看头的近似：** 叔块哈希空或不空；不是已经数清有几个叔块。
3. **可预期发行：** 官方说不能靠叔块率往上抬；不是发行已经锁死。

## 为什么要分开叫

官方把「算上叔块」和「只看头」写成同一份规范里的两句。把它们叫成一个「难度已经齐了」，会把 Homestead 均值、炸弹推迟和改奖励一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做难度，先点名问的是均值目标、叔块进不进目标，还是奖励。

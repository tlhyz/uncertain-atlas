# 模式：把带 nonce 的 ping / pong 三件事说成三个名字

**层次**：网络 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-31](https://github.com/bitcoin/bips/blob/master/bip-0031.mediawiki)。  
**例**：[pong ≠ 已经还活着](../../tracks/network/worked-example-pong-vs-live.md)。

## 三个名字

1. **加入：** 协议版本够了不是已经会带 nonce 的 ping，也不是已经会回 pong。
2. **对上：** 看见 pong / 回显了 nonce 不是已经对上那一次 ping。
3. **样本：** 看见回了 pong 不是已经还活着，也不是已经不卡。

## 为什么要分开叫

官方把「必须自己抬版本才能加入」和「重叠时必须靠 nonce 分开」写成两件独立的事，同时又把本页写成测死连接、测负载、测远近的工具。把它们叫成一个「回了 ping 就已经还活着」，会把功能协商和发现层的 ping 序号一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写对等探活，先数清问的是加入、对上还是一次样本，再决定要不要同一次发布。

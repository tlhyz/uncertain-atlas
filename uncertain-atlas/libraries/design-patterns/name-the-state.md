# 模式：把引擎 State 三件事说成三个名字

**层次**：实现 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[State](https://github.com/cometbft/cometbft/blob/main/spec/core/state.md)。  
**例**：[State 对象 ≠ 已经进了块](../../tracks/implementation/worked-example-state-vs-gossip.md)。

## 三个名字

1. **本地对象：** 看见 State 对象不是已经写进块，也不是已经流言，也不是已经算了 State 哈希。
2. **头上的根：** 看见验证者根或结果根不是已经有了 State 对象本身。
3. **落盘接口：** 看见能读本地 State 不是已经进了规范，也不是已经能在网上对上。

## 为什么要分开叫

官方把 `State` 对象本身写成实现细节，把进块的根和验证时用的值写成规范类型，又把怎么落盘、怎么查询写成不进规范。把它们叫成一个「看见本地 State 就已经在块里」，会把本头 AppHash 和快照一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「当前状态」，先数清问的是本地对象、头上的根，还是落盘接口，再决定要不要同一次发布。

# 模式：乐观并行，提交必须等于既定串行

**问题：** 事先声明读写集税高，漏列即失败；完全串行又吃不满多核。  
**方案：** 共识先给出块内序列 L；多线程投机执行，冲突则按 L 再跑；提交写集必须等于单线程按 L 执行。  
**适用：** 已有确定的 L；低冲突时想吃多核；程序员不便列全依赖。  
**优点：** 不要求事先写集；正确性定义清楚（≡ 串行 L）。  
**缺点：** 实现极难写对；高冲突回滚税；不要求 opacity 不等于中间态可对外观察；STM 跑完不是已经最终。  
**项目：** Aptos Block-STM（论文 + 官方 Execution 页）。同类思想被别家移植时，仍要各自证明 ≡ 自己的 L。  
**常见 bug：** 把 STM 说成代替共识；把加速比当安全；把投机写集给人看。  
**不确定：** 可以参考「并行必须等价于既定序列」；第一版先串行 `Apply`。见 [工作实例](../../tracks/parallelism/worked-example-block-stm.md)。

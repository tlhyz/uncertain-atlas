# 模式：拒绝必须先点名是策略门还是共识门

**问题：** 产品把「交易被拒绝」写成已经解释了链。用户把邻居不转发听成共识非法，或把费率高听成更正确，或把进了本节点 mempool 听成已经进块。  
**方案：** 每个拒绝句先点名问的是本地策略、共识规则、费率，还是本节点未确认筐。策略是共识之外、只管未确认、不作用于块内交易。  
**适用：** Bitcoin 式 mempool / 任何「节点不肯转发」的结算文案。  
**优点：** 用户能指出保安手册和法官不是同一本。  
**缺点：** 句子变长；不能再用「被拒绝」交差。  
**项目：** Bitcoin Core `doc/policy/README.md`：Policy 是共识之外的本地可配置规则；不作用于块内交易。  
**常见 bug：** 策略写成共识；费率写成正确性；进池写成进块。  
**不确定：** 第一版必须把本地错 / 池拒绝 / 共识非法三套文案分开。见 [工作实例](../../tracks/mempool/worked-example-policy-vs-consensus.md)。

# 模式：替换必须先点名是示意、本节点收了，还是已经进块

**问题：** 产品把「支持 RBF」写成已经换掉。用户把选择加入信号听成池里已换，或把较低序列号听成相对锁，或把未确认入账听成已经付款。  
**方案：** 每个替换句先点名问的是花费者示意、本节点 mempool 是否收替换，还是共识已经换。示意不是已经换掉。nSequence 示意不是相对锁。  
**适用：** Bitcoin 未确认替换文案 / 任何「先盖可改章」的结算产品。  
**优点：** 用户能指出信封章、邮局收条和已经改址不是同一盏灯。  
**缺点：** 句子变长；不能再用「支持 RBF」交差。  
**项目：** BIP-125：选择加入信号；节点可以替换；收款方可以等确认。  
**常见 bug：** 信号写成已换；序列号写成相对锁；未确认写成已付款。  
**不确定：** 必须把示意 / 本节点替换 / 块内合法分开。见 [工作实例](../../tracks/mempool/worked-example-rbf-signal-vs-replaced.md)。

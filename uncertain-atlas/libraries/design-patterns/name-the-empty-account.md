# 模式：自动删户必须先点名是空、不存在还是死

**问题：** 产品把「空账户」写成状态里已经没有这个地址。用户把死听成一种对象，或把碰到听成已经付过钱，或把规范 161 听成链绑定。  
**方案：** 每个删户句先点名问的是空（三项都零）、不存在，还是死（二者之一）。碰到含零值。存在但是空不得出现。交易结束才把碰到且空的变成不存在。  
**适用：** 账户模型文案 / 任何「自动清空户」的结算产品。  
**优点：** 用户能指出空页、撕掉的页和「死」这个总称不是同一盏灯。  
**缺点：** 句子变长；不能再用「空账户会清」交差。  
**项目：** EIP-161：空、不存在、死三盏灯；碰到含零值。  
**常见 bug：** 空写成已经不存在；死写成一种对象；规范 161 写成不变量 161 或 103。  
**不确定：** 第一版若自动删空账户，必须分开这三盏灯。见 [工作实例](../../tracks/state-models/worked-example-empty-vs-dead.md)。

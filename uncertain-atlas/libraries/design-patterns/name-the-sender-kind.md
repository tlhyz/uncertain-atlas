# 模式：发送者必须先点名是空代码还是已有代码

**问题：** 产品把「能恢复出私钥」写成已经能发交易。用户把合约地址听成 EOA，或把后来自毁听成已经变成可发送账户。  
**方案：** 每个发送句先点名问的是发送者代码哈希是不是空。已有代码必须拒；进块则块非法。RPC 预演放行不是共识放行。  
**适用：** Ethereum 交易准入 / 任何「地址上有代码就不能当发送者」的结算文案。  
**优点：** 用户能指出店规钥匙和家门钥匙不是同一盏灯。  
**缺点：** 句子变长；不能再用「有钥就能发」交差。  
**项目：** EIP-3607：发送者已有代码则交易非法、块非法。  
**常见 bug：** 合约地址写成 EOA；`eth_call` 绿写成已进块。  
**不确定：** 必须拒发送者已有代码的交易。见 [工作实例](../../tracks/state-models/worked-example-code-sender-vs-eoa.md)。

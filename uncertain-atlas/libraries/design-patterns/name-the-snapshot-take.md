# 模式：把拍快照三件事说成三个名字

**层次**：实现 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[Requirements for the Application](https://github.com/cometbft/cometbft/blob/main/spec/abci/abci++_app_requirements.md) Taking Snapshots。  
**例**：[拍了这个高度 ≠ 已经交差之后拍的](../../tracks/implementation/worked-example-snapshot-take-vs-commit.md)。

## 三个名字

1. **拍了这个高度不是已经交差之后拍的：** 看见标了高度不是已经没有更高高度的数据。
2. **没停链不是已经一致：** 看见在后台拍不是已经各节点字节相同。
3. **只留最近两份不是已经有了全部历史快照：** 看见 Hash 对上不是已经是同一份。

## 为什么要分开叫

官方把先 Commit 再拍、三件保证、只留最近两份写成三件事。把它们叫成一个「看见拍了就已经交差之后拍」，会把轻验 AppHash、装回、发现和切进共识一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「已经在拍快照」，先数清问的是拍了这个高度不是已经交差之后拍的、没停链不是已经一致，还是只留最近两份不是已经有了全部历史快照，再决定要不要同一次发布。

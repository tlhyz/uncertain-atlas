# 模式：把可复用付款码三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-47](https://github.com/bitcoin/bips/blob/master/bip-0047.mediawiki)。  
**例**：[付款码 ≠ 已经是存款地址](../../tracks/lifecycle/worked-example-payment-code-vs-notification.md)。

## 三个名字

1. **付款码：** 看见付款码不是已经是存款地址，也不是已经付过。
2. **通知输出：** 看见通知交易不是已经是付款；看见通知地址上有输出不是已经能花。
3. **第一次通知：** 看见第一次付款不是已经不必再通知；看见已经收过不是已经可以免通知。

## 为什么要分开叫

官方把付款码写成身份/账户上的扩展公钥加元数据，把存款地址写成通知之后才派生，又禁止把通知输出显示为可花余额，还把第一次往回打和从种子找回写成必须再发通知。把它们叫成一个「看见公开码就已经付到链上」，会把静默付款那种不必通知一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出可复用收款码，先数清问的是付款码是不是已经等于存款地址、通知输出是不是已经能花，还是第一次已经不必再通知，再决定要不要同一次发布。

# 设计模式：先点名校验和版本

## 一句话

看见后继见证地址，先问：这一串走的是哪一版校验和、版本字段是否和这一版配对。不要把校验过了写成已经是旧地址方案，也不要把看见地址写成已经有 UTXO。

## 问题

`Bech32`、`Bech32m`、`v0`、`v1+`、`地址`、`UTXO` 会被叠成一个词。BIP-350 把后继版本改到新校验和，正是为了不让只认旧校验和的发送者把币打到后继程序上。

## 做法

1. 先写校验和版本：旧方案还是后继方案。
2. 再写见证版本：`v0` 还是 `v1+`。
3. 再写配对：版本和校验和是否被解码器一起查。
4. 最后才问：这一串是不是已经对应链上 UTXO。

## 不要和谁弄混

- 不要和 [`name-the-address-object.md`](name-the-address-object.md) 弄混：那一页管的是看见地址 ≠ 已经有 UTXO；本页管的是看见后继地址 ≠ 已经是旧校验和方案。
- 不要和 [`name-the-psbt-role.md`](name-the-psbt-role.md) 弄混：那一页管的是未完成交易对象。
- 不要和 [`name-the-txid.md`](name-the-txid.md) 弄混：那一页管的是交易标识。

## 对 Uncertain 的建议

第一版如果以后要换地址或校验和，先点名「哪一版校验和」和「版本是否和这一版配对」。不要默认旧发送者认新串，也不要默认新串已经有 UTXO。

# 模式：签名必须先点名是数学验过、编码合法还是共识收下

**问题：** 产品把「验签过了」写成共识已经收下。用户把库的宽松听成合法集，或把转发策略已经要 DER 听成块里已经要，或把 66 听成 62 / 146 / 34。  
**方案：** 每个验签句先点名问的是曲线上对不对、字节是不是严格 DER，还是共识已经收下。编码立刻失败不是验签失败旧语义。66 不是延展菜谱，也不是低 S，也不是整数版本。  
**适用：** Bitcoin 签名编码文案 / 任何「库验过就算共识」的结算产品。  
**优点：** 用户能指出草稿纸对了和答题卡合法不是同一盏灯。  
**缺点：** 句子变长；不能再用「验签用业界库」交差。  
**项目：** BIP-66：交给 CHECKSIG 族且做 ECDSA 的签必须严格 DER。  
**常见 bug：** 库验过写成已合法；策略写成共识；66 写成 62 / 146 / 34。  
**不确定：** 必须把签名编码写成共识谓词。见 [工作实例](../../tracks/implementation/worked-example-valid-vs-der.md)。

# 模式：把单钥 P2TR 派生三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-86](https://github.com/bitcoin/bips/blob/master/bip-0086.mediawiki)。  
**例**：[派生钥 ≠ 已经是输出钥](../../tracks/implementation/worked-example-derived-vs-output-key.md)。

## 三个名字

1. **内部钥：** 看见派生钥不是已经是输出钥，也不是已经是链上那 32 字节。
2. **不可花承诺：** 看见不需要脚本路径不是已经不承诺脚本路径，也不是已经没有脚本路径。
3. **种子备份：** 看见种子备份不是已经能找回单钥 P2TR；看见已有描述符方案不是已经不必再写本页。

## 为什么要分开叫

官方把派生钥先当成内部钥，再承诺一条不可花脚本路径才得到输出钥，又把「备份里没有路径和脚本信息」写成仍要本页的理由。把它们叫成一个「看见同一份种子就已经能找回 Taproot」，会把钥匙路径和嵌套账户找回一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出单钥地址，先数清问的是派生钥是不是已经等于输出钥、不需要脚本路径是不是已经不承诺，还是种子备份已经能找回，再决定要不要同一次发布。

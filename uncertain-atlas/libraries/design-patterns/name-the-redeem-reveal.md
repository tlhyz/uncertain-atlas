# 模式：脚本哈希必须先点名是链上哈希还是花费时揭开的赎回

**问题：** 产品把「付给 P2SH」写成赎回脚本已经在链上。用户把旧节点 HASH160 EQUAL 通过听成新节点已经再跑，或把哈希对上听成内层已经验过，或把 16 听成地址 / 多重签 / Taproot。  
**方案：** 每个脚本哈希句先点名问的是链上哈希、花费时揭开的赎回，还是旧节点只验哈希。标准转发不是已经执行内层。16 不是 13，也不是 11，也不是钥匙路径。  
**适用：** Bitcoin 付给脚本哈希文案 / 任何「承诺哈希、花费时揭开」的结算产品。  
**优点：** 用户能指出信封上的指纹和里面的纸条不是同一盏灯。  
**缺点：** 句子变长；不能再用「支持 P2SH」交差。  
**项目：** BIP-16：付款人只给哈希；花费人揭开赎回；新节点再跑一遍。  
**常见 bug：** 哈希写成已经揭开；旧节点通过写成新节点已经再跑；16 写成 13 / 11 / Taproot。  
**不确定：** 若做付给哈希，必须把链上哈希 / 花费时揭开 / 旧节点只验哈希分开。见 [工作实例](../../tracks/state-models/worked-example-p2sh-hash-vs-redeem.md)。

# 模式：把路径模板三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-88](https://github.com/bitcoin/bips/blob/master/bip-0088.mediawiki)。  
**例**：[一条派生路径 ≠ 已经是一份路径模板](../../tracks/implementation/worked-example-template-vs-path.md)。

## 三个名字

1. **路径不是模板：** 看见一条派生路径不是已经是一份路径模板，也不是已经能被软件无歧义解析。
2. **写死熟路径不是互操作：** 看见写死了熟路径检查不是已经能换钱包，也不是已经挡住乱派生。
3. **完整不是半截：** 看见以 `m/` 开头的完整模板不是已经是半截模板；看见长度对上不是已经配上。

## 为什么要分开叫

官方把给人看的临时写法和给软件解析的模板写成两件东西，又把硬编码熟路径和可声明约束写成两条路，还把匹配整条、匹配一段、长度必须对齐写成三道门。把它们叫成一个「看见一条路径就已经能约束派生」，会把自称 compatible 已经能互操作和脚本已经该进路径一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果限制派生路径，先数清问的是模板、熟路径表还是完整/半截，再决定要不要同一次发布。

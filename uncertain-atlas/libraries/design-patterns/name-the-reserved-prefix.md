# 设计模式：先点名新返回代码的第一字节

## 一句话

看见「新合约不能以某字节开头」，先问：这一盏灯是新存进账户的第一字节，还是对象格式已经部署。不要把占位写成格式已经上线。

## 问题

`对象格式`、`保留首字节`、`已有代码`、`创建失败` 会被叠成一个词。EIP-3541 只占第一字节，好让以后的格式不会误认分叉前没验过的合约。

## 做法

1. 先写问的是新返回代码的第一字节，还是对象格式已经上线。
2. 再写链上已有同首字节代码有没有被本页改语义。
3. 再写失败看的是返回代码，还是 initcode 自己的开头。
4. 最后才问这是第一字节，还是返回有多长、构造代码有多长。

## 不要和谁弄混

- 不要和 [`name-the-deployed-bound.md`](name-the-deployed-bound.md) 弄混：那一页管的是返回代码有多长；本页管的是返回代码第一字节。
- 不要和 [`name-the-initcode-bound.md`](name-the-initcode-bound.md) 弄混：那一页管的是还没跑的构造代码有多长。
- 不要和 [`name-the-revert-leftover.md`](name-the-revert-leftover.md) 弄混：那一页管的是带回剩余气的回滚 ≠ 已经烧光。

## 对 Uncertain 的建议

第一版如果允许链上创建，先点名返回代码第一字节和对象格式是不是已经上线。不要默认占了首字节就是格式已验，也不要把已有同首字节代码写成已经被改。

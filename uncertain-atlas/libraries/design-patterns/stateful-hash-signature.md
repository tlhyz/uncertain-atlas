# 模式：有状态哈希签名（窄口）

**问题：** 要在无状态 PQ 标准就位前，用「主要靠哈希假设」的签；或固件/发行这种能控制签名环境的口。  
**方案：** XMSS / LMS（RFC 8391 / RFC 8554，轮廓见 SP 800-208）。一片 WOTS+/OTS 叶子只签一次；index 先写入非易失存储，再输出 σ；链上拒绝 `(pk, idx)` 复用。  
**适用：** 签名次数可预测、私钥不离开受控模块、没有热备复制私钥的场景。  
**优点：** 假设面相对「只靠哈希」；公钥可小。  
**缺点：** 状态即安全；崩溃/克隆/导出直接变成伪造窗口；一树签满必须换地址；投票签几乎不适用。  
**项目：** RFC 本身；链上产品例见 QRL 过滤器页（节点拒重复 OTS）。  
**常见 bug：** 先广播后写盘；两台机器恢复同一助记词；把 Table 3 调用次数当成验签毫秒。  
**不确定：** 建议热钱包与验证者投票不要以此为默认。见 `tracks/post-quantum/stateful-hbs.md`。

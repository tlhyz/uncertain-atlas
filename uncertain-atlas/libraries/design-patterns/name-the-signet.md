# 模式：把 signet 三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-325](https://github.com/bitcoin/bips/blob/master/bip-0325.mediawiki)。  
**例**：[signet ≠ 已经是 testnet](../../tracks/implementation/worked-example-signet-vs-testnet.md)。

## 三个名字

1. **可预期的不可靠：** 看见 signet 不是已经是 testnet，也不是已经和主网同一套结算。
2. **有代价：** 看见 signet 不是已经是 regtest；造块没有代价不是已经是本页。
3. **签过：** 看见头上有合法工作量不是已经签过，也不是已经全验证通过。

## 为什么要分开叫

官方把 testnet 的巨大重组和 regtest 的无代价独占写成两种不能当多方长期预演的病，同时又写「只加参数就能连」不是已经验了块签名。把它们叫成一个「看见测试网就已经能当主网」，会把主网身份和跳脚本加速一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写测试网，先数清问的是不可靠形状、谁能控制，还是块签名过了，再决定要不要同一次发布。

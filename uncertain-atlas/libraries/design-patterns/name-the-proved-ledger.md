# 模式：先点名证明覆盖哪一本账

**问题：** 递归或简短证明一出现，产品句容易把「历史合法」「最新余额」「质押快照」「自己的那一页」糊成同一个对象。  
**方案：** 每个证明对象必须写清：覆盖哪一本账（或哪一个状态承诺）、落后最新 Apply 几步、用户页另走哪条路径。递归层与证明系统分开点名。  
**适用：** 任何「验 π 代替重放」的结算或轻客户端文案。  
**优点：** 读者能指出自己还缺什么；升级电路时知道换的是哪一层。  
**缺点：** 句子变长；不能再用「整条链只有 xx kB」交差。  
**项目：** Mina 官方把 staged / SNARKed / staking 分成三个词；Pickles 是递归层，Kimchi 是证明系统。  
**常见 bug：** 验绿写成最新余额；进块写成已被 SNARK 覆盖；Pickles 写成 Kimchi；证明字节写成账户库。  
**不确定：** 可以参考「证明必须点名对象」；第一版不上递归 L1。见 [工作实例](../../tracks/light-clients/worked-example-snarked-vs-staged.md)。

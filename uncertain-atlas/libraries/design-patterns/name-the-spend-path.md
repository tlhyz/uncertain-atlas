# 模式：一把输出多条条件必须先点名走的是哪条花费路径

**问题：** 产品把「Taproot 输出」写成已经解释了脚本树。用户把钥匙路径听成已经揭开有没有脚本，或把脚本路径听成已经摊开全部条件。  
**方案：** 每个 Taproot 句先点名问的是钥匙路径、脚本路径，还是链上那个输出。钥匙路径不揭开有没有脚本树。脚本路径只揭开执行的那一支。  
**适用：** Bitcoin Taproot / 任何「一个输出、多条条件、平常只亮一把钥」的结算文案。  
**优点：** 用户能指出门牌、备用规章、正在用的那一本不是同一盏灯。  
**缺点：** 句子变长；不能再用「Taproot」交差。  
**项目：** BIP-341：钥匙路径不揭树；脚本路径只揭执行叶；两种政策并成一种输出。  
**常见 bug：** 钥匙路径写成已经没有脚本；输出写成已经能分辨 pay-to-pubkey / pay-to-scripthash。  
**不确定：** 若做「一个输出、多条条件」，必须写清平常那次花费揭不揭开树。见 [工作实例](../../tracks/implementation/worked-example-keypath-vs-scriptpath.md)。

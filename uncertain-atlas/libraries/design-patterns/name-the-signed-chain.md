# 模式：链绑定必须先点名是签名哈希还是钱包 JSON

**问题：** 产品把「有 chainId」写成已经防跨链重放。用户把 JSON 字段听成已经进哈希，或把 EIP-155 听成 1559。  
**方案：** 每个链号句先点名问的是九字段签名哈希、旧六字段签，还是钱包展示。旧签仍合法，不是已经防跨链。155 不是 1559。  
**适用：** Ethereum 用户交易签名 / 任何「这条签只能在本链用」的结算文案。  
**优点：** 用户能指出信封上的城名和信纸上签的城名不是同一盏灯。  
**缺点：** 句子变长；不能再用「有 chainId」交差。  
**项目：** EIP-155：应当把 chainid 编进签名哈希；旧六字段方案仍有效。  
**常见 bug：** JSON chainId 写成已经签过；155 写成费用市场。  
**不确定：** 签名预像必须含链绑定。见 [工作实例](../../tracks/crypto/worked-example-chainid-vs-signed.md)。

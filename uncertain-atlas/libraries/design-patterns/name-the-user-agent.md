# 模式：把协议版本和 user agent 三件事说成三个名字

**层次**：网络 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-14](https://github.com/bitcoin/bips/blob/master/bip-0014.mediawiki)。  
**例**：[协议版本 ≠ 客户端版本](../../tracks/network/worked-example-ua-vs-protocol.md)。

## 三个名字

1. **协议版本：** 看见协议版本不是已经是客户端版本，也不是已经是实现版本。
2. **信息牌：** 看见 user agent 不是已经可以按实现改行为。
3. **共用：** 看见同一协议版本不是已经是同一套实现；看见 user agent 栈不是已经是协议能力。

## 为什么要分开叫

官方把「协议从一家客户端的发版节奏拆开」写成动机，同时又禁止按 user agent 换协议。把它们叫成一个「看见版本号就已经知道是哪家」，会把功能协商和 pong 探活一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写对等握手，先数清问的是协议版本、实现号还是信息牌，再决定要不要同一次发布。

# 模式：把去掉六十四分之一说成一个名字

**层次**：实现 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[EIP-150](https://eips.ethereum.org/EIPS/eip-150)。  
**例**：[读树涨价 ≠ 已经换成 63/64](../../tracks/implementation/worked-example-call-63rds-vs-oog.md)。

## 三个名字

1. **读树涨价：** 读状态树的操作码当时标价过低；不是已经是后来的树依赖涨价，也不是已经是本笔冷热。
2. **去掉六十四分之一：** 问超了仍开子调用，只给去掉六十四分之一那一截；不是已经耗尽气，也不是已经没有深度上限。
3. **建议气限：** 建议抬高目标；不是已经是协议帽，也不是官网吞吐已经是事实。

## 为什么要分开叫

官方把涨价、子调用气、建议气限写进一次升级。把它们叫成一个「读树已经齐了」，会把 1884、2929、墙钟、协议帽和调用深度一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做子调用，先点名问的是父帧还剩多少、子执行能拿多少，还是深度上限。

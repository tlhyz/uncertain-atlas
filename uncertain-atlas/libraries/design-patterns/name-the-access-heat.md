# 模式：状态访问必须先点名是本笔第一次、再碰还是下一笔

**问题：** 产品把「冷热访问」写成已经永远热。用户把发送者预填听成任意地址已热，或把本笔再碰听成又是冷的，或把 2929 听成 2930 / 墙钟。  
**方案：** 每个冷热句先点名问的是本笔第一次、本笔再碰，还是下一笔重开。预填不是全城已热。2929 不是可选名单，也不是 gas 已经等于时间。  
**适用：** Ethereum 本笔访问集合文案 / 任何「同一趟熟、下趟重开」的结算产品。  
**优点：** 用户能指出第一家店、回头店和下一天不是同一盏灯。  
**缺点：** 句子变长；不能再用「支持冷热」交差。  
**项目：** EIP-2929：本笔集合；第一次冷，再碰热；回滚退集合。  
**常见 bug：** 预填写成全城已热；本笔热写成下一笔还热；2929 写成 2930。  
**不确定：** 必须把第一次 / 再碰 / 下一笔分开。见 [工作实例](../../tracks/implementation/worked-example-cold-vs-warm.md)。

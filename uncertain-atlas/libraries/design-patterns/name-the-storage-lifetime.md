# 模式：草稿必须先点名是瞬时店、持久店还是 memory

**问题：** 产品把「写过 storage」写成已经进账户。用户把 `TSTORE` 听成落盘，或把「交易结束丢掉」听成本笔里从未存在，或把同合约共用一份店听成 memory。  
**方案：** 每个草稿句先点名问的是本笔合约瞬时店、账户持久店，还是单帧 memory。瞬时店交易结束才清；同合约各帧共用；帧 revert 撤回该段写入。  
**适用：** Ethereum Cancun 之后的 `TLOAD`/`TSTORE` / 任何「交易级、按合约、不落盘」的结算文案。  
**优点：** 用户能指出黑板、铭牌、练习纸不是同一盏灯。  
**缺点：** 句子变长；不能再用「storage」交差。  
**项目：** EIP-1153：行为像 storage，寿命到交易结束；从不序列化进磁盘。  
**常见 bug：** `TSTORE` 写成已经进账户；交易结束丢掉写成本笔从未存在。  
**不确定：** 若做交易级草稿，必须写清三本账。见 [工作实例](../../tracks/state-models/worked-example-transient-vs-storage.md)。

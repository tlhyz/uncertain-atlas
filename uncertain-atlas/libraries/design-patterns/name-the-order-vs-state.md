# 模式：必须点名共识同意的是顺序还是本块状态根

**问题：** 共识先定序、执行后揭开，产品却只说「已经最终」。用户把顺序绿勾听成余额已经和全网交差。  
**方案：** 每个「到了」先点名问的是官方顺序、延迟根，还是已经揭开的本块状态。投机 RPC 另写。  
**适用：** 异步执行、任何「投票时还没 Apply」的结算文案。  
**优点：** 用户能指出墙上贴的是名单还是分数；不会把 `eth_call` 当成协议最终。  
**缺点：** 句子变长；不能再用「异步所以更快最终」交差。  
**项目：** Monad 官方 Asynchronous Execution：共识同意顺序，提案带 D 块前的根，不带本块根。  
**常见 bug：** 顺序写成状态；延迟根写成能证 N；投机 RPC 写成已经最终。  
**不确定：** 第一版可以保持投票前先跑完。若拆泳道，必须点名序还是根。见 [工作实例](../../tracks/consensus/worked-example-order-vs-state.md)。

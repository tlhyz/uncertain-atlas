# 模式：跨链必须先点名停在哪一层 IBC 对象

**问题：** 产品把「开了 IBC」写成已经解释了到账。用户把客户端听成连接，把连接听成通道，把 send 听成对岸已经 recv。  
**方案：** 每个跨链句先点名问的是 ICS-02 客户端、ICS-03 连接、ICS-04 通道，还是数据包。通道对载荷无所知。本链承诺不是对岸 recv。  
**适用：** IBC / 任何「轻客户端 + 握手 + 管道 + 外包投递」的结算文案。  
**优点：** 用户能指出通讯录、备案、管道、信封不是同一盏灯。  
**缺点：** 句子变长；不能再用「跨链了」交差。  
**项目：** cosmos/ibc ICS-02 / ICS-03 / ICS-04。连接定义授权；通道定义排序与恰好一次；包由 relayer 传。  
**常见 bug：** client 写成已开连接；通道写成已兑付；send 写成已 recv。  
**不确定：** 第一版可以不装 IBC。若对照，必须点名停在哪一层。见 [工作实例](../../tracks/economic/worked-example-ibc-client-vs-packet.md)。

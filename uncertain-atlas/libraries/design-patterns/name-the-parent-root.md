# 模式：执行层读共识根必须先点名是父根、当前头还是 finalized

**问题：** 产品把「EVM 能读信标」写成已经解释了当前头或已经最终。用户把头里的父根听成当前信标头，或把合约读到的根听成已经 finalized。  
**方案：** 每个链上信标根句先点名问的是父根、当前头还是 finalized。执行头钉的是父信标块。合约只留一小段，时间戳对不上就没有。  
**适用：** Ethereum 信标根进 EVM / 任何「执行层读共识累加器」的结算文案。  
**优点：** 用户能指出昨天的拓片、今天的门牌、教务处盖章不是同一盏灯。  
**缺点：** 句子变长；不能再用「链上能读共识」交差。  
**项目：** EIP-4788：执行头带父信标根；交易前系统写入；环缓冲按时间戳核对。  
**常见 bug：** 父根写成当前头；合约根写成已经 finalized。  
**不确定：** 若把共识根暴露进执行 VM，必须写清问的是哪一颗、环会不会过期。见 [工作实例](../../tracks/light-clients/worked-example-parent-root-vs-head.md)。

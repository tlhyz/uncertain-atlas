# 模式：只读必须先点名是静态帧还是高级语言只读

**问题：** 产品把「只读调用」写成已经开了虚拟机静态旗。用户把没转账听成已经只读，或把 `view` 听成已经是 STATICCALL。  
**方案：** 每个只读句先点名问的是静态帧、高级语言只读，还是没转账的普通调用。静态里改状态是异常。CALLCODE 带值官方不算改状态，不得写成产品功能。  
**适用：** EVM 调用文案 / 任何「这一层不许改状态」的结算产品。  
**优点：** 用户能指出阅览室、门口的只读牌和没带钱进门不是同一盏灯。  
**缺点：** 句子变长；不能再用「只读」交差。  
**项目：** EIP-214：子执行开静态旗，官方点名的改状态集合异常。  
**常见 bug：** view 写成已经静态；没转账写成已经只读；214 写成 140。  
**不确定：** 第一版必须分开静态帧和高级语言只读。见 [工作实例](../../tracks/implementation/worked-example-static-vs-view.md)。

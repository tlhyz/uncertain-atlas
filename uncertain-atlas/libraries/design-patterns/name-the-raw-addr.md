# 模式：把 raw / addr 三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-385](https://github.com/bitcoin/bips/blob/master/bip-0385.mediawiki)。  
**例**：[raw ≠ 已经具名脚本](../../tracks/implementation/worked-example-raw-vs-named.md)。

## 三个名字

1. **只能顶层的裸脚本：** 看见 raw 不是已经能套进 sh / wsh，也不是已经是具名表达式。
2. **地址包装：** 看见 addr 不是已经能套进 sh / wsh，也不是已经把那份输出脚本写在描述符里。
3. **包一个对象：** 看见一份 raw 或 addr 不是已经是一份 combo，也不是已经是一份钱包策略。

## 为什么要分开叫

官方把 raw 和 addr 都写成只能顶层，又把地址和地址产出的脚本写成两步，还把本页写成包一个对象。把它们叫成一个「看见任意脚本或地址就已经是具名描述符」，会把 combo 和地址已经有输出一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出 raw / addr，先数清问的是裸脚本、地址包装，还是一份包装已经当 combo，再决定要不要同一次发布。

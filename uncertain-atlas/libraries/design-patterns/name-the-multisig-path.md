# 模式：把多签派生层次三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-87](https://github.com/bitcoin/bips/blob/master/bip-0087.mediawiki)。  
**例**：[脚本各走各的路径 ≠ 已经是多签该有的树](../../tracks/implementation/worked-example-multisig-path-vs-script.md)。

## 三个名字

1. **单签那套拆法：** 看见脚本各走各的路径不是已经是多签该有的树，也不是已经不必再带描述符。
2. **脚本不进路径：** 看见路径里的脚本类型不是已经必要，也不是已经是 48 那种多插一层。
3. **种子不够找回：** 看见这份不按脚本拆的树不是已经给单签用，也不是看见主种子就已经够找回。

## 为什么要分开叫

官方把单签按脚本拆路径和 45 那种只认一种脚本写成对多签多余，又把脚本交给描述符、不让它和钥混在同一层，还把本页写成必须同时备描述符且只给多签。把它们叫成一个「看见多签就已经该按脚本拆路径」，会把 48 那种脚本类型层和钱包策略一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出多签派生，先数清问的是脚本还进不进路径、描述符定不定脚本，还是主种子已经够找回，再决定要不要同一次发布。

# 模式：把收据状态码说成一个名字

**层次**：实现 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[EIP-658](https://eips.ethereum.org/EIPS/eip-658)。  
**例**：[收据状态码 ≠ 剩余气](../../tracks/implementation/worked-example-receipt-status-vs-gas.md)。

## 三个名字

1. **收据状态码：** 顶层调用成功或失败；不是剩余气。
2. **中间状态根：** 被换掉的旧栏；不是本页还在印根。
3. **RPC 重放：** 全节点可以问；不是共识字段，也不是轻节点已经能验。

## 为什么要分开叫

官方把状态码写成替换中间根的最小改动，动机是故意回滚让「气烧光才失败」失效。把它们叫成一个「失败已经能看出来」，会把 140、返回缓冲和轻客户端重放一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做出收据，先点名问的是状态码、剩余气，还是返回数据。

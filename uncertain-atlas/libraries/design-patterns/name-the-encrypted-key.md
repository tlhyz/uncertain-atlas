# 模式：把口令保护私钥三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-38](https://github.com/bitcoin/bips/blob/master/bip-0038.mediawiki)。  
**例**：[加密私钥记录 ≠ 已经能用](../../tracks/implementation/worked-example-encrypted-key-vs-usable.md)。

## 三个名字

1. **还缺一样才能用：** 看见加密私钥记录不是已经是私钥，也不是已经能用。
2. **厂家代生成：** 看见椭圆曲线倍点那条路不是已经和「拿已知私钥再加密」是同一条，也不是厂家已经能兑。
3. **明文地址片段：** 看见地址哈希片段 / 这种打印前缀不是已经是地址，也不是已经解开，也不是已经推荐用。

## 为什么要分开叫

官方把「还缺口令」写成记录本身的定义，又把两条编法和厂家只知道派生串写成不同对象，还把明文相关性和解开后才能得到完整地址写成两件事。把它们叫成一个「看见加密串就已经能花」，会把助记词已经是种子一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人可打印的冷备份，先数清问的是记录、厂家能不能兑、明文片段是不是地址，再决定要不要同一次发布。官方评论已写一致不鼓励实现。

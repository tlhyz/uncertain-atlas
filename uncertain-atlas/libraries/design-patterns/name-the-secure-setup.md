# 模式：把安全多签开户三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-129](https://github.com/bitcoin/bips/blob/master/bip-0129.mediawiki)。  
**例**：[部分签名包 ≠ 已经是跨厂安全多签开户](../../tracks/implementation/worked-example-setup-vs-psbt.md)。

## 三个名字

1. **签流程不是开户：** 看见部分签名包不是已经是跨厂安全多签开户，也不是已经核过成员和门限。
2. **指纹不是精确比对：** 看见指纹对上不是已经核过 KEY；看见第一地址不是各方已经确认同一份。
3. **TOKEN 不是种子：** 看见 TOKEN 不是已经是钱包种子；看见存进签名器不是已经防篡改，也不是已经会用这份配置去长地址。

## 为什么要分开叫

官方把 174 理顺的签流程和仍缺的跨厂开户写成两件事，又把精确比对、第一地址确认、各方互核写成三道门，还把 TOKEN 和种子助记词、把存盘与以后长地址划出本页。把它们叫成一个「看见部分签名包就已经开好了多签」，会把登记已经批准这笔花和主种子已经够找回一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做跨设备多方开户，先数清问的是签流程、精确比对还是会话秘密，再决定要不要同一次发布。

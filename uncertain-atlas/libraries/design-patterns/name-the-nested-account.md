# 模式：把嵌套隔离见证三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-49](https://github.com/bitcoin/bips/blob/master/bip-0049.mediawiki)。  
**例**：[嵌套账户 ≠ 已经能挂在旧账户上找回](../../tracks/implementation/worked-example-nested-vs-same-account.md)。

## 三个名字

1. **漏币：** 看见同一套 BIP44 账户再加隔离见证写法不是已经能找回这些币。
2. **显眼失败：** 看见专用账户 / 换了用途不是已经向后兼容；不会本页的钱包根本发现不了。
3. **不必核余额：** 看见账户出现了不是已经齐；官方要的是要么出现、要么完全不出现。

## 为什么要分开叫

官方把「挂在旧账户上」写成可能账户出现却漏未花输出，所以故意另开专用账户，失败更显眼。把它们叫成一个「看见同一份种子就已经能在另一家找回」，会把用途层和账户发现一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果换脚本类型，先数清问的是旧账户还能不能找回、失败显不显眼，还是余额已经齐，再决定要不要同一次发布。

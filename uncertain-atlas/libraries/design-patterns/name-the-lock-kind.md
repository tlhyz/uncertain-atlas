# 模式：时间锁必须先点名是交易字段还是输出脚本

**问题：** 产品把「填了 nLockTime」写成输出已经锁住。用户把将来能花听成现在不能花，或把 CLTV 听成已经在跟墙上现在比。  
**方案：** 每个绝对时间锁句先点名问的是花费交易的 nLockTime，还是输出脚本里的 CLTV。CLTV 比的是本笔 nLockTime。输入 final 不是锁已经生效。  
**适用：** Bitcoin 绝对时间锁 / 任何「输出在某点之前不能花」的结算文案。  
**优点：** 用户能指出票上的时间和门上的锁不是同一盏灯。  
**缺点：** 句子变长；不能再用「有 locktime」交差。  
**项目：** BIP-65：CLTV 让输出在未来点之前花不掉；nLockTime 只能证明将来可能花。  
**常见 bug：** 交易字段写成输出已锁；CLTV 写成看现在。  
**不确定：** 若做绝对时间锁，必须写在输出脚本上。见 [工作实例](../../tracks/state-models/worked-example-cltv-vs-nlocktime.md)。

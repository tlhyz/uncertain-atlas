# 模式：把发现要记录三件事说成三个名字

**层次**：网络 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[EIP-868](https://eips.ethereum.org/EIPS/eip-868)。  
**例**：[发现要记录 ≠ 已经有](../../tracks/network/worked-example-enr-request-vs-have.md)。

## 三个名字

1. **ping 序号：** 通告发送方当前记录序号；不是已经有记录。
2. **请求 / 答复：** 要当前一份，并核是答复者签的；不是已经解析。
3. **查找再要：** FindNode 找到人之后再请求；不是已经有记录，也不是已经没有放大。

## 为什么要分开叫

官方把通告、索取、防护写进一次发现扩展，但每一件钉的是不同旋钮。把它们叫成一个「发现已经拿到最新记录」，会把记录格式、分叉标识、向前兼容和握手配额一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做发现要记录，先数清问的是通告序号、请求答复，还是查找路径，再决定要不要同一次发布。

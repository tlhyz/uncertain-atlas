# 模式：软分叉必须先点名是示意、锁定、激活还是失败

**问题：** 产品把「版本位置上」写成软分叉已经激活。用户把 LOCKED_IN 听成新规则已经强制，或把 9 听成 34 整数版本 / 被部署的那条规则。  
**方案：** 每个激活句先点名问的是示意、锁定、激活，还是失败。置位不是锁定。锁定再过一个调整窗才激活。本块不看自己的位。9 不是 34，也不是那条新规则。  
**适用：** Bitcoin 版本位文案 / 任何「举手、登记、才换尺子」的结算升级。  
**优点：** 用户能指出举手和已经换尺子不是同一盏灯。  
**缺点：** 句子变长；不能再用「用版本位激活」交差。  
**项目：** BIP-9：DEFINED / STARTED / LOCKED_IN / ACTIVE / FAILED。  
**常见 bug：** 置位写成已锁定；LOCKED_IN 写成已激活；9 写成 34 或写成脚本规则。  
**不确定：** 若做软分叉示意，必须把四态分开。见 [工作实例](../../tracks/implementation/worked-example-versionbit-vs-active.md)。

# 模式：把用途层三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-43](https://github.com/bitcoin/bips/blob/master/bip-0043.mediawiki)。  
**例**：[BIP32 compatible ≠ 已经能互操作](../../tracks/implementation/worked-example-purpose-vs-compatible.md)。

## 三个名字

1. **互操作：** 看见 BIP32 compatible 不是已经能互操作，也不是已经是同一套逻辑结构。
2. **用途：** 看见自称 BIPxx compatible / 只实现了其中一部分不是已经是那份 BIP 写的结构。
3. **前缀：** 看见同一套扩展钥前缀不是已经是比特币专用，也不是已经是 BIP32 默认账户。

## 为什么要分开叫

官方把「自称兼容」写成相当没用，因为逻辑结构可以不一样；又要求有限结构另写 BIP、另给用途。把它们叫成一个「看见 BIP32 就已经能互操作」，会把花费能力和描述符一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出分层钱包，先数清问的是兼容声明、用途层，还是花费能力，再决定要不要同一次发布。

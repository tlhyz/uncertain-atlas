# 模式：再声明的罚没必须点名谁定义「作恶」

**问题：** 产品把 restake / 共享安全写成已经和 Casper 或中继协议同一把尺子。用户把「也被罚了」听成两票谓词或脚本锁。  
**方案：** 每个罚没先点名问的是 Casper 关系、CometBFT 证据、Bitcoin 脚本，还是 AVS 自定条件。写出是否必须客观可归属、协议有没有否决。  
**适用：** 同一份底层质押被第二份声明盯着的结算文案。  
**优点：** 用户能指出扣的是课外班保证金，还是总务处那套出席签。  
**缺点：** 句子变长；不能再用「以太坊共享安全」交差。  
**项目：** ELIP-002：AVS 可以任何理由罚，不必链上可证；协议不提供否决。Unique Stake 一次只分给一个 AVS。  
**常见 bug：** restake 写成另一条信标；AVS 罚没写成 Casper；协议否决写成已有。  
**不确定：** 第一版不要把任意 AVS 再声明当默认模块。若对照，必须点名证据形状和谁执行。见 [工作实例](../../tracks/economic/worked-example-avs-slash-vs-casper.md)。

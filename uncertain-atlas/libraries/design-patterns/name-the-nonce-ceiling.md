# 模式：nonce 必须先点名是当前序号、上限灯还是下一笔还能发

**问题：** 产品把「账户有 nonce」写成永远还能加一。用户把很大听成没有顶，或把客户端窄整数听成共识已经写了上限，或把 2681 听成 155。  
**方案：** 每个 nonce 句先点名问的是当前序号、规范上限，还是下一笔还能不能发。交易达到上限是整笔非法；创建指令碰到上限是栈上推 0。客户端宽度不是共识已经有界。  
**适用：** 账户模型文案 / 任何「序号有顶」的结算产品。  
**优点：** 用户能指出柜台号、最后一张票和下一张票不是同一盏灯。  
**缺点：** 句子变长；不能再用「有 nonce」交差。  
**项目：** EIP-2681：账户 nonce 限制在规范写死的有限区间。  
**常见 bug：** 很大写成还能加；客户端窄写成共识已写；2681 写成 155。  
**不确定：** 若用账户序号，必须写死上限，并分开交易非法和创建失败。见 [工作实例](../../tracks/state-models/worked-example-max-nonce-vs-next.md)。

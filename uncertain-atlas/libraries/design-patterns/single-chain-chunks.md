# 模式：一条链上的分片块（chunk）

**问题：** 每条分片自养一条链，则每条都要自己的分叉选择；信标链与分片链的规则必须分开测、分开对。Nightshade 论文把这写成旧分片模型的复杂度。  
**方案：** 全网仍是**一条**块链。一个高度的块**逻辑上**包含所有分片的交易，**物理上**每分片最多一个 chunk；缺 chunk 的分片这一高度不推进执行。  
**适用：** 想水平切执行/状态，又不想维护 N 套分叉选择。  
**优点：** 规范序仍挂在一个块哈希上；「到了」可以先问这个块，再问该分片的 chunk 是否真在。  
**缺点：** 块头轻、体在 chunk 网上；DA 要另做（纠删/分片件）；跟踪全分片的出块者与只跟踪一分片的人假设不同。  
**项目：** NEAR Nightshade（论文 + nearcore `chain/chunks`：一块最多每分片一个 chunk；Reed–Solomon 出 PartialEncodedChunk）。  
**常见 bug：** 把 collator / 分片 RPC 当成最终；把「块已出」写成「该分片本高度已执行」。  
**不确定：** 第一版结算机若不分片，不需要本模式。若以后切执行，先写「一块一序、chunk 可缺」再谈吞吐。对照 Polkadot：那是中继 + 平行链，不是一条块里塞 chunk。

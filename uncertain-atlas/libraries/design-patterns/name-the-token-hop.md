# 模式：同质跨链必须先点名停在托管、铸券、烧掉还是解锁

**问题：** 产品把「跨链转账」写成已经解释了原币到账。用户把源链托管听成对岸已经有原币，或把带通道前缀的券听成原来的 denom。  
**方案：** 每个 ICS-20 句先点名问的是托管、铸券、烧掉还是解锁。source 是托管+对岸铸券。sink 是烧券+对岸解锁。券名叠端口/通道，不是原名。  
**适用：** IBC 同质转账 / 任何「锁在这边、对岸开收据」的结算文案。  
**优点：** 用户能指出保险箱、收据、原徽章不是同一盏灯。  
**缺点：** 句子变长；不能再用「跨链到账」交差。  
**项目：** ICS-20：source 托管并铸券；sink 烧掉并解锁；超时或失败 ack 退款。  
**常见 bug：** 托管写成对岸已铸；券名写成原 denom。  
**不确定：** 若做同质跨链，必须写清四步和券名。见 [工作实例](../../tracks/economic/worked-example-escrow-vs-voucher.md)。

# 模式：把 dummy 栈元素三件事说成三个名字

**层次**：共识 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-147](https://github.com/bitcoin/bips/blob/master/bip-0147.mediawiki)。  
**例**：[dummy ≠ 已经随便填](../../tracks/implementation/worked-example-dummy-vs-empty.md)。

## 三个名字

1. **空：** 看见多余栈元素不是已经随便填；必须是空字节，否则脚本立刻为假。
2. **见证：** 看见隔离见证 / txid 不能被第三方改不是已经没有这条延展；它仍改 wtxid。
3. **门：** 看见转发策略已经要空 dummy 不是已经是共识。

## 为什么要分开叫

官方把「验签之后多吃一个却不看」写成缺陷，同时又写隔离见证之后这条仍改 wtxid，并把早就当策略执行写成兼容事实。把它们叫成一个「多重签已经不可延展」，会把 DER、txid/wtxid 和策略大门一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写多重签，先数清问的是空 dummy、wtxid 还是共识门，再决定要不要同一次发布。

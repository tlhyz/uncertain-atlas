# 模式：把旧式签消息三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-137](https://github.com/bitcoin/bips/blob/master/bip-0137.mediawiki)。  
**例**：[本页这种签消息 ≠ 已经是 322](../../tracks/lifecycle/worked-example-legacy-sign-vs-322.md)。

## 三个名字

1. **兼容旧实现的签：** 看见本页这种签消息不是已经是 322，也不是已经是 258 那种控制资金。
2. **头字节上的种类：** 看见头字节标了地址种类不是已经有那条地址，也不是已经有一笔能花的输出。
3. **旧习惯还不够：** 看见旧的 P2PKH 签消息习惯不是已经是本页，也不是已经互操作。

## 为什么要分开叫

官方自己把本页写成兼容旧实现、把后继格式写成另一页，又把「能区分地址种类」和「链上已经有那条地址」写成两件事，还把旧习惯「大致懂」和旧校验器会拒新头写成不同对象。把它们叫成一个「看见用私钥签过就已经是 322」，会把签过就已经控制资金一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果让人签一条离线消息，先数清问的是不是 322、头字节是不是地址、旧习惯够不够，再决定要不要同一次发布。

# 模式：预声明访问必须先点名是计划、列表外还是已经读过

**问题：** 产品把「支持访问列表」写成已经访问过。用户把列入听成已经读过，或把列表外听成已经禁止，或把 2930 听成 2718 / 1559。  
**方案：** 每个访问列表句先点名问的是计划访问、列表外仍能碰，还是已经读到值。列入不是已经访问。2930 不是信封，也不是费用市场。  
**适用：** Ethereum 本笔计划访问文案 / 任何「先列名单再开跑」的结算产品。  
**优点：** 用户能指出购物清单、没写上的店和已经逛完不是同一盏灯。  
**缺点：** 句子变长；不能再用「支持访问列表」交差。  
**项目：** EIP-2930：计划访问的地址和键；列表外仍可访问，只是更贵。  
**常见 bug：** 列入写成已访问；列表外写成已禁止；2930 写成 1559。  
**不确定：** 必须把计划 / 列表外 / 已经读过分开。见 [工作实例](../../tracks/implementation/worked-example-listed-vs-accessed.md)。

# 模式：把 Prepare 改列表三件事说成三个名字

**层次**：实现 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[ABCI++ Methods](https://github.com/cometbft/cometbft/blob/main/spec/abci/abci++_methods.md) PrepareProposal Usage。  
**例**：[从提案拿掉 tx ≠ 已经从内存池删掉](../../tracks/implementation/worked-example-prepare-drop-vs-mempool.md)。

## 三个名字

1. **从提案拿掉 tx 不是已经从内存池删掉：** 看见本块不提不是已经永远不提。
2. **往提案加了一笔新的不是已经进了内存池：** 看见回包里有它不是已经过了 CheckTx。
3. **把 t1 改成 t2 不是已经还能按 t1 查到：** 看见 t2 进了块不是已经有人知道来源。

## 为什么要分开叫

官方把从提案拿掉不会出池、往提案加新的不会进池、改成另一笔可能丢掉可追踪性写成三件事。把它们叫成一个「看见本块不提就已经从池里删掉」，会把提案收了、整池可见和四门一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「看见本块不提就已经从池里删掉」，先数清问的是从提案拿掉 tx 不是已经从内存池删掉、往提案加了一笔新的不是已经进了内存池，还是把 t1 改成 t2 不是已经还能按 t1 查到，再决定要不要同一次发布。

# 设计模式：先点名描述符

## 一句话

看见钱包备份或导出，先问：这一份是密钥材料、输出脚本描述符，还是已经编成的收款地址。不要把有钥写成已经知道该看哪种脚本。

## 问题

`助记词`、`xpub`、`描述符`、`地址` 会被叠成一个词。BIP-380 把脚本类型和派生路径写成必须显式出现的语言，正是因为只备份钥不够。

## 做法

1. 先写有没有密钥材料。
2. 再写有没有显式的脚本类型。
3. 再写有没有显式的派生路径。
4. 最后才问：这是不是已经编成地址，以及链上有没有输出。

## 不要和谁弄混

- 不要和 [`name-the-mnemonic-seed.md`](name-the-mnemonic-seed.md) 弄混：那一页管的是看见词 ≠ 已经是种子；本页管的是种子齐了 ≠ 已经知道脚本。
- 不要和 [`name-the-extended-key.md`](name-the-extended-key.md) 弄混：那一页管的是看见扩展公钥 ≠ 已经能花。
- 不要和 [`name-the-address-object.md`](name-the-address-object.md) 弄混：那一页管的是看见地址 ≠ 已经有 UTXO。

## 对 Uncertain 的建议

第一版如果导出钱包，先点名「密钥」和「脚本类型」。不要默认助记词备份已经覆盖收款脚本，也不要把描述符写成已经是地址。

# 模式：高度必须先点名是头、coinbase 第一项还是奖励年龄

**问题：** 产品把「看见块头」写成高度已经在头上。用户把加大 version 听成 BIP-9，或把 coinbase 写了高度听成已经能花。  
**方案：** 每个高度句先点名问的是头、coinbase 第一项，还是成熟窗。整数 version 一次一条，不是位向量。交易 version 非标准不是共识已经禁止。  
**适用：** Bitcoin 块高度文案 / 任何「头不带高度、高度写在出块交易里」的结算产品。  
**优点：** 用户能指出门框、信封和能不能花不是同一盏灯。  
**缺点：** 句子变长；不能再用「块有高度」交差。  
**项目：** BIP-34：coinbase 第一项写本块高度；块 version 加大。  
**常见 bug：** 头写成已带高度；34 写成 9；写了高度写成已能花。  
**不确定：** 若头不带高度，必须写清高度承诺在哪。见 [工作实例](../../tracks/implementation/worked-example-coinbase-height-vs-header.md)。

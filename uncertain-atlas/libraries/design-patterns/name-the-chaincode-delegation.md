# 模式：把链码委托三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-89](https://github.com/bitcoin/bips/blob/master/bip-0089.mediawiki)。  
**例**：[共享了扩展公钥 ≠ 已经是链码委托](../../tracks/implementation/worked-example-delegation-vs-xpub.md)。

## 三个名字

1. **委托的是链码：** 看见共享了扩展公钥不是已经是本页，也不是已经对共同签名人藏住余额。交出链码不是交出签名权。
2. **委托方没有扩展钥：** 看见委托方那把非扩展钥对不是已经是扩展公钥，也不是已经能推出整棵钱包。
3. **本笔微调不是整棵树：** 看见这一输入的微调不是已经看见整棵派生，也不是已经是盲签，也不是已经核过找零金额。

## 为什么要分开叫

官方把分扩展公钥就能扫链和只委托链码写成两件相反的事，又把委托方不得持有链码、受托方的扩展公钥不得回传写成两道门，还把非盲只看见本笔、盲签看不见消息、找零微调另算写成三档。把它们叫成一个「看见共享了扩展公钥就已经对托管方藏住余额」，会把扩展公钥已经能花和聚合钥已经是扩展公钥一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果让一方替另一方持链码，先数清问的是委托对象、非扩展钥还是本笔微调，再决定要不要同一次发布。

# 模式：共识往执行推余额必须先点名是系统操作还是用户交易

**问题：** 产品把「提款到账」写成已经解释了用户转账。用户把信标链出队听成执行账户已加钱，或把无 gas 听成已经跑过合约。  
**方案：** 每个提款句先点名问的是系统操作、用户交易，还是共识层出队。操作由系统发起，活在交易域之外，无条件加余额，不得失败，没有 gas。  
**适用：** Ethereum 信标提款 / 任何「共识层往执行层推余额」的结算文案。  
**优点：** 用户能指出奖金划账、顾客汇款、出队通知不是同一盏灯。  
**缺点：** 句子变长；不能再用「提款」交差。  
**项目：** EIP-4895：push 的系统操作；与用户交易分域；用户交易之后才处理。  
**常见 bug：** 提款写成用户交易；出队写成执行已到账。  
**不确定：** 若让共识往执行推余额，必须写清这是系统操作还是用户交易。见 [工作实例](../../tracks/economic/worked-example-withdrawal-vs-tx.md)。

# 模式：把输入输出字典序三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-69](https://github.com/bitcoin/bips/blob/master/bip-0069.mediawiki)。  
**例**：[自家习惯顺序 ≠ 已经是字典序标准](../../tracks/implementation/worked-example-order-vs-lex.md)。

## 三个名字

1. **习惯顺序：** 看见自家习惯的输入输出顺序不是已经是本页，也不是已经没有指纹。
2. **信息标准：** 看见按字典序排了不是已经是共识，也不是已经决定这笔能不能花。
3. **确定不是私人：** 看见按字典序排了不是已经私人，也不是已经是随机打乱，也不是已经是 CoinJoin。

## 为什么要分开叫

官方把没有标准就会漏指纹写成动机，把顺序不影响功能写成适用范围，又把确定可审计和随机打乱写成两条相反的路。把它们叫成一个「看见排过就已经没有指纹」，会把 payjoin 提案不得打乱和策略已经是共识一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果规定输入输出怎么排，先数清问的是习惯是不是已经等于标准、标准是不是已经等于共识，还是排过是不是已经私人，再决定要不要同一次发布。

# 模式：把提议者选择三件事说成三个名字

**层次**：共识 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[Proposer Selection Procedure](https://github.com/cometbft/cometbft/blob/main/spec/consensus/proposer-selection.md)。  
**例**：[同一高度换轮 ≠ 已经换了集合](../../tracks/consensus/worked-example-round-vs-set.md)。

## 三个名字

1. **同一套：** 看见同一高度换轮不是已经换成应用刚回的那套。
2. **往后放：** 看见新验证者加进来不是已经能靠退出再加入跳到队头。
3. **压住范围：** 看见优先级差被缩放不是已经按人头轮，也不是已经没有优先级。

## 为什么要分开叫

官方把同一高度各轮共用一套、新加入往后放、压住优先级范围写成三件事。把它们叫成一个「看见换轮就已经换了名单」，会把生效延迟和提议者字段一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「该谁出块」，先数清问的是同一套、往后放，还是压住范围，再决定要不要同一次发布。

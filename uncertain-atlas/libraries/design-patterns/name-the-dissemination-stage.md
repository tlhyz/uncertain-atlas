# 模式：传播与排序必须点名停在哪一段

**问题：** 内存池、批次传播、已认证批次、元数据排序、并行执行、落盘被收成一句「已经进共识」。  
**方案：** 每个「到了」先点名问的是缓冲、传播、批次认证、排序、执行还是持久化。数据传播与元数据排序分开写。  
**适用：** Quorum Store / Narwhal 味拆层、任何「先散数据再排目录」的结算文案。  
**优点：** 用户能指出手里是货还是目录；不会把批次认证听成 commit QC。  
**缺点：** 句子变长；不能再用「Quorum」一个词交差。  
**项目：** Aptos Quorum Store；官方词汇表：传播批次，共识排已认证批次。  
**常见 bug：** 已认证批次写成 L；传播齐写成已提交；去掉领袖瓶颈写成没有领袖。  
**不确定：** 可以参考「到了必须点名对象」；第一版可以不拆传播层。见 [工作实例](../../tracks/consensus/worked-example-quorum-store-vs-order.md)。

# 模式：把账户发现三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-44](https://github.com/bitcoin/bips/blob/master/bip-0044.mediawiki)。  
**例**：[账户 ≠ 已经发现完](../../tracks/implementation/worked-example-account-vs-discovered.md)。

## 三个名字

1. **分币：** 看见同一份种子不是已经是同一条币，也不是已经可以混用地址。
2. **过往：** 看见下一个账户号不是已经有过往，也不是已经和上一户同一身份。
3. **发现：** 看见余额为零不是已经发现完；算法看过往，不看余额。

## 为什么要分开叫

官方把「同一片空间给多种币」写成有坏处，又把开新户绑在上一户已经有交易过往上，还把发现写成看过往、不看余额。把它们叫成一个「看见种子就已经扫完」，会把用途层和花费能力一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出多账户，先数清问的是哪一条币、哪一户过往，还是发现已经停，再决定要不要同一次发布。

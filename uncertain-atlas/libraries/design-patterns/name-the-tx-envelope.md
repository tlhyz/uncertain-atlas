# 模式：交易编码必须先点名是类型字节、载荷还是旧式列表

**问题：** 产品把「支持类型交易」写成已经解开内层，或把 2718 写成 1559。用户把类型号听成袋里的信，或把旧明信片听成已经装进新信封。  
**方案：** 每个编码句先点名问的是类型字节、不透明载荷，还是旧式列表。类型号不是已经解开。2718 不是 1559，也不是 155。  
**适用：** Ethereum 交易编码文案 / 任何「先盖袋号再装信」的结算产品。  
**优点：** 用户能指出袋号、袋里的信和旧明信片不是同一盏灯。  
**缺点：** 句子变长；不能再用「支持 2718」交差。  
**项目：** EIP-2718：类型字节再接不透明载荷；旧式列表仍合法。  
**常见 bug：** 类型号写成已解开；2718 写成费用市场。  
**不确定：** 必须把类型 / 载荷 / 旧式列表分开。见 [工作实例](../../tracks/implementation/worked-example-typed-vs-legacy.md)。

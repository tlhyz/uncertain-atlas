# 模式：把头通告偏好三件事说成三个名字

**层次**：网络 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-130](https://github.com/bitcoin/bips/blob/master/bip-0130.mediawiki)。  
**例**：[头通告偏好 ≠ 已经有块](../../tracks/network/worked-example-sendheaders-vs-have.md)。

## 三个名字

1. **更想收头：** 新块通告走头消息，不走库存通告。不是已经有块。
2. **许可不是必须：** 收到之后可以改口，也可以不改。不是已经照做。
3. **尖上 / 重组先发头：** 少一次回头要头；中间块能立刻要。不是已经有中间块。

## 为什么要分开叫

官方把偏好、许可、重组先发头写进一次空消息，但每一件钉的是不同旋钮。把它们叫成一个「发了偏好就已经看见新块」，会把宣布≠收到、compact 拼块和后继地址偏好一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做头通告偏好，先数清问的是信号、许可，还是已经有块，再决定要不要同一次发布。

# 模式：把 DNS 付款指示三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-353](https://github.com/bitcoin/bips/blob/master/bip-0353.mediawiki)。  
**例**：[可读名字 ≠ 已经该走 DNS](../../tracks/lifecycle/worked-example-dns-name-vs-instruction.md)。

## 三个名字

1. **优先：** 看见可读名字不是已经该走 DNS；有地址或 URI 就必须优先用那个。
2. **记录：** 看见 TXT 不是已经是合法指示；必须自己把 DNSSEC 验到根。
3. **当前：** 看见缓存或复制了名字不是已经是当前那条 URI。

## 为什么要分开叫

官方把「有明确地址就不得优先走 DNS」写成硬规则，同时又要求自己验到根，并把缓存钉在 TTL 上。把它们叫成一个「看见名字就已经能付」，会把付款 URI、远程取单和静默付款码一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写可读收款名，先数清问的是优先、记录还是当前 URI，再决定要不要同一次发布。

# 模式：把通用签消息三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-322](https://github.com/bitcoin/bips/blob/master/bip-0322.mediawiki)。  
**例**：[签过的消息 ≠ 已经控制资金](../../tracks/lifecycle/worked-example-signed-message-vs-control.md)。

## 三个名字

1. **签过：** 看见签过的消息不是已经证明能控制资金，也不是已经肯签真正的交易。
2. **发票地址将来控制：** 本页只谈打到这个地址的钱；证明发过上一笔做不到。
3. **清单：** 资金证明清单自选，不齐，未花要问链。

## 为什么要分开叫

官方把「没有任何签消息协议真能证明控制资金」写成限制，同时又只覆盖发票地址将来控制，并写下清单不齐、未花要问链。把它们叫成一个「签过就已经能花」，会把地址串、部分签名包和付款 URI 一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写签消息，先数清问的是签过、发票地址将来控制，还是链上未花，再决定要不要同一次发布。

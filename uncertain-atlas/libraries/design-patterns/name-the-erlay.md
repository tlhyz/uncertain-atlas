# 模式：把通告集合对账三件事说成三个名字

**层次**：网络 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-330](https://github.com/bitcoin/bips/blob/master/bip-0330.mediawiki)。  
**例**：[对账素描 ≠ 已经有交易](../../tracks/network/worked-example-erlay-vs-have.md)。

## 三个名字

1. **通告集合对账积木：** 两端对齐本来要通告的集合。Erlay 仍向一小撮邻居发洪水。不是已经代替库存通告。
2. **握手信号：** 应答之前表态，并且必须带着 wtxidrelay。不是已经在对账。
3. **素描与退回：** 解得开仍要再发库存通告；解不开退回洪水。不是已经有那些交易。

## 为什么要分开叫

官方把省带宽的对账、握手信号、素描解码写进一次转发协议，但每一件钉的是不同旋钮。把它们叫成一个「对账已经代替洪水」，会把按 wtxid 通告、费率过滤器和宣布≠收到一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果做通告集合对账，先数清问的是积木、握手信号，还是已经有交易，再决定要不要同一次发布。草案不是已经在主网默认打开。

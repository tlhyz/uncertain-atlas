# 模式：把非隔离见证描述符三件事说成三个名字

**层次**：应用 / 命名。  
**分类**：事实（官方拆法）+ 建议（产品）。  
**来源**：[BIP-381](https://github.com/bitcoin/bips/blob/master/bip-0381.mediawiki)。  
**例**：[pk ≠ 已经和 pkh / sh 同一套放置](../../tracks/implementation/worked-example-pk-vs-toplevel.md)。

## 三个名字

1. **放置：** 看见 pk 不是已经是 pkh 那种放置，也不是已经是 sh 那种只能顶层。
2. **另造的赎回脚本：** 看见 sh 产出不是已经有赎回脚本。
3. **眼熟不是兼容：** 看见熟悉的标准脚本不是已经能互操作。

## 为什么要分开叫

官方把三种表达式的出现位置写成三套规则，又把 `sh` 的输出脚本和另造的赎回脚本写成两份对象，还把「全新描述符」和「标准脚本眼熟」写成两句。把它们叫成一个「看见熟悉脚本就已经能互操作」，会把 16 那种哈希和描述符总语法一起吞掉。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出非隔离见证描述符，先数清问的是放置、另造的赎回脚本，还是眼熟已经当兼容，再决定要不要同一次发布。

# 实例：单元测试全绿，重复输入仍能过

目的 A/B。不是考试。结构取自 CVE-2018-17144 的**形状**，数字不是复现步骤。  
先修：L9.7、L9.9、博物馆 CVE-2018-17144。

---

## 故事

阿安的节点 CI 全绿：普通转账、找零、标准脚本都过。  
攻击者构造：同一笔交易的 vin 里，**同一个 prevout 出现两次**。幸福路径从来没有这种信封。

实现某条检查漏了。节点接受块，供给偷偷变多。  
PoW 还在，签名还在，覆盖率还很高。  
**层：实现 + 测试套件。** 「测试通过所以不会双花」是假学习第 9 条。

---

## 六种考试各自看见什么

| 种类 | 对本故事 |
|---|---|
| 单元 | 通常绿（没人写重复 vin） |
| 性质 / invariant | 若写下「无双花 / 供给守恒」且生成器会造重复引用，应红 |
| 模糊 | 可能撞上，也可能永远撞不上语义洞 |
| 差分 | 第二实现若拒、第一实现收 → 红；两家抄同一漏则仍绿 |
| 混沌 | 断电测不着通胀 |
| 变异 | 删掉重复检查后若测试仍绿，套件是摆设 |

## 五层

| 层 | 本故事 |
|---|---|
| 密码 | 仍可成立 |
| 协议 | 意图仍是固定供给 |
| 实现 | 检查漏了 |
| 部署 | 升级没跟上的节点继续收 |
| 经济 | 多出来的币按市价计，不是按覆盖率计 |

## 「不确定」测试句（建议）

```text
∀ 块. 同一花费授权在 vin 中出现两次 ⇒ 共识拒绝
∀ 块. Apply 后供给变化 ∈ 协议允许的发行集合
第二条实现对同一恶意块必须同拒
允许 skip 差分 ⇔ 日志写明「没有第二实现」，不得当通过
```

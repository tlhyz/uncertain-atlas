# 看见请求承诺不是已经由共识层处理完

> 类型：worked example（执行层请求总线 / 头承诺）  
> 范围：只写 [EIP-7685](https://eips.ethereum.org/EIPS/eip-7685) 官方页已经写明的对象。不写怎样造请求、怎样伪造承诺、怎样跳过共识层再验。  
> 五层：协议（头上多一个请求承诺；请求事后交给共识层） / 实现（空载荷不进承诺；类型升序） / 钱包（看见承诺不是已经办完） / 应用（请求不是已经有权单独促成动作） / 威胁（把看见承诺写成已经处理）。  
> 分类标签：事实 / 推断 / 建议 已分开。  
> 对读：[`../../libraries/invariants/README.md`](../../libraries/invariants/README.md) 不变量 192；[`../../libraries/adversarial-corpus/README.md`](../../libraries/adversarial-corpus/README.md) C196；[`../../libraries/anti-patterns/request-sold-as-action.md`](../../libraries/anti-patterns/request-sold-as-action.md)；[`../../libraries/design-patterns/name-the-request-bus.md`](../../libraries/design-patterns/name-the-request-bus.md)；课 [`../../courses/level-05-ethereum/L05-M02-el-cl-finality.md`](../../courses/level-05-ethereum/L05-M02-el-cl-finality.md)；档案 [`../../protocols/ethereum/README.md`](../../protocols/ethereum/README.md)。

## 事实（官方页能指回去）

1. [EIP-7685](https://eips.ethereum.org/EIPS/eip-7685) 题目是 General purpose execution layer requests。官方 EIP。不另写 19 节。
2. 官方页写：定义一套通用框架，用来存放合约触发的请求。执行头增加**一个**字段存放请求信息。
3. 官方页写：这些请求稍后暴露给共识层，由共识层再处理每一条。头上有承诺不是已经由共识层处理完。
4. 官方页写：一条请求由类型字节接上不透明载荷。每种请求类型自己定义载荷格式。看见类型字节不是已经解开载荷。
5. 官方页写：处理一块时，系统会产出多种类型的请求，累积进本块请求列表，再算头上的承诺。
6. 官方页写：算承诺时，只有载荷非空的项进入中间表；只剩类型字节、后面没有载荷的项被排除。空载荷被排除不是已经没有过这种类型。
7. 官方页写：中间表必须按类型字节升序。同一类型内部的顺序本页不规定，留给各类型自己写。
8. 官方页写：本页不严格规定请求从哪来、何时/如何验完。官方建议：执行层做它能做的核验，再交给共识层继续核验。
9. 官方页写：它们只被称为「请求」，**并不自己带有单方面促成动作的权力**。看见请求不是已经有权单独促成动作。
10. 官方页写：载荷从第二字节起用不透明字节，而不是某一种列表编码，以便以后换编码。不透明不是已经是某一种交易信封。
11. 官方页写：排除空项是为了让「本块没有任何请求载荷」时的承诺是与分叉无关的稳定空值。
12. 因此：EIP-7685 ≠ EIP-4895 ≠ EIP-2718。看见请求承诺不是已经由共识层处理完。请求不是已经有权单独促成动作。

## 推断（从官方句推出，不是另一条共识规则）

- 把「头上多了一个字段」读成「共识层已经办完」，会把官方「稍后交给共识层再处理」那一句丢掉。
- 把「请求」读成「已经是提款 / 已经是退出」，会把通用总线和 154 / 7002 那些具体类型糊成一句。
- 把类型字节读成已经解开载荷，会和 167 的信封糊成「带了类型」一句。

## 建议（对「不确定」）

第一版结算机若出现「执行层往共识层递条子」，先问四句：看见的是头上的承诺，还是共识层已经处理完？看见的是类型字节，还是已经是载荷？空项被排除了，还是这种类型从未出现？这是请求，还是已经有权单独促成动作？四句各指各的对象。不要发明请求配方或承诺算法常数。

## 五层（只展开本对象）

| 层 | 本对象要看见的 |
| --- | --- |
| 协议 | 头上一个请求承诺；请求事后交给共识层。 |
| 实现 | 空载荷不进承诺；跨类型按类型升序。 |
| 钱包 | 看见承诺不是已经办完。 |
| 应用 | 请求不是已经有权单独促成动作。 |
| 威胁 | 文案把看见承诺写成已经处理，或把总线写成已经是某一种提款。 |

## 禁句

- 「头上有请求承诺，共识层就已经处理完。」
- 「看见类型字节就是已经解开载荷。」
- 「承诺里没有这一项，就从未出现过这种请求。」
- 「请求已经有权单独促成动作。」
- 「EIP-7685 就是 EIP-4895 / EIP-2718。」
- 「这就是 149 的改头，或 154 的提款。」

## 边界（本页不写）

- 不写怎样造请求、怎样伪造承诺、怎样跳过共识层再验。
- 不写承诺算法常数、类型取值、系统合约地址。
- 不写 149 改头、154 提款、193 退出请求、194 存款请求本身（只说本页不是它们）。
- 不写具体请求类型的载荷字段。

## 和相邻对象的唯一性

1. **不是 149 / 处理完一块** — 149 是执行层跑完 ≠ 已经改规范头。本页是头里那个请求承诺 ≠ 共识层已经处理请求。
2. **不是 154 / EIP-4895** — 154 是信标提款系统操作 ≠ 用户交易。本页是通用总线。
3. **不是 193 / EIP-7002** — 193 是总线上的一种退出/部分提款请求。看见总线不是已经是那一页。
4. **不是 167 / EIP-2718** — 2718 是交易信封。本页是头上的请求对象，类型字节不是已经是交易类型。
5. **不是 156 / 父信标根** — 头里另一个根。本页不是当前头，也不是已经 finalized。
6. **不是 190 / EIP-7702** — 7702 是账户委托指示。本页不是授权名单。
7. **不是 194 / EIP-6110** — 6110 是总线上的一种存款请求。看见总线不是已经是那一页。

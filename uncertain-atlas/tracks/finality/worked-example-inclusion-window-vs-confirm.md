## 1. 核心问题

阿比看见证明能纳入的槽加长了，以为确认规则已经上线；或看见能收到下一纪元末，以为已经改了选头规则；或看见目标奖不再看纳入延迟，以为目标票的含义已经变了；或看见流言窗加长，以为已经改了执行层；或看见规范编号 7045，以为就是 7549，或已经是三种「到了」。

官方句（事实）：

- EIP-7045：把证明能纳入的最晚槽，从「证明所在槽再加一个纪元的槽」改成「证明所在纪元的下一纪元最后一槽」。
- 当初 Phase 0 选滚动的一个纪元窗，是因为每张证明纳入机会一样，被评估成「公平」。当时也考虑过：本纪元和下一纪元都能纳入——那样纪元开头造的证明，可比纪元末的多几个槽。
- 后来官方写：后一种设计对当时的 LMD-GHOST 安全证明、以及对一条新的确认规则，都是关键。官方预期确认规则能在正常主网条件下用很少几个槽确认块。看见本页，不是安全证明已经写完，也不是确认规则已经上线，也不是那几个槽已经是产品确认。
- 本页**不要求**改执行层。
- 共识层两处小改：处理证明时不再用槽上界卡死，纳入范围改由最早槽、以及目标纪元必须是本纪元或上一纪元来定；算参与旗标时，及时目标旗不再看纳入延迟，好让窗被拉长的证明仍有一份非零奖。
- 流言条件跟着改，好让加长后的窗里还能传单张证明和聚合证明。
- 去掉纳入延迟对目标奖的考虑：以前只有在一个纪元窗里纳入，才给正确目标票发这份奖。现在改成：只要这张证明还在合法纳入窗里，正确目标就能拿一份底线非零奖。这样客户端仍会尝试把这些证明装进块，安全分析才站得住。官方写：以前窗刚好等于这个上限时，本来就是这个意思。
- 向后：共识层验块规则不兼容，必须硬分叉。
- 安全段：官方写这改进 LMD-GHOST 安全，并让快确认规则成为可能。官方写没有已知的负面安全冲击。看见本页，不是确认规则已经在跑。
- 规范**没有**把加长纳入窗写成已经有确认规则，也没有把能收到下一纪元末写成已经改了选头，也没有把目标奖不再看延迟写成已经改了目标票，也没有把本页写成 7549 或三种「到了」。

纳入窗、选头规则、确认规则、目标票含义，是四件事。

## 2. 直觉（ELI15）

投票条以前只能在出门后的固定一截时间里被贴上墙。  
本页把截止时间改成「下一本周课表的最后一天」。  
墙能多贴几天，不是教务处已经盖了「本周已锁定」。  
也不是选哪张门口清单的规矩已经换了。  
晚到的条子仍能拿一点「目标写对了」的底线奖，不是目标这两个字已经换了意思。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 加长纳入窗 | 证明最晚能进到下一纪元最后一槽 | 已经有确认规则 |
| 下一纪元末 | 纳入范围的新上沿 | 已经改了 LMD-GHOST |
| 目标奖不看延迟 | 合法窗里正确目标仍有非零奖 | 已经改了目标票含义 |
| 流言窗加长 | 单张和聚合证明能在加长窗里传 | 已经改了执行层 |
| 7045 | 加长纳入与底线奖 | 7549 的委员会下标；三种「到了」 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气证明还能进哪一层」。

1. 看见证明能纳入的槽加长了。规范：最晚改到下一纪元最后一槽。不是已经有确认规则。
2. 看见能收到下一纪元末。规范：纳入范围改由最早槽和目标纪元来定。不是已经改了选头。
3. 看见目标奖不再看纳入延迟。规范：合法窗里正确目标仍有底线非零奖。不是目标票已经换了含义。
4. 看见流言窗加长。规范：只改证明流言条件。不是已经改了执行层。
5. 有人把这听成不变量 198。那是把委员会下标挪出已签名消息。本页不改下标住哪。
6. 有人把这听成不变量 127。那是 head / justified / finalized。本页是纳入窗，不是已经多了一档「到了」。
7. 有人把官方「很少几个槽」听成产品已经能这么确认。规范：那是确认规则的预期；看见本页不是规则已经上线。

「加长窗 = 已经确认 / 下一纪元末 = 已经改选头 / 7045 = 7549 / 7045 = 三种到了」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 证明仍是同一张已签名票；窗加长不是已经换了域 |
| 协议 | 必须点名问的是纳入窗、选头、确认规则，还是目标票 |
| 实现 | 处理函数去掉槽上界；参与旗标不再用纳入延迟挡目标奖 |
| 部署 | 官方要硬分叉；不把确认槽数抄进不确定 |
| 经济 | 底线非零奖是为了块里还肯装这些证明，不是已经更安全 |

**推断：** 产品句若只写「证明能多等一个纪元所以已经能快确认」，读者会把纳入窗听成确认规则，或把 7045 听成 7549。  
**建议：** 第一版可以不抄信标证明纳入窗。若对照，必须分开纳入窗、选头、确认规则、目标票。不要发明「看见 7045 就已经有确认规则」。不要抄每纪元槽数或确认槽数。不要写怎样塞晚到的证明。

## 6. 和另外几句不是同一句

1. **委员会下标被挪出签名 ≠ 已经没有委员会**（不变量 198）：7549 改的是下标住外层。本页改的是最晚能进哪一槽。
2. **head ≠ justified ≠ finalized**（不变量 127）：三种「到了」。本页不发明第四档确认。
3. **处理完一块 ≠ 已经改规范头**（不变量 149）：执行层处理。本页不改执行层。
4. **同步委员会必须点名样本**（不变量 22）：轻客户端样本。本页是全证明纳入窗。

不要抄分叉时间戳、每纪元槽数、确认槽数、规范提交哈希。不要写怎样把晚到的证明塞进块。不编博物馆页。不另写 19 节。不转规范代码。EIP-7549 委员会下标、三种「到了」、确认规则产品、执行层是另一对象。委员会下标精读：[`worked-example-committee-index-vs-signed.md`](worked-example-committee-index-vs-signed.md)（不变量 198）。

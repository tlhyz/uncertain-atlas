## 1. 核心问题

阿比看见「Quorum Store 也有 quorum」，或看见一批交易已经在验证者之间传开、甚至已经认证，以为共识序 L 已经写好，或以为领袖已经消失、这笔已经提交。

官方句（事实）：

- 词汇表：内存池是验证者内存里的缓冲，装着**已经提交、但尚未达成一致、也尚未执行**的交易。
- 同一页现行句：随后 **Quorum Store（仲裁存储）以批次在验证者集合内传播**这些交易。当前验证者是领袖时，共识提议一个**对已认证批次排序**的块。验证者法定人数对该提案投票。
- 词汇表给 Quorum Store 的定义：在验证者集合里**按批次传播交易**的组件。它把**数据传播**和**元数据排序**拆开，让验证者异步并行传播数据。官方另写它「去掉领袖瓶颈」——那是数据传播句，不是已经没有领袖。同一页仍写「当当前验证者是领袖」。
- 白皮书摘要把流水线拆成可并发的几段：**交易传播、块元数据排序、并行执行、批量存储、账本认证**。传播不是排序，排序不是执行，执行不是账本认证。
- 深潜页仍写：领袖可从内存池拉一批、复制成提案。同一页写：交易进了提议的共识块，**不保证**最终会落到分布式数据库。
- 词汇表把更多实现细节指到一篇博客。本页**不抄博客**。加密内存池（AIP-144）是另一对象：待处理负载可加密，不是本页的传播≠排序。

批次、已认证批次、提案里的序、投票、执行、落盘，是不同对象。

## 2. 直觉（ELI15）

先把报纸捆好送到各报摊：Quorum Store。  
主编再决定今天头版用哪几捆、什么顺序：共识。  
报摊都有货，不是已经出刊。  
捆上盖了「这捆我存到了」：已认证批次。这不是已经排好今天的目录，更不是已经印上街。

小朋友看见名字里有 Quorum，以为已经有一张 commit 证书。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 内存池 | 已提交、尚未一致、尚未执行的缓冲 | 已经排序；已经执行 |
| Quorum Store | 在验证者集合里按批次传播交易 | 已经写出 L；已经 commit |
| 已认证批次 | 词汇表里给共识去排序的对象 | 已经落盘；已经等于 STM 的 L |
| 元数据排序 | 共识对已认证批次排块 | 数据已经传到；执行已经完 |
| 领袖 | 现行句里提议排序的人 | 已经被 QS「去掉」 |
| 进了提议块 | 深潜页里的提案成员 | 已经持久化 |
| 加密内存池 | 待处理负载可加密 | 本页的传播≠排序 |

## 4. 最小案例

用户在 Aptos 转一笔。

1. 交易进某个验证者内存池。官方写：还没达成一致，也还没执行。
2. Quorum Store 把它放进某批，在验证者集合里传播。传播开了不是已经排序。
3. 某批成为词汇表写的「已认证批次」。认证不是已经写出 L，也不是已经提交。
4. 轮到的领袖提议一个对已认证批次排序的块。法定人数投票。这才是在写 L。
5. STM 若开着，算的是这块的 L，不是 Quorum Store 的批次表。精读仍是不变量 122。
6. 有人把「去掉领袖瓶颈」写成已经没有领袖：词汇表同一页还在写领袖提议。
7. 有人把「进了提议块」写成已经上链：深潜页写不保证落盘。

「批次齐了所以已经 commit」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 批次认证仍是验证者签；没有新的「仲裁存储哈希」 |
| 协议 | 必须点名问的是传播、已认证批次、排序、执行还是落盘 |
| 实现 | 深潜页仍有从内存池拉批的入口；词汇表现行句排的是已认证批次。两句都留 |
| 部署 | explorer「已进池 / 已传播」若只跟批次，不是已经排序 |
| 经济 | 「去掉领袖瓶颈」不是已经没有出块租金；不要抄吞吐 |

**推断：** 产品句若只写「Quorum 所以已经最终」，读者会把批次认证听成 commit QC。  
**建议：** 不确定第一版可以不拆传播层。若拆，用户可见的「到了」必须点名停在传播、已认证、已排序、已执行还是已落盘。不要把 Quorum Store 的名字听成已经有一张 QC。不要抄吞吐。

## 6. 和另外几句不是同一句

1. **STM 跑完 ≠ 已经最终**（不变量 122）：执行必须等于串行 L。本页是 L **还没写出来** 之前的传播层。
2. **谁写顺序**（不变量 27）：Builder API ≠ 信标共识。本页不是 PBS。
3. **CheckTx ≠ Prepare ≠ Process**（不变量 33）/ **单笔绿 ≠ 整包可提案**（不变量 69）：ABCI 四门与装箱。本页是验证者之间的批次传播。
4. **进了共识块 ≠ 已被接受**（不变量 128）：Sui 的接受票。本页是 Aptos 批次 vs 排序。
5. **抽样 α ≠ QC**（不变量 131）：Snow 样本多数。本页名字里的 Quorum 不是 Avalanche，也不是已经有 QC。

不要把官方吞吐、纪元小时、气价、博客组批步骤抄进不确定常量。不要写怎样扣批次或只给一部分人货。不编博物馆页。加密内存池另页，不在这里展开。

## 7. 「不确定」测试句（建议）

```text
内存池里有 ≠ 已经达成一致 / 已经执行
Quorum Store 传开 ≠ 已经写出 L
已认证批次 ≠ 已经排序
已认证批次 ≠ 已经 commit
去掉领袖数据瓶颈 ≠ 已经没有领袖
进了提议块 ≠ 已经落盘
传播 / 排序 / 并行执行 / 批量存储 / 账本认证 ≠ 同一段
Quorum Store 的 quorum ≠ 已经有一张 commit QC
```

## 精密检查

**禁止假学习：** 「Quorum Store 也有 quorum 所以已经最终。」「批次传开就是已经排序。」「已认证批次就是 L。」「去掉领袖瓶颈所以没有领袖。」「进了提议块就是已经上链。」  
**边界：** 不抄博客组批 / 签名收集步骤。不填吞吐。不写怎样扣批次。不把加密内存池并进本页。深潜页「从内存池拉批」与词汇表「排已认证批次」两句都留着，不互相改写。Aptos §15 仍无官方主网七问，不编事故。

## 1. 核心问题

阿比看见「顺序已经最终」或看见 `eth_call` 已经能读新余额，以为本块状态根已经和超多数交差，或以为投票者已经跑完 `Apply`。

官方句（事实）：

- 共识是节点对交易**官方顺序**达成一致。执行是真的去跑这些交易、改状态。
- 文档把 Ethereum 和多数链写成：执行是共识的前提。对一块达成共识，是同时同意 (1) 块里的交易列表，和 (2) 跑完这份列表之后的 Merkle 根。领袖提议前必须先跑完；投票者投票前也必须先跑完。
- Monad：节点对官方顺序达成一致时，**不必执行过这些交易**。领袖可以在不知道结果根的情况下提议顺序。投票者可以在不知道交易会不会 revert 的情况下投有效性。
- 块最终之后，网上每个节点（验证者与全节点）才可以执行，得到大家同意的最新状态。
- 同页标题句：顺序一旦定，真实世界的状态就已经被决定。执行是把真相揭开。揭开之前，用户看见的根 / 回执还不是已经交差。
- 交易可以「失败」仍然有效：比如只剩 1 个代币却转 10 个。直觉失败，交易仍可进块；结果仍是确定的。
- 延迟 Merkle 根：提案不带本块状态根，另带 **D 块之前**的根，用来发现节点是否走散。`D` 是全网参数。文档写测试网/主网当前是 3——那是部署数字，本页不抄进不确定常量。
- 延迟根是块有效性的一部分。领袖提议了但延迟根错，这块会被拒。
- 文档：对块 `N` 达成共识之后（同页写通常是收到带这块 QC-on-QC 的 `N+2`），网上同意的是：`N-D` 的官方后果是根 `M`。轻客户端这时才能向全节点问 `N-D` 的 Merkle 证明。
- 在 `N-D` 执行错的节点，从块 `N` 开始掉出共识，再回滚到 `N-D-1` 末态重放。
- Reserve Balance：共识只能假定自己看见最多滞后 `D` 块的全局状态，所以必须另写纳入规则和执行期 revert。阈值不抄。那是另一对象。
- 投机执行：MonadBFT 里节点在槽 `N` 收到提案，官方写要到槽 `N+2` 才最终。中间可以本地先跑，供更新指针，也供 `eth_call` / `eth_estimateGas` 对着投机状态模拟。投机 RPC 不是协议最终。
- 新账户：零余额账户入账之后，要等这笔入账满 `D` 块才能自己发交易。文档另写的等待秒数不抄。
- 同页指向「block states」。本页不发明那些名字。

顺序最终、延迟根交差、本地揭开、投机 RPC，是不同对象。

## 2. 直觉（ELI15）

老师先在黑板上写下「今天作业按这个顺序做」。  
全班先举手同意这份名单。还没人动笔。  
名单定了，答案在数学上已经定了。  
交卷、对答案、把总分贴到墙上，是后一步。  
有人提前在草稿纸上算，给前台看——那是模拟，不是墙上的官方分数。

小朋友看见「名单已经通过」或前台已经能读余额，以为墙上已经贴了本块的根。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 官方顺序 | 共识同意的交易列表 | 本块状态根已经交差 |
| 交错执行（文档对照） | 投票前必须先跑完；提案带本块根 | Monad 这一页 |
| 异步执行 | 共识热路径里不跑 `Apply` | 已经没有执行；已经不需要确定性 |
| 延迟 Merkle 根 | 提案里 D 块前的根；错则拒块 | 本块根；轻客户端此刻能证 N |
| 揭开 | 最终之后各节点执行，看见已决定的状态 | 顺序通过当时余额已经全网交差 |
| 投机执行 / `eth_call` | 对着尚未最终的提案本地模拟 | 协议最终 |
| Reserve Balance | 滞后视角下的纳入 / revert 规则 | 本页已经写完的气费表 |
| 新账户满 D 块 | 入账之后才能自己发 | 已经能立刻花 |
| block states | 官方另页 | 本页已经展开 |

## 4. 最小案例

用户在这种链上转一笔。

1. 领袖交出一份顺序，没有本块状态根。投票者按有效性规则举手。顺序通过不是根已经交差。
2. 提案里带着 D 块前的根。这根错，这块无效。对上了也只证明旧高度，不是本块已经揭开。
3. 块最终后，节点才跑 `Apply`。用户本地看见回执。这是揭开，不是「投票当时就已经交差」。
4. 有人用 `eth_call` 去读还没最终的提案。官方允许对着投机状态模拟。不是协议最终。
5. 有人把「先定序」写成 Aptos STM：那边投票仍要一个确定的串行 L，并且执行必须等于按 L 串行。本页是投票时可以还没跑。
6. 有人把「先定序」写成 Quorum Store：那边拆的是传播和排序。本页拆的是排序和执行。
7. 有人把「谁写顺序」写成 Builder API：那是另一根钉子。本页是顺序已定之后还要不要立刻交差根。

「顺序过了所以余额已经和全网一样」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 延迟根是 Merkle 根；本页不证 |
| 协议 | 必须点名问的是官方顺序、延迟根、还是已经揭开的本块状态 |
| 实现 | 文档不是冻结规范；`D` 与 Reserve Balance 以现行页为准，本页不填 |
| 部署 | 执行错会迟到才掉出共识；那是滞后发现，不是已经交差 |
| 经济 | Reserve Balance / 新账户满 D 块是纳入税；阈值不抄 |

**推断：** 产品句若只写「异步所以更快最终」，读者会把顺序绿勾听成本块根已经贴上墙。  
**建议：** 不确定第一版可以保持「投票前先跑完、提案带本块根」。若拆泳道，用户可见的「到了」必须点名是序还是根。不要抄 `D`、秒数或执行预算表。不要写 19 节。

## 6. 和另外几句不是同一句

1. **STM 跑完 ≠ 已经最终**（不变量 122）：那边先有 L，再并行，提交 ≡ 串行。本页是投票时可以还没执行。
2. **已认证批次 ≠ 已经写出 L**（不变量 132）：传播层。本页是 L 已有之后还要不要交差根。
3. **谁写顺序**（不变量 27）：Builder API / 签盲头。本页是顺序对象与状态对象。
4. **processed ≠ finalized**（不变量 133）：Tower 三档。本页没有 PoH。
5. **Doomslug ≠ BFT**（不变量 135）：头上两枚最终哈希。本页是序 vs 根。
6. **进块 ≠ 已被接受**（不变量 128）：Sui 证书。本页没有快路径。

不要把 `D` 的现行数字、等待秒数、Ethereum gas/时间对照、官网吞吐抄进不确定常量。不要写怎样塞付不起气费的交易，或怎样交一份错的延迟根。不编博物馆页。不写 19 节。Reserve Balance 与 block states 不在本页展开。

## 7. 「不确定」测试句（建议）

```text
官方顺序已定 ≠ 本块状态根已经交差
领袖不知结果根 ≠ 已经没有执行
投票时不知是否 revert ≠ 交易已经无效
延迟 D 块根对上 ≠ 轻客户端能证高度 N
投机 eth_call 绿 ≠ 协议最终
零余额入账 ≠ 已经能自己发交易
先定序再 Apply ≠ STM 跑完 ≠ 已经最终
先定序 ≠ 已认证批次已经写出 L
```

语料：[C140](../../libraries/adversarial-corpus/README.md)。

## 精密检查

**禁止假学习：** 「顺序过了就是余额已经到。」「异步所以投票者已经跑完。」「`eth_call` 能读就是已经最终。」「延迟根对上就是本块已经交差。」「这就是 STM。」  
**边界：** 不写 19 节、不填 `D` / 秒数 / 执行预算。不证 MonadBFT。不把文档数字当永恒常数。Reserve Balance 与 block states 另标。

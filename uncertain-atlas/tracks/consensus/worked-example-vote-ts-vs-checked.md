# 例：看见票或提案带了 Timestamp 不是已经验过这个时间；看见冲突提案不是已经有证据；看见非法票被断开不是已经罚了签的人

**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。

## 官方三件事

规范把签字前的校验写成三件独立的共识事，不是「看见签过就已经验过时间、已经能交提案证据」一件事：

1. **看见票或提案带了 Timestamp / 看见字段在 不是已经验过这个时间。**  
   官方写：收到的 `Proposal` 或 `Vote` 上的时间戳，目前没有校验。一般期望验证者填自己的本地钟，也期望同一人严格单调，但这两句都没有强制。看见字段在，不是已经验过。看见单调，不是已经执行。看见 BFT Time 会用 precommit 的时间去算下一块，不是收到时已经验过。看见 PBTS 要求提案时间对上块时间，不是票上的时间已经有要求。
2. **看见冲突提案 / 看见双签证据机制 不是已经有提案证据。**  
   官方写：引擎能公布冲突票的证据，好让应用罚。冲突提案目前没有证据，以后也许有。看见能交双签证据，不是提案冲突已经能交。看见两份提案，不是已经有对象。看见「以后也许有」，不是已经有。
3. **看见非法票被断开 / 看见没过基本校验 不是已经罚了签的人。**  
   官方写：不过基本校验的票和提案算非法。流言它们的对等节点可能被断开。但目前没有明确机制，去罚签了这种非法对象的验证者。看见被断开，不是已经罚了。看见非法，不是已经上链。看见没过基本校验，不是已经是双签。

类型字节、链号长度、可恢复签编码是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **带了 Timestamp ≠ 已经验过：** 官方把字段在和收到时没有校验分开。
- **冲突提案 ≠ 已经有证据：** 官方把票的证据和提案的证据分开。
- **断开 ≠ 已经罚了：** 官方把对等路径踢人和验证者惩罚分开。

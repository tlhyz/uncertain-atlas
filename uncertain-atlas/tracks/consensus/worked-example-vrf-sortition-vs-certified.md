## 1. 核心问题

阿比看见「密码抽签」或看见某账户出示了 VRF 证明，以为这块已经结算，或以为抽签就是 Avalanche 那种问邻居，或以为一人一个账户更占便宜。

官方句（事实）：

- 官方页自称简化、只覆盖理想条件，细节指向白皮书和源码。本页只钉这一页写明的对象，不把论文步骤发明成现行规范。
- VRF 吃一把密钥和一个值，吐出伪随机输出，外加别人能验的证明。它像抽签，用来选**提议块的领袖**和**给块投票的委员会**。
- 对某个账户跑 VRF，输出按二项分布抽样，用来模拟账户里**每一个 Algo 自己抽一次**。Algo 越多，被抽中的机会越大。官方写：拆成多个账户不会因此占便宜。
- 账户必须 **online** 才能参与共识。花费钥不拿来签共识。用户另注册一把参与钥（若干轮），再派生每轮一次性钥；用完删除。官方写：节点被拿下，代币仍靠花费钥；删旧钥是前向安全。
- 共识三步：propose → soft vote → certify vote。每一步另抽一个委员会。消息用参与钥签，委员会身份用 VRF 验。
- 提议：节点对自己管着的、有有效参与钥的 online 账户跑 VRF。抽中则广播块和 VRF 输出，证明自己是合法提议者。抽中不是已经认证。
- Soft vote：先验签、再验 VRF。各节点比较已验赢家的 VRF 哈希，**只转发最低的那份提案**。过一段固定时间后，再抽 soft vote 委员会；票按该账户的 Algo 加权，投的是超时当时算出的最低 VRF 块。委员会大小用 Algo 量化；要到下一步，必须凑齐相对期望委员会大小的某个比例。本页**不抄**那个比例和超时。
- Certify：又一个新委员会检查 soft vote 选出的块有没有超花、双花或其它问题。有效再投一次。票凑齐，节点才给这块写证书、写入账本，本轮结束。Soft vote 齐了不是已经 certify。
- 认证委员会在超时内凑不齐法定人数，官方写网络进入 recovery。那是活性路径，不是本页已经展开的第四步。不抄超时。
- 官方把「Pure Proof of Stake」写成：委员会按账户里的 Algo 抽，投票权跟 **online stake** 走。这不是 NPoS 那种当选后等权，也不是一人一票。
- 同页另有 state proof 钥，用来做可带走的后量子状态证明。链上随机信标另页说调用同一类 VRF，但是应用对象。两句都不是本页的三步共识。

抽中、最低哈希、soft vote、certify、参与钥、花费钥，是不同对象。

## 2. 直觉（ELI15）

今晚谁上台，先各自在家里拆信封：VRF。  
信封能给门口验：我没撒谎。  
拆中了可以交稿，不是已经出版。  
编辑部先只传哈希最小的那一份：soft vote 过滤。  
另一批人再查账有没有花两次：certify。  
家里开门的钥匙和上台用的临时证不是同一把。

小朋友看见「抽中了」或「也是 PoS」，以为已经最终，或以为这和问邻居是同一件事。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| VRF 抽签 | 私下抽、出示证明；选领袖和委员会 | 已经认证；问邻居 |
| 每 Algo 一次彩票 | 二项抽样模拟每个 Algo 抽一次 | 拆账户更占便宜；一人一票 |
| 参与钥 / 一次性钥 | 签共识消息；用完删除 | 花费钥；节点被拿下等于币没了 |
| 提议 | 抽中则广播块 + VRF 证明 | 已经 soft vote；已经 certify |
| 最低 VRF 哈希 | soft vote 用来收成一份提案 | 已经认证 |
| Soft vote | 新委员会按 Algo 加权，投最低那份 | 已经检查超花 / 双花；已经落账 |
| Certify | 又一个新委员会查块并写证书 | 抽中当时已经最终 |
| Recovery | 认证票超时未齐 | 本页已经写完的第四步 |
| State proof 钥 | 可带走的状态证明 | 本页三步共识 |
| 链上随机信标 | 应用层 VRF | 本轮谁出块 |

## 4. 最小案例

用户在 Algorand 转一笔。

1. 某 online 账户被 VRF 抽中提议。广播块和证明。抽中不是已经认证。
2. 网上同时有好几份提案。节点只转发已验过、VRF 哈希最低的那份。最低不是已经 soft vote。
3. Soft vote 委员会按 Algo 加权投这份。票齐了进入 certify。不是已经写入账本。
4. 新委员会查超花 / 双花。再齐一次，才写证书、落账。
5. 有人把「抽签」写成 Avalanche 问邻居：那边没有「出示我被抽中」的证明，也没有这三步。
6. 有人把「按质押抽」写成 NPoS 当选后等权：本页官方写委员会票权跟 online stake 走。
7. 有人把节点被入侵写成币已经没了：官方把花费钥和参与钥拆开。

「抽中了所以已经最终」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | VRF 输出 + 可验证明；参与钥 ≠ 花费钥 |
| 协议 | 必须点名停在抽中、最低哈希、soft vote 还是 certify |
| 实现 | 官方页是理想条件简化；参数以现行规范为准，本页不填 |
| 部署 | 抽中者一露面可被打；那是部署税，不是已经认证 |
| 经济 | 票权跟 online Algo 走；拆账户官方写不占便宜 |

**推断：** 产品句若只写「密码抽签所以秒最终」，读者会把 VRF 证明听成已经落账。  
**建议：** 不确定第一版可以不上 VRF 委员会。若对照，用户可见的「到了」必须点名停在哪一步。不要把抽签和 Snow 抽样、NPoS 等权糊成「都是随机委员会」。不要抄超时或官网快慢句。

## 6. 和另外几句不是同一句

1. **抽样 α ≠ QC**（不变量 131）：Snow 问邻居、数连续轮。本页是出示 VRF 证明、另走 BA 三步。
2. **抽样委员会 2/3 ≠ 全集 2/3**（不变量 22）：Altair 固定委员会 QC。本页每步另抽，委员会大小用 Algo 量化。
3. **NPoS 等权**（不变量 129）：当选后共识按验证者人数。本页官方写票权跟 online stake 走。两句都留着，不要互相改写。
4. **BABE VRF 抽槽**（不变量 126）：中继出块抽签，最终仍是 GRANDPA。本页三步都在同一套抽签委员会上，仍不是抽中已经最终。
5. **PoH ≠ Tower**（不变量 133）：钟不是票。本页没有 PoH。
6. **链上随机 / DKG**（不变量 93）与官方随机信标：应用对象。本页是谁被抽来提议和投票。

不要把委员会 Algo 数、法定比例、超时、版本号、官网「很快 / 很少算力」抄进不确定常量。不要写怎样磨最低哈希或打刚露面的提议者。不编博物馆页。State proof 与随机信标不在本页展开。

## 7. 「不确定」测试句（建议）

```text
VRF 抽中 ≠ 已经认证
最低 VRF 提案 ≠ 已经 soft vote
soft vote 齐了 ≠ 已经 certify / 已经落账
参与钥 ≠ 花费钥
按每个 Algo 抽一次 ≠ 一人一账户更占便宜
委员会票权跟 online stake 走 ≠ NPoS 当选后等权
VRF 出示证明 ≠ Avalanche 问邻居
state proof 钥 ≠ 本轮三步共识
随机信标 ≠ 谁出块
超时进 recovery ≠ 本页已经写完第四步
```

## 精密检查

**禁止假学习：** 「抽中了就是已经最终。」「最低 VRF 就是已经认证。」「soft vote 就是已经落账。」「抽签就是问邻居。」「拆账户更占便宜。」「节点被拿下币就没了。」  
**边界：** 不证白皮书、不填委员会大小 / 法定比例 / 超时。不把官方「理想条件」写成已经覆盖分区和恶意。不写怎样磨 VRF。State proof 与随机信标另标。NPoS 等权句不改写成本页。

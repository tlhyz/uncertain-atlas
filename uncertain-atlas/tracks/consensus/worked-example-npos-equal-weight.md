## 1. 核心问题

阿比听见「Polkadot 是质押选出验证者」，或看见某验证者背后质押特别多，以为凑 ⅔ **质押** 就已经过了官方超多数，或以为提名时按币加权，当选后共识也按币加权。

官方句（事实）：

- NPoS 是**选集合**的机制：验证者出块、验平行块、担保最终；提名者用自己的质押支持他们信任的候选人。选举用顺序 Phragmén，目标是选出集合，并把背后质押尽量摊平。
- 选举本身是质押加权的。Wiki 写明：验证者选举和议会选举都按持币加权，不是一人一票。
- **当选之后**，官方 Cosmos 对照页另写一句：**所有验证者在共识协议里权重相同。** 要让一条链得到超过官方超多数的支持，必须超过官方超多数的**验证者**承诺，而不是超过官方超多数的**质押**。
- 同一页写 Cosmos Hub：共识投票和奖励都按质押。那边要超过官方超多数的**质押**承诺，而不是超过官方超多数的**验证者**。
- 奖励：对照页写验证者奖励绑在活动上（主要是出块和最终性证明），不绑在质押数量。进阶质押页写：两名验证者做同样的活，拿到的代币大体相同，**不**按背后总质押比例发。背后质押少的验证者，每枚币通常分给提名者更多，从而把提名往低质押验证者推，长期把质押摊开。
- 治理与质押官方写成完全拆开：提名一个验证者，**不**把治理投票权交给他。Cosmos 对照：提名者自己不投公投时，验证者接过那份治理权。
- Consensus 页另有一句，必须单独留着：**BABE 按质押给验证者分配出块槽**，再用中继随机周期抽签。本页**不**把这句话改写成「BABE 也是等权」。等权官方句讲的是「一条链得到超多数支持」——那是对链投票的尺子，不是把出块抽签也改成人数。

提名时的加权、选举摊平、当选后的共识等权、BABE 抽槽「按质押」、奖励按活动，是不同对象。

## 2. 直觉（ELI15）

班委选举按家里捐了多少粉笔计票：NPoS 选举。  
选出来的班委开会举手：每人一只手。要过官方超多数，数的是手，不是谁家粉笔多。  
隔壁班开会：谁捐的粉笔多，谁的手算得更重。  
发点心按今天谁值日，不按谁家粉笔多。  
谁当选，不自动拿到改校规的笔。

小朋友看见「班委是按粉笔选的」，以为开会也按粉笔凑 ⅔。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| NPoS 选举 | 用质押加权的票选出验证者集合；Phragmén 尽量摊平背后质押 | 当选后共识已经按质押计票 |
| 提名 | 持币者支持候选人 | 已经把治理权交给验证者；已经等于共识票 |
| 当选验证者 | 进本届集合，共识协议里官方写等权 | 背后质押多所以票更重 |
| 共识超多数（Polkadot 官方对照） | 超过官方超多数的**验证者**承诺一条链 | 超过官方超多数的**质押** |
| 共识超多数（Cosmos 官方对照） | 超过官方超多数的**质押**承诺 | 超过官方超多数的**验证者人数** |
| 奖励 | 按活动（出块 / 最终性证明）；同等工作大体同等份 | 按背后总质押比例发验证者那一份 |
| BABE 抽槽 | 官方写按质押分配出块槽 | 已经解释了 GRANDPA 等权；已经等于 Cosmos 按质押凑 ⅔ |
| 治理权 | 与质押官方写成拆开 | 提名过的验证者已经代投公投 |

## 4. 最小案例

用户看见验证者 A 背后质押远多于验证者 B。

1. 选举时：A 更容易进集合；Phragmén 会尽量把提名摊开，让当选者背后质押别差太远。
2. 当选之后：官方写 A 和 B 在共识协议里权重相同。给一条链凑超多数，数的是有多少验证者承诺，不是 A 的质押有没有过半。
3. 奖励：A 和 B 若做同样的活，验证者那一份大体相同；A 的提名者每枚币通常分得更少。
4. 用户若只提名了 A，官方写这**不**等于把治理票也交给 A。
5. 若 BABE 抽到槽，那是出块抽签。Consensus 页写抽签按质押；不要把它听成「GRANDPA 也按质押」。出了块仍不是已经最终，见 [BABE ≠ GRANDPA](worked-example-babe-vs-grandpa.md)。

「A 的质押已经过半」不是「官方超多数已经到」。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 每张共识票仍是一个验证者钥上的签；等权不是少验签 |
| 协议 | 必须先点名超多数的单位是验证者还是质押；选举加权 ≠ 共识等权 |
| 实现 | 计票若把质押系数乘进已当选集合，就和官方对照句分手 |
| 部署 | explorer 上的「总质押」不是已经过了 GRANDPA 超多数 |
| 经济 | 奖励按活动，把提名往低质押验证者推；不要抄示例 DOT |

**推断：** 产品句若只写「PoS 所以 ⅔ 质押」，读者会把 Cosmos 的尺子套到 Polkadot 的链投票上。  
**建议：** 不确定第一版先点名超多数的单位。若抄 CometBFT，单位是投票权 / 质押。不要把 NPoS 的「选人按质押、开会按人头」两段糊成一句，也不要发明「所有 PoS 都按人数」或「所有 PoS 都按质押」。

## 6. 和另外几句不是同一句

1. **BABE 出块 ≠ GRANDPA 最终**（不变量 126）：两套装置。本页是当选之后**计票单位**，不是出块灯 vs 最终灯。
2. **出块还在 ≠ 纪元已转**（不变量 110）：选举分地板 / 许可冷冻。本页是正常协议里等权 vs 加权，不是事故。
3. **抽样委员会 2/3 ≠ 全集 2/3**（不变量 22）：样本 vs 全集。本页是同一集合里单位是人还是质押。
4. **+2/3 ≠ 其余槽位已签**（不变量 65）：Commit 槽位。本页不是「凑够就停验」。
5. **注入扩展 ≠ 投票权**（不变量 68）：提议者改权重。本页是官方规定的等权，不是被注入物骗了。
6. **Gasper ⅔ 总质押 → justified**（不变量 127）：以太坊官方单位就是总质押。本页是对照页把 Polkadot 写成验证者人数。
7. **集合何时生效**（不变量 35 / L4.5）：哪一高度用哪张表。本页是表上每个人多重。

不要把计划中的验证者上限、每名提名者可提名人数据、选举 nominator 条数、槽秒数、示例 DOT、袋子区间、wiki 超多数符号抄进不确定常量。也不要写怎样冷冻验证者、怎样在袋子里插队。不编博物馆页。

## 7. 「不确定」测试句（建议）

```text
NPoS 当选 ≠ 共识票已经按质押加权
提名时的质押加权 ≠ 当选后的共识等权
⅔ 验证者承诺一条链 ≠ ⅔ 质押已经承诺
Cosmos ⅔ 质押 ≠ Polkadot 官方对照里的同一把尺子
奖励按活动 ≠ 验证者那一份已经按质押比例发
Phragmén 把背后质押摊平 ≠ 共识已经按质押计票
BABE 按质押抽槽 ≠ GRANDPA 也按质押凑 ⅔
提名了某人 ≠ 治理票已经交给他
explorer 上某验证者质押过半 ≠ 官方超多数已经到
```

语料：[C133](../../libraries/adversarial-corpus/README.md)。

## 精密检查

**禁止假学习：** 「PoS 所以 ⅔ 永远是质押。」「NPoS 选出来以后大户票更重。」「A 的质押过半就是已经最终。」「BABE 按质押抽槽所以 GRANDPA 也按质押。」「提名了就等于把治理权给了验证者。」「这和选举地板事故是同一句话。」  
**边界：** 不讲 Phragmén 逐步公式、袋子列表插队、怎样冷冻、怎样拼选举解。不抄上限 / 提名数 / 示例 DOT。BABE 抽槽只保留官方「按质押」那句，不把它改写成等权。出块 ≠ 最终仍指 [BABE ≠ GRANDPA](worked-example-babe-vs-grandpa.md)。

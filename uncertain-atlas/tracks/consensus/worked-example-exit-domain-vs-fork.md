# 工作实例：看见签过的自愿退出不是已经永远有效

> **事实 / 推断 / 建议** 已分开。
> 对照：[L5.2](../../courses/level-05-ethereum/L05-M02-el-cl-finality.md)、[L1.2](../../courses/level-01-crypto/L01-M02-signatures.md)、[执行层退出请求 ≠ 已经退出](../economic/worked-example-el-exit-vs-withdrawal.md)、[提款 ≠ 用户交易](../economic/worked-example-withdrawal-vs-tx.md)、[请求承诺 ≠ 已处理](../finality/worked-example-request-vs-action.md)、[投票域](worked-example-vote-signbytes.md)。
> 主文献：[EIP-7044](https://eips.ethereum.org/EIPS/eip-7044) Perpetually Valid Signed Voluntary Exits。官方 EIP。核心层。最终标准。不另写 19 节。
> 本页钉 **看见签过的自愿退出 ≠ 已经永远有效**、**看见域锁在某次分叉 ≠ 已经改了执行层**、**看见分叉两边都能重放 ≠ 已经丢资金**、**看见用后继分叉域预签 ≠ 本页之后仍然有效**、**EIP-7044 ≠ EIP-7002 ≠ EIP-4895 ≠ EIP-7685**。不抄分叉版本字节、规范提交哈希、预签流程。不写怎样造锁死域的签，也不写怎样在分叉两边重放。

## 1. 核心问题

阿比看见一张签过的自愿退出，以为已经永远有效；或看见域锁在某一次分叉，以为已经改了执行层；或看见官方写分叉两边都能重放，以为已经丢资金；或看见用后继分叉域预签，以为本页之后仍然有效；或看见规范编号 7044，以为就是 7002、4895 或 7685。

官方句（事实）：

- EIP-7044：把自愿退出的签名域锁在某一次已经过去的分叉上，好让签过的退出以后一直能用。
- 当时：签过的自愿退出，进块只在两代升级里有效。信标状态只认当前和下一代分叉版本。
- 这会让一类质押操作变复杂：值班的人握活动钥，钱的主人握提款凭证。自愿退出只能由活动钥签。两边分开时，要提前换签过的退出，而且分叉次数事先不知道。
- 当初限时效，是为了两条都还活着的硬分叉里把退出隔开。验证者两边都值班，发出去的退出两边都能重放。官方写：这个可能不够用来牺牲上面那种用法；**没有资金风险**，质押者可以在一条或两条上再质押。
- 本页只改共识层状态转移：处理自愿退出时，签名域和根改成按那一次锁死的分叉算。流言条件跟着变。为了向后兼容，域锁在那一次分叉。
- 本页**不要求**改执行层。
- 理由：永远有效的签过退出，让质押操作更简单。也让这类对象的用法对齐改提款凭证和存款，下游工具不必再跟着分叉版本改。看见本页，不是已经是改提款凭证，也不是已经是存款。
- 向后：对共识层处理块的逻辑向后兼容。对「以后还有效」的预期**不向前**兼容。已经用后继分叉域预签、以为还能用的人，必须知道那些预签**不再被认成有效**。以后还要跨分叉有效，必须按锁死的那一次分叉域签。
- 安全段：分叉两边以前靠不同签名域，两代硬分叉之后就挡得住重放。本页让这层重放保护不再存在。这些重放可能影响分叉两边各自的质押者，**不把资金置于风险，也不影响链的安全**。
- 规范**没有**把看见签过的退出写成已经永远有效，也没有把域锁写成已经改了执行层，也没有把两边能重放写成已经丢资金，也没有把本页写成 7002、4895 或 7685。

签过的退出、锁死的签名域、已经退出、已经提到执行层，是四件事。

## 2. 直觉（ELI15）

值班的人提前写好一张「我不干了」的纸条，交给管钱的人保管。  
以前这张纸条只在最近两次换班规矩里好用。  
本页把纸条上的印章钉死在某一次旧规矩上，以后换班仍认这枚章。  
钉死印章，不是已经办完离职，也不是钱已经打回账户。  
两条还活着的分叉都能认出同一枚章，官方写这不是已经丢钱。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 签过的自愿退出 | 活动钥签的退出消息 | 已经永远有效；已经退出 |
| 锁死的签名域 | 处理退出时按某一次分叉算域 | 已经改了执行层 |
| 分叉两边能重放 | 本页之后不再靠两代分叉隔开 | 已经丢资金 |
| 后继分叉域预签 | 按本页之后的分叉域签的旧纸条 | 本页之后仍然有效 |
| 7044 | 把退出域锁死 | 7002 执行层请求；4895 提款操作；7685 总线 |

---

## 4. 最小案例

一条 Ethereum 要对齐「这一口气退出签在哪一层」。

1. 看见一张签过的自愿退出。规范：以前只在两代升级里有效。看见本页不是纸条已经永远有效。
2. 看见域锁在某一次分叉。规范：只改处理自愿退出时怎么算域。不是已经改了执行层。
3. 看见官方写分叉两边都能重放。规范：没有资金风险，也不影响链的安全。
4. 看见用后继分叉域预签。规范：那些预签不再被认成有效。
5. 有人把这听成不变量 193。那是执行层提款凭证触发的请求，先附在执行块上。本页是活动钥自愿退出的签名域。
6. 有人把这听成不变量 154。那是共识层出队的提款操作。本页不把余额打进执行账户。
7. 有人把这听成不变量 192。那是头上的请求承诺。本页不发明总线。

「看见签过的退出 = 已经永远有效 / 域锁 = 已经改了执行层 / 两边能重放 = 已经丢钱 / 7044 = 7002」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 签名域锁在某一次分叉；域对上不是已经退出 |
| 协议 | 必须点名问的是签过的退出、锁死的域、已经退出，还是已经提到执行层 |
| 实现 | 只改共识层处理函数和流言条件；执行层不改 |
| 部署 | 已经用后继分叉域预签的人必须改签；不把版本字节抄进不确定 |
| 经济 | 两边能重放不是已经丢资金；可以再质押 |

**推断：** 产品句若只写「退出签一次就永远有效」，读者会把域锁听成已经办完退出，或把 7044 听成 7002。  
**建议：** 第一版可以不抄信标自愿退出。若对照，必须分开活动钥预签、锁死的域、执行层请求、提款操作。不要发明「看见 7044 就已经永远退出」。不要抄分叉版本字节。不要写怎样重放。

## 6. 和另外几句不是同一句

1. **执行层退出请求 ≠ 已经退出**（不变量 193）：7002 是提款凭证走执行层。本页是活动钥自愿退出的签名域。
2. **提款操作 ≠ 用户交易**（不变量 154）：4895 是系统级加余额。本页不发明提款操作。
3. **请求承诺 ≠ 已处理**（不变量 192）：7685 是执行层往共识层递条子。本页不改执行层。
4. **域分离**（不变量 6 / 19）：投票步类型进被签字节。本页锁的是退出对象的分叉域，不是 Prevote / Precommit。

不要抄分叉版本字节、规范提交哈希、预签流程。不要写怎样造锁死域的签，或怎样在分叉两边重放。不编博物馆页。不另写 19 节。不转规范代码。EIP-7002 执行层退出、EIP-4895 提款操作、EIP-7685 总线、改提款凭证对象是另一对象。执行层退出精读：[`../economic/worked-example-el-exit-vs-withdrawal.md`](../economic/worked-example-el-exit-vs-withdrawal.md)（不变量 193）。

## 7. 「不确定」测试句（建议）

```text
看见签过的自愿退出 ≠ 已经永远有效
看见域锁在某次分叉 ≠ 已经改了执行层
看见分叉两边都能重放 ≠ 已经丢资金
看见用后继分叉域预签 ≠ 本页之后仍然有效
EIP-7044 ≠ EIP-7002 ≠ EIP-4895 ≠ EIP-7685
```

# 例：看见难度把叔块算进去不是已经按叔块个数调；看见可预期发行不是已经没有炸弹

**对应课文**：[L3.1](../../courses/level-03-bitcoin/L03-M01-nakamoto-finality.md)。

## 官方三件事

规范把一次难度改写成三件独立的事，不是「出块更稳了」一件事：

1. **难度调整现在盯的是「含叔块在内」的平均出块速率。**  
   官方写：这样发行速率可预期，不能靠操纵叔块率往上抬。看见把叔块算进去，不是已经改了出块奖励，也不是已经写了 Homestead 那次朝均值收敛（不变量 234），也不是已经没有炸弹。
2. **精确按叔块个数调的公式要看整块，本页改用只看头的近似。**  
   官方写：精确式差不多等于「有 k 个叔块的一块，当成 k+1 块、同一时间戳排成一串」；但精确式依赖整块，不只依赖头。本页用近似：头上的叔块哈希是不是空哈希。看见头上叔块哈希不是空，不是已经数清有几个叔块。
3. **分母从旧档改到新档，是为了让出块时间大致还在原来那一带。**  
   看见改了分母，不是已经量过不确定的墙钟，也不是官网吞吐已经是事实。

分叉高度、公式常数、叔块率估计是规范里的常数，本页不抄。

## 官方为什么这样拆

- **含叔块 ≠ 已经齐了：** 官方说旧式只看父子时间，叔块率可以被拿来抬发行。看见本页，不是发行已经锁死，也不是已经取消叔块奖励。
- **只看头 ≠ 已经数清：** 官方主动放弃精确个数，换「空哈希 / 非空」这一档，好让难度只吃头。看见能调难度，不是已经按个数调。
- **可预期发行 ≠ 已经没有炸弹：** 本页改的是均值目标里有没有叔块，不是炸弹项。看见可预期，不是已经写了后来那些推迟炸弹、改奖励的分叉。

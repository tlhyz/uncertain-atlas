## 1. 核心问题

阿比看见下一纪元的 RANDAO 种子已经提前知道，以为出块人名单已经锁死；或看见信标状态多了一份前瞻名单，以为已经是 based 预确认，或已经是秘密领袖选举，或执行层已经能用；或看见规范编号 7917，以为就是 4399，或已经是 7251。

官方句（事实）：

- EIP-7917：每个纪元开头，预先算出并写进信标状态一份确定的出块人前瞻，覆盖从本纪元起再往后看得见的那几纪元。
- 和 RANDAO 种子不同：种子至少提前一截就能确定。但 **N+1 纪元的出块日程，在 N 纪元期间并不能从当时的信标状态完全预知**。
- 原因：活跃验证者的有效余额还会在 N 纪元里变；有效余额正是 N+1 纪元选人的输入。
- 创世以来，罚没和罚金积到规范写的那一档，就能改活跃者的有效余额，从而让出块日程在种子已知时仍不确定。
- 抬高有效余额上限（7251）会加重这种不确定：奖励、合并、存款都能让活跃者的有效余额再长。
- 本页另外让下一纪元日程能经信标根和一份简单 Merkle 证明进应用层。看见本页，不是已经是 based 预确认。
- 读出块人下标的函数改成读这份预先算好的名单，不再当场现算。
- 纪元边界：把本纪元那一段挪走，再接上下一段新算的。分叉后第一块要把看得见的前瞻填满。
- 备选「只缓存有效余额」会多占状态，而且不能经信标根把前瞻交给执行层。
- 将来若做秘密领袖选举，官方写仍可能带一份加密前瞻，可复用本字段；若完全去掉前瞻，可以把名单放空。本页不是已经是秘密领袖选举，也不是挡路。
- 安全：本页不加大「改前瞻占便宜」的机会。RANDAO 那一截延迟不改。改的是有效余额用哪一纪元开头的快照，从而去掉「看见种子再改余额」这条边。
- 规范**没有**把种子已知写成日程已经锁死，也没有把前瞻名单写成已经是预确认、已经是秘密领袖选举、或已经等于执行层产品能力，也没有把本页写成 4399 或 7251。

种子、有效余额、出块日程，是三件事。

## 2. 直觉（ELI15）

明天谁当值的抽签种子，今天就已经封好了。  
这不是值班表已经印好。  
有人今天还能改自己口袋里的筹码，明天抽到谁仍可能变。  
墙上多了一张预告名单，不是已经帮别人把货先订走，也不是值日生已经隐身。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| RANDAO 种子已知 | 选人随机输入提前齐 | 已经锁死下一纪元出块人 |
| 有效余额仍可变 | 本纪元里活跃者的余额还能动 | 种子已知就已经排完 |
| 前瞻名单 | 信标状态里预先算好的出块人下标 | 已经是 based 预确认；已经是秘密领袖选举 |
| 7917 | 把种子延迟和余额快照对齐 | 4399 的 mix；7251 的上限 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气出块人在哪一层锁死」。

1. 看见下一纪元种子已经知道。规范：种子提前齐，日程仍可能因有效余额变。
2. 本纪元里有效余额还能动。规范：罚没、罚金、奖励、合并、存款都能改输入。
3. 看见信标状态多了前瞻名单。规范：预先算好并写进状态。不是已经是预确认。
4. 有人把这听成执行层已经能用。规范：经信标根加证明才可能；看见字段不是产品已经接上。
5. 有人把这听成 4399（不变量 157）。那是执行层读上一块 mix。本页是共识层出块日程。
6. 有人把这听成 7251（不变量 196）。那是抬高有效余额上限。本页拿它当动机，不是已经是那一页。
7. 有人把这听成秘密领袖选举。官方只写将来若做，可能复用或放空本字段。

「种子已知 = 日程已锁 / 看见名单 = 已经预确认 / 7917 = 4399 / 7917 = 7251」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 种子提前齐 ≠ 日程已锁；余额快照和种子必须对齐 |
| 协议 | 必须点名问的是种子、有效余额、出块日程，还是预确认 |
| 实现 | 纪元边界整段重算；读下标改走预存名单 |
| 部署 | 不把「状态里有字段」写成执行层已经能用 |
| 经济 | 不把预确认产品句写成已经随本页上线 |

**推断：** 产品句若只写「出块人提前看得见了」，读者会把种子已知听成日程已锁，或把字段听成已经在做预确认。  
**建议：** 第一版可以不抄信标出块日程。若对照，必须分开种子、有效余额、预存名单、应用层证明。不要发明「看见 7917 就已经锁死下一纪元出块人」。不要抄种子前瞻纪元数 / 余额台阶。不要把 7917 写成 4399。

## 6. 和另外几句不是同一句

1. **PREVRANDAO ≠ 无偏骰子**（不变量 157）：执行层读上一块 mix。本页是共识层出块日程。
2. **抬高有效余额上限 ≠ 已经取消最低激活额**（不变量 196）：7251 加重本页要修的不确定。本页不是已经改上限。
3. **排序权必须点名**（不变量 27）：谁写列表、谁签头。本页不改 Builder API。
4. **VRF 抽中 ≠ 已经认证**（不变量 134）：另一条链的抽签。本页是信标出块人前瞻。

不要抄种子前瞻纪元数 / 有效余额台阶 / 每纪元槽数 / 向量长度。不要写怎样打磨有效余额。不编博物馆页。不另写 19 节。不转规范代码。EIP-4399 mix、EIP-7251 上限、秘密领袖选举、域外预确认产品是另一对象。mix 精读：[`../crypto/worked-example-prevrandao-vs-difficulty.md`](../crypto/worked-example-prevrandao-vs-difficulty.md)（不变量 157）。

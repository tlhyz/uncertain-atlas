# 看见合并请求不是已经并成一把

> 类型：worked example（抬高有效余额上限 / 协议内合并）  
> 范围：只写 [EIP-7251](https://eips.ethereum.org/EIPS/eip-7251) 官方页已经写明的对象。不写怎样构造合并调用、怎样挤占队列、怎样改罚没比例。  
> 五层：协议（抬高有效余额上限，另立最低激活额） / 实现（待处理存款不是已经记上有效余额） / 钱包（付了费进队不是已经并成一把） / 应用（激活资格看最低激活额，不再看旧上限） / 威胁（把看见合并请求写成已经并成一把或已经是 7002 退出）。  
> 分类标签：事实 / 推断 / 建议 已分开。  
> 对读：[`../../libraries/invariants/README.md`](../../libraries/invariants/README.md) 不变量 196；[`../../libraries/adversarial-corpus/README.md`](../../libraries/adversarial-corpus/README.md) C200；[`../../libraries/anti-patterns/consolidation-sold-as-done.md`](../../libraries/anti-patterns/consolidation-sold-as-done.md)；[`../../libraries/design-patterns/name-the-consolidation.md`](../../libraries/design-patterns/name-the-consolidation.md)；课 [`../../courses/level-05-ethereum/L05-M02-el-cl-finality.md`](../../courses/level-05-ethereum/L05-M02-el-cl-finality.md)；档案 [`../../protocols/ethereum/README.md`](../../protocols/ethereum/README.md)。

## 事实（官方页能指回去）

1. [EIP-7251](https://eips.ethereum.org/EIPS/eip-7251) 题目是 Increase the MAX_EFFECTIVE_BALANCE。官方 EIP。核心层。依赖 EIP-7002、EIP-7685。不另写 19 节。
2. 官方页写：抬高有效余额上限，同时保留最低质押额。这让大节点运营者能并成更少把验证者，也让单独质押者能拿复利、按更灵活的增量质押。
3. 官方页写：旧上限是原分片设计留下的技术债：那时子委员会要多数诚实。现行设计里这些子委员会只做证明聚合，诚实假设变成「至少有一个」。安全模型不再依赖把上限压得很低。
4. 官方页写：本页这种请求是 7685 总线上的一种类型，字段是来源地址、来源公钥和目标公钥。看见总线不是已经是本页。看见 7002 退出请求不是已经是本页。
5. 官方页写：合约有三条路径：加入合并请求（要付够当时的费）、查询当前费、系统进程按块从队列弹出。付了费、进了队，不是已经出队进本块名单，也不是已经并成一把。
6. 官方页写：每条请求必须按出队顺序出现在 7685 名单里。系统调用发生在处理完本块交易、并且做完块体合并请求校验之后。无代码或调用失败，块必须非法。
7. 官方页写：多付的费不退。从普通账户直接请求总会多付。调用者必须等于信标状态里记下的那一类执行层提款凭证。超出硬上限的合并会被共识层丢掉，费也不退。
8. 官方页写：本页四个定义特征。一是抬高上限、另立最低激活额，允许可变大小验证者。二是协议内把多把下标并起来，不必再走退出再激活。三是执行层部分提款（属于 7002）让人能抽超额而不整把退出。四是把初始罚没改得可忽略，降低合并风险。
9. 官方页写：激活资格改对照最低激活额，不再对照旧上限。流失按权重，不再按把数。退出队列按余额限流，不再按把数。
10. 官方页写：进来的存款先放进待处理存款。从存款造验证者时，有效余额先写成零，再由待处理存款流程更新。看见待处理存款不是已经记上有效余额。
11. 官方页写：`process_consolidation` 启动协议内合并，并把一把验证者切到复利提款凭证。看见复利前缀不是已经并完，也不是已经是 7002 退出。
12. 因此：EIP-7251 ≠ EIP-7002 ≠ EIP-6110 ≠ EIP-7685。看见合并请求不是已经并成一把。抬高有效余额上限不是已经取消最低激活额。进了待处理存款不是已经记上有效余额。

## 推断（从官方句推出，不是另一条共识规则）

- 把「质押」一句用完，会把存款、退出、合并和抬高上限糊成同一对象。
- 把「7685 名单里有一项」读成「已经并成一把」，会把官方「共识层再处理、超出硬上限会丢掉」丢掉。
- 把本页和 7002 糊成「执行层请求」，会把退出/部分提款和合并两个方向听成一句。

## 建议（对「不确定」）

第一版结算机若出现「一把验证者可变大小」，先问四句：看见的是抬高上限，还是已经取消最低激活额？看见的是合并请求，还是已经并成一把？进了待处理存款，还是已经记上有效余额？这是协议内合并，还是已经走了退出再激活？四句各指各的对象。不要发明合并配方或队列挤占法。

## 五层（只展开本对象）

| 层 | 本对象要看见的 |
| --- | --- |
| 协议 | 抬高有效余额上限，另立最低激活额。 |
| 实现 | 待处理存款不是已经记上有效余额；流失按权重。 |
| 钱包 | 付了费不是已经并成一把；多付不退。 |
| 应用 | 激活资格看最低激活额；复利凭证不是已经并完。 |
| 威胁 | 文案把看见合并请求写成已经并成一把，或写成已经是 7002 退出。 |

## 禁句

- 「看见合并请求，就已经并成一把。」
- 「抬高了上限，最低激活额就已经取消。」
- 「进了待处理存款，有效余额就已经记上。」
- 「付了费进队就是已经出队。」
- 「EIP-7251 就是 EIP-7002 / EIP-6110 / EIP-7685。」
- 「这就是退出再激活，或 154 那种无条件加余额。」

## 边界（本页不写）

- 不写怎样构造合并调用、怎样挤占队列、怎样改罚没比例。
- 不写预部署地址、类型取值、每块上限、费公式、字段宽度、硬上限条数。
- 不写 193 退出请求、194 存款请求、192 通用总线本身（只说本页不是它们）。
- 不写官方页里那份读费再付款的合约配方。

## 和相邻对象的唯一性

1. **不是 193 / EIP-7002** — 7002 是执行层触发退出/部分提款。本页依赖它，但本页是抬高上限和协议内合并。看见退出请求不是已经是本页。
2. **不是 194 / EIP-6110** — 6110 是执行层从日志供应存款。本页是合并请求和可变大小验证者。
3. **不是 192 / EIP-7685** — 7685 是通用总线。本页是总线上的一种合并请求。
4. **不是 154 / EIP-4895** — 4895 是共识层推进执行层的无条件加余额。本页不是提款操作。
5. **不是退出再激活** — 官方写大户若走退出再进会极慢极贵，所以才做协议内合并。

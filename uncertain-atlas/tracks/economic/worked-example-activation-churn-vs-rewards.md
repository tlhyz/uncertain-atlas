## 1. 核心问题

阿比看见每纪元激活流失被加上限，以为奖励曲线已经改了；或看见入口变慢，以为出口也已经同样加帽；或看见官方说质押占比里程碑被推迟，以为发奖公式已经重写；或看见规范编号 7514，以为就是 7251。

官方句（事实）：

- EIP-7514：给每纪元流失加一个上沿，把验证者集合的最快增长从指数改成线性。
- 官方写：本页承认改奖励曲线很复杂，本页只用来减慢增长。
- 官方写：信标链奖励函数是 2020 年上线前选的，当时的研究还在 MEV 之前。值得讨论奖励要不要改，好让质押过了某一点之后不那么划算。本页**不尝试**做这件事，只给社区多留讨论时间。
- 官方写：现在先限制每纪元流失，到达总 ETH 质押关键里程碑的时间会显著推迟。这给更完整的方案和研究共识留时间。
- 本页**不要求**改执行层。
- 共识层：新增带上沿的激活流失函数；登记更新改走这条有界激活流失。
- 向后：共识层验块规则不兼容，必须硬分叉。
- 安全段：官方写本页打破验证者入口队列和出口队列的对称。入口受激活流失上沿约束，出口不受同一上沿约束。
- 规范**没有**把激活流失帽写成已经改了奖励曲线，也没有把入口帽写成已经是出口帽，也没有把推迟里程碑写成已经改了发奖公式，也没有把本页写成 7251。

激活流失帽、奖励曲线、出口队列、有效余额上限，是四件事。

## 2. 直觉（ELI15）

新柜台每天只能办完有限几个「入职」。  
本页给入职窗口加了顶。  
入职变慢，不是工资表已经改了。  
也不是离职窗口已经同样加顶。  
更不是「大柜台可以并成一把」那一页。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 激活流失帽 | 每纪元最多能激活多少把的上沿 | 已经改了奖励曲线 |
| 入口帽 | 只约束激活队列 | 已经是出口帽 |
| 推迟里程碑 | 总质押占比到关键点更慢 | 已经改了发奖公式 |
| 7514 | 给激活流失加顶 | 7251 的上限与合并 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气质押还停在哪一层」。

1. 看见每纪元激活流失加了顶。规范：把最快增长从指数改成线性。不是已经改了奖励曲线。
2. 看见入口变慢。规范：只给激活流失加顶。不是出口已经同样加帽。
3. 看见官方说关键质押占比会更晚到。规范：本页只用来减慢增长、多留讨论时间。不是发奖公式已经重写。
4. 看见本页。规范：不改执行层。不是已经改了执行规则。
5. 有人把这听成不变量 196。那是抬高有效余额上限、另立最低激活额。本页不改那两把尺子。
6. 有人把这听成不变量 193。那是执行层退出请求。本页是共识层激活流失。
7. 有人把帽取值或日期表抄进不确定。规范：那些是当时推演，不是产品常量。

「激活帽 = 已经改奖励 / 入口帽 = 已经是出口帽 / 7514 = 7251」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 不换签算法；流失帽不是已经换了域 |
| 协议 | 必须点名问的是激活帽、奖励曲线、出口队列，还是有效余额上限 |
| 实现 | 登记更新改走有界激活流失；出口仍走原来的流失 |
| 部署 | 官方要硬分叉；不把帽取值或日期表抄进不确定 |
| 经济 | 减慢增长不是已经改了发奖；入口加顶不是出口已经对称 |

**推断：** 产品句若只写「质押涨太快所以奖励已经改了」，读者会把激活帽听成奖励曲线，或把 7514 听成 7251。  
**建议：** 第一版可以不抄信标激活流失。若对照，必须分开激活帽、奖励曲线、出口队列、有效余额上限。不要发明「看见 7514 就已经改了奖励」。不要抄帽取值或日期百分比表。不要写怎样灌满存款队列。

## 6. 和另外几句不是同一句

1. **抬高有效余额上限 ≠ 已经取消最低激活额**（不变量 196）：7251 改的是一把能有多大、怎么并。本页改的是每纪元最多激活多少。
2. **执行层退出请求 ≠ 已经退出**（不变量 193）：7002 是执行层条子。本页是共识层激活流失。
3. **签过的自愿退出 ≠ 已经永远有效**（不变量 213）：7044 锁的是退出域。本页不改签名域。
4. **存款日志 ≠ 已经办完**（不变量 194）：6110 是存款供应。本页是激活排队速度。

不要抄帽取值、日期百分比表、收益率、规范提交哈希。不要写怎样灌满存款队列或打磨流失。不编博物馆页。不另写 19 节。不转规范代码。EIP-7251 上限与合并、奖励曲线产品、出口队列、执行层是另一对象。合并精读：[`worked-example-maxeb-vs-minact.md`](worked-example-maxeb-vs-minact.md)（不变量 196）。

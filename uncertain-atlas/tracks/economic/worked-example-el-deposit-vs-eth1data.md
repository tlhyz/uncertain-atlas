# 看见执行层存款日志不是已经由共识层办完

> 类型：worked example（执行层供应验证者存款）  
> 范围：只写 [EIP-6110](https://eips.ethereum.org/EIPS/eip-6110) 官方页已经写明的对象。不写怎样构造存款交易、怎样解析日志、怎样伪造名单。  
> 五层：协议（存款名单附在执行块上，纳入与校验改由执行层负责） / 实现（日志顺序必须等于本块请求名单顺序） / 钱包（看见存款交易不是已经进名单） / 应用（旧投票关掉不是已经过渡完） / 威胁（把看见日志写成已经是验证者或已经办完）。  
> 分类标签：事实 / 推断 / 建议 已分开。  
> 对读：[`../../libraries/invariants/README.md`](../../libraries/invariants/README.md) 不变量 194；[`../../libraries/adversarial-corpus/README.md`](../../libraries/adversarial-corpus/README.md) C198；[`../../libraries/anti-patterns/deposit-sold-as-validator.md`](../../libraries/anti-patterns/deposit-sold-as-validator.md)；[`../../libraries/design-patterns/name-the-el-deposit.md`](../../libraries/design-patterns/name-the-el-deposit.md)；课 [`../../courses/level-05-ethereum/L05-M02-el-cl-finality.md`](../../courses/level-05-ethereum/L05-M02-el-cl-finality.md)；档案 [`../../protocols/ethereum/README.md`](../../protocols/ethereum/README.md)。

## 事实（官方页能指回去）

1. [EIP-6110](https://eips.ethereum.org/EIPS/eip-6110) 题目是 Supply validator deposits on chain。官方 EIP。依赖 EIP-7685。不另写 19 节。
2. 官方页写：把验证者存款附进执行块结构。存款的纳入与校验改由执行层负责，共识层不再需要存款投票（或 eth1data 投票）。
3. 官方页写：一块里供应的存款名单，来自该块里每笔存款交易发出的存款合约日志。看见存款交易不是已经进了本块请求名单。看见日志不是已经解析成本页这种请求。
4. 官方页写：本页这种请求是 7685 总线上的一种类型，字段是公钥、提款凭证、金额、签名和下标。看见总线不是已经是本页。
5. 官方页写：从分叉块起，本块累积的每条存款必须按日志出现顺序出现在 7685 请求名单里。进了日志不是已经进了名单。
6. 官方页写：必须按合约地址和事件签名过滤。同一合约还可以发出别种事件。看见合约地址对得上不是已经是本页这种存款事件。
7. 官方页写：共识层新增存款请求名单、用来切换旧机制的起始下标、过渡期约束旧投票、以及处理存款请求的函数。过渡完成之后，客户端可以各自关掉旧投票，不必齐步。看见新字段不是已经关掉旧投票。
8. 官方页写：过渡完成的点，是旧存款下标已经等于新机制起始下标。两个下标还没对齐，不是已经能拆掉旧投票。
9. 官方页写：下标用来确定性初始化起始下标，避免旧投票退役时同一笔存款被办两次。看见下标不是已经办过，也不是已经不会再办。
10. 官方页写：旧投票因为跟随距离大，新验证者下标在不同分叉上保持同一把。本页打破这条，同一公钥在不同分叉上可以有不同下标。看见公钥对得上不是跨分叉已经是同一把验证者。
11. 官方页写：存款操作名单不设条数上限。不设上限不是已经没有代价，也不是已经由共识层办完。
12. 官方页写：协议内处理让诚实在线节点即使面对超过三分之二的敌对质押，也不会被说服去办假存款。在线节点的执行层会对照本块执行再验名单。乐观同步仍靠诚实多数；能最终敲定一条非法链的对手，也能让同步中的节点收下假存款。这仍落在今天执行世界状态的同一安全模型里。
13. 因此：EIP-6110 ≠ EIP-7685 ≠ EIP-7002 ≠ EIP-4895。看见执行层存款日志不是已经由共识层办完。看见存款交易不是已经进了本块请求名单。旧投票不是已经关掉。公钥有了下标不是跨分叉已经同一把。

## 推断（从官方句推出，不是另一条共识规则）

- 把「存款」一句用完，会把用户交易、合约日志、本块请求名单和共识层办完糊成同一对象。
- 把「7685 名单里有一项」读成「已经是验证者」，会把官方「共识层再处理」和「下标跨分叉可变」丢掉。
- 把本页和 7002 糊成「执行层请求」，会把存款纳入与退出请求两个方向听成一句。

## 建议（对「不确定」）

第一版结算机若出现「执行层供应验证者存款」，先问四句：看见的是存款交易，还是已经解析成请求？进了日志，还是已经按顺序进了本块名单？名单里有一条，还是共识层已经办完？旧投票还在过渡，还是两个下标已经对齐？四句各指各的对象。不要发明日志解析配方或假存款构造法。

## 五层（只展开本对象）

| 层 | 本对象要看见的 |
| --- | --- |
| 协议 | 存款名单附在执行块上；纳入与校验改由执行层负责。 |
| 实现 | 日志顺序必须等于本块请求名单顺序；必须按地址和事件签名过滤。 |
| 钱包 | 看见存款交易不是已经进名单，也不是已经是验证者。 |
| 应用 | 旧投票关掉不是已经过渡完；下标跨分叉可以不同。 |
| 威胁 | 文案把看见日志写成已经是验证者，或写成已经办完。 |

## 禁句

- 「看见存款交易，验证者就已经在。」
- 「看见存款日志，共识层就已经办完。」
- 「进了本块请求名单，就已经是验证者。」
- 「有了新字段，旧投票就已经关掉。」
- 「公钥对得上，跨分叉就已经是同一把。」
- 「EIP-6110 就是 EIP-7685 / EIP-7002 / EIP-4895。」

## 边界（本页不写）

- 不写怎样构造存款交易、怎样解析日志、怎样伪造名单。
- 不写合约地址、事件哈希、类型取值、字段宽度、布局常数、气价或条数上限。
- 不写 154 无条件加余额、192 通用总线、193 退出请求本身（只说本页不是它们）。
- 不写怎样在乐观同步里塞假存款。

## 和相邻对象的唯一性

1. **不是 192 / EIP-7685** — 7685 是通用总线。本页是总线上的一种存款请求。看见总线不是已经是本页。
2. **不是 193 / EIP-7002** — 193 是执行层请求共识层退出或部分提款。本页是执行层从日志供应存款给共识层。方向不同。
3. **不是 154 / EIP-4895** — 4895 是共识层推进执行层的无条件加余额。本页是执行层把存款名单交给共识层。
4. **不是 149 / 处理完一块** — 149 是执行层跑完 ≠ 已经改头。本页是存款请求 ≠ 已经办成验证者。
5. **不是旧 eth1data 投票** — 本页要拆掉的就是那套投票。看见新名单不是已经过渡完。

# 看见执行层退出请求不是已经退出

> 类型：worked example（执行层触发退出 / 部分提款请求）  
> 范围：只写 [EIP-7002](https://eips.ethereum.org/EIPS/eip-7002) 官方页已经写明的对象。不写怎样构造调用、怎样挤占队列、怎样用热钥或冷凭证抢先退出。  
> 五层：协议（执行层退出消息先附在执行块上，再交给共识层） / 实现（进队不是已经出队；名单顺序必须等于出队顺序） / 钱包（付了费不是已经退出） / 应用（校验失败块不必非法） / 威胁（把看见请求写成已经退出或已经是 4895 提款）。  
> 分类标签：事实 / 推断 / 建议 已分开。  
> 对读：[`../../libraries/invariants/README.md`](../../libraries/invariants/README.md) 不变量 193；[`../../libraries/adversarial-corpus/README.md`](../../libraries/adversarial-corpus/README.md) C197；[`../../libraries/anti-patterns/queued-sold-as-exited.md`](../../libraries/anti-patterns/queued-sold-as-exited.md)；[`../../libraries/design-patterns/name-the-el-exit.md`](../../libraries/design-patterns/name-the-el-exit.md)；课 [`../../courses/level-05-ethereum/L05-M02-el-cl-finality.md`](../../courses/level-05-ethereum/L05-M02-el-cl-finality.md)；档案 [`../../protocols/ethereum/README.md`](../../protocols/ethereum/README.md)。

## 事实（官方页能指回去）

1. [EIP-7002](https://eips.ethereum.org/EIPS/eip-7002) 题目是 Execution layer triggerable withdrawals。官方 EIP。依赖 EIP-7685。不另写 19 节。
2. 官方页写：增加一种机制，让验证者能用**执行层提款凭证**触发退出和部分提款。这些执行层退出消息先附在执行块上，再由共识层处理。
3. 官方页写：验证者有两把钥。活动钥热着签名、值班；提款凭证可以冷着，只做有限的提款和所有权操作。提款凭证才是押金和奖励的最终主人。
4. 官方页写：按当时的既有规则，**只有活动钥能发起验证者退出**。提款凭证持有人不能独自选择退出。本页让执行层地址型提款凭证也能触发退出。
5. 官方页写：本页这种请求是 7685 总线上的一种类型，字段是来源地址、验证者公钥和金额。看见总线不是已经是本页这种退出请求。
6. 官方页写：合约有三条路径：加入请求（要付够当时的费）、查询当前费、系统进程按块从队列弹出。付了费、进了队，不是已经出队进本块名单。
7. 官方页写：每条请求必须按出队顺序出现在 7685 请求名单里。进了合约队列不是已经进了本块名单。
8. 官方页写：共识层草图新增一种操作。处理函数类似自愿退出，但校验失败（例如已经退出）时**块不必失败**，类似从执行层来的存款。看见名单里有一条，不是已经退出，也不是已经提款。
9. 官方页写：多把验证者可以共用同一执行层提款凭证，所以要用公钥区分要退出的是哪一把。看见凭证对得上不是已经点名了哪一把。
10. 官方页写：请求必须嵌进信标块体，让共识层能在执行层离线时仍跑完共识那一半。不能靠同步去问执行层「这一块有哪些请求」。
11. 官方页写：调用者必须等于信标状态里记下的执行层提款凭证。调用成功不是已经由共识层办完。
12. 官方页写：多付的费不退。费在交易创建和入块之间可以变。系统调用失败则块非法；合约里没有代码就激活，后续块会一直非法。
13. 因此：EIP-7002 ≠ EIP-4895 ≠ EIP-7685。看见执行层退出请求不是已经退出。进了本块名单不是已经由共识层办完。付了费进队不是已经出队。

## 推断（从官方句推出，不是另一条共识规则）

- 把「提款」一句用完，会把 154 那种共识层推进执行层的无条件加余额，和本页这种执行层请求共识层退出糊成同一对象。
- 把「7685 名单里有一项」读成「已经退出」，会把官方「校验失败块不必失败」那一句丢掉。
- 把「活动钥自愿退出」和「提款凭证触发退出」糊成一句，会把官方「当时只有活动钥能发起退出」那一句丢掉。

## 建议（对「不确定」）

第一版结算机若出现「执行层触发退出 / 部分提款」，先问四句：看见的是活动钥自愿退出，还是提款凭证触发的请求？进了队，还是已经出队进本块名单？名单里有一条，还是共识层已经办完？这是请求共识层，还是已经是 4895 那种无条件加余额？四句各指各的对象。不要发明调用配方或队列挤占法。

## 五层（只展开本对象）

| 层 | 本对象要看见的 |
| --- | --- |
| 协议 | 执行层退出消息先附在执行块上，再交给共识层。 |
| 实现 | 进队不是已经出队；名单顺序必须等于出队顺序。 |
| 钱包 | 付了费不是已经退出；多付不退。 |
| 应用 | 校验失败块不必非法；公钥用来区分共用凭证。 |
| 威胁 | 文案把看见请求写成已经退出，或写成已经是 4895 提款。 |

## 禁句

- 「看见执行层退出请求就是已经退出。」
- 「进了本块请求名单，共识层就已经办完。」
- 「付了费进队就是已经出队。」
- 「校验失败，这块就已经非法。」
- 「EIP-7002 就是 EIP-4895 / EIP-7685。」
- 「这就是活动钥自愿退出，或 154 那种无条件加余额。」

## 边界（本页不写）

- 不写怎样构造调用、怎样挤占队列、怎样抢先退出。
- 不写预部署地址、类型取值、每块上限、费公式、字段宽度。
- 不写 154 无条件加余额、192 通用总线、194 存款请求本身（只说本页不是它们）。
- 不写系统调用失败后怎样洗交易集。

## 和相邻对象的唯一性

1. **不是 154 / EIP-4895** — 4895 是共识层推进执行层的系统提款，无条件加余额。本页是执行层请求共识层退出或部分提款，方向相反。
2. **不是 192 / EIP-7685** — 7685 是通用总线。本页是总线上的一种退出/部分提款请求。看见总线不是已经是本页。
3. **不是活动钥自愿退出** — 官方写当时只有活动钥能发起退出。本页补的是提款凭证也能触发。
4. **不是 149 / 处理完一块** — 149 是执行层跑完 ≠ 已经改头。本页是退出请求 ≠ 已经退出。
5. **不是 190 / EIP-7702** — 7702 是账户委托指示。本页不是授权名单。
6. **不是 194 / EIP-6110** — 6110 是执行层从日志供应存款。本页是执行层请求共识层退出。方向不同。看见存款日志不是已经是本页。

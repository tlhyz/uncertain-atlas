# 例：看见收据状态码不是已经能从剩余气推断成功

**层次**：实现 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Ethereum [EIP-658](https://eips.ethereum.org/EIPS/eip-658)（Final, Core；依赖 EIP-140）。  
**对应课文**：[L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)。  
**不要写进**：`index/03` 共识行、M5.4、L5.4。

## 官方三件事

规范把收据里的成功/失败写成一个独立字段，不是「气烧没烧完」一件事：

1. **收据里的中间状态根，换成顶层调用成功或失败的状态码。**  
   看见状态码，不是收据里还印着中间状态根。官方写：中间状态根已经被另一份规范废掉；本页是最小改动，用来取出成功或失败。看见本页，不是已经写了那份废掉中间根的规范。
2. **有了故意回滚之后，不能再假定「失败当且仅当气烧光」。**  
   官方原文：用户不能再靠气是否烧光判断这笔成没成、状态改动有没有落地。看见还剩气，不是已经成功；看见气烧光，不是已经失败。看见本页，不是已经写了带回剩余气的回滚（不变量 177）。
3. **靠重放交易问 RPC，不是共识解。**  
   官方写：全节点可以重放；快同步节点只能对自己的枢轴之后重放；轻节点根本做不到。看见 RPC 能告诉你成没成，不是收据里已经有状态码，也不是轻客户端产品已经齐。

状态码只区分顶层调用成功或失败。看见失败档，不是已经带上返回数据；看见成功档，不是已经把返回数据写进收据。返回缓冲是另一对象（不变量 232）。

分叉高度是规范里的常数，本页不抄。

## 官方为什么这样拆

- **状态码 ≠ 剩余气：** 官方说，故意回滚让「气烧光才是失败」这条旧假定失效。没有共识字段，调用方没有清楚的办法知道状态改动有没有落地。
- **状态码 ≠ 中间状态根：** 官方说，本页替换的是收据里已经过时的中间根字段，不是另开一栏。看见状态码，不是轻客户端已经能从收据复算中间根。
- **状态码 ≠ RPC 重放：** 官方把重放标成非共识、而且轻节点做不到。看见钱包绿了，不是收据字段已经齐。

官方还写：这补上了收据里原先缺的返回信息。看见状态码，不是返回数据已经进了收据，也不是已经写了返回缓冲。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 收据状态码 | 顶层成功或失败 | 不是剩余气已经够用 |
| 剩余气推断 | 旧假定，140 之后失效 | 不变量 177 是回滚留气 ≠ 烧光 |
| 中间状态根 | 被本页换掉 | 废掉中间根的那份规范是另一对象 |
| RPC 重放 | 非共识 | 不是轻客户端已经能验 |
| 返回数据 | 不是本页字段 | 不变量 232 |
| 线上收据无布隆 | 另一对象 | 不变量 207 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见还剩气就已经知道成功 / 看见 RPC 绿了收据就已经有状态码 / 看见状态码就已经有返回数据」。成功或失败若要给轻节点看，必须写进共识对象，不能靠重放。

## 本页不抄

- 分叉高度、状态码取值。
- 怎样重放交易问 RPC，怎样改收据编码，怎样从枢轴之后补状态。

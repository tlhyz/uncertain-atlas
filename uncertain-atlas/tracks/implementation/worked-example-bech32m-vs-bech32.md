# 工作实例：后继校验过了不是已经是旧校验那套地址

> **事实 / 推断 / 建议** 已分开。
> 对照：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[地址 ≠ 已有输出](worked-example-address-vs-utxo.md)、[钥匙路径 ≠ 揭树](worked-example-keypath-vs-scriptpath.md)、[工作包 ≠ 已广播](worked-example-psbt-vs-broadcast.md)。
> 主文献：[BIP-350](https://github.com/bitcoin/bips/blob/master/bip-0350.mediawiki) Bech32m format for v1+ witness addresses。官方 BIP。应用层。替换 BIP-173 对版本 1 及以后的用法。不另写 19 节。
> 本页钉 **后继校验过了 ≠ 已经是旧校验那套地址**、**版本 0 过了后继校验 ≠ 已经合法**、**更高版本过了旧校验 ≠ 已经合法**、**看见后继地址串 ≠ 已经有 UTXO**、**BIP-350 ≠ BIP-173 ≠ BIP-141**。不抄校验常数 / 字符表 / 例地址 / 长度窗。不写怎样插删字符让旧校验仍过，也不写怎样造「旧校验过、版本却是新的」的串。

## 1. 核心问题

阿比看见地址过了校验，以为 173 和 350 已经是同一盏灯；或看见更高版本的见证地址，以为旧校验过了就已经合法；或看见规范编号 350，以为已经覆盖「看见地址 = 已经有输出」那一页。

官方句（事实）：

- BIP-350：定义一种改进的变体，叫 Bech32m，并改正 BIP-173：原生隔离见证**版本 1 及以后**用 Bech32m。版本 0 仍用 Bech32。
- 本页替换 173 对更高版本的用法。其它方面（含可读前缀）不变。
- 官方动机：173 的校验有一个意外弱点，在特定插入/删除下仍可能过。现有版本 0 地址因长度被限在两种，不受影响。以后的用法和其它应用可能受影响。本页用变体缓解这个插入弱点。
- 生成：版本 0 用旧校验；版本 1 及以上用后继校验。
- 解码：必须同时能认两套，或用同时支持两套的解码器，并且**核编码与版本是否配对**——版本 0 必须是旧校验，其它必须是后继。
- 同一长度下，合法的旧串和后继串至少差几个字符，不会同时两套都合法。
- 若版本 0 同时允许两套编码，检错能力会变弱。官方因此不允许。
- 故意打断「旧软件按 173 就能给更高版本付款」的向前兼容。新地址过不了旧校验，现有发送者不会踩那个插入弱点，也不会再出现实验里见过的「给版本 1 付款却烧币」。
- 更高版本应当被认成合法收款对象，但在网上还没定义之前，钱包不应当去创建它们。
- 和 173 一样：可以指出可能错在哪，不应当拿纠错当改对。
- 规范**没有**把后继校验过写成已经是旧校验，也没有把看见后继串写成已经有输出，也没有把本页写成 141。

后继校验、旧校验、链上输出，是三件事。

---

## 2. 直觉（ELI15）

新门锁和旧门锁长得很像，钥匙孔却不是同一把。  
旧钥匙能开 0 号门，开不了 1 号门。新钥匙反过来。  
看见一串过了某一把锁的校验，不是门后面已经有东西，也不是另一把锁已经认。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 旧校验（Bech32） | 版本 0 原生见证地址用的那套 | 已经覆盖版本 1 及以后 |
| 后继校验（Bech32m） | 版本 1 及以后用的变体 | 已经是 173；已经是链上输出 |
| 版本与编码配对 | 0 必须旧，其它必须后继 | 过了任意一套就已经合法 |
| 故意不向前兼容 | 新地址过不了旧校验 | 已经是 173 那页的「看见地址」 |

---

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气地址校验卡在哪」。

1. 版本 0 地址。规范：仍用旧校验。不是已经改用后继。
2. 版本 1 及以后。规范：必须用后继。旧校验过了不是已经合法。
3. 版本 0 却用了后继。规范：不合法。不是「过了后继 = 已经更好」。
4. 看见后继串。规范：仍是收款写法。不是已经有 UTXO（那是不变量 174）。
5. 有人把这听成 141。141 是见证程序本身。本页是地址用哪套校验。
6. 有人把这听成 174 那页。174 是「看见串 ≠ 已经有输出」。本页再拆两套校验。
7. 有人把这听成钥匙路径（不变量 153）。那是怎么花 Taproot。本页是地址编码。

「过了校验 = 已经是 173 / 更高版本过了旧校验 = 已经合法 / 350 = 看见就有 UTXO」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新原语；改的是校验常数 |
| 协议 | 必须点名问的是旧校验、后继校验，还是链上输出 |
| 实现 | 两家必须核「版本与编码配对」；不得两套都收版本 0 |
| 部署 | 应用层；故意打断旧发送者对更高版本的向前兼容 |
| 经济 | 认更高版本为可收款不是钱包已经该创建它们 |

**推断：** 产品句若只写「支持 Bech32」，读者会把后继校验听成已经是 173，或把更高版本过了旧校验听成已经能付。  
**建议：** 第一版若提供原生见证地址，必须分开旧校验和后继校验，并核版本配对。不要发明「过了校验 = 已经是同一套」。不要抄常数。不要把 350 写成 173。

---

## 6. 和另外几句不是同一句

1. **地址 ≠ 已有输出**（不变量 174）：看见串不是账本对象。本页再拆两套校验。
2. **钥匙路径 ≠ 揭树**（不变量 153）：Taproot 怎么花。本页是地址用哪套校验。
3. **txid ≠ wtxid**（不变量 152）：交易身份。本页不是见证哈希。
4. **工作包 ≠ 已广播**（不变量 179）：签名传到哪一步。本页是收款写法。

不要抄校验常数 / 字符表 / 例地址 / 长度窗 / 可读前缀。不要写怎样插删字符让旧校验仍过，或怎样造版本与编码不对的串。不编博物馆页。不另写 19 节。BIP-173 旧校验页、BIP-141 程序长度表、纠错当改对是另一对象。

## 精密检查

**禁止假学习：** 「过了校验 = 已经是 173。」「更高版本过了旧校验 = 已经合法。」「版本 0 用后继 = 已经更好。」「350 = 已经有输出。」「350 = 141。」  
**边界：** 不抄常数。不另写 19 节。不写怎样插删字符。看见串见 **C178**。钥匙路径见 **C157**。

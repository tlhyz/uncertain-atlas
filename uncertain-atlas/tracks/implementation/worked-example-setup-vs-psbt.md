# 例：看见部分签名包不是已经是跨厂安全多签开户；看见指纹对上不是已经核过 KEY；看见 TOKEN 不是已经是钱包种子

**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-129](https://github.com/bitcoin/bips/blob/master/bip-0129.mediawiki)（Complete, Applications, Specification）。依赖 BIP-32、BIP-174、BIP-322、BIP-380、BIP-381、BIP-382、BIP-383。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。

## 官方三件事

规范把跨厂安全多签开户写成三件独立的结构事，不是「看见部分签名包就已经开好了多签」一件事：

1. **看见部分签名包 / 看见签流程 不是已经是跨厂安全多签开户，也不是已经核过成员、脚本类型、派生路径和门限。**  
   官方写：174 把多方签名体验理顺了。可是跨不同厂家安全开好多签钱包，还缺一份标准流程。官方另写：要管的是配置有没有被改、开户时钥和配置有没有漏出去、签名器有没有把配置存下来、用什么格式存。能改配置的对手可以骗用户打到错地址；改不了、只看见钥或配置的对手可以盯这笔钱包。看见包还能签，不是已经开过户。看见签流程齐了，不是成员名单已经核过。
2. **看见指纹对上 / 看见钥记录 不是已经核过 KEY，也不是已经各方确认同一份。**  
   官方写：签名器必须核对描述符或描述符模板里有没有自己的 KEY，而且必须做精确比对，不能走指纹那种捷径，因为指纹很容易伪造。官方另写：签名器必须给用户看钱包第一地址和政策参数，至少包括派生路径限制、M、N，以及自己的 KEY 在政策脚本里的位置。N 是为了挡住插钥攻击；位置在钥顺序有意义的脚本里才要紧。各方必须互相核：除了 KEY 位置，所有签名器看到的确认必须一样。核对过了，签名器必须把描述符记录存下来。看见指纹对上，不是已经对上那把 KEY。看见第一地址，不是各方已经对过同一份。
3. **看见 TOKEN / 看见加密会话 不是已经是钱包种子，也不是已经防篡改存储，也不是已经会用这份配置去长地址。**  
   官方写：TOKEN 只在开户阶段需要，开完可以丢掉；不建议同一把 TOKEN 开多份钱包。TOKEN 也可以编成 39 那种词表助记句，可是扩展模式不建议这么做，免得和种子助记词搞混。官方另写：存储防不防篡改、签名器以后会不会用这份配置去长收款和找零地址，由签名器自己处理，不在本页范围。看见 TOKEN，不是已经是那份钱包种子。看见存进了签名器，不是存储已经防篡改，也不是以后长地址已经齐。

记录行格式、加密配方、测试向量、描述符模板展开是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **部分签名包 ≠ 已经是跨厂安全多签开户：** 官方把签流程和开户流程写成两件缺一不可的事。
- **指纹对上 ≠ 已经核过 KEY：** 官方把精确比对、第一地址确认、各方互核写成三道门，不是看见指纹就过。
- **TOKEN ≠ 已经是钱包种子：** 官方把开户会话秘密和钱包备份分开，还把存盘与以后长地址划出本页。

## 1. 核心问题

阿比看见存储按净计量计价，以为已经是瞬时存储；或看见只谈当前值和新值，以为已经没有「这一笔开始时的原来值」；或看见同帧里再写更便宜，以为已经能在转账津贴里改槽；或看见规范编号 2200，以为就是 3529 的退款削减，或已经是 2929 的冷热，或已经是 1283 那道津贴洞。

官方句（事实）：

- EIP-2200：给存储写入做**净计量**，并把 1283 与 1706 合成一页、用参数写清。看见本页，不是已经是瞬时存储。
- 官方写：计价用的是槽的**原来值**、**当前值**和退款计数。看见只谈当前值和新值，不是已经齐了。
- 官方写：当前值等于新值是空操作，按读价扣。看见空操作，不是已经「从未写过」。
- 官方写：原来值等于当前值，才是这一执行上下文第一次改这个槽；原来值不等于当前值，这个槽已经脏了。看见脏了，不是已经是第一次写。
- 官方写：剩余气小于等于转账津贴时，写存储让当前帧以气不够失败。看见净计量，不是已经能在转账津贴里改槽。
- 官方写：1283 原定义会给已有合约带来一种新的重入危险，因为高级语言默认给简单转账一笔津贴；若低剩余气时不许写存储，这个危险就容易挡住，且不拆 1283 的原意。看见本页，不是已经是 1283 那道洞。
- 官方写：本页大体做到瞬时存储想做的事，但不必引入脏图或另一套存储结构。看见本页，不是已经是 1153。
- 官方写：和当时旧表比，本页不会更贵。看见净计量，不是已经涨价。
- 规范**没有**把净计量写成已经是瞬时存储，也没有把本页写成 3529 或 2929，也没有把本页写成已经能在津贴帧里改槽。

原来值、当前值、新值、已经是瞬时存储，是四件事。

## 2. 直觉（ELI15）

柜子上现在记三件事：开店时什么样、刚才什么样、你要改成什么样。  
三本账，不是已经另开了一间下班就拆的临时库房。  
刚才已经改过，不是今天第一次开门。  
口袋里只剩「送货小费」那么多气，这页不许再改柜子——不是小费帧里已经能写存储。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 净计量 | 按原来值 / 当前值 / 新值计价 | 已经是瞬时存储 |
| 原来值 | 这一笔开始时槽上的值 | 已经是当前值；已经是新值 |
| 津贴帧禁写 | 剩余气不够则写存储失败 | 已经能在转账津贴里改槽 |
| 2200 | 净计量 | 1153；3529；2929；1283 那道洞 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气存储计价还停在哪一层」。

1. 看见存储按净计量计价。规范：用原来值、当前值、退款计数。不是已经是瞬时存储。
2. 看见当前值等于新值。规范：空操作，按读价扣。不是已经从未写过。
3. 看见原来值不等于当前值。规范：这个槽已经脏了。不是已经是这一上下文第一次写。
4. 看见剩余气只够转账津贴。规范：这时写存储，当前帧以气不够失败。不是已经能在津贴帧里改槽。
5. 有人把这听成不变量 159。那是 1153 另开一套本笔结束丢掉的店。本页官方写：大体做到瞬时存储想做的事，但不另开一套。
6. 有人把这听成不变量 223。那是 3529 削薄清零退款。本页是三值计价和津贴帧禁写；3529 只动其中一档退款。
7. 有人把这听成不变量 169。那是 2929 冷热访问。本页管的是原来 / 当前 / 新，不是冷热集合。
8. 有人把气价名取值、津贴数字或测试向量抄进不确定。规范：数字是尺子，不是产品常量。

「2200 = 已经是瞬时存储 / 只有当前值和新值 / 津贴帧里已经能写 / 2200 = 3529 / 2200 = 2929 / 2200 = 1283 那道洞」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 净计量不换签算法 |
| 协议 | 必须点名问的是原来值、当前值、新值，还是已经另开瞬时店 |
| 实现 | 官方写帧级退款计数可以落到负；整笔退款计数保持非负。看见计数不是已经能在执行当中花 |
| 部署 | 官方写这是硬分叉；不预期比旧表更贵 |
| 经济 | 同帧再写更便宜不是已经能在转账津贴里改槽 |

**推断：** 产品句若只写「净计量所以已经是瞬时存储」，读者会把三本账听成临时库房，或把 2200 听成 3529，或把津贴帧禁写听成已经能写。  
**建议：** 第一版可以不抄这套三值表。若对照，必须分开原来值、当前值、新值、已经是瞬时存储。可以跳过「看见 2200 就已经是 1153」。225 net-meter vs transient bundled unbundling 完成（1419 item 1 / 1420 item 2 / 1421 item 3）；精读 [`worked-example-nmet-not1153-vs-bundled.md`](worked-example-nmet-not1153-vs-bundled.md)（不变量 1419 item 1）、[`worked-example-nmet-notcur-vs-bundled.md`](worked-example-nmet-notcur-vs-bundled.md)（不变量 1420 item 2）、[`worked-example-nmet-notstip-vs-bundled.md`](worked-example-nmet-notstip-vs-bundled.md)（不变量 1421 item 3）。不要发明「看见 2200 就已经是 1153」。不要抄气价名取值或津贴数字。不要写怎样在津贴帧里改槽、做重入或实现脏图。

## 6. 和另外几句不是同一句

1. **瞬时存储 ≠ 账户持久存储**（不变量 159）：1153 另开一套本笔丢掉的店。本页官方写不必引入脏图或另一套结构。
2. **退款削减 ≠ 已经没有退款**（不变量 223）：3529 只动 2200 里「原来非零、写成零」那一档。本页是三值计价本身。
3. **本笔第一次碰 ≠ 已经热**（不变量 169）：2929 管冷热集合。本页管原来 / 当前 / 新。
4. **看见退款计数 ≠ 已经能在执行当中用**（不变量 223）：退款仍在整笔之后结算。本页另写：帧级计数可以落到负。

不要抄气价名取值、津贴数字、测试向量。不要写怎样在津贴帧里改槽、怎样做重入、怎样实现脏图。不编博物馆页。不另写 19 节。不转规范代码。1153 瞬时店、3529 退款削减、2929 冷热、1283 原文是另一对象。瞬时存储精读：[`../state-models/worked-example-transient-vs-storage.md`](../state-models/worked-example-transient-vs-storage.md)（不变量 159）。

看见津贴帧里写存储会停 ≠ 已经能在转账津贴里改槽

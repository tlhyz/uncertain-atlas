# 例：看见现有多签派生习惯不是已经要搬家；看见脚本类型层不是已经是账户层；看见本页多签不是已经不排序

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-48](https://github.com/bitcoin/bips/blob/master/bip-0048.mediawiki)（Deployed, Applications）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「多签层次不是已经是账户层 / 已经不排序」，不是用途层已经能互操作，也不是嵌套单签已经能挂在旧账户上找回。

## 官方三件事

规范把多签层次写成三件独立的结构事，不是「看见多签路径就已经是账户发现」一件事：

1. **看见现有多签派生习惯 / 看见本页 不是已经要搬家，也不是已经可以改路径。**  
   官方写：本页要把业界已经在用的那套多签派生习惯写成标准，好让别的实现也能用。本页要维持现有真实用法。不做破坏性改动，免得现有用户丢币。已经在用这套习惯的钱包，不必为了合规再改。看见本页，不是已经要迁移。看见写了标准，不是已经可以换路径。
2. **看见脚本类型层 / 看见账户层 不是已经是同一层；看见本页 不是已经每来一种脚本都要再写一份 BIP。**  
   官方写：这一层把钥空间按脚本类型拆开。为了给以后的脚本类型留向前兼容，本页可以接着往下加，不必每来一种脚本再另写一份 BIP。眼下只覆盖原生隔离见证脚本哈希和嵌套隔离见证脚本哈希。钱包建议默认走原生那一支。看见账户号，不是已经选定脚本类型。看见本页，不是已经把以后的脚本类型都写死。
3. **看见本页多签 / 看见多签路径 不是已经不排序，也不是已经是 BIP44 那条路径。**  
   官方写：任何支持本页的钱包，本身就支持按确定性排序公钥来派生所有可能的多签地址和脚本。看见本页，不是已经可以按随便的顺序拼多签。看见多签层次，不是已经是单签账户发现那条路径。

脚本类型取值、例路径、怎样排序公钥是规范里的取值或另一页的事，本页不抄。

## 官方为什么这样拆

- **现有习惯 ≠ 已经要搬家：** 官方把「不做破坏性改动」写成免得现有用户丢币。
- **脚本类型 ≠ 已经是账户：** 官方另开一层，好给以后的脚本类型往下加。
- **本页多签 ≠ 已经不排序：** 官方把确定性排序写成支持本页就自带的能力。

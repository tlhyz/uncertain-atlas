# 例：看见 pk 不是已经和 pkh / sh 同一套放置；看见 sh 产出不是已经有赎回脚本；看见熟悉的标准脚本不是已经能互操作

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-381](https://github.com/bitcoin/bips/blob/master/bip-0381.mediawiki)（Deployed, Applications, Informational）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「非隔离见证描述符的放置不是已经同一套 / 眼熟不是已经兼容」，不是付给脚本哈希已经揭开赎回，也不是看见描述符已经是地址。不要另写怎样拼 P2PK。

## 官方三件事

规范把非隔离见证描述符写成三件独立的结构事，不是「看见熟悉的标准脚本就已经能读这份描述符」一件事：

1. **看见 pk / 看见写在某一层 不是已经是 pkh 那种放置，也不是已经是 sh 那种只能顶层。**  
   官方写：`pk` 可以出现在任何上下文或任何一层。`pkh` 可以当顶层，也可以套进 `sh` 或 `wsh`。`sh` 只能当顶层。看见写了 `pk`，不是已经能套进任意外层。看见写了脚本表达式，不是已经能再套一层 `sh`。
2. **看见 sh 产出 / 看见 P2SH 输出脚本 不是已经有赎回脚本，也不是已经能花。**  
   官方写：`sh` 还会另造一份赎回脚本，花费时要用。这份赎回脚本就是参数那条脚本表达式产出的输出脚本。看见 `sh` 产出了 P2SH 输出脚本，不是已经把赎回脚本交出来。看见套进了脚本表达式，不是已经揭开赎回。这和 16 那种「付给哈希不是已经揭开赎回」不是同一句。
3. **看见熟悉的标准脚本 / 看见旧节点认得输出 不是已经能互操作，也不是已经不必再写本页。**  
   官方写：这些是全新的描述符，和任何实现都不兼容。不过产出的脚本是标准脚本，现有软件多半认得。看见脚本眼熟，不是已经能读这份描述符。看见旧钱包认得输出，不是已经能导入这段字。

脚本模板、测试向量、例钥、十六进制脚本是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **pk ≠ 已经同一套放置：** 官方把三种表达式的出现位置写成三套规则。
- **sh 产出 ≠ 已经有赎回脚本：** 官方把输出脚本和另造的赎回脚本写成两份对象。
- **眼熟 ≠ 已经兼容：** 官方把「全新描述符」和「标准脚本眼熟」写成两句。

## 和相邻页的边界

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出非隔离见证描述符，必须分开放置、赎回脚本、眼熟不是兼容。可以跳过「看见熟悉脚本就已经能互操作」。若对照，必须分开本页赎回脚本和 16 那种哈希。不要另写怎样拼 P2PK。

## 本页不抄

- 怎样算 HASH160、怎样拼赎回、怎样嵌套。

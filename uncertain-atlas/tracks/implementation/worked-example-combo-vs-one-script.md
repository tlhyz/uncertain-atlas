# 例：看见 combo 不是已经只能产出一种脚本；看见未压缩钥不是已经带齐见证对；看见一份 combo 不是已经是一份钱包策略

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-384](https://github.com/bitcoin/bips/blob/master/bip-0384.mediawiki)（Deployed, Applications, Informational）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「combo 不是已经一种脚本 / 未压缩钥不是已经带齐见证对」，不是 pk 已经和 pkh / sh 同一套放置，也不是钱包策略已经是一条描述符。不要另写怎样拼那几份输出脚本。

## 官方三件事

规范把 combo 描述符写成三件独立的结构事，不是「看见一把钥就已经是一种输出脚本」一件事：

1. **看见 combo / 看见一把钥 不是已经能套进 sh / wsh，也不是已经是一种输出脚本。**  
   官方写：`combo(KEY)` 只能当顶层表达式。它只吃一把钥表达式。看见写了 combo，不是已经能再套进 `sh` 或 `wsh`。看见一把钥，不是已经是 381 那种只产出一种脚本的表达式。
2. **看见未压缩钥 / 看见总是那两份旧脚本 不是已经带齐见证对，也不是已经固定四份。**  
   官方写：combo 永远产出 P2PK 和 P2PKH，和把这把钥分别放进 `pk()`、`pkh()` 一样。只有钥本身是或能长出压缩公钥时，才再产出 P2WPKH 和 P2SH-P2WPKH，和放进 `wpkh()`、`sh(wpkh())` 一样。看见未压缩钥，不是已经有那一对见证脚本。看见永远有两份，不是已经有四份。
3. **看见一份 combo 产出两份或四份脚本 不是已经是一份钱包策略，也不是已经把 381 / 382 那几条表达式写齐。**  
   官方写：一份 combo 按这把钥产出两份或四份输出脚本。看见一份表达式，不是已经是 388 那种「一个账户所需的全部描述符」。看见产出和 `pk` / `pkh` / `wpkh` / `sh(wpkh)` 一样的脚本，不是已经写了那几条表达式，也不是已经是地址。

脚本模板、测试向量、例钥、十六进制脚本是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **combo ≠ 已经一种脚本：** 官方把它写成只能顶层，并且按钥产出两份或四份。
- **未压缩钥 ≠ 已经带齐见证对：** 官方把见证那一对写成只在压缩钥时才出现。
- **一份 combo ≠ 已经是一份钱包策略：** 官方把本页写成一把钥上的几份传统脚本，不是账户上的全部描述符。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 放置 | 只能顶层 | 不是已经和 pk / pkh / sh 同一套放置（276） |
| 见证对 | 压缩钥才另出 | 不是已经是 wpkh / wsh 那套放置（277） |
| 一份表达式 | 一把钥上的两份或四份脚本 | 不是已经是一份钱包策略（280） |
| 描述符总语法 | 本页是 combo 函数 | 不是已经是地址（184） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出 combo，必须分开只能顶层、压缩才出见证对、两份或四份不是账户策略。可以跳过「看见一把钥就已经是一种输出脚本」。若对照，必须分开本页 combo 和 388 那种账户策略。不要另写怎样拼那几份输出脚本。

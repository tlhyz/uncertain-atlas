## 1. 核心问题

阿比看见各家客户端默认配置里的气限改成同一档，以为协议已经写死块气帽；或看见这份建议绑到一次硬分叉发布，以为共识已经改了；或看见默认配置齐了，以为已经是单笔气帽；或看见规范编号 7935，以为就是 7825、7934，或已经是 Sepolia 那次通道尺寸。

官方句（事实）：

- EIP-7935：建议在一次硬分叉发布时，各家执行层客户端把默认配置里生成的气限改到同一档。
- 本页是 Informational。改的是默认配置，不是协议写死的块气帽。
- 各家配置格式不同。要改的是各自默认配置里生成的那个值。
- 动机：想扩一层执行，可以先不加新功能。更高气限会逼出客户端 bug，需要开发者时间去测、去修，所以建议写进一次硬分叉，当作承诺。
- 过去各家默认气限不好齐，所以建议把新默认绑到一次硬分叉发布。
- 向后：更高气限不该弄坏已有合约。官方写：气限抬高之后，新交易有可能超过当时建议的单笔气帽，两份日程要对齐。看见本页，不是已经是那道单笔气帽。
- 安全段：要用各家执行层和共识层的组合开测试网，灌满块，看网络和节点。有 bug 就修，再重来。看起来稳再一点点加。已经研究过会把最坏块体积顶大的构造；官方写在某一档气以下，这不该成为因素，因为那一档靠近当前最坏块体积碰到共识层流言上限的地方。
- 规范**没有**把默认配置写成已经是协议帽，也没有把绑到硬分叉写成已经改了共识，也没有把默认齐了写成已经是单笔气帽，也没有把本页写成不变量 203、202 或 96。

默认配置、协议块气、单笔气帽、通道尺寸，是四件事。

## 2. 直觉（ELI15）

工厂说明书把默认转速写成同一档。  
说明书齐了，不是法律已经把转速写死。  
绑到一次发版日，不是已经改了交通法。  
默认转速齐了，也不是已经给每辆车单独加了限速牌。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 客户端默认气限 | 默认配置里生成的块气建议值 | 已经是协议帽 |
| 绑到硬分叉发布 | 用发版日把各家默认齐起来 | 已经改了共识 |
| 默认配置齐了 | 各家出厂值同一档 | 已经是单笔气帽 |
| 7935 | 默认配置建议 | 单笔气帽；编码硬帽；通道尺寸 |

## 4. 最小案例

一条 Ethereum 要对齐「气限写在哪一层」。

1. 看见各家默认配置改成同一档。规范：Informational，改默认。不是协议已经写死块气帽。
2. 看见绑到一次硬分叉发布。规范：过去默认不好齐。不是共识已经改了。
3. 看见默认齐了。规范：出厂值。不是已经是单笔气帽。
4. 看见要和单笔气帽的日程对齐。规范：两份是两份。不是本页已经是 7825。
5. 有人把这听成不变量 203。那是单笔交易的协议帽。本页是客户端默认。
6. 有人把这听成不变量 202。那是编码体积帽。本页不改编码。
7. 有人把这听成不变量 96。那是出块通道尺寸。本页不改通道。

「看见默认气限 = 已经是协议帽 / 绑到硬分叉 = 共识已改 / 默认齐了 = 已经是单笔帽 / 7935 = 203」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 不涉及新原语 |
| 协议 | 必须点名问的是默认配置、协议块气，还是单笔气帽 |
| 实现 | 各家配置格式不同；默认值不是已经写进共识 |
| 部署 | 官方要组合测试网；不把默认取值抄进不确定 |
| 经济 | 不把「默认抬了」写成已经更安全 |

**推断：** 产品句若只写「气限已经抬到某一档」，读者会把客户端默认听成协议帽，或把绑到硬分叉听成共识已改。  
**建议：** 第一版必须把客户端默认和协议帽分开写。不要发明「看见 7935 就已经改了块气」。不要抄默认取值。不要写怎样抬气限。

---

## 6. 和另外几句不是同一句

1. **单笔气帽 ≠ 已经改了块气限**（不变量 203）：协议给每一笔加帽。本页是客户端默认。
2. **编码硬帽 ≠ 已经改了气限**（不变量 202）：编码体积。本页不改编码。
3. **通道尺寸 ≠ 拼块已齐**（不变量 96）：Engine API 尺寸。本页不改通道。
4. **气 ≠ 墙钟**（不变量 101）：计量尺子。本页是默认配置。

不要抄默认取值、当时主网取值、单笔建议帽、最坏体积、流言上限。不要写怎样抬气限、怎样灌满块，或怎样造最坏块。不编博物馆页。不另写 19 节。单笔气帽、编码硬帽、通道尺寸、气≠墙钟是另一对象。单笔气帽精读：[`worked-example-tx-gas-cap-vs-block.md`](worked-example-tx-gas-cap-vs-block.md)（不变量 203）。

# 例：看见同一套钥不是已经是同一条 P2SH 地址；看见只共享门限和主公钥不是已经够了；看见未压缩钥不是已经是本页

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-67](https://github.com/bitcoin/bips/blob/master/bip-0067.mediawiki)（Complete, Applications）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「同一套钥不是已经是同一条地址 / 未压缩钥不是已经是本页」，不是付给脚本哈希已经揭开赎回，也不是脚本类型层已经是账户层。不要另写 BIP-11 / BIP-45 怎样做多签。

## 官方三件事

规范把确定性多签地址写成三件独立的结构事，不是「看见同一套钥就已经是同一条地址」一件事：

1. **看见同一套钥 / 同一门限 不是已经是同一条赎回脚本，也不是已经是同一条 P2SH 地址。**  
   官方写：赎回脚本并不要求公钥按某一种顺序或某一种编码。同一套钥、同一门限，可以有多到 `2(n!)` 条标准赎回脚本，各有一条 P2SH 地址。遵守顺序和编码，才能让这一「账户」（钥集合加门限）只有一条规范地址。看见钥集合对齐了，不是已经对齐了赎回脚本。看见门限一样，不是已经是同一条地址。
2. **看见只共享门限和参与者主公钥 不是已经够了（没有本页排序），也不是已经要为每个地址另存状态。**  
   官方写：采用本页排序和编码之后，合规钱包对同一套钥、同一门限总会长出同一条 P2SH 地址，好认这笔多签账户的交易。这对分层确定性多签钱包尤其省状态：只要共享门限和参与者的主公钥，各钱包就会长出同一批地址。官方还写：这能让 2-of-3 代签服务之外的一方，在服务不帮忙时也能找回钱包。看见只共享了门限和主公钥，不是已经够了。看见还没采用本页，不是已经必须为每个地址另存一份状态。
3. **看见未压缩钥 / 看见一条 P2SH 地址 不是已经是本页，也不是已经能当网络规则。**  
   官方写：未压缩钥和本页不兼容。兼容实现不应当自动把钥压成压缩形式。收到未压缩钥，应当当成对端实现不兼容。P2SH 地址并不露出里面的脚本，所以本页不能写成网络规则，那样会硬分叉。一群人没有全部合规时，可能有人长出别人认不出的地址。看见未压缩钥，不是已经是本页。看见一条 P2SH 地址，不是已经能当网络规则。

压缩钥例、地址例、脚本十六进制、怎样按字节字典序排是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **同一套钥 ≠ 已经是同一条地址：** 官方把「不要求顺序或编码」写成可以长出多到 `2(n!)` 条标准赎回。
- **只共享门限和主公钥 ≠ 已经够了：** 官方把「只要这两样、各钱包就会长出同一批地址」写成采用本页之后才成立。
- **未压缩钥 ≠ 已经是本页：** 官方禁止自动压缩，并把本页写成不能当网络规则。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出多签地址，必须分开赎回脚本、共享了什么、未压缩钥。可以跳过「看见同一套钥就已经是同一条地址」。若对照，必须分开排序和已经能当网络规则。不要另写怎样按字节字典序排公钥，也不要另写 BIP-11 / BIP-45。270 sorted vs one-address bundled unbundling 完成（1133 item 1 / 1134 item 2 / 1135 item 3）；精读 [`worked-example-sort67-notaddr-vs-bundled.md`](worked-example-sort67-notaddr-vs-bundled.md)（不变量 1133 item 1）。

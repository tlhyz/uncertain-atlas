# 例：看见加密私钥记录不是已经能用；看见厂家代生成不是已经能兑；看见地址哈希片段不是已经是地址

**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。

## 官方三件事

规范把口令保护的私钥记录写成三件独立的备份事，不是「看见一串加密私钥就已经能花」一件事：

1. **看见加密私钥记录 / 看见「还缺一样才能用」 不是已经是私钥，也不是已经能用。**  
   官方写：本页给纸钱包和实物币用，把口令保护的私钥记录编成一串可打印字符。每条记录里有凑回私钥所需的信息，就缺口令。官方另写：用户眼里，开头那种标记代表「一把还缺一样才能用的私钥」。看见加密记录，不是已经能签。看见有了记录，不是已经有口令。看见能打印，不是已经能花。
2. **看见厂家代生成 / 看见椭圆曲线倍点那条路 不是已经和「拿已知私钥再加密」是同一条，也不是厂家已经能兑。**  
   官方写：本页给两种编法。一种是：任何人拿已知私钥、配任意口令，编出记录。另一种是共享生成：编出最终记录和对应地址的那一方（例如实物币厂家）只知道从口令派生出来的一串，真正兑付还要原来的口令。官方动机写：不能被发行方连坐的实物币，比能被发行方拿走的更值。看见厂家编得出地址，不是厂家已经能兑。看见同一种打印串，不是已经能分辨走了哪条编法。看见共享生成，不是已经是「先有私钥再加密」。
3. **看见明文里的地址哈希片段 / 看见这种打印前缀 不是已经是地址，也不是已经解开，也不是已经推荐用。**  
   官方写：结果地址的一小段哈希以明文放进记录，不知道口令的人也能按一定概率把记录对上某条地址；完整地址要解开之后才能得到。官方评论摘要写：一致不鼓励实现。看见能对上某条地址，不是已经解开。看见这种前缀，不是已经是未加密的钱包导入格式。看见本页已部署，不是已经推荐拿来当第一版备份。

加密步骤、口令派生、前缀取值、例串是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **加密记录 ≠ 已经能用：** 官方把「还缺口令」写成记录本身的定义，不是实现没做好。
- **厂家代生成 ≠ 已经能兑：** 官方把两条编法、以及厂家只知道派生串写成不同对象。
- **地址哈希片段 ≠ 已经是地址：** 官方把明文相关性和解开后才能得到完整地址写成两件事，评论还另写不鼓励实现。

# 工作实例：看见助记词不是已经是种子

> **事实 / 推断 / 建议** 已分开。
> 对照：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L1.6](../../courses/level-01-crypto/L01-M06-randomness-and-determinism.md)、[扩展公钥 ≠ 已能花](worked-example-xpub-vs-spendable.md)、[地址 ≠ 已有输出](worked-example-address-vs-utxo.md)。
> 主文献：[BIP-39](https://github.com/bitcoin/bips/blob/master/bip-0039.mediawiki) Mnemonic code for generating deterministic keys。官方 BIP。应用层。规范型。不另写 19 节。
> 本页钉 **看见助记词 ≠ 已经是二进制种子**、**用户自造句子 ≠ 已经是本页那种助记词**、**口令不同 ≠ 已经非法，是另一份钱包**、**助记词校验过了 ≠ 已经能改对**、**BIP-39 ≠ BIP-32 ≠ BIP-173 ≠ BIP-380**。不抄词表 / 熵长表 / 迭代次数 / 盐字符串。不写怎样从句子推出种子，也不写怎样造脑钱包。

## 1. 核心问题

阿比看见十二个词，以为已经拿到种子，已经拿到扩展私钥，已经能花；或把用户自己编的一句话写成已经是本页那种助记词；或把口令写错听成「非法」，而不是另一份钱包。

官方句（事实）：

- BIP-39：用一组好记的词，给确定性钱包当助记码。分两截：先生成助记句，再把助记句转成二进制种子。这份种子**以后**才能交给 BIP-32 或同类方法去长树。
- 本页是把机器生成的随机数用人能抄的写法运走。**不是**把用户自己造的句子（脑钱包）加工成种子。
- 用户可以再加口令。没有口令时用空串。从助记句到种子的转换，和生成句子完全分开。
- 每一份口令都会得到一份合法种子，因而得到一份确定性钱包；只有对的那一份才是想要的钱包。这是官方写的可否认性，不是「口令错了就不合法」。
- 没用本页算法生成的句子也能拿去转种子，但不建议。软件必须按词表算校验，非法要警告。警告不是已经拒绝转种子，也不是已经改对。
- 种子取决于当时用的那份词表。把同一句翻成另一份词表，必然得到完全不同的种子。
- 从助记句到种子是单向的：任意一份 BIP-32 种子，不能用本页句子反过来表示。
- 校验很短：只能中等概率抓住随机错，不能帮忙改对。规范原先没有版本方案；现在多靠描述符钱包（BIP-380）另标地址格式，不是看见句子已经知道该用哪种地址。
- 绝大多数钱包只认英文词表。官方**强烈不建议**用非英文词表生成句子。
- 规范**没有**把看见助记词写成已经是种子，也没有把种子写成已经是扩展钥，也没有把本页写成 32 / 173 / 380。

助记词、二进制种子、扩展钥，是三件事。

---

## 2. 直觉（ELI15）

纸上那几个词像行李标签，不是箱子里的钥匙。  
标签抄对了，还要再开一道口令门，才拿得到种子。  
口令写错，门也会开，只是开进另一间房。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 助记句 | 给人抄写的词序列 | 已经是种子；已经是扩展钥；已经能花 |
| 二进制种子 | 助记句再加口令之后的产物 | 已经是 BIP-32 树；已经是地址 |
| 口令 | 换一份合法种子 | 写错就已经非法 |
| 本页算法生成 | 运走机器随机数 | 已经允许脑钱包 |

---

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气备份卡在哪」。

1. 看见助记句。规范：还要再转成种子。不是已经是种子。
2. 转成种子。规范：以后才能交给 BIP-32。不是已经是扩展私钥（那是不变量 182）。
3. 用户自己编一句话。规范：本页不是脑钱包。不是「能记住 = 已经是 39」。
4. 口令不同。规范：另一份合法钱包。不是已经非法，也不是已经能改回原钱包。
5. 校验过了。规范：只能中等概率抓随机错，不能改对。不是已经是用户要的那句。
6. 有人把这听成 173 / 350。那是收款地址校验。本页是备份写法。
7. 有人把这听成 32。32 是种子之后怎么长树。本页是种子还没长出来。

「看见词 = 已经是种子 / 已经能花 / 39 = 32」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新曲线；句子到种子是单向哈希族 |
| 协议 | 必须点名问的是助记句、二进制种子，还是扩展钥 |
| 实现 | 必须按词表算校验并警告；不得把脑钱包写成已经是本页 |
| 部署 | 应用层；非英文词表官方强烈不建议 |
| 经济 | 口令不同是另一份钱包，不是已经丢了，也不是已经还在原钱包 |

**推断：** 产品句若只写「支持助记词」，读者会把看见词听成已经是种子，或把口令写错听成非法。  
**建议：** 第一版若给人抄备份，必须分开助记句、种子、扩展钥。不要发明「看见词 = 已经能花」。不要抄词表。不要把 39 写成 32。

---

## 6. 和另外几句不是同一句

1. **扩展公钥 ≠ 已能花**（不变量 182）：种子之后的树。本页是种子还没长出来。
2. **地址 ≠ 已有输出**（不变量 174）：收款写法。本页是备份写法。
3. **后继校验 ≠ 已是旧方案**（不变量 181）：地址用哪套校验。本页不是 Bech32。
4. **工作包 ≠ 已广播**（不变量 179）：未完成交易。本页还没有交易。
5. **钥备份 ≠ 已知道脚本**（不变量 184）：种子齐了仍不知道脚本类型。本页是词还不是种子。

不要抄词表 / 熵长表 / 迭代次数 / 盐字符串 / 例口令。不要写怎样从句子推出种子，怎样造脑钱包，或怎样靠短校验去改词。不编博物馆页。不另写 19 节。BIP-32 树、BIP-173 地址、BIP-380 描述符、SLIP-39 后继方案是另一对象。

## 7. 「不确定」测试句（建议）

```text
看见助记词 ≠ 已经是二进制种子
用户自造句子 ≠ 已经是本页那种助记词
口令不同 ≠ 已经非法
助记词校验过了 ≠ 已经能改对
BIP-39 ≠ BIP-32 ≠ BIP-173 ≠ BIP-380
```

语料：[C187](../../libraries/adversarial-corpus/README.md)。

## 精密检查

**禁止假学习：** 「看见词 = 已经是种子。」「39 = 已经能花。」「39 = 32。」「口令错 = 已经非法。」「能记住 = 已经是脑钱包合法。」「校验过 = 已经改对。」  
**边界：** 不抄词表。不另写 19 节。不写怎样推种子。扩展钥见 **C186**。看见地址见 **C178**。

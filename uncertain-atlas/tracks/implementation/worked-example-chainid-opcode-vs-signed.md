## 1. 核心问题

阿比看见多了一条能读本链号的指令，以为交易已经按 EIP-155 把链号编进签名；或看见指令返回配置链号，以为这笔交易已经带了 EIP-155 唯一标识；或看见 EIP-712 域里写了链号，以为编译期写死就已经能在硬分叉后继续用；或看见链号指令，以为应用已经能处理有争议的分裂；或看见规范编号 1344，以为就是 155，或已经是 712，或已经是不变量 161。

官方句（事实）：

- EIP-1344：给 EVM 加一条读本链配置链号的指令。
- 官方写：EIP-155 防止交易在链与链之间被重放。本页把同样的可能加进智能合约内部，尤其是二层与 EIP-712 一类方案。看见本页，不是交易已经按 155 把链号编进哈希。
- 官方写：按 155，一笔交易**不是必须**带 EIP-155 唯一标识。那种情形下，本页指令**仍然返回配置链号，而不是某个默认值**。看见能读到配置链号，不是这笔交易已经带了 155 标识。
- 官方写：现行 EIP-712 一类做法把链号写在编译期，硬分叉之后会出问题；再加上人为写错，会导致丢资金或已签消息被重放。看见编译期写死的链号，不是已经在硬分叉后仍安全。
- 官方写：用户必须确保应用能处理潜在的链号更新。无信任预言机是一种选项，不是规范强制。官方用 Plasma 当例子：全局预言机并不总是对的。看见本页，不是已经处理好有争议的分裂。
- 官方写：最简单的访问最合适。看见本页，不是已经换成更复杂、自己规定分裂行为的预编译或合约。
- 规范**没有**把链号指令写成已经是 155 的签名绑定，也没有把返回配置链号写成这笔交易已经带了 155 标识，也没有把编译期链号写成硬分叉后已经安全，也没有把本页写成已经是 712 域或已经是不变量 161。

钱包 JSON 里的链号、签进哈希的链号、链上读本链号、编译期写死的 712 域链号，是四件事。

## 2. 直觉（ELI15）

门口挂着一块「本店店号」牌子。  
本页给店里每人发一张只看这块牌子的纸条。  
有这张纸条，不是客人信封上已经签了这家店号。  
纸条上能读到店号，不是客人这封信已经按店号加密过。  
把店号印在说明书封面上，不是招牌换号之后说明书还对。  
有人说再雇一个全局报号员，不是每家分店分裂时都该听同一个人。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 链号指令 | 把本链配置链号压进栈 | 已经是签进哈希的链号 |
| 指令返回配置链号 | 合约看见本链配置 | 这笔交易已经带了 EIP-155 标识 |
| 编译期写死的链号 | 当前 712 一类做法 | 已经在硬分叉后仍安全 |
| 1344 | 合约内读本链号 | 155；712；不变量 161 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气链号还停在哪一层」。

1. 看见多了一条链号指令。规范：给合约内部加读本链号的可能，尤其是二层与 712。不是交易已经按 155 绑了链。
2. 看见指令返回配置链号。规范：就算这笔交易没带 155 标识，指令仍返回配置链号，不是默认值。不是这笔交易已经带了 155 标识。
3. 看见 712 域在编译期写了链号。规范：硬分叉之后会出问题，人为写错会丢资金或重放已签消息。不是已经在硬分叉后仍安全。
4. 看见有人说再加一个无信任预言机。规范：这是一种选项，不是强制；Plasma 是官方例子，说明全局预言机并不总是对。不是已经处理好分裂。
5. 有人把这听成不变量 161。那是钱包 JSON 里的 chainId 与签进哈希。本页是合约里读配置链号。
6. 有人把这听成不变量 218 / 219。那是读基础费或 blob 基础费。本页读的是链号。
7. 有人把操作码号或实现仓库抄进不确定。规范：计价档和实现链接是尺子，不是产品常量。

「CHAINID = 已经是 EIP-155 / 能读到 = 这笔已经绑了链 / 编译期写死 = 分叉后仍安全 / 1344 = 712 / 1344 = 161」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 不换签算法；读本链号不是已经把链号编进这笔交易的哈希 |
| 协议 | 必须点名问的是读本链号、签进哈希、编译期写死，还是分裂后谁说了算 |
| 实现 | 返回配置链号，不是默认值；不是已经换成规定分裂行为的预编译 |
| 部署 | 用户必须能处理链号更新；无信任预言机是选项，不是强制 |
| 经济 | 编译期写错或分叉后仍用旧域，官方写会丢资金或重放已签消息 |

**推断：** 产品句若只写「能读链号所以交易已经绑了这条链」，读者会把合约读数听成 155 签名绑定，或把编译期 712 域听成硬分叉后仍安全。  
**建议：** 第一版可以不加这条读数指令。若对照，必须分开读本链号、签进哈希、编译期写死、分裂后谁说了算。不要发明「看见 1344 就已经是 155」。不要抄操作码号或实现仓库。不要写怎样实现预言机、处理 Plasma 分裂或重放未绑链号的签。

## 6. 和另外几句不是同一句

1. **JSON 里的 chainId ≠ 已经编进签名哈希**（不变量 161）：155 管的是交易哈希里有没有链号。本页管的是合约能不能读配置链号。
2. **基础费指令 ≠ 已经改了费用市场**（不变量 218）：3198 读本块基础费。本页读的是链号。
3. **blob 基础费指令 ≠ 已经是执行层基础费指令**（不变量 219）：7516 读 blob 价。本页不读费用。
4. **EIP-712 域分离**（不变量 18 的对照对象）：712 是结构化消息域。本页官方只说：把链号写在编译期，硬分叉后会出问题。

不要抄操作码号、气价档、位宽、实现仓库、测试仓库指针。不要写怎样实现链号预言机、怎样处理 Plasma 分裂、怎样拿未绑链号的签去另一条链重放。不编博物馆页。不另写 19 节。不转规范代码。签进哈希、编译期 712 域、费用读数指令是另一对象。JSON chainId 精读：[`../crypto/worked-example-chainid-vs-signed.md`](../crypto/worked-example-chainid-vs-signed.md)（不变量 161）。

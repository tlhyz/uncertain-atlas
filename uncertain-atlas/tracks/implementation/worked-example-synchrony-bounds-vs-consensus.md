# 例：看见 precision 上界 30s 不是已经是协议常数；看见写的是实现强制不是已经进了共识；看见防溢出不是已经选型

**层次**：实现 / 同步参数上界。  
**分类**：事实（官方标注）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [Core Data Structures](https://github.com/cometbft/cometbft/blob/main/spec/core/data_structures.md) SynchronyParams。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行、L4.5。本页是「precision 上界 30s 不是已经是协议常数 / 写的是实现强制不是已经进了共识 / 防溢出不是已经选型」，不是 Precision 不是已经 MessageDelay，也不是这两个参数就已经是永恒常数。不要另写怎样设上界。

## 官方三件事

规范把这两个上界写成**实现里强制的**、目的是**防时间戳校验时溢出**、而且给的是具体两个数，写成三件独立的事实，不是「看见 30s 就已经是共识常数、已经进了协议、已经能抄进选型」一件事：

1. **看见 `precision` 上界 `30s` / 看见这个数 不是已经是协议常数，也不是已经是共识值。**  
   官方写：`precision` 不得超过 `30s`。看见这个数，不是已经是写在共识规则里的界。看见有上界，不是已经改了 `ConsensusParams` 的语义。看见具体数字，不是已经是未标注版本的永恒常数。
2. **看见写的是「在实现里强制」/ 看见这半句 不是已经进了共识，也不是已经是协议保证。**  
   官方写：这两个参数都有在**实现里强制**的上界。看见实现里卡住，不是已经写进共识。看见强制的，不是已经由协议投票决定。看见能卡，不是已经不需要点名是哪一版实现。
3. **看见目的是防溢出 / 看见这半句 不是已经选型，也不是已经是活性或安全下界。**  
   官方写：目的是**防止时间戳校验时的溢出错误**。看见防溢出，不是已经给了活性或安全的界。看见有这个守卫，不是已经选好 `precision` 该填多少。看见两个数，不是已经是产品建议值。

怎样设 `precision` / `message_delay`、怎样选启用高度是规范里的做法，本页不抄。`Precision` 不是已经 `MessageDelay` 是不变量 336，本页不抄。`PbtsEnableHeight` 写成 0 不是已经启用 PBTS 是不变量 343，本页不抄。

## 官方为什么这样拆

- **上界 `30s` ≠ 协议常数：** 官方把它放在 `Note:` 里作为实现约束，而不是放在共识参数语义里。
- **实现强制 ≠ 进了共识：** 它防的是本实现算时间戳时溢出，不是投票决定的规则。
- **防溢出 ≠ 选型：** 守卫的存在不告诉你该填多少。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| precision 上界 30s | 不是已经是协议常数 | 不是 Precision 就已经是 MessageDelay、就已经 timely（336） |
| 写的是实现强制 | 不是已经进了共识 | 不是填了两个就已经启用 PBTS（336） |
| 目的是防溢出 | 不是已经选型 | 不是 PbtsEnableHeight 写成 0 就已经启用（343） |
| 本页不涉及 | — | 不是块时间必须点名算法（40） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「看见同步参数有上界就已经是共识规则」，必须分开 precision 上界 30s 是不是已经是协议常数、写的是实现强制是不是已经进了共识、防溢出是不是已经选型。**这两个数不得抄成「不确定」的共识常数或产品建议值**；若引用，必须标明是 CometBFT 实现的上界并写出处与版本。可以跳过「看见同步参数有上界就已经是共识规则」。不要另写怎样设上界。

## 本页不抄

- 怎样设 `precision` / `message_delay`、怎样选启用高度。
- `Precision` 不是已经 `MessageDelay`、填了两个不是已经启用 PBTS。那是不变量 336。
- `PbtsEnableHeight` 写成 0 不是已经启用 PBTS。那是不变量 343。
- 块时间必须点名算法。那是不变量 40。

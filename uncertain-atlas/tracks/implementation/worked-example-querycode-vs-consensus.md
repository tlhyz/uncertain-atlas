# 例：看见 Query 回包 code 是回包码不是已经过了共识；看见 Query 回包 log 是应用日志输出不是已经新鲜；看见 Query 回包 info 是附加信息不是已经是按键查

**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [ABCI++ Methods](https://github.com/cometbft/cometbft/blob/main/spec/abci/abci++_methods.md) Query Response。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)。

## 官方三件事

规范把 Query 回包 `code` 是回包码、`log` 是应用日志输出、`info` 是附加信息写成三件独立的实现事，不是「看见 Query 回了码就已经过了共识、已经新鲜、已经是按键查」一件事：

1. **看见 Query 回包 `code` 是回包码 / 看见回了码 不是已经过了共识，也不是已经没进块。**  
   官方写：`code` 是回包码。看见回了码，不是已经过了共识。看见有码，不是已经是 CheckTx 那种拒广播。看见能回，不是已经交差。
2. **看见 Query 回包 `log` 是应用日志输出 / 看见回了日志 不是已经新鲜，也不是已经复制到各节点。**  
   官方写：`log` 是应用日志的输出。看见回了日志，不是已经新鲜。看见有日志，不是已经复制到各节点。看见能读，不是已经交差。
3. **看见 Query 回包 `info` 是附加信息 / 看见回了信息 不是已经是按键查，也不是已经对上 AppHash。**  
   官方写：`info` 是附加信息。看见回了信息，不是已经按 `/store` 按键查。看见有附加字段，不是已经对上 AppHash。看见能回，不是已经交差。

怎样写 Query 回包码、怎样填日志、怎样填附加信息是规范里的做法，本页不抄。引擎对回包码不再赋予别的含义就已经被引擎用了 Data 是不变量 373，本页不抄。

## 官方为什么这样拆

- **Query 回包 code 是回包码 ≠ 已经过了共识：** 官方把 Query 回包码和已经过了共识分开。
- **Query 回包 log 是应用日志输出 ≠ 已经新鲜：** 官方把应用日志和已经新鲜分开。
- **Query 回包 info 是附加信息 ≠ 已经是按键查：** 官方把附加信息和回包键值分开。

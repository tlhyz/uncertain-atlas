## 官方三件事

规范把 CheckTx 是内存池的守卫、每条节点先跑 CheckTx 才让交易进本地池、这笔可以来自外部用户也可以来自另一节点、默克尔证明带自描述 type 好支持多种默克尔树和编码写成三件独立的实现事，不是「看见回了 CheckTx 守卫余量就已经是技术上可选、已经保证不重放、已经是 ProofOp 类型」一件事：

1. **看见 CheckTx 是内存池的守卫、每条节点先跑 CheckTx 才让交易进本地池 / 看见先跑了 不是已经是技术上可选，也不是已经是四门已经结算。**  
   官方写：CheckTx 是内存池的守卫；每条节点在让一笔交易进自己本地池之前，都先跑 `CheckTx`。看见先跑了，不是已经是 CheckTx 技术上可选、不参与处理块那种四门齐了。看见守着本地池，不是已经交差。看见每条节点都跑，不是已经从池里删掉。
2. **看见这笔可以来自外部用户、也可以来自另一节点 / 看见送来了 不是已经保证不重放，也不是已经从池里删掉。**  
   官方写：这笔交易可以来自外部用户，也可以来自另一节点。看见送来了，不是已经内存池去重那种保证不重放。看见能来自邻居，不是已经过了 CheckTx 就有应用级保护。看见能来自用户，不是已经交差。
3. **看见默克尔证明带自描述 `type`、好支持多种默克尔树和编码 / 看见写了 type 不是已经是 ProofOp 类型，也不是已经对上 AppHash。**  
   官方写：默克尔证明带自描述的 `type` 字段，好支持多种默克尔树和编码格式。看见写了 type，不是已经是 `ProofOp.type` 那种按键查。看见能支持多种树，不是已经 Query 回了 Proof 就对上 AppHash。看见能回证明，不是已经交差。

怎样写 CheckTx 守卫余量、怎样挑邻居、怎样编 type 是规范里的做法，本页不抄。CheckTx 技术上可选、不参与处理块就已经是四门已经结算是不变量 373，本页不抄。

## 官方为什么这样拆

- **CheckTx 是内存池的守卫、每条节点先跑 CheckTx 才让交易进本地池 ≠ 已经是技术上可选：** 官方把本地池入口守卫和技术上可选分开。
- **这笔可以来自外部用户、也可以来自另一节点 ≠ 已经保证不重放：** 官方把送来的来源和已经保证不重放分开。
- **默克尔证明带自描述 type、好支持多种默克尔树和编码 ≠ 已经是 ProofOp 类型：** 官方把自描述 type 和按键查分开。

# 工作实例：新代码以保留首字节开头不是已经是对象格式已经部署

> **事实 / 推断 / 建议** 已分开。
> 对照：[L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)、[返回代码 ≠ initcode](worked-example-returned-vs-initcode.md)、[initcode ≠ 运行时代码](worked-example-initcode-vs-runtime.md)、[回滚 ≠ 烧光](worked-example-revert-vs-invalid.md)。
> 主文献：[EIP-3541](https://eips.ethereum.org/EIPS/eip-3541) Reject new contract code starting with the reserved format byte。官方 EIP。核心层。不另写 19 节。
> 本页钉 **新创建要存上链的代码以保留首字节开头 ≠ 已经是对象格式已经部署**、**链上已有以该字节开头的代码 ≠ 已经被本页改语义**、**initcode 里出现该字节 ≠ 已经是本页失败**、**本页失败是创建异常中止 ≠ 已经是返回超界也不是已经是 initcode 超界**、**EIP-3541 ≠ EOF 规范本身 ≠ EIP-170 ≠ EIP-3860**。不抄保留字节取值 / 分叉高度 / 例串。不写怎样造以该字节开头的返回代码。

## 1. 核心问题

阿比看见「新合约不能以某字节开头」，以为对象格式已经上线、已经验过；或看见链上已有以该字节开头的账户，以为本页已经改了它的语义；或看见 initcode 里出现该字节，以为创建已经按本页失败；或看见规范编号 3541，以为已经是 170 的长度界或 3860 的构造界。

官方句（事实）：

- EIP-3541：禁止**新**部署以保留首字节开头的代码。账户树里**已经存在**、以该字节开头的代码，语义不被本页改动。
- 动机是给以后的可执行对象格式留魔法第一字节，让分叉前已经部署、当时没按新格式验过的合约，以后不会被认成那种格式。魔法第一字节若以后不做对象格式，还可以给别的版本方案用；版本方案若作废，也可以再允许这种部署。
- 分叉之后，创建交易、创建指令、带盐创建指令，只要**要存进账户的那份代码**第一字节是保留字节，创建按异常中止。
- initcode 是创建上下文里先跑的那份；它**返回**的代码才被插入账户。本页看的是返回代码的第一字节，不是 initcode 自己以什么开头。
- 该字节当时是未定义指令：执行它会异常中止。initcode 或已部署代码以它开头，执行时本来就会停。本页额外挡的是**新**把这样的代码存进账户。
- 这次中止和创建过程里其它异常中止一样：创建交易或创建指令拿到的气烧光。
- 规范**没有**把本页写成对象格式已经部署、已经验过，也没有把已有代码写成已经被改语义，也没有把 initcode 里出现该字节写成已经是本页失败，也没有把本页写成 170 的长度界或 3860 的构造界。

保留首字节、对象格式、返回代码有多长，是三件事。

## 2. 直觉（ELI15）

物业先把「E 字头门牌」空出来，不等于新楼盘已经验收入住。  
旧房子碰巧挂了这块空牌，物业说这次不管它。  
施工说明书封面上有个 E，不等于交房钥匙已经按这块空牌被拒。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 保留首字节 | 新存进账户的代码不许用的第一字节 | 对象格式已经部署 |
| 已有同首字节代码 | 分叉前已经在账户树里的 | 已经被本页改语义 |
| 本页失败 | 返回代码第一字节是保留字节，创建异常中止 | initcode 自己的开头；返回超界；initcode 超界 |
| 对象格式 | 以后才可能上的可执行格式 | 本页已经把它验过、上线 |

---

## 4. 最小案例

一条 Ethereum 要对齐「这一口气创建卡在哪一盏灯」。

1. 创建跑完，要存进账户的代码以保留首字节开头。规范：创建异常中止。不是对象格式已经部署。
2. 账户树里本来就有以该字节开头的代码。规范：语义不被本页改。不是已经按新格式重验。
3. initcode 自己以该字节开头。规范：执行未定义指令本来就会停。不是已经触发「新代码不许这样存」。
4. 有人把这听成 170（不变量 185）。那是返回代码有多长。本页是返回代码第一字节。
5. 有人把这听成 3860（不变量 176）。那是还没跑的构造代码有多长。本页是要存上链的第一字节。
6. 有人把这听成带回剩余气的回滚（不变量 177）。本页官方写成和创建过程其它异常中止一样烧光拿到的气。
7. 有人把「不能以某字节开头」听成以后的对象格式已经上线。本页只占位。格式规范是另一份。

「不能用这个开头 = 已经是对象格式 / 已有同首字节 = 已经被改 / 3541 = 170」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新原语 |
| 协议 | 必须点名问的是新返回代码的第一字节、已有代码，还是对象格式已经上线 |
| 实现 | 两家必须在插入账户前看返回代码第一字节 |
| 部署 | 核心层；占位可以以后收回 |
| 经济 | 这次中止烧光创建拿到的气，不是已经按长度界或构造界计价 |

**推断：** 产品句若只写「支持对象格式 / 合约有开头限制」，读者会把占位听成格式已经上线，或把已有代码听成已经被改。  
**建议：** 第一版若允许链上创建，必须分开返回代码第一字节、返回代码长度、initcode 长度。不要发明「占了首字节就是格式已上」。不要抄保留字节取值。不要把 3541 写成 170 或对象格式规范。

## 6. 和另外几句不是同一句

1. **返回代码 ≠ initcode**（不变量 185）：返回有多长。本页是返回第一字节。
2. **initcode ≠ 运行时代码**（不变量 176）：还没跑的构造代码有多长。本页不是那道长度界。
3. **回滚 ≠ 烧光**（不变量 177）：失败要不要留下剩余气。本页官方写成烧光创建拿到的气。
4. **自毁 ≠ 已删**（不变量 160）：账户还在不在。本页不写怎样同址再部署。

不要抄保留字节取值 / 分叉高度 / 例串 / 操作码号。不要写怎样造以该字节开头的返回代码。不编博物馆页。不另写 19 节。EOF 对象格式规范、EIP-170 长度界、EIP-3860 initcode 界是另一对象。

## 精密检查

**禁止假学习：** 「不能用这个开头 = 已经是对象格式。」「已有同首字节 = 已经被改。」「initcode 有这个字节 = 已经是本页失败。」「3541 = 170。」「3541 = 3860。」「中止 = 已经是带回剩余气。」  
**边界：** 不抄保留字节取值。不另写 19 节。不写怎样造这种返回代码。返回长度见 **C189**。initcode 见 **C180**。回滚见 **C181**。

# 工作实例：ECDSA 验得过不是已经是严格 DER

> **事实 / 推断 / 建议** 已分开。
> 对照：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L1.2](../../courses/level-01-crypto/L01-M02-signatures.md)、[编码故事](worked-example-encoding.md)、[策略 ≠ 共识](../mempool/worked-example-policy-vs-consensus.md)、[txid ≠ wtxid](worked-example-txid-vs-wtxid.md)。
> 主文献：[BIP-66](https://github.com/bitcoin/bips/blob/master/bip-0066.mediawiki) Strict DER signatures。官方 BIP。共识层软分叉。不另写 19 节。
> 本页钉 **ECDSA 数学上验得过 ≠ 已经是严格 DER**、**库接受某种变形 ≠ 共识已经接受**、**转发策略已经要 DER ≠ 共识已经要**、**编码检查立刻失败 ≠ 验签失败还按旧语义继续**、**BIP-66 ≠ BIP-62 延展菜谱 ≠ BIP-146 低 S ≠ BIP-34 整数版本**。不抄长度上下限 / 类型字节 / 激活票数 / 例脚本。不写怎样把非 DER 改成 DER，也不写怎样造能过库、过不了共识的签。

## 1. 核心问题

阿比看见某条签在密码库里验过，以为共识已经收下；或看见节点转发早就要求 DER，以为块里也已经按这把尺子；或看见规范编号 66，以为就是延展菜谱、低 S 规则或 BIP-34 整数版本。

官方句（事实）：

- BIP-66 收紧交易有效规则：交给 `CHECKSIG` / `CHECKSIGVERIFY` / `CHECKMULTISIG` / `CHECKMULTISIGVERIFY`、并且会做 ECDSA 验证的签名，必须是严格 DER。
- 动机：参考实现曾靠 OpenSSL 验签，等于把块合法集交给一个**不保证版本之间 bug-for-bug** 的库。库一改解析，有的节点会拒链。
- 编码检查不过：整段脚本立刻为假。编码过、ECDSA 不过：按该操作码原来的失败语义继续，有时会跳过后面的签名，后面那些就不再做编码检查。
- 长度为 0 的签名不做本页编码检查：给故意无效的签一条短编码。
- 字节串末尾的 sighash 旗标在 DER 规范外，本页不改它。
- 这是软分叉：只增加失败，不把旧失败改成成功。
- 转发策略可以早就只要 DER；那不是共识已经只要 DER。
- 规范**没有**把「库验过」写成已经是严格 DER，也没有把策略已经要写成共识已经要，也没有把本页写成 BIP-62、BIP-146 或 BIP-34。

数学验过、编码合法、共识收下，是三件事。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| ECDSA 验过 | 这对钥和签在曲线上对得上 | 已经是严格 DER；共识已经收下 |
| 严格 DER | 共识写死的签名字节形状 | 某个库今天愿意解析的形状 |
| 编码立刻失败 | 整段脚本立刻为假 | 验签失败还按旧语义继续 |
| 转发要 DER | 本节点可以不帮传 | 块内已经按这把尺子 |

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气签名字节是哪一盏灯」。

1. 密码库收下一种变形编码。规范：库不是共识。不是已经是严格 DER。
2. 同一对钥和签，编码不过。规范：整段脚本立刻为假。不是「数字对了就能进块」。
3. 编码过、ECDSA 不过。规范：按旧失败语义继续。不是和编码失败同一条路。
4. 本节点转发早就只要 DER。规范：策略。不是共识已经要。
5. 有人把这听成 txid ≠ wtxid（不变量 152）。152 是身份哈希域。本页是签名字节形状。
6. 有人把这听成策略 ≠ 共识（不变量 144）。144 是大类。本页是「策略已经要 DER」仍不是共识已经要。
7. 有人把 66 听成 62 / 146 / 34。62 是延展菜谱。146 是低 S。34 是整数版本一次滚一条。本页是签名编码谓词。

「库验过所以共识已收 / 转发要所以块里已经要」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | ECDSA 对上不是编码已经合法 |
| 协议 | 必须把签名编码写成共识谓词，不得交给库的解析习惯 |
| 实现 | 两家必须同一套立刻失败 / 旧语义继续 |
| 部署 | 软分叉；激活用的是整数版本开关，不是本页规则本身 |
| 经济 | 编码不唯一会让跟错根的人放货 |

**推断：** 产品句若只写「验签用业界库」，读者会把库的宽松听成全网合法集。  
**建议：** 第一版必须把签名编码写成共识谓词。不要发明「库验过 = 已经合法」。不要抄长度。不要写怎样改编码。

## 6. 和另外几句不是同一句

1. **两实现同根**（不变量 3）：总原则。本页是签名字节这一处必须离开库。
2. **txid ≠ wtxid**（不变量 152）：身份哈希域。本页是 DER 形状。
3. **策略 ≠ 共识**（不变量 144）：本地不转发。本页再钉「策略已经要 DER」不是共识已经要。
4. **置位 ≠ 已激活**（不变量 171）：版本位四态。本页只复用 34 那种整数开关来部署，不是 9。
5. **信封 ≠ 内层**（不变量 167）：交易外壳。本页是签名本身。

不要抄长度上下限 / 类型字节 / 激活票数 / 例脚本 / 库版本号。不要写怎样把非 DER 改成 DER，怎样造能过库过不了共识的签，或怎样靠多重签失败顺序跳过后面的编码检查。不编博物馆页。不另写 19 节。BIP-62 延展菜谱、BIP-146 低 S、BIP-34 整数版本、Schnorr / BIP-340 是另一对象。

## 精密检查

**禁止假学习：** 「库验过 = 共识已收。」「策略已经要 DER = 共识已经要。」「数字对了 = 编码已经合法。」「编码失败 = 验签失败同一条路。」「66 = 62。」「66 = 146。」「66 = 34。」  
**边界：** 不抄长度。不另写 19 节。不写怎样改编码。策略见 **C148**。txid 见 **C156**。激活见 **C175**。

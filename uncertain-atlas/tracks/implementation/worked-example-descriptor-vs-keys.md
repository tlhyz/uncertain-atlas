## 1. 核心问题

阿比看见助记词或一把扩展钥，以为钱包已经知道该生成哪种收款脚本；或看见一串描述符，以为已经是地址、已经有 UTXO；或看见规范编号 380，以为已经覆盖「看见词 = 已经是种子」或「看见 xpub = 已经能花」。

官方句（事实）：

- BIP-380：输出脚本描述符是一种简单语言，用来描述**一批输出脚本**。本页只写总语法、描述符校验、以及公共表达式。具体脚本函数在后续 BIP。
- 传统钱包先存一组钥，再序列化、变形，才得到它要看的输出脚本和给人的地址。备份常常只剩私钥，如今主要是 BIP-39 助记词。**只拿私钥，恢复后的钱包无法知道该产出哪几种输出脚本和地址。** 隔离见证之后更不够。
- BIP-32 派生路径也会添乱。虽有几份 BIP 给不同脚本和地址写过标准路径，但并非所有钱包都支持或都用。备份和导出里没有路径信息，钱包之间会继续对不上。
- 现有补丁不通用，也可看成越层：给扩展钥换一套版本字节来表示脚本类型，既把钥派生和脚本类型焊在一起，又只服务某一条路径和某一种脚本。
- 描述符的通用解法：脚本类型用脚本表达式显式写出；钥的派生路径用钥表达式显式写出。备份和导出因此能点名要产出的脚本、内层脚本和钥。
- 顶层是脚本表达式，后面可以跟校验。解析时校验可选；应用可以拒没有校验的描述符。校验过了只说明这一串过了描述符校验，不是已经解开成合法脚本集合，也不是已经是地址。
- 钥表达式里若是扩展钥，必须先按后面的派生信息推出子钥，才能造输出脚本。看见描述符里的 xpub，不是已经能长出脚本，更不是已经能花（那是不变量 182）。
- 导出不含私钥的描述符时，必须先走到最后一级硬化，再把那里的扩展公钥写进去，派生步骤并进钥来源。本页只点名这盏灯，不写步骤。
- 规范**没有**把看见助记词或私钥写成已经知道脚本类型，也没有把看见描述符写成已经是地址或已经有输出，也没有把本页写成 39 / 32 / 173。

描述符、密钥备份、收款地址，是三件事。

---

## 2. 直觉（ELI15）

钥匙串能开门，但不知道这栋楼哪一扇是你家的。  
描述符像门牌说明：哪一种锁、从哪一层钥数下来。  
看见说明不是门后已经有信，也不是钥匙已经能开。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 描述符 | 描述一批输出脚本的语言 | 已经是地址；已经有 UTXO |
| 只备份钥 / 助记词 | 花费材料 | 已经知道该看哪种脚本 |
| 脚本表达式 | 显式写出脚本类型 | 已经解开内层函数 BIP |
| 钥表达式里的扩展钥 | 还要再派生才造脚本 | 已经能花；已经是描述符本身 |

---

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气钱包导出卡在哪」。

1. 只拿回助记词。规范：不够知道该产出哪几种脚本。不是已经覆盖不变量 183 那页的「词 ≠ 种子」；本页再拆「种子齐了 ≠ 脚本类型齐了」。
2. 只拿回扩展钥。规范：钥派生和脚本类型不该焊在同一套版本字节上。不是已经能花（不变量 182）。
3. 看见描述符。规范：这是脚本集合的写法。不是已经是地址，更不是已经有 UTXO（不变量 174）。
4. 描述符校验过了。规范：解析仍可能拒、仍可能不是合法脚本。不是已经能收款。
5. 描述符里有 xpub。规范：还要按后面的派生信息推子钥才造脚本。不是已经长出输出。
6. 有人把这听成 173 / 350。那是地址校验。本页是脚本集合语言。
7. 有人把这听成 381 及以后的具体函数。那些是脚本表达式清单。本页只钉总语法。

「有钥 = 已经知道脚本 / 看见描述符 = 已经是地址 / 380 = 39」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新原语；校验是另一套纠错码 |
| 协议 | 必须点名问的是密钥备份、描述符，还是收款地址 |
| 实现 | 解析可把校验当可选；应用可以拒无校验；扩展钥必须先派生再造脚本 |
| 部署 | 应用层；具体脚本函数在后续 BIP |
| 经济 | 只备份钥会让恢复后的钱包对不上要看的输出 |

**推断：** 产品句若只写「支持描述符 / 助记词备份」，读者会把看见词听成已经知道脚本，或把看见描述符听成已经是地址。  
**建议：** 第一版若导出钱包，必须分开密钥材料、脚本类型、收款地址。不要发明「有钥 = 已经知道看哪种脚本」。不要抄常数。不要把 380 写成 39 或 32。

## 6. 和另外几句不是同一句

1. **助记词 ≠ 已是种子**（不变量 183）：句子还不是种子。本页是种子齐了仍不知道脚本类型。
2. **扩展公钥 ≠ 已能花**（不变量 182）：树节点。本页是脚本类型要另写。
3. **地址 ≠ 已有输出**（不变量 174）：收款写法。本页是脚本集合语言。
4. **后继校验 ≠ 已是旧方案**（不变量 181）：地址用哪套校验。本页不是 Bech32。
5. **Miniscript ≠ 已是链上脚本**（不变量 191）：本页是描述符总语法。脚本表达式扩张是另一页。看见描述符不是已经是本页那种分析语言。

不要抄校验字符表 / 例串 / 指纹宽度 / 函数名单 / 长度窗。不要写怎样拼描述符，怎样从扩展钥推子脚本，或怎样导出无私钥描述符。不编博物馆页。不另写 19 节。BIP-39 助记词、BIP-32 树、BIP-173 地址、BIP-381 及以后的脚本函数是另一对象。BIP-379 Miniscript 见不变量 191。

## 7. 「不确定」测试句（建议）

```text
看见私钥或助记词备份 ≠ 已经知道该看哪种输出脚本
看见描述符 ≠ 已经是地址
描述符里的扩展钥 ≠ 已经能长出脚本
描述符校验过了 ≠ 已经是合法脚本集合
BIP-380 ≠ BIP-39 ≠ BIP-32 ≠ BIP-173
```

## 精密检查

**禁止假学习：** 「有钥 = 已经知道脚本。」「看见描述符 = 已经是地址。」「380 = 39。」「380 = 32。」「校验过 = 已经能收款。」「xpub 写进描述符 = 已经能花。」  
**边界：** 不抄常数。不另写 19 节。不写怎样拼描述符。助记词见 **C187**。扩展钥见 **C186**。看见地址见 **C178**。

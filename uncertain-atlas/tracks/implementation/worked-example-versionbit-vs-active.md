# 工作实例：版本位被置上不是已经锁定，锁定不是已经激活

> **事实 / 推断 / 建议** 已分开。
> 对照：[L3.3](../../courses/level-03-bitcoin/L03-M03-conservative-evolution.md)、[CSV 部署名 ≠ 操作码](../state-models/worked-example-csv-vs-cltv.md)、[MTP 三把尺](../consensus/worked-example-mtp.md)、[哈希 ≠ 已揭开赎回](../state-models/worked-example-p2sh-hash-vs-redeem.md)。
> 主文献：[BIP-9](https://github.com/bitcoin/bips/blob/master/bip-0009.mediawiki) Version bits with timeout and delay。官方 BIP。信息层，不是共识层。不另写 19 节。
> 本页钉 **版本位被置上 ≠ 已经锁定**、**锁定 ≠ 已经激活**、**超时未锁定 ≠ 已经可以当激活**、**本块自己的版本位 ≠ 已经决定本块状态**、**BIP-9 ≠ BIP-34 比整数版本 ≠ 被部署的那条新规则**。不抄阈值 / 窗长 / 版本取值范围 / 位数。不写怎样假示意或拖激活。

## 1. 核心问题

阿比看见矿工把头上某一位置上，以为软分叉已经锁定；或看见文案写 LOCKED_IN，以为新规则已经在强制；或看见规范编号 9，以为就是 BIP-34 比整数版本，或已经在讲被部署的那条脚本规则。

官方句（事实）：

- BIP-9 给块头 `version` 一种位向量读法，让多条向后兼容的软分叉可以**并行**部署。
- 每个部署有名字、用哪一位、开始时刻、超时。开始与超时看**父块 MTP**。
- 每个块、每条软分叉对应一个部署状态：DEFINED、STARTED、LOCKED_IN、ACTIVE、FAILED。创世对每条部署都是 DEFINED。
- 一个难度调整窗里的块，对每条部署共享同一状态。
- STARTED 之后，若一个调整窗里置位的块够数，下一个状态是 LOCKED_IN。LOCKED_IN 再过一个调整窗，自动变成 ACTIVE。
- 新共识规则**只对 ACTIVE 的块强制**。
- 超时且尚未 LOCKED_IN，走 FAILED。超时优先于锁定，免得两位复用打架。
- 本块状态**从不**看自己的 `nVersion`，只看祖先。
- LOCKED_IN 期间矿工仍可置位，方便看见跟进；这对共识**没有效果**。
- 规范**没有**把置位写成已经锁定，也没有把锁定写成已经激活，也没有把本页写成 BIP-34 整数版本比较或被部署的那条新规则。

示意、锁定、激活、失败，是四件事。

---

## 2. 直觉（ELI15）

班上举手表示「下个月换新尺子」。  
举手的人够了，先登记「下个月换」，不是今天已经换完。  
登记后再过一轮，新尺子才真正用。举手本身不是新尺子。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 版本位示意 | STARTED 窗里把头上某一位置上 | 已经 LOCKED_IN；已经 ACTIVE |
| LOCKED_IN | 够数之后再等一个调整窗 | 新规则已经强制 |
| ACTIVE | 新规则开始强制 | 置位当时就已经生效 |
| FAILED | 超时且从未锁定 | 已经可以当成激活 |

---

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气软分叉激活是哪一盏灯」。

1. 矿工把头上某一位置上。规范：STARTED 窗里的示意。不是已经锁定。
2. 一个调整窗够数。规范：下一状态 LOCKED_IN。不是新规则已经强制。
3. 再过一个调整窗。规范：自动 ACTIVE，这时才强制新规则。
4. 超时且从未锁定。规范：FAILED。不是已经可以当激活。
5. 看本块自己的版本位。规范：本块状态不看自己。不是这块已经决定自己的状态。
6. 有人把这听成「CSV 之后」（不变量 165）。165 是部署名不是操作码。本页是示意 / 锁定 / 激活 / 失败四态。
7. 有人把这听成 MTP 三把尺（不变量 41）。41 是头太早 / locktime / 太新。本页只用父 MTP 当部署钟。
8. 有人把 9 听成 34。34 是整数版本一次只能滚一条。本页是位向量，可并行。

「置位所以已经锁定 / LOCKED_IN 所以已经在强制新规则」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新原语 |
| 协议 | 必须点名问的是示意、锁定、激活，还是失败 |
| 实现 | 两家必须同一套状态机；本块不看自己的位 |
| 部署 | 本页就是部署协调；信息层，不是已经换完规则 |
| 经济 | 并行示意省协调；不是置位已经等于全网升级 |

**推断：** 产品句若只写「用版本位激活」，读者会把举手听成新尺子已经在用。  
**建议：** 第一版可以不抄版本位并行激活。若做软分叉示意，必须把示意、锁定、激活、失败四套文案分开。不要发明「置位 = 已经激活」。不要抄阈值。不要写怎样假示意。

## 6. 和另外几句不是同一句

1. **CSV 部署名 ≠ 操作码**（不变量 165）：「CSV 之后」四个字。本页是四态状态机。
2. **MTP 三把尺**（不变量 41）：拒块的三把钟。本页只用父 MTP 当开始/超时。
3. **策略 ≠ 共识**（不变量 144）：本地不转发。本页是部署状态，不是 mempool。
4. **哈希 ≠ 已揭开赎回**（不变量 170）：P2SH 那次软分叉本身。本页不是赎回脚本。

不要抄阈值 / 窗长 / 版本取值范围 / 位数 / 开始秒数。不要写怎样假示意、怎样拖激活、怎样复用位去骗旧软件。不编博物馆页。不另写 19 节。BIP-8 必示意 / LOT、BIP-34 整数版本、挖矿模板字段是另一对象。

## 精密检查

**禁止假学习：** 「置位 = 已经锁定。」「LOCKED_IN = 已经强制新规则。」「超时 = 已经当激活。」「本块的位 = 本块状态。」「9 = 34。」「9 = 被部署的那条规则。」  
**边界：** 不抄阈值。不另写 19 节。不写怎样假示意。部署名见 **C169**。MTP 见不变量 41。

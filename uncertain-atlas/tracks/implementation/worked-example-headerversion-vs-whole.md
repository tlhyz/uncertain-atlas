# 例：看见 Header.Version 是「应用与块版本」不是已经知道是哪一版的什么；看见 Block 必须全网一致不是 App 也由应用定；看见一个版本号不是已经点名了整个协议

**层次**：实现 / 头版本栏。  
**分类**：事实（官方标注）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [Core Data Structures](https://github.com/cometbft/cometbft/blob/main/spec/core/data_structures.md) Header / Version。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行、L4.5。本页是「Header.Version 是应用与块版本不是已经知道是哪一版的什么 / Block 必须全网一致不是 App 也由应用定 / 一个版本号不是已经点名了整个协议」，不是 Info 回包的 app_version 就已经印进本头 AppHash，也不是 ConsensusParams.version 就已经是 app_version 进了头。不要另写怎样填版本。

## 官方三件事

规范把 `Header.Version` 这一栏、它的两个子字段**校验不同**（`Block` 必须全网一致，`App` 由应用定）、以及这一节顶上**两条 TODO**（版本通论还没写），写成三件独立的事实，不是「看见头里有版本号就已经知道是哪一版的什么、已经点名了整个协议」一件事：

1. **看见 `Version` 表头写「应用与块版本」/ 看见这一栏 不是已经知道是哪一版的什么。**  
   官方在这一节顶上写明：这一节**更确切地说是共识版本**，而且**不包含 P2P 版本**这类信息。看见这一栏，不是已经拿到完整版本信息。看见「应用与块」，不是已经知道 P2P 那一版。看见能填，不是已经点名了整个协议。
2. **看见 `Version.Block` 必须全网一致 / 看见这条 不是 `App` 也走同一条。**  
   官方写：`Block` 代表块版本，**必须在整个运行网络里一致**；校验是等于网络在用的块版本（`block.Version.Block == state.Version.Consensus.Block`）。而 `App` 是**由应用决定**的，校验与 `state` 比对。看见两个子字段在同一张表、校验长得像，不是同一种权威来源。看见 `Block` 一致，不是 `App` 也一致。
3. **看见一个版本号 / 看见表里只有两个字段 不是已经点名了整个协议。**  
   官方在这一节顶上留了两条 **TODO**（要写一篇能引用的版本通论）。看见有版本号，不是已经有版本通论。看见两个字段，不是已经覆盖 `block_version` / `p2p_version` / `abci_version` 那些别处的版本列。看见一处版本，不是已经能说「这条链是哪个版本」。

怎样填版本、怎样做版本升级是规范里的做法，本页不抄。`Info` 回包的 `app_version` 不是不变量 370，本页不抄。`ConsensusParams.version` 不是不变量 385，本页不抄。`ConsensusParams` 跨文档不齐是不变量 447，本页不抄。

## 官方为什么这样拆

- **有一栏 ≠ 知道是哪一版的什么：** 官方自己说这一节是**共识版本**、不含 P2P 版本。
- **`Block` 必须全网一致 ≠ `App` 也由应用定：** 同一张表里两个字段的权威来源不同。
- **一个版本号 ≠ 点名了整个协议：** 官方留了两条 TODO，版本通论尚未成文。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「看见头里有版本号就已经知道是哪一版」，必须分开 Version 这一栏是不是已经知道是哪一版的什么、`Block` 必须全网一致是不是 `App` 也走同一条、一个版本号是不是已经点名了整个协议。**产品句不得只写一个版本号就声称「协议版本已点名」**：必须说明是块版本、应用版本、P2P 版本还是 ABCI 版本，并写出处。可以跳过「看见头里有版本号就已经知道是哪一版」。不要另写怎样填版本。

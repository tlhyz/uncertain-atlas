# 例：看见同一份种子不是已经是同一条币；看见下一个账户号不是已经有过往；看见余额为零不是已经发现完

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-44](https://github.com/bitcoin/bips/blob/master/bip-0044.mediawiki)（Deployed, Applications）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「账户层不是已经发现完 / 已经混在同一条币」，不是扩展公钥已经能花，也不是用途层已经能互操作。

## 官方三件事

规范把多账户层次写成三件独立的发现事，不是「看见同一份种子就已经扫完」一件事：

1. **看见同一份种子 / 同一颗主节点 不是已经是同一条币，也不是已经可以混用地址。**  
   官方写：一颗主节点可以给无限种独立的币用。可是把不同币挤在同一片空间里有坏处。本层给每一种币单独一棵子树，免得跨币复用地址、也改善隐私。看见同一份种子，不是已经是同一条币。看见还能再长出别的币，不是已经可以共用地址。
2. **看见下一个账户号 / 去开新账户 不是已经有过往，也不是已经和上一户同一身份。**  
   官方写：这一层把钥空间拆成彼此独立的用户身份，钱包不得把不同账户的币混在一起。软件应当阻止去开新账户，只要上一户还没有交易过往（意思是它的地址都还没用过）。用户可以用这些账户像银行账户那样整理资金。看见账户号往上加，不是上一户已经有过往。看见两户，不是已经可以混花。
3. **看见余额为零 / 看见一串没用过的地址 不是已经发现完，也不是已经没有后面的账户。**  
   官方写：从外面导进种子之后，软件应当按过往去发现账户。算法看的是交易过往，不是账户余额；一户总额可以是零，发现仍会继续。若连着碰到一串没用过的地址，软件才预期后面没有用过的地址并停搜。只扫外链，因为内链只收从对应外链过来的币。看见余额为零，不是已经没有这一户。看见停搜，不是链上已经没有后面的付款。

间隙条数、用途号、币种表、例路径是规范里的取值，本页不抄。

## 官方为什么这样拆

- **种子 ≠ 已经是同一条币：** 官方把「同一片空间给多种币」写成有坏处，要求每种币单独一棵子树。
- **账户号 ≠ 已经有过往：** 官方要求上一户还没有交易过往时，不得开新户。
- **余额为零 ≠ 已经发现完：** 官方把发现写成看过往、不看余额。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出多账户，必须分开币种子树、账户过往、发现停搜。可以跳过「看见余额为零就已经扫完」。若对照，必须分开过往和余额。不要另写怎样扫间隙或枚举账户。

- 怎样扫外链、怎样从种子枚举账户、怎样按间隙停搜。

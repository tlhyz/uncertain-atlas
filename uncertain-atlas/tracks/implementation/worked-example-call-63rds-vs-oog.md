# 例：看见读树涨价不是已经换成 63/64；看见 63/64 不是已经问超了就 OOG

**层次**：实现 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Ethereum [EIP-150](https://eips.ethereum.org/EIPS/eip-150)（Final, Core；Tangerine Whistle）。  
**对应课文**：[L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)。  
**不要写进**：`index/03` 共识行、M5.4、L5.4。

## 官方三件事

规范把一次读树涨价写成三件独立的事，不是「气贵了」一件事：

1. **读状态树的操作码当时标价过低，本页给它们涨价。**  
   官方写：读盘慢；这类操作码仍是用交易垃圾拖慢网络最容易的已知办法。看见读树涨价，不是磁盘已经是常数时间，也不是已经写了后来那次树依赖涨价（不变量 229），也不是已经写了本笔冷热（不变量 169），也不是气已经等于墙钟（不变量 101）。
2. **调用若要的气比父帧还能给的还多，不要报耗尽气；改成只给「去掉六十四分之一」那一截。**  
   官方原文：`CREATE` 也只把父帧去掉六十四分之一之后的气给子执行。看见问超了，不是已经耗尽气。看见去掉六十四分之一，不是已经没有调用深度上限。
3. **建议把气限目标抬高，好保住当时平均合约的吞吐。**  
   看见建议目标，不是已经是协议帽（不变量 211）。官网吞吐不是事实。

分叉高度、气价数字、建议气限取值是规范里的常数，本页不抄。

## 官方为什么这样拆

- **读树涨价 ≠ 已经齐了：** 官方说还会靠软件缓解，但读树仍会是最容易的拖慢面。看见本页，不是已经永远够，也不是已经量过不确定的墙钟。
- **去掉六十四分之一 ≠ 问超了就失败：** 官方引入这件事，是因为当时合约常用「剩下的气再减一截」去开子调用；若问超了直接耗尽气，那些合约会停。看见还能开子调用，不是已经把父帧气全给了子执行。
- **软深度 ≠ 已经没有深度：** 官方把硬调用栈深度上限换成按气收紧的软限制，并写这能消掉一类深度攻击。看见软限制，不是深度对象已经消失，也不是深度已经无限。
- **建议气限 ≠ 协议帽：** 官方写抬高是建议，动机是保住吞吐。看见建议，不是已经改了共识帽，也不是官网吞吐已经是事实。

官方还写：自毁现在也要付钱；自毁碰到新账户再加一笔，像带值调用那样。那是自毁家族的另一对象，不是本页已经写了不变量 160 / 223 / 208。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见读树涨价就已经齐了 / 看见问超了就已经耗尽气 / 看见软深度就已经没有深度 / 看见建议气限就已经是协议帽」。子调用能拿多少气，必须写成共识对象，不能靠「剩下的再减一截」。237 call 63rds vs oog bundled unbundling 完成（1298 item 1 / 1299 item 2 / 1300 item 3）；精读 [`worked-example-c63-notprice-vs-bundled.md`](worked-example-c63-notprice-vs-bundled.md)（不变量 1298 item 1）、[`worked-example-c63-notoog-vs-bundled.md`](worked-example-c63-notoog-vs-bundled.md)（不变量 1299 item 2）、[`worked-example-c63-notcap-vs-bundled.md`](worked-example-c63-notcap-vs-bundled.md)（不变量 1300 item 3）。官网吞吐不得当事实。

## 本页不抄

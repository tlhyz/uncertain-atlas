# 例：看见旧 PSBT 栏不是已经能装 Taproot；看见输出脚本里的钥不是已经是内部钥；看见 Taproot 输入不是已经必须带整笔前交易

## 官方三件事

规范把 Taproot 工作包栏写成三件独立的结构事，不是「看见部分签名包就已经能签 Taproot」一件事：

1. **看见旧 PSBT 栏 / 看见 174 那套字段 不是已经能装 Taproot，也不是已经能签 Taproot 输入。**  
   官方写：现有 PSBT 栏没法支持 Taproot。新的签名算法，再加上脚本嵌进 Taproot 输出的方式，都和旧栏对不上。所以必须另开一套栏，才能把签 Taproot 输入所需的信息装进去。看见包还在，不是已经能装这些对象。看见旧软件会忽略新栏，不是已经能签。
2. **看见输出脚本里的钥 / 看见钥匙路径那张签 不是已经是内部钥，也不是已经同一把钥。**  
   官方写：钥匙路径那张签直接对应输出脚本里的公钥，所以不必再附一把钥的元数据。内部钥不一定就是输出脚本里那把。341 建议用钥对自己的哈希做微调。签名人可能必须先知道内部钥是什么，才能判断自己能不能签。看见输出脚本里的钥，不是已经有内部钥。看见钥匙路径签，不是已经不必再给内部钥。
3. **看见 Taproot 输入 / 看见 174 建议带整笔前交易 不是已经必须带整笔前交易，也不是已经和其它输入同一套 UTXO 栏。**  
   官方写：174 建议所有输入都带整笔前交易，免得更新者谎报金额。Taproot 签名会承诺本交易各输入花掉的金额和输出脚本，谎报会让签作废。所以 Taproot 输入可以只带见证 UTXO 栏。看见 174 那条建议，不是已经是本页。看见只带了见证 UTXO，不是已经是旧输入那套。

类型号、签名宽度、测试向量、控制块做法是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **旧栏 ≠ 已经能装 Taproot：** 官方把新签法和脚本嵌法写成旧栏装不下。
- **输出脚本里的钥 ≠ 已经是内部钥：** 官方把钥匙路径签和内部钥写成两份对象。
- **Taproot 输入 ≠ 已经必须带整笔前交易：** 官方把承诺金额写成可以只带见证 UTXO。

## 1. 核心问题

阿比看见栈上多了一条「数前导零」，以为零知识证明已经更便宜；或看见动机里写了后量子签名方案，以为链上已经有后量子签；或看见官方说最低位可以靠它再表达，以为已经有数尾零；或看见规范编号 7939，以为就是模幂输入帽、配对预编译或 P256 验签。

官方句（事实）：

- EIP-7939：加入一条新操作码。从栈弹出一个值，压回这个值里最高有效 1 前面有多少个前导零。若输入是零，压回字宽。
- 动机：许多处理器本来就有这条。它是数学、字节、压缩、数据结构的一块积木，动机也点名后量子签名方案。
- 官方预期：算得更便宜、零知识证明更便宜、字节码更短。最快的高级语言写法要用不少动态右移，证明起来贵。
- 官方更想先加数前导零，不先加数尾零：最低位可以用数前导零再表达；反过来不行。
- 这是以前没有的新操作码。
- 安全段：无状态，最坏内存、计算和证明代价都低且恒定；官方不预期它被拿来做拒绝服务。
- 规范**没有**把看见本页写成已经更便宜的 ZK 证明，也没有把动机点名后量子签写成已经有后量子签名，也没有把能表达最低位写成已经有数尾零，也没有把本页写成不变量 206、199 或 204。

数前导零、证明已经便宜、后量子签已经落地，是三件事。

## 2. 直觉（ELI15）

桌上有一排开关。从左边数，有几颗还没拨开。  
这不是已经证明了一份更短的零知识证明。  
说明书提到「以后签名也可以用」，不是签名算法已经换完。  
能从「左边空几颗」再推出「右边哪一颗亮」，不是已经另买了「从右边数」的工具。

| 数前导零 | 栈上一条新操作码，数最高有效 1 前面有多少零 | 已经更便宜的 ZK 证明 |

| 能表达最低位 | 官方更想先加这一条的理由 | 已经有数尾零 |
| 7939 | 新操作码 | 模幂输入帽；配对预编译；P256 验签 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气操作码在哪一层」。

1. 看见栈上能数前导零。规范：弹出一个值，压回前导零个数。不是已经更便宜的 ZK。
2. 看见输入是零。规范：压回字宽。不是已经换了字宽，也不是已经证明过。
3. 看见动机写了后量子签名方案。规范：它是一块积木。不是已经有后量子签。
4. 看见官方更想先加数前导零。规范：最低位可以再表达；反过来不行。不是已经有数尾零。
5. 有人把这听成不变量 206。那是模幂输入长度帽。本页是新操作码。
6. 有人把这听成不变量 199。那是曲线算术预编译。本页不是预编译。
7. 有人把这听成不变量 204。那是 P256 验签。本页不验签。

「看见 CLZ = 已经更便宜 ZK / 动机写了 PQ = 已经有后量子签 / 能表达最低位 = 已经有 CTZ / 7939 = 206」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 动机点名后量子签，不是已经换了签名方案 |
| 协议 | 必须点名问的是新操作码、证明已经便宜，还是数尾零 |
| 实现 | 以前没有这条；零输入回字宽 |
| 部署 | 不把气价 / 操作码号抄进不确定 |
| 经济 | 不把「证明更便宜」写成已经更安全 |

**推断：** 产品句若只写「有了数前导零」，读者会把一条栈操作听成证明系统已经便宜，或把动机里的后量子举例听成签名已经换完。  
**建议：** 第一版可以不加这条操作码。若加，必须分开前导零、证明费、签名方案、尾零。不要发明「看见 7939 就已经更便宜的 ZK」。不要抄操作码号 / 气价。不要写怎样拼数尾零。

## 6. 和另外几句不是同一句

1. **模幂长度帽 ≠ 已改计价**（不变量 206）：预编译输入有界。本页是新操作码。
2. **预编译算术 ≠ 已验 BLS**（不变量 199）：曲线算术预编译。本页不是预编译，也不验签。
3. **P256 验签 ≠ 已验 k1**（不变量 204）：第二条曲线的验签。本页不验签。

不要抄操作码号、气价、高级语言实现、测试向量。不要写怎样用它拼数尾零，或怎样压证明费。不编博物馆页。不另写 19 节。不转测试向量。模幂输入帽、配对预编译、P256 验签是另一对象。模幂精读：[`worked-example-modexp-bound-vs-price.md`](worked-example-modexp-bound-vs-price.md)（不变量 206）。

## 1. 核心问题

阿比看见钱包导出一串扩展公钥，以为已经能花里面的币；或看见能从它推出一批收款写法，以为已经是地址、已经有 UTXO；或看见规范编号 32，以为已经覆盖「看见地址 = 已经有输出」或「看见工作包 = 已经能广播」。

官方句（事实）：

- BIP-32：分层确定性钱包。一份树可以部分或整份分享给不同系统，**每一份可以带、也可以不带花费能力**。
- 规范分两截：先从一颗种子长出密钥树；再在树上套默认钱包布局。第二截是默认，客户端被鼓励模仿，但不是已经必须。
- 扩展私钥 = 普通私钥再加一份链码。扩展公钥 = 对应点再加同一份链码。去势函数只留点和链码，**拿掉签名能力**。
- 从公钥父节点推公钥子节点，只对未硬化的下标有定义。硬化下标必须失败。从公钥父节点推私钥子节点，规范写成不可能。
- 知道一枚扩展私钥，能重建它下面所有子孙的私钥和公钥。知道一枚扩展公钥，只能重建它下面**未硬化**的子孙公钥。
- 扩展密钥的标识用的是内嵌公钥的哈希，和传统地址用的那份数据对得上。规范**不建议**把这份标识写成地址那种编码，因为会被听成已经能收款；钱包也**不必**接受打到这颗链节点本身的付款。
- 导入序列化扩展公钥时，必须核内嵌点是否在曲线上；不在则这份扩展公钥非法。
- 规范**没有**的性质：看见父扩展公钥和一枚子公钥，并不保证难猜下标；看见父扩展公钥和一枚**未硬化**子孙私钥，并不保证难还原父私钥。官方因此要求扩展公钥比普通公钥更小心：父扩展公钥加上任何一枚未硬化子孙私钥，就等于知道父扩展私钥，也等于知道这棵子树里每一枚私钥。硬化下标存在，正是为了让账户层及以下的私钥泄漏，不再危及主密钥或其它账户。
- 兼容最低要求：至少能导入一枚扩展公钥或扩展私钥，并把它的**直接子孙**当钱包密钥用。账户 / 内外链布局是建议，不是已经强制。
- 规范**没有**把看见扩展公钥写成已经能花，也没有把能推出子公钥写成已经是地址或已经有输出，也没有把本页写成 173 / 174 / 350。

扩展公钥、收款地址、链上输出，是三件事。

## 2. 直觉（ELI15）

一串扩展公钥像一本只能看、不能签字的户口簿。  
看见户口簿，不是已经拿到私章，也不是门牌上已经有信。  
硬化的那一层像加了锁的柜门：从外面那本簿子推不进去。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 扩展公钥 | 点 + 链码；可推未硬化子孙公钥 | 已经能花；已经是地址；已经有 UTXO |
| 去势 | 从扩展私钥去掉签名能力 | 已经是普通单点公钥 |
| 硬化下标 | 公钥父节点必须失败的那一支 | 已经能从扩展公钥推出 |
| 链节点标识 | 和传统地址同源的哈希 | 已经该写成收款地址 |

---

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气钱包导出卡在哪」。

1. 扩展公钥。规范：去势后没有签名能力。不是已经能花。
2. 从它推出未硬化子孙公钥。规范：仍是公钥。不是已经编成地址，更不是已经有 UTXO（那是不变量 174）。
3. 硬化下标。规范：公钥父节点必须失败。不是「看见扩展公钥 = 整棵树已打开」。
4. 链节点标识。规范：和地址用同一份哈希，但不建议写成地址，也不必接受打到这颗节点的付款。
5. 有人把这听成 173 / 350。那两页是收款写法用哪套校验。本页是密钥树。
6. 有人把这听成 174 工作包。那是未完成交易对象。本页是还没构造交易。
7. 有人把这听成钥匙路径（不变量 153）。那是怎么花 Taproot。本页是怎么长出一棵钥。

「看见 xpub = 已经能花 / 能推子钥 = 已经是地址 / 32 = 已经有 UTXO」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新曲线；加的是链码和硬化分界 |
| 协议 | 必须点名问的是扩展公钥、收款地址，还是链上输出 |
| 实现 | 导入必须核点在曲线上；硬化下标从公钥路径必须失败 |
| 部署 | 应用层；钱包布局是建议，不是已经强制 |
| 经济 | 能看进账不是已经能花；泄漏扩展公钥加未硬化子孙私钥等于泄漏整棵子树 |

**推断：** 产品句若只写「支持 HD / xpub」，读者会把看见扩展公钥听成已经能花，或把能推子钥听成已经是地址。  
**建议：** 第一版若导出分层钱包，必须分开扩展公钥、收款地址、花费能力。不要发明「看见 xpub = 已经能花」。不要抄常数。不要把 32 写成 173 或 174。

## 6. 和另外几句不是同一句

1. **地址 ≠ 已有输出**（不变量 174）：看见串不是账本对象。本页是密钥树还没编成地址。
2. **后继校验 ≠ 已是旧方案**（不变量 181）：两套地址校验。本页不是校验和。
3. **工作包 ≠ 已广播**（不变量 179）：签名传到哪一步。本页是还没有交易。
4. **钥匙路径 ≠ 揭树**（不变量 153）：Taproot 怎么花。本页是怎么长出一棵钥。
5. **助记词 ≠ 已是种子**（不变量 183）：备份句还没长成树。本页是种子之后的扩展钥。
6. **钥备份 ≠ 已知道脚本**（不变量 184）：脚本类型要另写。本页是树节点还不是描述符。

不要抄版本字节 / 例串 / 下标常数 / 种子口令 / 字符长度。不要写怎样从扩展公钥推子钥，或怎样用父扩展公钥加一枚未硬化私钥还原整棵树。不编博物馆页。不另写 19 节。BIP-173 地址、BIP-174 工作包、BIP-44 账户编号习惯是另一对象。

## 7. 「不确定」测试句（建议）

```text
看见扩展公钥 ≠ 已经能花
去势后的扩展公钥 ≠ 已经是普通公钥
硬化子密钥 ≠ 已经能从公钥推出
链上标识对得上 ≠ 已经该当成收款地址
BIP-32 ≠ BIP-173 ≠ BIP-174 ≠ BIP-350
```

语料：[C186](../../libraries/adversarial-corpus/README.md)。

## 精密检查

**禁止假学习：** 「看见 xpub = 已经能花。」「能推子钥 = 已经是地址。」「32 = 已经有 UTXO。」「32 = 173。」「32 = 174。」「硬化 = 已经能从公钥推出。」  
**边界：** 不抄常数。不另写 19 节。不写怎样还原父私钥。看见串见 **C178**。后继校验见 **C185**。工作包见 **C183**。

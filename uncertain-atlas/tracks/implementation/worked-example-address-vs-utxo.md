## 1. 核心问题

阿比看见钱包里一串 Bech32，以为链上已经有这笔输出；或看见校验过了，以为见证程序已经在链上；或看见规范编号 173，以为就是 BIP-141 那条程序规则，或已经是后来的后继校验。

官方句（事实）：

- BIP-173：提出一种带校验的 base32 格式，名叫 Bech32；再用它给**原生隔离见证输出**写地址标准。
- 一层是通用串：可读前缀、分隔、数据。数据末尾一段是校验，**不含信息**。合法串必须过校验谓词。
- 一层是见证地址：把网络前缀、见证版本、BIP-141 定义的见证程序编进上述格式。
- 解读地址的软件必须核前缀、核版本范围，再把其余数据还原成程序。解码器应当再执行 BIP-141 已知的程序长度限制。实现必须允许任何规范版本，不得只认眼下常见的那一档。
- 编码器必须整串小写。解码器不得收大小写混写。
- 规范写明：纠错会侵蚀检测。把非法输入改成另一条合法输入，若错得比检测设计更多，合法串可能不是用户要的那串；用错串会不可挽回地丢币。因此实现不应当做自动纠错，最多指出可能错在哪，不得替用户改。
- 地址转成 scriptPubKey 时，版本号要落到对应操作码。转错了，结果多半不能花或不安全。
- 只有新软件、且收款方也启用了隔离见证，才能用这种地址。其它情况仍用旧地址包装。
- 本页替换 BIP-142。后来的 BIP-350 被标成本页的拟议替换。
- 2024 年官方补记：设计疏漏让校验对**短连续增删**并不总稳健。BIP-350 因此主张：本页这套校验只留给原生隔离见证版本 0。
- 规范**没有**把看见地址写成链上已经有输出，也没有把校验过写成程序已经上链，也没有把本页写成 BIP-141、BIP-350 或 BIP-13。

地址串、校验灯、链上那枚输出，是三件事。

## 2. 直觉（ELI15）

门牌号印对了，不等于这栋楼已经盖好、钥匙已经插上。  
校对章盖过，不等于房子已经在登记簿上。  
把门牌改成另一条也能过校对的号，可能指到别人家。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| Bech32 串 | 带校验的收款写法 | 链上已经有输出 |
| 校验 | 串自己过不过 | 程序已经上链；已经付款 |
| 见证地址 | 版本 + 程序的编码 | BIP-141 那条花费规则本身 |
| 后继校验 | 后来限制本页只用在版本 0 | 本页已经覆盖更高版本 |

---

## 4. 最小案例

一条 Bitcoin 要对齐「这一口气地址是哪盏灯」。

1. 只看见一串 Bech32。规范：这是收款写法。不是链上已经有这笔输出。
2. 校验过了。规范：串自己合法。不是见证程序已经在链上，也不是已经付过款。
3. 编出了版本和程序。规范：地址是这两样的编码。不是已经进 UTXO 集。
4. 实现自动把非法串改成另一条合法串。规范：不应当自动纠错。改对了校对，可能指错人。
5. 有人把这听成 BIP-141（不变量 152 的亲戚）。141 是链上见证程序。本页是怎么把程序写成给人看的串。
6. 有人把这听成 BIP-16 / BIP-13（不变量 170）。那是付给脚本哈希及其地址写法。本页是原生见证地址。
7. 有人把这听成 BIP-350。350 是后继：本页这套校验后来只留给版本 0。本页不是已经覆盖更高版本。

「看见地址所以已经有 UTXO / 校验过所以已经上链 / 173 = 141 / 173 = 350」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新原语；校验是检错码，不是签名 |
| 协议 | 必须点名问的是地址串、校验灯，还是链上输出 |
| 实现 | 两家必须同一套：小写输出、拒混写、不自动纠错、版本落到对应操作码 |
| 部署 | 应用层信息 BIP；只有新软件 + 启用见证的收款方能用 |
| 经济 | 转错 scriptPubKey 会不能花或不安全；错串会丢币 |

**推断：** 产品句若只写「支持 Bech32 地址」，读者会把看见串听成已经有 UTXO，或把校验过听成已经上链。  
**建议：** 第一版若提供收款地址，必须写清地址是给人看的编码，不是账本对象。不要发明「看见地址 = 已经有输出」。不要抄字符表。不要把 173 写成 350 或 141。

## 6. 和另外几句不是同一句

1. **txid ≠ wtxid**（不变量 152）：交易身份和见证身份。本页是收款写法。
2. **钥匙路径 ≠ 揭树**（不变量 153）：Taproot 怎么花。本页不是已经在讲钥匙路径。
3. **哈希 ≠ 已揭开**（不变量 170）：P2SH 哈希与赎回。13 是那种输出的地址写法。本页是原生见证地址。
4. **高度 ≠ 已在头上**（不变量 173）：高度写在哪。本页是地址写的是哪。
5. **工作包 ≠ 已广播**（不变量 179）：签名传到哪一步。本页是收款写法。
6. **后继校验 ≠ 已是旧方案**（不变量 181）：两套校验。本页是看见串 ≠ 已经有输出。
7. **扩展公钥 ≠ 已能花**（不变量 182）：密钥树还没编成地址。本页是看见串 ≠ 已经有输出。

不要抄字符表 / 生成式 / 例地址 / 网络前缀常数 / 长度窗 / 版本取值范围。不要写怎样造能过校验却指错程序的串，或怎样靠增删字符撞合法。不编博物馆页。不另写 19 节。BIP-350 后继校验、BIP-141 程序长度表、BIP-142 旧稿、SLIP 前缀登记是另一对象。

## 7. 「不确定」测试句（建议）

```text
看见 Bech32 地址串 ≠ 链上已经有这笔输出
校验过 ≠ 见证程序已经在链上
编出版本和程序 ≠ 已经付过款
纠错改成合法串 ≠ 已经是用户要的那串
BIP-173 ≠ BIP-350 ≠ BIP-141 ≠ BIP-142 ≠ BIP-13
```

## 精密检查

**禁止假学习：** 「看见地址 = 已经有 UTXO。」「校验过 = 程序已经上链。」「编出程序 = 已经付款。」「自动纠错 = 已经改对。」「173 = 141。」「173 = 350。」「173 = 13。」  
**边界：** 不抄字符表。不另写 19 节。不写怎样增删字符。见证身份见 **C156**。哈希见 **C174**。

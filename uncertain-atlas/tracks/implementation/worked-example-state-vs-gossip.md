# 例：看见 State 对象不是已经进了块；看见头上的根不是已经有了 State；看见能读本地 State 不是已经进了规范

**层次**：实现 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [State](https://github.com/cometbft/cometbft/blob/main/spec/core/state.md)（Data Structures）。  
**对应课文**：[L4.2](../../courses/level-04-bft/L04-M02-rounds-and-steps.md)、[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)、[L9.3](../../courses/level-09-systems/L09-M03-storage.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行。本页是「本地 State 对象不是已经进了块 / 不是已经流言」，不是本头 AppHash 已经交差，也不是快照已经从创世重放。不要另写怎样拼 State 字段或怎样算头上的根。

## 官方三件事

规范把引擎里的 `State` 写成三件独立的实现事，不是「看见本地 State 就已经在块里」一件事：

1. **看见 State 对象 / 看见本地 State 不是已经写进块，也不是已经流言，也不是已经算了 State 哈希。**  
   官方写：`State` 对象本身是实现细节。它从不写进块，也不在网上流言，也不给它算哈希。看见本机有一份 `State`，不是这份已经进了某块。看见能读到它，不是邻居已经收到同一份。看见字段齐了，不是已经有一个 `State` 哈希可以对。
2. **看见头上的 Merkle 根 / 看见验证者根或结果根 不是已经有了 State 对象本身。**  
   官方写：`State` 里的类型属于规范，因为这些对象的 Merkle 根会进块，验证时也要用到里面的值。验证者集合和交易结果从不整份写进块，只进根。看见头上有根，不是已经有了本地那份 `State`。看见根对上了，不是 `State` 对象已经流言过。
3. **看见 State 的落盘或查询接口 / 看见能读本地 State 不是已经进了规范，也不是已经能在网上对上。**  
   官方写：`State` 怎么落盘、怎么查询，是实现细节，不写进规范。看见能读本地 `State`，不是这份接口已经是规范对象。看见落盘了，不是已经能在网上对上。看见查询回了字段，不是这些字段已经进了块。

验证者人数上限、字段表、创世高度取值是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **State 对象 ≠ 已经进了块：** 官方把本地这份对象写成实现细节，从不进块、不流言、不算哈希。
- **头上的根 ≠ 已经有了 State：** 官方把进块的是根、验证时用值，和对象本身分开。
- **落盘或查询接口 ≠ 已经进了规范：** 官方把怎么存、怎么查写成不进规范。

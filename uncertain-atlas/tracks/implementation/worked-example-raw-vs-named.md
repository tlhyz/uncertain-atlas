# 例：看见 raw 不是已经能套进具名表达式；看见 addr 不是已经是那份输出脚本；看见一份包装不是已经是 combo

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-385](https://github.com/bitcoin/bips/blob/master/bip-0385.mediawiki)（Deployed, Applications, Informational）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「raw 不是已经具名脚本 / addr 不是已经是那份输出脚本」，不是描述符已经是地址，也不是 combo 已经一种脚本。不要另写怎样把地址解成脚本。

## 官方三件事

规范把 raw / addr 描述符写成三件独立的结构事，不是「看见任意脚本或地址就已经是具名描述符」一件事：

1. **看见 raw / 看见一串十六进制脚本 不是已经能套进 sh / wsh，也不是已经是 pk / sh 那种具名表达式。**  
   官方写：`raw(HEX)` 只能当顶层描述符。参数是一串表示 Bitcoin 脚本的十六进制。这份描述符产出的输出脚本，就是 HEX 表示的那条脚本。看见写了 raw，不是已经能再套进 `sh` 或 `wsh`。看见交出了脚本字节，不是已经写了 381 那种具名函数。
2. **看见 addr / 看见一个地址 不是已经能套进 sh / wsh，也不是已经把那份输出脚本写在描述符里。**  
   官方写：`addr(ADDR)` 只能当顶层描述符。它只吃一个地址。这份描述符产出的输出脚本，就是这个地址产出的那份输出脚本。看见一个地址，不是已经是本页描述符。看见用 addr 包住了地址，不是已经把脚本表达式写出来，也不是已经在链上有这笔输出。
3. **看见一份 raw 或 addr 包住一个对象 不是已经是一份 combo，也不是已经是一份钱包策略。**  
   官方写：raw 把任意输出脚本包成描述符；addr 把一个地址包成描述符。看见一份包装，不是已经是 384 那种一把钥产出两份或四份。看见能包住今天在用的脚本或地址，不是已经是 388 那种账户所需的全部描述符，也不是已经是地址。

十六进制脚本、测试向量、例地址是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **raw ≠ 已经具名：** 官方把它写成只能顶层，参数就是脚本本身。
- **addr ≠ 已经是那份输出脚本：** 官方把地址和地址产出的脚本写成两步。
- **一份包装 ≠ 已经是 combo：** 官方把本页写成包一个对象，不是一把钥上的几份传统脚本。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 地址 | 包进 addr 才是本页描述符 | 不是已经是地址串已经有输出（174） |
| 描述符 | 包装不是已经具名 | 不是已经是地址（184） |
| 一份表达式 | 包一个脚本或一个地址 | 不是已经是 combo（281） |
| 放置 | 只能顶层 | 不是已经和 pk / pkh / sh 同一套放置（276） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出 raw / addr，必须分开只能顶层、地址不是脚本、一份包装不是 combo。可以跳过「看见任意脚本或地址就已经是具名描述符」。若对照，必须分开本页包装和 384 那种一把钥多份脚本。不要另写怎样把地址解成脚本。

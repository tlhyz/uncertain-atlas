# 例：看见 BlockID.Hash 是头字段的默克尔根不是整块的根；看见 PartSetHeader 是整块的根不是头；看见两块的 BlockID 有一个根对上不是已经是同一块

**层次**：实现 / BlockID 双根。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [Core Data Structures](https://github.com/cometbft/cometbft/blob/main/spec/core/data_structures.md) BlockID / PartSetHeader。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行、L4.5。本页是「BlockID.Hash 是头字段的默克尔根不是整块的根 / PartSetHeader 是整块的根不是头 / 两块的 BlockID 有一个根对上不是已经是同一块」，不是同一对上不同 BlockID 就已经构成双签证据，也不是部分对象外层下标必须与证明下标同一对象。不要另写怎样算 BlockID。

## 官方三件事

规范把 `BlockID.Hash` 是**头字段**的默克尔根、`BlockID.PartSetHeader` 是**完整序列化块**切成片后的默克尔根、以及 `PartSetHeader.Total` 是片数，写成三件独立的事实，并明写 `BlockID` 含「**两个不同的默克尔根**」，不是「看见一个根对上就已经是同一块、已经是同一种承诺」一件事：

1. **看见 `BlockID.Hash` 是头字段的默克尔根 / 看见有哈希 不是已经是整块的根，也不是已经覆盖交易。**  
   官方写：`Hash` 是头里全部字段的默克尔根（即 `MerkleRoot(header)`）。校验要求长度必须是 32。看见哈希对上，不是已经覆盖了交易或证据。看见有根，不是已经是整块那份根。看见 32 字节，不是已经同一块。
2. **看见 `PartSetHeader` 是完整序列化块的根 / 看见有它 不是已经是头，也不是已经是共识里那份头哈希。**  
   官方写：`PartSetHeader` 用来在共识期间安全地流言块，它是**完整序列化块**切成片之后的默克尔根（即 `MerkleRoot(MakeParts(block))`）。看见有它，不是已经是头那份根。看见能流言，不是已经收到整块。看见根对上，不是已经能执行。
3. **看见 `PartSetHeader.Total` 是片数 / 看见数对上 不是已经收到那些片，也不是已经齐。**  
   官方写：`Total` 是这块的片数，校验要求必须大于 0；而 `Hash` 长度必须是 32。看见片数在，不是已经收到那么多片。看见数对上，不是已经拼得出块。看见大于 0，不是已经交差。

怎样算 `BlockID`、怎样切片、怎样流言是规范里的做法，本页不抄。同一对上不同 `BlockID` 就已经构成双签证据是不变量 21，本页不抄。部分对象外层下标必须与证明下标同一对象是不变量 59，本页不抄。

## 官方为什么这样拆

- **`BlockID.Hash` 是头字段的根 ≠ 已经是整块的根：** 官方把「头的根」和「整块的根」写成两个不同的默克尔根。
- **`PartSetHeader` 是整块的根 ≠ 已经是头：** 官方把它写成用于流言的整块根，而不是头哈希。
- **`Total` 是片数 ≠ 已经收到那些片：** 官方把「报了片数」和「已经拼出块」分开。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| BlockID.Hash 是头字段的默克尔根 | 不是已经是整块的根 | 不是同一对上不同 BlockID 就已经构成双签证据（21） |
| PartSetHeader 是整块的根 | 不是已经是头，也不是已经收到整块 | 不是部分对象外层下标就已经与证明下标同一对象（59） |
| PartSetHeader.Total 是片数 | 不是已经收到那些片 | 不是宣布了新块就已经收到（36） |
| 本页不涉及 | — | 不是第 0 项 UNKNOWN 那种枚举语义（439） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「看见一个根对上就已经是同一块」，必须分开 BlockID.Hash 是头字段的默克尔根是不是已经是整块的根、PartSetHeader 是整块的根是不是已经是头、两块的 BlockID 有一个根对上是不是已经是同一块。可以跳过「看见一个根对上就已经是同一块」。不要另写怎样算 BlockID。

## 本页不抄

- 怎样算 `BlockID`、怎样切片、怎样流言。
- 同一对上不同 `BlockID` 就已经构成双签证据。那是不变量 21。
- 部分对象外层下标必须与证明下标同一对象。那是不变量 59。
- 宣布了新块就已经收到。那是不变量 36。

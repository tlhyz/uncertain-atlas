# 实例：高度 50 写到一半断电

目的 A/B。不是考试。  
先修：L4.4、L9.3、反模式 half-written-state。

---

## 故事

CometBFT 风格引擎刚对高度 50 出了 commit。应用开始写：

1. 账户阿安余额已减 1  
2. 阿比余额还没加  
3. 进程被杀  

重启后若直接服务：阿安少了 1，阿比没有，应用哈希与引擎「已 commit 50」对不上邻居。  
两台诚实机器，一台停在 49 的完整状态，一台停在半个 50。用户问「到了吗」——**实现/部署**，不是投票算术错了。

正确醒来只允许：完整的 49（将重放 50），或完整的 50 + 一致的锁/哈希。

---

## 和 lock 一起坏

若 WAL 没记下「已 lock 块 X」，重启后在同高度投了 Y：  
这是**安全**事故（L4.3），不是「掉线一下」。  
层：实现没守协议的锁。

---

## 五层

| 层 | 本故事 |
|---|---|
| 密码 | 通常无关 |
| 协议 | commit/lock 定义可以仍对 |
| 实现 | 半提交、丢 lock |
| 部署 | SIGKILL、满盘、容器 OOM |
| 经济 | 若半状态被当成最终，放货 |

## 「不确定」测试句（建议）

```text
crash_at_any_point ⇒ restart ∈ {pre_H, post_H_complete}
restart ⇒ 不发出与旧 lock 矛盾的票
```

后量子验签再慢，也不许用「先写一半」换吞吐。

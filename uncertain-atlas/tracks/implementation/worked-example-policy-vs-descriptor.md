# 例：看见钱包策略不是已经是一条描述符；看见钥占位不是已经是那把精确公钥；看见登记过不是已经批准这笔花

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-388](https://github.com/bitcoin/bips/blob/master/bip-0388.mediawiki)（Complete, Applications, Specification）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「钱包策略不是已经是一条描述符 / 登记过不是已经批准这笔花」，不是看见描述符已经是地址，也不是看见 Miniscript 已经是链上脚本。不要另写怎样编译占位。

## 官方三件事

规范把钱包策略写成三件独立的结构事，不是「看见账户就已经是一条描述符」一件事：

1. **看见钱包策略 / 看见一个账户 不是已经是一条描述符，也不是已经把账户收成一句描述符。**  
   官方写：钱包策略由一份描述符模板，加上一列钥信息组成。一个账户包接收款和找零地址。每一份钱包策略代表描述这个账户所需的全部描述符。看见策略，不是已经是 380 那条描述符。看见账户，不是已经不必再展开。
2. **看见钥占位 / 看见账户根 不是已经是那把精确公钥，也不是已经带齐派生。**  
   官方写：KEY 表达式永远对应最终脚本里那一把精确公钥，派生步骤都写在 KEY 里。钥占位对应这个账户所有可能 UTXO 的公钥根，占位里不许再写派生。看见占位，不是已经对上某一把脚本公钥。看见列开了扩展公钥，不是已经是描述符里那把 KEY。
3. **看见登记过 / 看见登记证明 不是已经批准这笔花，也不是已经是 Miniscript 那种 policy 语言。**  
   官方写：第一次用之前，用户要先在签名器上登记这份策略。登记证明让签名器确认用户以前批准过这份策略，才不必再走一遍昂贵核验。官方另写：本页钱包策略和那种能编译成 Miniscript 的 policy 语言不是一回事。看见登记过，不是已经批准这一笔。看见写了 policy，不是已经是 379 那种语言。

占位写法、编译步骤、测试向量、例路径是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **策略 ≠ 已经是一条描述符：** 官方把模板和钥信息列写成两份对象。
- **占位 ≠ 已经是精确公钥：** 官方把 KEY 的派生和占位的账户根写成两套。
- **登记过 ≠ 已经批准这笔花：** 官方把登记证明写成可以少核验，不是已经签过这一笔。

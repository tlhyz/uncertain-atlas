# 例：看见一条派生路径不是已经是一份路径模板；看见写死了熟路径检查不是已经能互操作；看见完整模板不是已经是半截模板

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-88](https://github.com/bitcoin/bips/blob/master/bip-0088.mediawiki)（Complete, Applications, Informational）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「一条派生路径不是已经是一份路径模板 / 写死了熟路径检查不是已经能互操作」，不是自称 compatible 已经能互操作，也不是路径里的脚本类型已经必要。不要另写怎样解析或匹配模板。

## 官方三件事

规范把路径模板写成三件独立的结构事，不是「看见一条路径就已经是一份能约束派生的模板」一件事：

1. **看见一条派生路径 / 看见 43 / 44 / 45 / 49 / 84 那种方案 不是已经是一份路径模板，也不是已经能被软件无歧义解析。**  
   官方写：32 那种路径写法很通用，后面又出了 43 和别的派生方案。可是就算用了这些方案，各家钱包用得并不齐。官方另写：有人用竖线把几条路径或几个下标写在一起，只是给人看的临时写法，没有写成给软件解析的规范。本页这份格式既要给人一眼看出哪一段是模板，也要让软件无歧义解析。看见一条路径，不是已经有约束。看见写了 44，不是各家已经对齐。
2. **看见写死了熟路径检查 不是已经能互操作，也不是已经是本页。**  
   官方写：在软件或固件里写死熟路径检查，互操作会变差。厂家不能为自己那种非通用应用选合适的自定义路径，只能硬塞进熟路径，或去说服别人认自己的路径。这条路不好扩展。官方另写：不加限制地用派生路径，在有些场合不安全。尤其是找零打到发送方不认识的路径上，发送方可能丢掉全部找零。本页的灵活做法，是用一份标准记号写下要对路径施加的约束。看见写死了 44 / 49 / 84，不是已经能换钱包。看见熟路径表，不是已经挡住乱派生。
3. **看见以 m/ 开头的完整模板 不是已经是半截模板；看见模板长度对上 不是已经是同一条路径。**  
   官方写：以 `m/` 开头的是完整模板，匹配整条路径。不以 `m/` 开头的是半截模板，只在合适的场合匹配路径的一段。完整模板不能再和另一份完整模板拼。实现必须能解析完整模板并拿整条路径去配；半截模板可以不做。官方另写：路径长度和模板长度对不上就失败。只有单位下标的完整模板，本身也是一条合法 32 路径。看见以 `m/` 开头，不是已经允许只配后半段。看见长度一样，不是已经配上。看见看起来像路径的模板，不是已经带了通配或区间约束。

语法取值、匹配步骤、形式化状态机、模板例句是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **一条路径 ≠ 已经是一份路径模板：** 官方把给人看的临时写法和给软件解析的模板写成两件东西。
- **写死熟路径 ≠ 已经能互操作：** 官方把硬编码熟路径和可声明的约束写成两条扩展性不同的路。
- **完整模板 ≠ 已经是半截模板：** 官方把匹配整条、匹配一段、长度必须对齐写成三道门。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |

| 兼容声明 | 写死熟路径不是已经能换钱包 | 不是自称 compatible 已经能互操作（266） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果限制派生路径，必须分开一条路径不是模板、写死熟路径不是互操作、完整模板不是半截。可以跳过「看见一条路径就已经能约束派生」。若对照，必须分开模板、熟路径表、完整/半截。不要另写怎样解析或匹配模板。

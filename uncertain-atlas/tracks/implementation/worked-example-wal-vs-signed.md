# 例：看见写下每条消息不是已经 fsync；看见回放时又要签不是已经双签；看见 LastSignBytes 对上不是已经换了高度

**层次**：实现 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [WAL](https://github.com/cometbft/cometbft/blob/main/spec/consensus/wal.md)（Software, Consensus）。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)、[L9.3](../../courses/level-09-systems/L09-M03-storage.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行。本页是「共识模块的预写日志不是已经防了双签 / 不是已经发出新票」，不是锁谓词，也不是应用半写。不要另写怎样按旋转体积切文件或怎样从损坏里恢复。

## 官方三件事

规范把共识模块的预写日志写成三件独立的实现事，不是「看见写下就已经防了双签」一件事：

1. **看见共识模块写下每条消息 / 看见 WAL 里有消息 不是已经对本节点签过的消息做了 fsync，也不是已经防了双签。**  
   官方写：共识模块把每条消息写入 WAL。对本节点签过的消息，还会走 fsync，为的是防双签。看见写下了，不是已经刷盘。看见别人的消息也在日志里，不是那些消息已经按本节点签名那条路刷过。看见有预写日志，不是已经守住「同一高度不得再签矛盾票」。
2. **看见崩溃后回放上一高度 / 看见私钥签名器在回放时又要签 不是已经双签，也不是已经发出新的一票。**  
   官方写：崩溃后，共识模块会回放 WAL 里上一高度写下的全部消息。私钥签名器有点各走各的，并不知道正在回放，回放时可能再想签。例如 WAL 已经走到 precommit 再崩溃：回放提案之后，签名器会想签 prevote，但会失败——这没关系，因为后面还会看见 WAL 里那张 prevote。看见回放，不是已经对外发出新票。看见签名器又要签，不是已经双签。看见这次失败，不是回放已经坏了。
3. **看见 LastSignBytes 对上 / 看见回放走到 precommit 不是已经换了高度，也不是已经是新的承诺。**  
   官方写：回放到 precommit 时，签名器里有 `LastSignBytes`，这一次会成功，然后会再回放 WAL 里那张 precommit。看见 `LastSignBytes` 对上，不是已经换了高度。看见回放走到 precommit，不是已经发出另一张承诺。看见签名器这次肯签，不是已经是崩溃之后的新一轮。

旋转体积、总上限、损坏恢复步骤是规范或运维里的取值或做法，本页不抄。

## 官方为什么这样拆

- **写下 ≠ 已经 fsync：** 官方把「每条都写」和「本节点签名才刷盘」写成两件事。
- **回放时再签 ≠ 已经双签：** 官方把签名器不知道正在回放、先失败再看见 WAL 里旧票，写成正常回放。
- **LastSignBytes 对上 ≠ 已经换了高度：** 官方把对上旧字节写成能继续回放，不是新高度的新承诺。

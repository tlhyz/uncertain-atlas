# 例：看见共享主公钥不是已经是本页；看见能独立长地址不是已经能独立签；看见前面分支没有交易不是已经发现完

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-45](https://github.com/bitcoin/bips/blob/master/bip-0045.mediawiki)（Complete, Applications）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「共享主公钥不是已经是本页 / 前面分支没有交易不是已经发现完」，不是同一套钥已经是同一条地址，也不是余额为零已经发现完。不要另写 BIP-11 / BIP-67 怎样排序公钥。

## 官方三件事

规范把分层确定性多签结构写成三件独立的结构事，不是「看见多签路径就已经能扫完」一件事：

1. **看见共享主公钥 / 看见扩展公钥 不是已经是本页，也不是已经够了。**  
   官方写：各方各自独立生成自己的主私钥。各参与方之间不共享主公钥，只共享硬化用途层扩展公钥，并且用这一把去推子扩展公钥。看见共享了主公钥，不是已经是本页。看见扩展公钥，不是已经共享了本页要的那一层。
2. **看见能独立长地址 / 看见不必通信就能长地址 不是已经能独立造交易，也不是已经能独立签名。**  
   官方写：长地址不应当要求各方通信，所以每一方都必须能长出所有公钥。造交易和签名要求各方通信。看见能独立长地址，不是已经能独立花。看见同一条路径，不是已经是同一个人的钥。
3. **看见前面的联合签名人分支没有交易 不是已经发现完，也不是已经可以只扫第一支。**  
   官方写：发现看过往、不看余额。和 BIP-44 相反，即使前面的分支没有交易，也必须检查每一个联合签名人分支。官方还写：每个联合签名人只在自己的分支上长地址，免得两个人同时长出同一条地址、同时收款。看见前面一支没有交易，不是已经扫完。看见余额为零，不是已经没有这一支。

用途号、间隙条数、例路径、怎样按用途公钥排联合签名人下标是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **共享主公钥 ≠ 已经是本页：** 官方把「只共享硬化用途层扩展公钥」写成和主公钥不是同一把。
- **能独立长地址 ≠ 已经能独立签：** 官方把长地址写成不必通信，把造交易和签名写成必须通信。
- **前面分支没有交易 ≠ 已经发现完：** 官方明确写成和 BIP-44 相反，每一支都要查。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 共享主公钥 | 不是已经是本页 | 不是已经能花（182） |
| 能独立长地址 | 不是已经能独立签 | 不是已经是同一条地址（270） |
| 前面分支没有交易 | 不是已经发现完 | 不是已经发现完那句账户发现（267） |
| 用途层 | 本页只用硬化用途层扩展公钥 | 不是已经能互操作（266） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出多方多签，必须分开共享了哪一层、长地址和签名、每一支都要不要查。可以跳过「看见多签路径就已经能扫完」。若对照，必须分开本页发现和 BIP-44 账户发现。不要另写怎样按用途公钥排下标，也不要另写 BIP-11 / BIP-67。

## 本页不抄

- 用途号、间隙条数、例路径、例压缩钥。
- 怎样按用途公钥排联合签名人下标、怎样从种子扫每一支。

# 例：看见 BIP32 compatible 不是已经能互操作；看见自称 BIPxx compatible 不是已经是那份结构；看见同一套扩展钥前缀不是已经是比特币专用

**来源**：Bitcoin [BIP-43](https://github.com/bitcoin/bips/blob/master/bip-0043.mediawiki)（Deployed, Applications）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。

## 官方三件事

规范把用途层写成三件独立的钱包结构事，不是「看见 BIP32 compatible 就已经能互操作」一件事：

1. **看见 BIP32 compatible 不是已经能互操作，也不是已经是同一套逻辑结构。**  
   官方写：分层确定性钱包结构是体验和安全上的重要一步，但规范给实现留了太多自由度。多家实现都可以自称 BIP32 compatible，底下却长出不同的逻辑结构，彼此不能互操作。这种局面让「BIP32 compatible」这句话变得相当没用。看见自称兼容，不是已经同一套树。看见都能从同一份种子长钥，不是已经能互相发现账户。
2. **看见自称 BIPxx compatible / 只实现了其中一部分 不是已经是那份 BIP 写的结构。**  
   官方写：第一层应当当「用途」。用途决定这颗节点下面还长什么样。不是所有钱包都想支持这些 BIP 写全的功能。与其随便抽子集还自称 BIPxx compatible，需要有限结构的软件应当另写一份 BIP，并换一个用途值。看见用途号，不是已经支持那份 BIP 的全部能力。看见自称兼容，不是已经是那份结构。
3. **看见同一套扩展钥前缀 / 同一套版本魔数 不是已经是比特币专用，也不是已经是 BIP32 默认账户。**  
   官方写：这套方案一次可以给多种币、甚至完全无关的东西长节点，所以没有必要再给扩展钥另写一套版本魔数；建议继续用同一套公钥 / 私钥前缀。官方还写：BIP32 默认账户那一支已经被占了，本页之前就存在。看见还是那套前缀，不是已经只服务一条链。看见默认账户支，不是已经是本页这种用途层。

用途号怎么取、魔数怎么写、SLIP 预留段是规范里的取值，本页不抄。

## 官方为什么这样拆

- **兼容声明 ≠ 已经互操作：** 官方把「自称 BIP32 compatible」写成相当没用，因为逻辑结构可以不一样。
- **子集兼容 ≠ 已经是那份结构：** 官方要求有限结构另写 BIP、另给用途，而不是抽子集还挂原名。
- **同一前缀 ≠ 已经是比特币专用：** 官方把「还能给别的币、甚至无关的东西长节点」写成不必另开魔数。

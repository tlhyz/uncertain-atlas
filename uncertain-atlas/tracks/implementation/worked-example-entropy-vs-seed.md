# 例：看见一份助记词不是已经能备齐所有钱包；看见扩展根钥不是已经能倒回助记词；看见派生出的熵不是已经是目标钱包的种子

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-85](https://github.com/bitcoin/bips/blob/master/bip-0085.mediawiki)（Deployed, Applications, Informational）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「一份助记词不是已经能备齐所有钱包 / 派生出的熵不是已经是目标钱包的种子」，不是助记词已经是二进制种子，也不是扩展公钥已经能花。不要另写怎样从子钥算出熵。

## 官方三件事

规范把从一把扩展根钥导出熵写成三件独立的结构事，不是「看见一份种子就已经能喂给所有钱包」一件事：

1. **看见一份助记词 / 看见一份种子备份 不是已经能备齐所有钱包，也不是已经该在多个钱包之间共用。**  
   官方写：没法只备一份助记词种子，就覆盖各种钱包用的全部钥链，因为标准互不兼容。为了安全，也不该把同一份种子分给多个钱包。看见一份助记词，不是已经能找回热钱包、节点和别的币那种各自的方案。看见共用了种子，不是已经更安全。
2. **看见扩展根钥 / 看见派生出的子私钥 不是已经能倒回助记词，也不是已经是那份熵。**  
   官方写：存下助记词就够重建整棵 32 钥链，但扩展根钥不能倒回助记词。本页不关心这把根钥当初怎么来。官方另写：给每个要单独开钱包的应用，先硬化派生出一把子私钥，再把它变换成熵；目的是导出熵，不是把这把子钥直接当私钥用。看见扩展根钥，不是已经能写出助记句。看见子私钥，不是已经是那份熵。
3. **看见派生出的熵 / 看见截过的比特 不是已经是目标钱包的种子，也不是已经是本钱包里的钥。**  
   官方写：用 32 本身导出「初始熵」，再按目标钱包自己的标准去造助记词或种子。每个应用应按自己需要的比特数来取，其余截掉。看见导出了熵，不是已经是 39 那种种子，也不是已经能花本页这棵树上的币。看见给另一个应用用了，不是已经是同一份钱包。

应用编号、路径常数、测试向量、例句、变换配方是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **一份助记词 ≠ 已经能备齐所有钱包：** 官方把互不兼容的标准和「不该共用种子」写成两件独立的限制。
- **扩展根钥 ≠ 已经能倒回助记词：** 官方把助记词能重建钥链、根钥不能倒回、子钥还要再变成熵写成三步。
- **派生出的熵 ≠ 已经是目标钱包的种子：** 官方把本页熵写成只是目标标准的输入，不是已经长出那棵树。

## 官方三件事

规范把 `retain_height` 默认全留、低于这个高度的块可以被删、全网都删会永久丢写成三件独立的实现事，不是「看见 Commit 回了高度就已经在剪、已经没有历史、已经能从创世再装」一件事：

1. **看见 `retain_height` 默认 0、表示全留 / 看见没填 不是已经在剪，也不是已经交差。**  
   官方写：`CommitResponse.retain_height` 默认是 `0`，表示全留。看见字段在，不是已经在剪。看见没填，不是已经交差。看见 Commit 回了，不是已经没有历史。
2. **看见低于这个高度的块可以被删 / 看见回了高度 不是已经是这个节点快照截断，也不是已经没有历史。**  
   官方写：低于这个高度的块可以被删。看见回了高度，不是已经删完。看见能删，不是已经是切进共识之后这个节点在快照高度被截断。看见能剪，不是已经没有历史。
3. **看见全网都删了会永久丢、除非开了 state sync / 看见能剪 不是已经能从创世再装，也不是已经能给轻客户端验。**  
   官方写：若网上所有节点都删了历史块，这些数据就永久丢了；除非链上开了 state sync，否则新节点加不进来、也引导不起来。审计、回放没落盘的高度、轻客户端核验也可能还要用这些历史块。看见能剪，不是已经能从创世再装。看见开了 state sync，不是已经能给轻客户端验。看见能丢，不是已经交差。

怎样填 `retain_height`、怎样删块、怎样开 state sync 是规范里的做法，本页不抄。崩溃三步就已经 Commit 是不变量 320，本页不抄。

## 官方为什么这样拆

- **retain_height 默认 0 ≠ 已经在剪：** 官方把默认全留和已经在剪分开。
- **低于这个高度的块可以被删 ≠ 已经没有历史：** 官方把可以删和已经删完分开。
- **全网都删了会永久丢 ≠ 已经能从创世再装：** 官方把能剪和还能从创世核验分开。

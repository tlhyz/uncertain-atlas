## 1. 核心问题

阿比看见一条 BLAKE2 压缩函数预编译，以为合约已经能算 BLAKE2b 哈希；或看见官方写能便宜跑更高轮的 64 位变体，以为 Equihash 工作量已经能验、跨链中继已经上线、原子交换已经能做、隐私已经有了；或看见规范编号 152，以为已经是 keccak / SHA3。

官方句（事实）：

- EIP-152：加入一条预编译，实现 BLAKE2 密码哈希算法里用的压缩函数 F。目的是让 EVM 和 Zcash 一类链能互操作，并给 EVM 多一种更灵活的哈希积木。看见本页，不是已经是完整哈希，也不是互操作已经上线。
- 官方写：本页让 BLAKE2b 以及其它更高轮的 64 位 BLAKE2 变体能在 EVM 上便宜跑。看见能便宜跑，不是已经封装成一条「哈希」指令。
- 官方写：BLAKE2 本身是有用的密码哈希，也是 SHA3 决赛候选。看见本页，不是已经是 keccak，也不是已经是 SHA3。
- 官方写：它还能让 Equihash 工作量证明验起来便宜，好让类似「把另一条链的头当轻客户端」的做法在以太坊上成为可能。官方写：一次这样的验证要很多次哈希，用高级语言实现会贵到几乎不能用。看见本页，不是已经能验 Equihash，也不是中继已经上线。
- 官方写：和 Zcash 互操作，有可能做成不靠托管的原子交换，从而给公开账本补一块隐私。看见本页，不是原子交换已经能做，也不是隐私已经有了。
- 官方写：先做压缩函数 F，是互操作项目当时严格必需的一块。完整的 BLAKE2b 预编译是加分项：不同项目要的接口和内部改动不一样，当时不清楚能不能及时找到一套够用、又够灵活的完整哈希 API。看见本页，不是已经有完整哈希 API。
- 官方写：只实现核心压缩函数，协议改动小，却能留下树哈希、增量哈希、带钥 / 加盐 / 个性化、以及可变长度摘要这些空间。这些当时在 EVM 上都还没有。看见本页，不是这些用法已经上线。
- 官方写：输入按规范紧凑编码，长度必须刚好是那一档；长度不对就报错。末尾那一个是否最后一块的旗标，只有两个合法取值，其它取值是非法编码。看见定长输入，不是已经能吃任意哈希 API。
- 官方写：预编译按 RFC 算出 F，返回更新后的状态向量，编码不变。看见返回状态向量，不是已经返回一份消息摘要。
- 规范**没有**把压缩函数写成已经是 BLAKE2b 哈希，也没有把本页写成已经能验 Equihash、已经是中继、已经是原子交换或已经有隐私，也没有把本页写成 keccak / SHA3。

压缩函数 F、完整哈希、工作量验证 / 中继、已经有隐私，是四件事。

---

## 2. 直觉（ELI15）

厨房里多了一台只会「压一轮」的机器，不是已经端出一盘完整哈希菜。  
说明书上写「以后也许能拿它去对另一条链的工作量、甚至做不靠托管的交换」，不是这些菜已经上桌，更不是账本已经变私密。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 压缩函数 F | BLAKE2 里的一轮压缩预编译 | 已经是 BLAKE2b 哈希 |
| 定长输入 | 按规范紧凑编码，长度和旗标都有合法档 | 已经是任意哈希 API |
| 互操作动机 | 让 Equihash / 跨链中继 / 原子交换变得可能 | 已经能验；中继已上线；已经有隐私 |
| 152 | 给 EVM 加 F | 完整 BLAKE2b；keccak / SHA3 |

---

## 4. 最小案例

一条 Ethereum 要对齐「这一口气哈希积木在管什么」。

1. 看见压缩函数 F。规范：实现 BLAKE2 里的 F，返回更新后的状态向量。不是已经是哈希。
2. 看见定长输入和最后一块旗标。规范：长度必须刚好，旗标只有两档合法。不是已经能吃任意哈希 API。
3. 看见官方写能便宜跑更高轮的 64 位变体。规范：这是动机。不是已经封装成哈希指令。
4. 看见官方写 Equihash 验证、跨链中继、原子交换、隐私。规范：这些是「可能」。不是已经能验，也不是产品已经上线。
5. 看见官方写先做 F、完整哈希是加分项。规范：当时找不到一套够用的完整 API。不是已经有完整 BLAKE2b。
6. 有人把这听成不变量 199。那是后来的 BLS12 算术。本页是哈希压缩积木。
7. 有人把这听成不变量 228。那是 bn128 三条预编译改价。本页是新加一条压缩预编译。
8. 有人把这听成不变量 221。那是读账户代码哈希。本页不读账户。
9. 有人把预编译地址、输入宽度、每轮气价或测试向量抄进不确定。规范：数字是尺子，不是产品常量。

「152 = 已经是 BLAKE2b / F = 已经能验 Equihash / 152 = 中继已上线 / 152 = 已经有隐私 / 152 = keccak」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | F 是压缩积木，不是完整哈希，也不是工作量方案 |
| 协议 | 必须点名问的是压缩函数、完整哈希、工作量验证 / 中继，还是已经有隐私 |
| 实现 | 输入必须定长、旗标必须合法；看见报错不是已经算出摘要 |
| 部署 | 官方写完整哈希 API 当时还没对齐；看见本页不是各项目已经能直接调用哈希 |
| 经济 | 更便宜不是中继、原子交换或隐私已经免费 |

**推断：** 产品句若只写「以太坊终于有 BLAKE2 了」，读者会把压缩函数听成已经是哈希，或把动机听成 Equihash 中继和隐私已经齐。  
**建议：** 第一版可以不加这条压缩预编译。若对照，必须分开压缩函数、完整哈希、工作量验证 / 中继、已经有隐私。不要发明「看见 152 就已经能验 Equihash」。不要抄预编译地址或测试向量。不要写怎样叠压缩函数去验工作量或做跨链交换。

## 6. 和另外几句不是同一句

1. **预编译算术 ≠ 已验 BLS**（不变量 199）：2537 是曲线算术。本页是哈希压缩积木。
2. **bn128 预编译降价 ≠ 已验签**（不变量 228）：1108 是给已有曲线预编译改价。本页是新加压缩预编译。
3. **代码哈希指令 ≠ 已看见代码**（不变量 221）：1052 读账户代码哈希。本页不读账户。
4. **本账户余额指令 ≠ 已是 BALANCE**（不变量 229）：1884 管余额读。本页不管余额。

不要抄预编译地址、输入宽度、每轮气价、测试向量。不要写怎样叠压缩函数去验工作量、怎样做跨链中继或原子交换。不编博物馆页。不另写 19 节。不转规范代码。完整 BLAKE2b、Equihash 验证、keccak / SHA3、跨链中继产品是另一对象。

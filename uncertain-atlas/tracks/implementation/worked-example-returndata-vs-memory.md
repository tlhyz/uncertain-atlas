## 1. 核心问题

阿比看见返回数据缓冲，以为被调写回的那块内存已经就是返回数据；或看见官方写「很像 calldata」，以为已经是调用数据；或看见能再取失败数据，以为 140 已经齐了；或看见缓冲，以为下一次类调用之后还在。

官方句（事实）：

- EIP-211：调用结束之后，返回数据留在一份虚拟缓冲里；调用方再把它（或其中一段）拷进内存。看见缓冲，不是已经在内存里。
- 官方写：做法很像已经有的 calldata：调用后再拷；下一次类调用会覆盖这份缓冲。看见很像 calldata，不是已经是 calldata。看见本页，不是下一次类调用之后缓冲还在。
- 官方写：不定长返回原则上不必改 EVM，例如先调一次只算长度。这些办法至少在若干场合很贵。看见能拆成两次调用，不是已经是本页。
- 官方写：通用转发合约不知道被调会吐多长，没法先定输出区。看见本页，不是转发产品已经上线。
- 官方写：本页让 140 那次「故意回滚也能带数据」好用得多：调用已经报失败之后，仍可再取失败数据，即使当初预留的常规输出区不够大。看见能再取，不是已经是 140，也不是输出区已经自动够大。
- 官方写：每个新调用帧的缓冲一开始是空的。执行任何类调用时先清空。类调用跑完，把完整返回数据或失败数据放进**调用方**的缓冲。看见本帧缓冲，不是已经是被调那一帧的内存。
- 官方写：创建类指令成功时视为空缓冲，失败时放失败数据。类调用没真正开出新帧（例如转账金额不够，或被调不存在）时，缓冲为空。看见空，不是已经成功返回。
- 官方写：从缓冲里读，越出长度就失败；从末尾读零字节可以，从末尾再往外一字节读零字节会异常。看见能读尺寸，不是已经能随便越界读。
- 官方写：资源已经在被调的内存里付过。实现可以留下被调整份内存，也可以只拷返回段。看见实现选型，不是协议已经规定必须留整份内存。
- 官方写：除了新加两条指令，向后完全兼容。看见本页，不是旧字节码行为已经变了。
- 规范**没有**把返回数据缓冲写成已经是内存，也没有把本页写成已经是 calldata 或已经用两次调用先问长度，也没有把能再取失败数据写成已经是 140，也没有把缓冲写成下一次类调用之后还在。

返回数据缓冲、内存 / 预留输出区、calldata / 两次调用、已经是 140，是四件事。

## 2. 直觉（ELI15）

柜台喊完一声，回音先停在传声筒里，不是已经写在你的草稿纸上。  
传声筒很像进门时那支话筒，不是同一支。  
下一声柜台一喊，旧回音就被盖掉。  
能把「失败时捎的字条」再抄一遍，不是失败语义已经齐了。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 返回数据缓冲 | 类调用之后、调用方那份虚拟缓冲 | 已经是内存；已经是 CALL 预留输出区 |
| 下一次类调用 | 先清空再覆盖 | 旧返回还在 |
| 两次调用先问长度 | 不改 EVM 也能做、更贵 | 已经是本页 |
| 211 | 缓冲 + 读尺寸 / 再拷 | 已经是 140；已经是通用转发产品 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气返回数据在管什么」。

1. 看见返回数据缓冲。规范：调用后再拷进内存。不是已经在内存里。
2. 看见很像 calldata。规范：下一次类调用会覆盖。不是已经是 calldata。
3. 看见能拆成两次调用先问长度。规范：更贵。不是已经是本页。
4. 看见能再取失败数据。规范：让 140 更好用。不是已经是 140。
5. 看见创建成功。规范：成功时视为空缓冲。不是已经返回了新地址字节。
6. 有人把这听成不变量 177。那是回滚留不留气。本页是返回缓冲。
7. 有人把这听成不变量 216。那是内存拷到内存。本页是从返回缓冲拷。
8. 有人把这听成不变量 217。那是用返回数据长度凑零。本页是缓冲本身。
9. 有人把这听成不变量 3 / CVE-2021-39137。那是实现把返回缓冲和内存别名错了。本页是协议对象。
10. 有人把操作码号、气价公式或分叉块号抄进不确定。规范：数字是尺子，不是产品常量。

「211 = 已经是内存 / 211 = 已经是 calldata / 能再取失败数据 = 已经是 140 / 缓冲 = 下一次调用后还在」是假学习。

## 5. 五层

| 层 | 本页 |

| 密码学 | 无新原语 |
| 协议 | 必须点名问的是返回缓冲、内存 / 预留输出区、calldata / 两次调用，还是已经是 140 |

**推断：** 产品句若只写「终于能返回不定长了」，读者会把预留输出区听成已经是缓冲，或把能再取失败数据听成 140 已经齐。  
**建议：** 第一版可以不另开返回缓冲。若对照，必须分开返回缓冲、内存 / 预留输出区、calldata / 两次调用、已经是 140。可以跳过「看见返回数据缓冲就已经是内存」。232 returndata buffer vs memory bundled unbundling 完成（1386 item 1 / 1387 item 2 / 1388 item 3）；精读 [`worked-example-rdata-notmem-vs-bundled.md`](worked-example-rdata-notmem-vs-bundled.md)（不变量 1386 item 1）、[`worked-example-rdata-notcalld-vs-bundled.md`](worked-example-rdata-notcalld-vs-bundled.md)（不变量 1387 item 2）、[`worked-example-rdata-not140-vs-bundled.md`](worked-example-rdata-not140-vs-bundled.md)（不变量 1388 item 3）。不要发明「看见 211 就已经是内存」。不要抄操作码号。不要写怎样做通用转发或怎样在失败后再抽超长回滚数据。

## 6. 和另外几句不是同一句

1. **回滚留气 ≠ 烧光剩余气**（不变量 177）：140 是失败怎么停。本页是失败数据放哪、怎么再取。
2. **内存拷 ≠ 已是身份预编译**（不变量 216）：5656 是内存到内存。本页是从返回缓冲拷。
3. **压零 ≠ 已是带立即数的压 0**（不变量 217）：3855 举过返回数据长度凑零。本页是缓冲本身。
4. **原生移位 ≠ 已用算术拼**（不变量 231）：145 是移位。本页是返回数据。

不要抄操作码号、气价公式、分叉块号。不要写怎样做通用转发、怎样在失败后再抽超长回滚数据、怎样把缓冲和内存叠成同一块后备。不编博物馆页。不另写 19 节。不转规范代码。140 回滚语义、calldata、内存拷、Geth 返回数据别名是另一对象。别名精读：[`../failure-museum/cve-2021-39137.md`](../failure-museum/cve-2021-39137.md)（不变量 3）。

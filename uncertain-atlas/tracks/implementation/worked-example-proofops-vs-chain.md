# 例：看见 ProofOps.ops 是多条证明不是已经串上了；看见各条 type 可以不同不是已经是同一棵树；看见最后一条的根才该对上待验根不是已经对了中间某一条

**层次**：实现 / ProofOps 链。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [ABCI++ Methods](https://github.com/cometbft/cometbft/blob/main/spec/abci/abci++_methods.md) Data Types ProofOps。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行、L4.5。本页是「ProofOps.ops 是多条证明不是已经串上了 / 各条 type 可以不同不是已经是同一棵树 / 最后一条的根才该对上待验根不是已经对了中间某一条」，不是 Query 回了 Proof 就已经对上 AppHash，也不是一层 ProofOp 的根就已经是下一层要验的值。不要另写怎样写 ProofOps 链。

## 官方三件事

规范把 `ProofOps.ops` 是多条**成链**的默克尔证明、各条可以是**不同类型**、以及**最后一条**的默克尔根才该等于正在核对的最终根，写成三件独立的实现事，不是「看见 `ops` 有多条就已经串上了、已经是同一棵树、已经对上了」一件事：

1. **看见 `ProofOps.ops` 是多条证明 / 看见条数在 不是已经串上了，也不是已经交差。**  
   官方写：`ops` 是一串成链的默克尔证明，可能类型不同。看见有多条，不是已经按顺序接上。看见链在，不是已经能验完。看见能装多条，不是已经交差。
2. **看见各条的 `type` 可以不同 / 看见类型名对上 不是已经是同一棵树，也不是已经是同一种编码。**  
   官方写：可能是不同类型的证明。`ProofOp.type` 是默克尔证明的类型**以及它怎样编码**。看见两条都填了 `type`，不是已经是同一棵树。看见名字一样，不是已经同一套编码。看见能混装，不是已经能互相验。
3. **看见最后一条的根才该等于待验根 / 看见中间某条的根对上 不是已经是对上了，也不是已经能停。**  
   官方写：一条 op 的默克尔根，是下一条 op 里正在被证明的值。最后一条 op 的默克尔根，才该等于正在核对的最终根哈希。看见中间某条的根对上，不是已经整链对上。看见前几条全绿，不是已经能停。看见最后一条没验，不是已经交差。

怎样编 `ProofOps` 链、怎样种多层树、怎样挑 `type` 是规范里的做法，本页不抄。Query 回了 Proof 就已经对上 AppHash 是不变量 325，本页不抄。

## 官方为什么这样拆

- **`ProofOps.ops` 是多条证明 ≠ 已经串上了：** 官方把「列表里有几条」和「这几条已经按前一条的根接上下一条」分开。
- **各条的 `type` 可以不同 ≠ 已经是同一棵树：** 官方把「可能不同类型 / 不同编码」和「同一棵树同一套编码」分开。
- **最后一条的根才该对上待验根 ≠ 已经对了中间某一条：** 官方把「某一条对了」和「整条链的锚对了」分开。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| ProofOps.ops 是多条证明 | 不是已经串上了 | 不是 Query 回了 Proof 就已经对上 AppHash（325） |
| 各条的 type 可以不同 | 不是已经是同一棵树 | 不是 ProofOp.key 就已经是 Query 回包键（390）；不是看见写了自描述 type（405） |
| 最后一条的根才该对上待验根 | 不是已经对了中间某一条 | 不是一层 ProofOp 的根就已经是下一层要验的值、也不是已经对上最终 AppHash（325） |
| 本页不涉及 | — | 一条 op 里的 key 不是 Query 回包键（390） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「看见 ProofOps.ops 有多条就已经串上了、已经是同一棵树、已经对上了」，必须分开 ProofOps.ops 是多条证明是不是已经串上了、各条 type 可以不同是不是已经是同一棵树、最后一条的根才该对上待验根是不是已经对了中间某一条。可以跳过「看见 ProofOps.ops 有多条就已经串上了」。不要另写怎样写 ProofOps 链。

## 本页不抄

- 怎样编 ProofOps 链、怎样种多层树、怎样挑 type。
- Query 回了 Proof 就已经对上 AppHash。那是不变量 325。
- 一层 ProofOp 的根就已经是下一层要验的值、就已经对上最终 AppHash。那是不变量 325。
- ProofOp.key 就已经是 Query 回包键、ProofOp.data 就已经是 proof_ops。那是不变量 390。
- 看见写了自描述 type 就已经是 ProofOp 类型。那是不变量 405。

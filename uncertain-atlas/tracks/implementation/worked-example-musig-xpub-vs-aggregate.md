# 例：看见 MuSig2 聚合钥不是已经是扩展公钥；看见合成扩展公钥不是已经能硬化派生；看见派生出的子钥不是已经能不带微调去签

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-328](https://github.com/bitcoin/bips/blob/master/bip-0328.mediawiki)（Complete, Applications, Informational）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「聚合钥不是已经是扩展公钥 / 合成扩展公钥不是已经能硬化派生」，不是扩展公钥已经能花，也不是派生钥已经是输出钥。不要另写怎样算派生微调。

## 官方三件事

规范把 MuSig2 聚合钥上的派生写成三件独立的结构事，不是「看见聚合钥就已经能当普通扩展公钥用」一件事：

1. **看见 MuSig2 聚合钥 / 看见一把普通公钥 不是已经是扩展公钥，也不是已经能按 32 那种树往下长。**  
   官方写：本页指定怎样从 BIP-327 的明文聚合公钥造出一份合成扩展公钥，以及这份钥该怎样派生。聚合公钥看起来像普通公钥，所以可以这样用。看见聚合钥，不是已经带了深度、子号和链码。看见能当普通公钥用，不是已经是 32 那种扩展公钥。
2. **看见合成扩展公钥 / 看见没有聚合私钥 不是已经能做硬化派生，也不是已经能从许多扩展公钥再聚合。**  
   官方写：没有聚合私钥，所以只能从聚合公钥做未硬化派生。官方另写：更省事的做法是从一份扩展公钥派生，而不是每次先从许多扩展公钥派生再聚合。看见合成扩展公钥，不是已经能硬化。看见少存了几份扩展公钥，不是已经是脚本多签那种各自派生再拼。
3. **看见派生出的子钥 / 看见一次签名会话 不是已经能不带微调去签，也不是已经按 x-only 微调。**  
   官方写：签名时，所有签名人都必须算出 BIP-32 派生用到的那些微调。每一步用的是派生算法里算出的那一份微调，并且以明文微调模式放进会话。看见子钥，不是已经能直接当聚合钥去签。看见写了微调，不是已经是 x-only 那种微调。

固定链码取值、测试向量、例钥、派生公式是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **聚合钥 ≠ 已经是扩展公钥：** 官方把合成扩展公钥写成另造深度、子号和链码。
- **合成扩展公钥 ≠ 已经能硬化：** 官方把「没有聚合私钥」写成只能未硬化。
- **子钥 ≠ 已经能不带微调去签：** 官方把每一步派生微调写成签名会话里必须带上的对象。

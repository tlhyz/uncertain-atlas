# 例：看见从提案拿掉 tx 不是已经从内存池删掉；看见往提案加了一笔新的不是已经进了内存池；看见把 t1 改成 t2 不是已经还能按 t1 查到

## 官方三件事

规范把从提案拿掉、往提案加新的、改成另一笔写成三件独立的实现事，不是「看见本块不提就已经从池里删掉、已经进了内存池、已经还能按原哈希查到」一件事：

1. **看见从提案拿掉 tx / 看见本块不提 不是已经从内存池删掉，也不是已经永远不提。**  
   官方写：应用若认为这笔不该进本块，就不要写进 `PrepareProposalResponse.txs`。这**不会**把它从内存池删掉，只是推迟。看见本块不提，不是已经出池。看见拿掉了，不是已经永远不提。看见回包没有它，不是已经交差。
2. **看见往提案加了一笔新的 / 看见回包里有它 不是已经进了内存池，也不是已经过了 CheckTx。**  
   官方写：应用若要加一笔新的，就写进 `PrepareProposalResponse.txs`。引擎**不会**把它加进内存池。看见回包里有它，不是已经进池。看见能提，不是已经过了 CheckTx。看见加进去了，不是已经交差。
3. **看见把 t1 改成 t2 / 看见 t1 没进块 不是已经还能按 t1 查到，也不是已经有人知道 t2 来自 t1。**  
   官方写：拿掉再加可能丢掉可追踪性。客户端去查 t1，会发现 t1 没进已提交块（若再检又把它踢出池），误以为没上块。t2 会在已提交块里，但除非应用自己记，没有组件知道 t2 来自 t1。看见 t1 没进块，不是已经还能按 t1 查到。看见 t2 进了块，不是已经有人知道来源。看见改了，不是已经交差。

怎样改 Prepare 列表、怎样记派生哈希、怎样再检踢池是规范里的做法，本页不抄。提案收了就已经从池里删掉是不变量 301，本页不抄。

## 官方为什么这样拆

- **从提案拿掉 tx ≠ 已经从内存池删掉：** 官方把本块不提和出池分开。
- **往提案加了一笔新的 ≠ 已经进了内存池：** 官方把回包里有它和进池分开。
- **把 t1 改成 t2 ≠ 已经还能按 t1 查到：** 官方把改列表和可追踪性分开。

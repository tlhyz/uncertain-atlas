## 1. 核心问题

阿比看见文案写「只读调用」或高级语言的 `view`，以为虚拟机已经开了静态帧；或看见这次没转账，以为已经是静态调用；或看见规范编号 214，以为就是回滚那一页，或已经是瞬时店不许写那一句。

官方句（事实）：

- EIP-214：增加一道调用，调用另一个合约（或自己），并在这次调用及其子调用里**不许改状态**。谁要改，就异常，而不是改成。
- 虚拟机多一面 `STATIC` 旗。一开始是关的。子调用会抄这面旗。本页这道指令是例外：它把子执行的旗打开。子调用返回后，旗回到调用前的值。
- 这道指令的行为像普通调用，但不带转账参数，转账按 0。子执行开着静态旗。
- 静态旗打开时，创建、写日志、写持久存储、自毁，以及带非零转账的普通调用，都异常。
- 官方例外：`CALLCODE` **不算**改状态，即使带了非零值。
- 官方动机：普通调用之后，除非你认识被调合约，否则不能对账户状态作任何假设。静态调用之后，可以假定所有账户状态与调用前相同。
- 规范**没有**把高级语言的只读函数写成已经是这面旗，也没有把「没转账」写成已经静态，也没有把本页写成回滚或瞬时店禁写。

静态帧、高级语言只读、没转账的普通调用，是三件事。

## 2. 直觉（ELI15）

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 静态帧 | 这面旗开着的这一层执行 | 已经是高级语言的只读函数 |
| 没转账的普通调用 | 转账为 0 的 CALL | 已经打开静态旗 |
| 静态里改状态 | 异常，不改成 | 已经改成；已经是回滚那一页 |
| CALLCODE 带非零值 | 官方不算改状态 | 已经是普通 CALL 带值；已经可以当产品缺口去用 |

---

## 4. 最小案例

一条 Ethereum 要对齐「这一口气只读卡在哪」。

1. 走本页这道调用。规范：子执行开静态旗。不是已经是高级语言 `view`。
2. 普通调用只是没转账。规范：旗可以仍是关的。不是已经静态。
3. 静态帧里写存储 / 写日志 / 创建 / 自毁 / 带值的普通调用。规范：异常。不是已经改成。
4. `CALLCODE` 带非零值。规范：不算改状态。不是已经和普通 CALL 带值同一盏灯。
5. 子调用返回。规范：旗回到调用前。不是外层已经永远只读。
6. 有人把这听成 140（不变量 177）。那是失败要不要留下剩余气。本页是这面旗开不开。
7. 有人把这听成瞬时店禁写（不变量 159）。那是 TSTORE 在静态帧里必须异常。本页是旗本身。

「view = 已经静态 / 没转账 = 已经只读 / 214 = 140」是假学习。

## 5. 五层

| 层 | 本页 |

| 密码学 | 无新原语 |
| 协议 | 必须点名问的是静态帧、高级语言只读，还是没转账的普通调用 |

| 部署 | 网络升级；旧合约不被这道新指令改语义，除非被它调到 |
| 经济 | 不把「只读」写成已经便宜或已经不能重入 |

**推断：** 产品句若只写「支持只读调用」，读者会把编译器的 `view` 听成已经开了静态旗，或把没转账听成已经只读。  
**建议：** 第一版必须分开静态帧和高级语言只读。可以跳过「看见 view 就已经开了静态旗」。178 STATICCALL flag vs view bundled unbundling 完成（1383 item 1 / 1384 item 2 / 1385 item 3）；精读 [`worked-example-stcall-notview-vs-bundled.md`](worked-example-stcall-notview-vs-bundled.md)（不变量 1383 item 1）、[`worked-example-stcall-notxfer-vs-bundled.md`](worked-example-stcall-notxfer-vs-bundled.md)（不变量 1384 item 2）、[`worked-example-stcall-notchg-vs-bundled.md`](worked-example-stcall-notchg-vs-bundled.md)（不变量 1385 item 3）。不要发明「没转账 = 已经不能改状态」。不要抄操作码号。不要把 214 写成 140。不要把 CALLCODE 例外写成产品功能。

## 6. 和另外几句不是同一句

1. **回滚 ≠ 烧光**（不变量 177）：失败怎么停。本页是这面旗开不开。
2. **瞬时 ≠ 持久**（不变量 159）：TSTORE 在静态帧里必须异常。本页是旗本身，不是那份店。
3. **自毁 ≠ 已删**（不变量 160）：后来只转余额。本页是静态帧里自毁会异常。
4. **有代码 ≠ 能发**（不变量 162）：发送者像不像 EOA。本页不是发送者有没有代码。

不要抄操作码号 / 参数个数 / 例调用。不要写怎样把会改状态的被调包进静态帧，或怎样靠 CALLCODE 带值。不编博物馆页。不另写 19 节。高级语言 `view` / `pure`、回滚原因编码、瞬时店禁写细则是另一对象。

## 精密检查

**禁止假学习：** 「view = 已经静态。」「没转账 = 已经只读。」「静态里写了 = 已经改成。」「214 = 140。」「CALLCODE 带值 = 已经算改状态，可以当产品功能。」  
**边界：** 不抄操作码号。不另写 19 节。不写怎样绕静态帧。回滚见 **C181**。瞬时店见 **C163**。

## 1. 核心问题

阿比看见各家客户端的分叉配置 RPC 对上了，以为已经过多客户端同根；或看见 current / next / last 三份对象，以为共识已经改了；或看见 RPC 绿了，以为对等节点没有撒谎；或看见规范编号 7910，以为就是 Engine API 已经改头，或已经是只改 blob 的专用分叉，或已经是线协议历史窗。

官方句（事实）：

- EIP-7910：加一条 RPC，报告本节点当前、下一份、以及已知最后一份分叉配置。
- 动机：历史上有客户端没配好即将到来的硬分叉，过了分叉边界就掉出共识。官方点名一次测试网激活：多家客户端存款合约配置不对，错误链被 justified。
- 本页**不改**以前的行为。它是运维和监控用来在分叉前核对配置的接口。
- current / next / last 三份。若客户端没配未来分叉，next 和 last 可以为空。下一份就是最后一份时，两份相同。
- 必须报本页列全的字段。必须跟本节点给出的最新头对齐；若缓存，过了分叉边界必须清掉。
- 可以走 Engine API 再暴露一次。不该原样回未处理的配置文件。
- 只改 blob 参数的专用分叉，在本页里当成一份新分叉：以父分叉为底，只改 blob 日程那一项。看见本页，不是已经是那套专用分叉机制。
- 官方不用配置哈希做快对：工具可以按键排序再比 JSON，哈希多余。
- 安全段：配置可能漏运维细节，官方建议只给可信接口。客户端可以谎报。对等节点或监控可以对照规范或其他节点。可以缓存并限速。
- 规范**没有**把 RPC 对上写成已经过多客户端同根，也没有把三份对象写成已经改了共识，也没有把 RPC 绿写成对等节点没有撒谎，也没有把本页写成不变量 149、209 或 207。

配置对上看起来齐、过了分叉仍同根，是两件事。

## 2. 直觉（ELI15）

出发前大家把旅行清单对一遍。  
清单对上了，不是已经到了同一座城。  
有人可以把清单抄错了还念给你听。  
换了一张「只改行李额」的清单，不是已经改了整部交通法。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 分叉配置 RPC | 本节点报告当前 / 下一份 / 最后一份配置 | 已经过多客户端同根 |
| current / next / last | 三份配置对象 | 已经改了共识 |
| RPC 绿 | 接口回了对象 | 对等节点没有撒谎 |
| 7910 | 分叉前核对配置的 RPC | Engine API 已经改头；专用分叉机制；线协议历史窗 |

---

## 4. 最小案例

一条 Ethereum 要对齐「这一口气配置在哪一层」。

1. 看见各家 RPC 对上了。规范：运维可以在分叉前核对。不是已经过多客户端同根。
2. 看见 current / next / last。规范：三份配置对象。不是已经改了共识。
3. 看见 RPC 绿。规范：官方写客户端可以谎报。不是对等节点已经诚实。
4. 看见没有配置哈希。规范：官方觉得哈希多余。不是已经不能对。
5. 有人把这听成不变量 149。那是处理完一块是不是已经改头。本页是分叉前配置核对。
6. 有人把这听成不变量 209。那是只改 blob 参数的专用分叉机制。本页只是怎么把那种分叉报进配置对象。
7. 有人把这听成不变量 207。那是线协议宣布历史窗。本页是本节点 RPC。

「看见 eth_config 对上 = 已经同根 / 三份对象 = 共识已改 / RPC 绿 = 没人撒谎 / 7910 = 149」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 官方不用配置哈希；能比 JSON 不是已经验过签 |
| 协议 | 必须点名问的是配置核对、共识已改，还是已经同根 |
| 实现 | 过了分叉边界必须清缓存；原样回配置文件不是本页 |
| 部署 | 官方建议只给可信接口；不把示例配置抄进不确定 |
| 经济 | 不把「对上了」写成已经更安全 |

**推断：** 产品句若只写「各家配置对上了」，读者会把分叉前核对听成已经过了分叉，或把 RPC 绿听成对等节点没有撒谎。  
**建议：** 第一版可以不提供这条 RPC。若提供，必须分开配置核对、共识已改、已经同根。不要发明「看见 7910 就已经多客户端同根」。不要抄激活时间 / 地址。不要写怎样谎报配置。

## 6. 和另外几句不是同一句

1. **处理完一块 ≠ 已经改头**（不变量 149）：Engine API 绿不是已经改规范头。本页是分叉前配置核对。
2. **专用分叉 ≠ 已改执行**（不变量 209）：只改 blob 参数的机制。本页只是怎么把那种分叉报进对象。
3. **对等窗 ≠ 已改共识**（不变量 207）：线协议历史窗。本页是本节点 RPC。
4. **通道尺寸 ≠ 拼块已齐**（不变量 96）：Engine API 尺寸。本页不改通道。

不要抄激活时间、链号、分叉哈希、预编译地址、示例配置。不要写怎样谎报配置，或怎样跳过缓存失效。不编博物馆页。不另写 19 节。不转示例 JSON。Engine API 改头、专用分叉机制、线协议历史窗是另一对象。改头精读：[`../finality/worked-example-processed-vs-forkchoice.md`](../finality/worked-example-processed-vs-forkchoice.md)（不变量 149）。

# 例：看见创世 app_state 不是已经验过应用状态；看见节点起来不是已经过了 genesis_time；看见创世 validators 空不是已经没有集合

**层次**：实现 / 创世对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [Genesis](https://github.com/cometbft/cometbft/blob/main/spec/core/genesis.md)。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)、[L9.3](../../courses/level-09-systems/L09-M03-storage.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行。本页是「创世文件里的应用段不是已经验过 / 进程起来不是已经开出块 / 空名单不是已经没有集合」，不是快照已经从创世重放，也不是本头 AppHash 已经交差。不要另写怎样填创世字段或怎样调 InitChain。

## 官方三件事

规范把创世文件写成三件独立的起步事，不是「看见创世文件就已经验过应用、已经开链」一件事：

1. **看见创世里的 app_state / 看见引擎收下这份创世 不是已经验过应用状态。**  
   官方写：应用往创世的 `app_state` 填自己要的字段。CometBFT 验不了这一段，因为它不知道应用状态由什么组成。看见创世文件齐了，不是应用段已经验过。看见引擎收下了，不是已经懂余额。看见有 `app_state`，不是已经交差。
2. **看见节点已经启动 / 看见进程起来了 不是已经过了 genesis_time 开始出块。**  
   官方写：`genesis_time` 是链开始或将要开始的时间。节点若在这个时间之前起来，会空坐到指定时刻。看见进程起来了，不是已经开出块。看见握手过了，不是已经过了创世时间。看见本机钟到了，不是邻居已经一起动。
3. **看见创世 validators 空 / 看见 app_hash 空 不是已经没有集合，也不是已经没有根。**  
   官方写：`validators` 可以空，若应用在 `InitChain` 给出集合。`app_hash` 起步不必填，应用也可经 `InitChain` 给出。看见名单空，不是已经没有验证者。看见根空，不是已经没有状态根。看见 `InitChain` 被叫了，不是已经过了四门。

`time_iota_ms`、曲线名单、字段表是规范里的取值或过期项，本页不抄。

## 官方为什么这样拆

- **app_state ≠ 已经验过：** 官方把引擎不认识应用状态，和文件已经收下分开。
- **进程起来 ≠ 已经过了 genesis_time：** 官方把空坐等到指定时刻，和节点已经启动分开。
- **空名单 / 空根 ≠ 已经没有：** 官方把起步可以空，和 `InitChain` 再给分开。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「创世已经齐」，必须分开应用段是不是已经验过、进程起来是不是已经开出块、空名单是不是已经没有集合。可以跳过「看见创世文件就已经验过应用」。不要另写怎样填创世字段或怎样调 InitChain。

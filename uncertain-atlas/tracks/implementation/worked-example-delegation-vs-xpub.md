# 例：看见共享了扩展公钥不是已经是链码委托；看见委托方那把非扩展钥不是已经能推出整棵钱包；看见这一输入的微调不是已经是盲签

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-89](https://github.com/bitcoin/bips/blob/master/bip-0089.mediawiki)（Deployed, Applications, Specification）。依赖 BIP-32、BIP-340、BIP-341。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「共享了扩展公钥不是已经是链码委托 / 委托方那把非扩展钥不是已经能推出整棵钱包」，不是扩展公钥已经能花，也不是聚合钥已经是扩展公钥。不要另写怎样做委托微调或盲签。

## 官方三件事

规范把链码委托写成三件独立的结构事，不是「看见共享了扩展公钥就已经对托管方藏住余额」一件事：

1. **看见共享了扩展公钥 / 看见共享了描述符 不是已经是本页，也不是已经对共同签名人藏住余额。**  
   官方写：多签里把扩展公钥或描述符分给各方，所有人都能扫链、推断对方在干什么。本页让没有特权的一方只拿一把非扩展钥对，并且只在要签的时候拿到这一笔最少的数据。官方另写：本页委托的对象是链码，不是签名权。交出链码的人仍能共签，只是看不见整棵派生、余额，也看不见别的花费组合。看见共享了扩展公钥，不是已经藏住余额。看见能共签，不是已经交出了签名权。
2. **看见委托方那把非扩展钥对 不是已经是扩展公钥，也不是已经能推出整棵钱包。**  
   官方写：委托方必须自己造一把普通钥对，把公钥交给对方。委托方不得留下、也不得被发给这把钥的链码。指定的受托方算出并留下绑在这把公钥上的链码，由此形成一份扩展公钥，而且这份扩展公钥不得再透露给委托方。从这份扩展钥往下长，只能走未硬化派生。委托方拿到微调后，只能为这一路径验和签，认不出别的路径上的钥。看见一把普通公钥，不是已经带了链码。看见受托方有扩展公钥，不是委托方已经看见整棵树。
3. **看见这一输入的微调 / 看见一次签名会话 不是已经看见整棵派生，也不是已经是盲签，也不是已经核过找零金额。**  
   官方写：受托方在签名时按输入给出标量微调。找零输出的微调，只有委托方想算出自己花了多少时才需要。非盲模式里，委托方只看见自己要签的那些子钥和交易，看不见更宽的地址空间。盲模式里，委托方连消息和子钥都看不见，只看见一个被盲过的挑战。两种模式产出的都是合法的 340 签。官方另写：这份明文盲签协议并不是并发安全的；签名器不得并行开多场盲签，也不得把状态交错着用。怎样把微调包送过去，不在本页范围。看见这一输入的微调，不是已经能扫整棵钱包。看见能签，不是已经是盲签。看见签过了，不是已经核过找零。

微调算法、验输入/找零步骤、盲 nonce 配方、曲线常数、测试向量是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **共享扩展公钥 ≠ 已经是链码委托：** 官方把「分扩展公钥就能扫链」和「只委托链码、不交签名权」写成两件相反的事。
- **非扩展钥对 ≠ 已经能推出整棵钱包：** 官方把委托方不得持有链码、受托方的扩展公钥不得回传写成两道门。
- **这一输入的微调 ≠ 已经是盲签：** 官方把非盲只看见本笔、盲签看不见消息、找零微调另算写成三档。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果让一方替另一方持链码，必须分开交出的是链码不是签名权、委托方看不见整棵树、这一笔微调不是盲签。可以跳过「看见共享了扩展公钥就已经对托管方藏住余额」。若对照，必须分开委托对象、非扩展钥、本笔微调。不要另写怎样做委托微调或盲签。

# 例：看见旧 PSBT 栏不是已经能装 MuSig2；看见聚合钥栏不是已经是输出钥；看见参与者钥不是已经能出部分签

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-373](https://github.com/bitcoin/bips/blob/master/bip-0373.mediawiki)（Complete, Applications, Specification）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「旧栏不是已经能装 MuSig2 / 聚合钥栏不是已经是输出钥」，不是旧 PSBT 栏已经能装 Taproot，也不是聚合钥已经是扩展公钥。不要另写怎样造 nonce 或部分签。

## 官方三件事

规范把 MuSig2 工作包栏写成三件独立的结构事，不是「看见 Taproot 工作包栏就已经能签 MuSig2」一件事：

1. **看见旧 PSBT 栏 / 看见 371 那套 Taproot 栏 不是已经能装 MuSig2，也不是已经能走完多轮。**  
   官方写：现有工作包栏没法支持 MuSig2，因为它引入了新概念，还要多几轮通信。所以必须另定新栏，才能装出合法 MuSig2 签所需的信息。看见 174 那套栏，不是已经能装。看见 371 补了 Taproot 栏，不是已经是本页。
2. **看见聚合钥栏 / 看见压缩聚合钥 不是已经是 Taproot 输出钥，也不是已经是内部钥，也不是已经是 x-only。**  
   官方写：这份聚合钥不一定以 x-only 出现在输出钥、内部钥或脚本里。它也可以是派生出那些钥的父钥。官方另写：32 那种扩展公钥要带偶奇字节，指纹还要用到纵坐标，所以本页聚合钥必须用压缩公钥，不能只用 x-only。看见栏里有聚合钥，不是已经对上输出脚本里那把。看见压缩，不是已经是 371 那种 x-only。
3. **看见参与者钥 / 看见 nonce 栏 不是已经有部分签，也不是已经是 BIP-340 那张签。**  
   官方写：nonce 栏和部分签栏里的参与者公钥必须是输出钥，或出现在脚本里。它不是内部钥，也不是派生出它的那把聚合钥。官方还写：没有 nonce 栏才去补 nonce；nonce 齐了才出部分签；部分签齐了，最后一位才可能聚成能放进 Taproot 签栏的 BIP-340 签。看见参与者名单，不是已经有 nonce。看见 nonce，不是已经有部分签。看见部分签，不是已经是 371 那种 Taproot 签。

类型号、字节宽度、测试向量、例钥、算法名单是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **旧栏 ≠ 已经能装 MuSig2：** 官方把新概念和多轮通信写成现有栏装不下。
- **聚合钥栏 ≠ 已经是输出钥：** 官方把这份钥写成可能只是父钥，而且必须压缩。
- **参与者钥 ≠ 已经有部分签：** 官方把名单、nonce、部分签、最后那张 BIP-340 签写成四步。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出 MuSig2 工作包，必须分开旧栏装不下、聚合钥不一定是输出钥、名单不是已经有部分签。可以跳过「看见 Taproot 工作包栏就已经能签 MuSig2」。若对照，必须分开本页新栏和 371 那种 Taproot 栏。不要另写怎样造 nonce 或部分签。

- 怎样造 nonce、怎样聚合 nonce、怎样出部分签、怎样聚成 BIP-340 签。

# 例：看见脚本各走各的路径不是已经是多签该有的树；看见路径里的脚本类型不是已经必要；看见主种子不是已经够找回

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-87](https://github.com/bitcoin/bips/blob/master/bip-0087.mediawiki)（Complete, Applications, Specification）。  
**对应课文**：[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「脚本各走各的路径不是已经是多签该有的树 / 路径里的脚本类型不是已经必要」，不是 48 那种脚本类型层已经是账户层，也不是钱包策略已经是一条描述符。不要另写怎样加账户号。

## 官方三件事

规范把多签派生层次写成三件独立的结构事，不是「看见多签就已经该按脚本拆路径」一件事：

1. **看见 44 / 49 / 84 那种脚本各走各的路径 / 看见 45 那种只认一种脚本 不是已经是多签该有的树，也不是已经不必再带描述符。**  
   官方写：单签按脚本拆路径，备份时只靠私钥信息就能找回。多签还要所有共同签名人的公钥。有了描述符之后，这种按脚本拆路径对多签是多余的。官方另写：45 那种树不必要地只认一种脚本；在送给协调人之前先按公钥排序再定路径，也是多余的，因为描述符自己能定顺序或按字典序排。看见单签那套拆法，不是已经是本页。看见 45，不是已经是本页。
2. **看见路径里的脚本类型 / 看见 48 那种多插一层 不是已经必要，也不是已经是本页。**  
   官方写：不该把钥和脚本混在同一层。钱包先造与脚本类型无关的扩展钥，描述符再告诉钱包该看哪一种多签输出。官方另写：48 把脚本类型插进路径是不必要的，因为描述符已经定了脚本；那样做仍要维护一份多余的脚本类型名单。看见路径里写了脚本类型，不是已经是本页。看见 48 那一层，不是已经不必再带描述符。
3. **看见这份不按脚本拆的树 / 看见主种子 不是已经给单签用，也不是已经够找回。**  
   官方写：这份不按脚本拆的层次只给多签。单签仍可靠主私钥信息找回；若单签也用本页，用户就得另备描述符，或让钱包对每个账户试遍脚本类型。官方另写：按本页做的是描述符钱包，共同签名人必须同时备份私钥信息和描述符，以后才能正确找回。看见主种子，不是已经够找回本页钱包。看见本页树，不是已经能当单签默认树。

用途号、间隔上限、例路径、例描述符是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **脚本各走各的路径 ≠ 已经是多签该有的树：** 官方把单签那套拆法和 45 那种只认一种脚本写成对多签多余。
- **路径里的脚本类型 ≠ 已经必要：** 官方把脚本交给描述符，不让它和钥混在同一层。
- **主种子 ≠ 已经够找回：** 官方把本页写成必须同时备描述符，且只给多签。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果导出多签派生，必须分开脚本不进路径、描述符定脚本、主种子不够找回。可以跳过「看见多签就已经该按脚本拆路径」。若对照，必须分开本页树和 48 那种脚本类型层。不要另写怎样加账户号。

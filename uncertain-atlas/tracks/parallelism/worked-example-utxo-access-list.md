## 1. 核心问题

阿比看见「也是声明依赖」或看见「UTXO 所以能并行」，以为和 Solana 账户锁是同一把尺子，或以为谓词过了脚本已经跑完，或以为只读碰到同一份对象就必须串行，或以为并行了所以不再需要 canonical 序。

官方句（事实）：

- 规范 Transaction Validity：一笔交易进场按这个顺序：预检 → **谓词验证** → **脚本执行** → 后检。四步不是同一扇门。
- 访问集：下面的合法性按**顺序**验证副作用（状态改动）。构造上，**写访问集不相交**的交易可以并行验证，即使**只读访问集重叠**。写访问集相交的交易必须按拓扑序验证并放进块。
- 只读 / 写毁访问集里的 UTXO 和合约必须已经存在。对同一状态元素 ID，写创建必须先于写毁。
- 写毁集按输入类型点名：`InputType.Coin` / `InputType.Contract` 用 UTXO ID `(txId, outputIndex)`；`InputType.Message` 用 `messageID`。写创建集：新合约用 `contractID`，以及新造出的 UTXO ID。出块者对合约输入/输出用 `contractID`，不是那一对 `(txId, outputIndex)`。
- 谓词：每个 `Coin` / `Message` 输入若 `predicateLength > 0`，必须先验它的谓词。`predicateLength == 0` 才走见证签。谓词过了不是脚本已经执行。
- 脚本：`scriptLength == 0` 是简单转余额，规范写不必再检。`scriptLength > 0` 必须执行脚本。官方书：脚本是一次性的，**没有**自己的持久存储；可以调用当作输入的合约。合约有持久存储，本身是交易输入。
- 官方书：Bitcoin 脚本缺持久存储，常被错怪成「UTXO 不能合约」。Fuel 的办法是把**有状态合约当成输入**，再用一次性脚本去调它。这不是已经变成账户模型，也不是已经不需要声明这份合约输入。
- 规范**没有**把并行写成可以没有顺序副作用，也没有把只读重叠写成必须串行，也没有把谓词写成已经跑了脚本。

谓词、脚本、合约输入、只读重叠、写集相交、顺序副作用 L，是不同对象。

## 2. 直觉（ELI15）

先检查钥匙孔上的纸条（谓词）：这张支票你有没有权花。纸条通过，不等于已经进店点菜。  
进店点菜是一次性菜单（脚本）。厨房里那台有抽屉的机器才是合约。  
两桌可以同时看同一本菜单（只读重叠）。两桌不能同时改同一口锅（写集相交）。  
调度员让不相交的桌子并行上菜，菜谱对不对仍按一张总菜单的顺序算。

小朋友看见「UTXO 并行」，以为和账户锁是同一句话，或以为并行了就不用总菜单。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 谓词 | 先验的、无持久存储的花费授权 | 已经跑脚本；已经改合约存储 |
| 脚本 | 一次性程序，可调合约输入 | 自己有抽屉；谓词已经替它跑过 |
| 合约输入 | 有持久存储的 UTXO 输入 | Bitcoin 脚本；账户模型 |
| 只读重叠 | 规范允许并行 | 已经写冲突；必须串行 |
| 写集相交 | 必须拓扑序 | 可以并行；已经不需要 L |
| 顺序副作用 | 合法性按串行状态改动定义 | 并行了所以顺序作废 |
| Solana 账户锁 | 账户主键上的读写锁 | 本页的 UTXO ID / `contractID` |
| STM | 不事先声明写集，提交仍 ≡ L | 本页的访问集先验 |

## 4. 最小案例

两笔 Fuel 交易。

1. A 花一枚硬币，谓词为真。规范：还没到脚本。不是已经改了合约存储。
2. A 的脚本去调一个 AMM 合约输入。官方书：必须先把该合约列进输入，跑完再吐出合约输出。漏列不是「已经有人锁上」。
3. B 只读同一份菜单、写另一枚硬币。规范：只读重叠仍可并行。不是必须跟 A 串行。
4. C 也要写那个 AMM 合约。规范：与 A 写集相交，必须按拓扑序。并行调度不是已经让两笔同时改一口锅。
5. 有人把这听成 Solana：账户列表上的锁。本页主键是 UTXO ID / `contractID`，并且只读重叠被规范单独放开。
6. 有人把这听成 Block-STM：先跑再检测。不变量 122：STM 不要求事先写集。本页访问集在验证前就有。

「UTXO 所以和账户锁是同一句并行」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无谓词时验见证签；有谓词时先验谓词。本页不证伪造 |
| 协议 | 必须点名问的是谓词、脚本、只读重叠、写集相交，还是顺序 L |
| 实现 | 调度器可以并行，合法性仍按串行副作用 |
| 部署 | 排序从哪来（自身 / 房东）是部署事实 |
| 经济 | 合约 UTXO 仍是热点；官网吞吐不是安全证明 |

**推断：** 产品句若只写「UTXO 并行」或「也是声明依赖」，读者会把谓词听成脚本，或把只读重叠听成必须串行，或把并行听成不需要 L。  
**建议：** 不确定第一版不必上整套短槽 + 声明调度。若对照，必须点名访问集主键和并行放开的是读还是写；不要抄核数或官网 TPS。不要写怎样漏列输入去抢跑。

## 6. 和另外几句不是同一句

1. **STM 跑完 ≠ 最终**（不变量 122）：不事先写集，提交仍 ≡ L。本页访问集先验。
2. **owned ≠ 快路径**（不变量 128）：对象所有权决定版本走哪条路。本页是 UTXO / 合约输入。
3. **顺序 ≠ 状态根**（不变量 136）：共识先定序、后揭状态。本页并行的是验证，不是「没有 L」。
4. **批次 ≠ L**（不变量 132）：传播层。本页不是 Quorum Store。
5. **Bitcoin UTXO**（L2.1）：冲突可见，规范没写按访问集并行验证。
6. **eUTXO**（L2.5）：整笔校验；不是本页的只读重叠可并行。引用输入 ≠ 已经花费：[`../state-models/worked-example-refinput-vs-spent.md`](../state-models/worked-example-refinput-vs-spent.md)（不变量 150）。

不要把 `MAX_INPUTS`、气价公式、核数、官网吞吐抄进不确定常量。不要写怎样漏列合约输入。不编博物馆页。不另写 19 节。哪条部署当 rollup 租户、Upgrade / Upload 交易类型，标成另一对象。

## 7. 「不确定」测试句（建议）

```text
谓词验证 ≠ 已经跑脚本
脚本过了 ≠ 合约已经有自己的持久脚本存储
只读访问集重叠 ≠ 写冲突 / 必须串行
写集相交 ≠ 可以并行
并行验证 ≠ 已经不需要顺序副作用 L
UTXO / contractID 访问集 ≠ Solana 账户锁
声明了合约输入 ≠ 已经变成账户模型
```

## 1. 核心问题

阿比看见「多核同时在跑」，以为顺序已经不重要，或者 STM 跑完余额已经最终。

官方句（事实）：

- Aptos：执行是把**已排序的一块交易**应用到账本。输出必须确定：同一初态、同一块，诚实验证者必须得到同一写集。超过三分之二投票权同意该结果之后，块才提交。
- Aptos：动态并行在运行时找冲突。交易投机执行；撞车则后一笔再跑。**提交结果必须仍等于按预设共识顺序执行这块。**
- 论文：每一块的执行必须得到同一确定结果；该结果必须与按预设顺序串行执行一致。引擎**不要求事先知道写集**。核心是执行任务与校验任务的协作调度。
- 论文：区块链按**整块**更新状态，因此可以懒提交整块，而不必每笔单独同步提交。智能合约跑在封装好的 VM 里，因此**不要求 opacity**（不必保证并发中间态对外也像串行）。

没有名单 L，对错没有定义。STM 是算 L 的机器，不是写 L 的机器。

## 2. 直觉（ELI15）

老师已经写好名单：先甲、再乙、再丙。  
三个助教同时批。乙偷看了甲还没改完的卷，对不上就作废重批。  
助教再多，分数必须和「一个人按名单批」完全一样。  
批完交卷，还要校长盖章。助教齐活，不是已经毕业。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| `L` | 共识给出的块内序列 | STM 算出来的顺序 |
| 投机执行 | 可能看见过期版本 | 已提交写集 |
| 校验 | 读到的版本是否等于「串行走到 i」 | 最终性 |
| 提交 | 整块写集对外可见 | 单笔先提交 |
| 投票 | 验证者对执行结果签同意 | STM 线程数 |

**静态并行（对照，事实）：** 事先声明访问集，调度不重叠的交易。声明往往比真实访问宽，不冲突的也会被串起来。  
**动态并行（本页）：** 运行时发现冲突。开发者写普通 Move，不必先列表。

---

## 4. 最小案例

`L = [T0 写 X, T1 读 X 写 Y, T2 只写 Z]`。

1. T2 与前两笔无交，可先跑完。这是性能，不是 T2 排到了 T0 前面。
2. T1 若在 T0 提交前读了旧 X：校验失败，按 L 重做。
3. 最终写集必须 = 先 T0 再 T1 再 T2 的单线程写集。
4. 该写集被超级多数投票之后才进已提交状态。STM 线程都 idle，不是已经最终。

论文还写：某笔校验失败，下标更大的交易只有再校验通过才能提交。后笔「看起来跑完」不是前缀已经齐。

崩溃留下「T0 写了、T1 没写」：半提交。属实现，见 [half-written-state](../../libraries/anti-patterns/half-written-state.md)。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | STM 不提供新的签名假设 |
| 协议 | 提交 ≡ 串行 L；L 来自共识；结果还要被投票 |
| 实现 | 多版本读、协作调度、整块懒提交必须确定 |
| 部署 | 高冲突时回滚吃 CPU；不要把加速比当 SLA |
| 经济 | 吞吐广告不能代替 L 的最终性 |

**推断：** 热共享资源会把动态并行压回近串行，还多付检测税。  
**建议：** 结算第一版先串行 `Apply`。先有 L，再谈要不要 STM。

## 6. 和另外两张地图

| | 声明锁 | 所有权 | Block-STM |
|---|---|---|---|
| 冲突何时可见 | 调度前 | 类型 / 对象图 | 执行后 |
| 没有 L 时 | 不能安全调度 | owned 快路径仍要论证 | **正确性无定义** |
| 程序员 | 列账户 | 对象思维 | 较低 |
| 最坏 | 锁等待 | shared 排队 | 回滚风暴 |

不要把三张糊成「新一代都并行所以更安全」。

---

## 7. 论文里两句容易假学习的事实

1. **不要求事先写集** 不是已经不需要顺序。顺序是正确性定义，写集是实现输入。
2. **不要求 opacity** 不是中间投机状态已经可以给用户看。VM 把不安全行为封在里面；对外可见的仍是整块提交后的串行结果。

不要把论文或官网的加速比、线程数、块时间抄进不确定常量，也不要把它们当安全。

## 8. 「不确定」测试句（建议）

```text
同一 (S, L)：STM 提交写集 = 单线程按 L 的写集
STM 线程 idle ≠ 该块已最终
未声明写集 ≠ 已经不需要 L
某 i 校验失败 ⇒ i 之后不得按旧投机结果提交
```

语料：[C126](../../libraries/adversarial-corpus/README.md)。

## 精密检查

**禁止假学习：** 「STM 代替共识。」「并行结果可以重排。」「STM 跑完就是最终。」「不声明写集所以没有顺序。」「不要求 opacity 所以中间态可以给人看。」  
**边界：** 不讲 Move 语法；不把 Polygon / Sei / Starknet 的移植当 Aptos 规范；Aptos 档案 §15 仍无官方主网七问，本页不编事故。Quorum Store 批次 ≠ L 见 [`../consensus/worked-example-quorum-store-vs-order.md`](../consensus/worked-example-quorum-store-vs-order.md)（不变量 132）。

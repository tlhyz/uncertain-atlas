# 例：看见付款码不是已经是存款地址；看见通知输出不是已经能花；看见第一次付款不是已经不必再通知

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-47](https://github.com/bitcoin/bips/blob/master/bip-0047.mediawiki)（Deployed, Applications）。  
**对应课文**：[L0.7](../../courses/level-00-machine/L00-M07-one-payment-lifecycle.md)、[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「付款码不是已经是存款地址 / 通知输出不是已经能花」，不是静默付款地址已经有输出，也不是种子备份已经能找回单钥 P2TR。不要另写怎样做 ECDH 或怎样拼通知。

## 官方三件事

规范把可复用付款码写成三件独立的付款事，不是「看见一条公开码就已经付到链上」一件事：

1. **看见付款码 / 看见公开身份 不是已经是存款地址，也不是已经付过。**  
   官方写：付款码是一把扩展公钥加上元数据，和某个身份或账户绑在一起。存款地址是通知之后才派生的一次性付款脚本哈希地址。看见付款码，不是已经有一笔链上输出。看见公开身份，不是已经付过。
2. **看见通知交易 / 看见通知地址上有输出 不是已经是付款，也不是已经能花。**  
   官方写：爱丽丝第一次给鲍勃付款之前，必须先用通知交易把她的付款码告诉鲍勃。通知之后才可能继续付（最多付很多笔），之后不必再发通知。通知地址上收到的输出不得显示为可花余额，也不得拿去参与本页那种共享秘密计算。看见通知地址进了币，不是已经付到存款地址。看见通知输出，不是已经能花。
3. **看见第一次付款 / 看见已经收过 / 看见 352 不必通知 不是已经不必再发通知。**  
   官方写：即使鲍勃以前收过爱丽丝的钱，他第一次往回打仍必须先发通知。从种子找回之后，必须当成新钱包再发通知；发出去的通知名单会丢。这和 352 官方写成「不必再发链上通知」不是同一句。看见已经收过，不是已经可以免通知。看见静默付款不必通知，不是已经是本页。

用途号、编码版本字节、共享秘密公式、通知脚本拼法、测试向量是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **付款码 ≠ 已经是存款地址：** 官方把付款码写成身份/账户上的扩展公钥加元数据，把存款地址写成通知之后才派生。
- **通知输出 ≠ 已经能花：** 官方禁止把通知地址上的输出显示为可花余额。
- **已经收过 ≠ 已经不必通知：** 官方把第一次往回打和从种子找回都写成必须再发通知。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 付款码 | 不是已经是存款地址 | 不是已经有输出（260） |
| 通知输出 | 不是已经能花 | 不是已经授权（255） |
| 第一次必须通知 | 本页要发 | 352 官方写成不必再发（260） |
| 种子找回 | 必须当成新钱包再通知 | 不是已经知道该看哪种脚本（184） |

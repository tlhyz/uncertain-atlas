# 例：看见带 pj= 的付款 URI 不是已经是 payjoin 付款；看见原始包不是已经是提案；看见收款方加了输入不是已经另开一笔

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-78](https://github.com/bitcoin/bips/blob/master/bip-0078.mediawiki)（Deployed, Applications, Specification）。取代 BIP-79。  
**对应课文**：[L0.7](../../courses/level-00-machine/L00-M07-one-payment-lifecycle.md)、[L1.4](../../courses/level-01-crypto/L01-M04-canonical-encoding.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、03 共识、M5.4、L5.4。本页是「带 pj= 的付款 URI 不是已经是 payjoin 付款 / 原始包不是已经是提案」，不是付款 URI 已经授权，也不是部分签名包已经能广播。不要另写怎样构造提案或怎样加费。

## 官方三件事

规范把 payjoin 写成三件独立的付款事，不是「看见 URI 上有 pj= 就已经付过 payjoin」一件事：

1. **看见带 pj= 的付款 URI / 看见 payjoin 端点 不是已经是原始包，也不是已经是提案，也不是已经是 payjoin 付款。**  
   官方写：收款方出示一条 BIP-21 URI，上面用 `pj=` 描述一个端点，发送方把原始包 POST 到那里。`pjos=0` 是另一条信号，发送方必须禁止替换付款输出。金额参数不是必须的。看见 `pj=`，不是已经付过。看见端点，不是已经有原始包。看见 `pjos=0`，不是已经做完 payjoin。
2. **看见原始包 不是已经是 Payjoin 提案，也不是已经是 Payjoin 交易。**  
   官方给了三个名字。原始包：已经签过、已经定稿，必须能广播。Payjoin 提案：收款方自己签过的输入输出，加上发送方那些；必须用上原始包的全部输入；只定稿收款方新加的输入。Payjoin 交易：发送方核过提案、重签自己的输入、再广播出去。看见一份能广播的原始包，不是已经是 payjoin。看见提案，不是已经广播。
3. **看见收款方加了输入 / 看见合并整理 不是已经另开一笔，也不是已经对全网私人，也不是已经能把 payjoin 交易再当原始包。**  
   官方写：收款方可以整理自己的未花输出、也可以把自己的付款并进这一笔，并不另开一笔交易。这份提案存在，也会让那三条启发式对**没用本页的人**变得不可靠。收款方必须确认原始包里的输入以前没见过：既挡探测，也挡把一笔 payjoin 交易再拿来当新的原始包。会交互的收款方不必核原始包，因为他们不会被探测。不是大家熟知的错误码和错误句，不得出现在发送方界面上，免得钓鱼。看见加了输入，不是已经另开一笔。看见提案存在，不是已经对全网私人。看见一笔 payjoin 交易，不是已经能再当原始包。

HTTP 配方、加费公式、发送方/收款方核对清单、怎样构造或下毒、混输入宽限期、版本不支持载荷是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **端点 ≠ 已经是付款：** 官方把 `pj=` 写成端点描述，把 `pjos=0` 写成另一条禁止替换信号。
- **原始包 ≠ 已经是提案 ≠ 已经是交易：** 官方把这三个名字写成三道门。
- **加输入 ≠ 已经另开一笔：** 官方把合并整理写成不另开交易，又把探测和再入写成必须挡。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果让收款方往付款里加输入，必须分开 URI 上的端点、原始包、提案、payjoin 交易。可以跳过「看见 pj= 就已经是 payjoin 付款」。若对照，必须分开端点、原始包 / 提案 / 交易、加输入不是另开一笔。不要另写怎样构造提案或怎样加费。290 payjoin vs original bundled unbundling 完成（1184 item 1 / 1185 item 2 / 1186 item 3）；精读 [`worked-example-pj78-noturi-vs-bundled.md`](worked-example-pj78-noturi-vs-bundled.md)（不变量 1184 item 1）。

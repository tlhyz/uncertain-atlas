# 例：看见付款 URI 不是已经授权；看见路径没有链上地址不是已经没有付款指示；看见不认识的必选参数不是已经能付

**层次**：生命周期 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-321](https://github.com/bitcoin/bips/blob/master/bip-0321.mediawiki)（Complete, Applications；替换 BIP-21）。  
**对应课文**：[L0.7](../../courses/level-00-machine/L00-M07-one-payment-lifecycle.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：`index/03` 共识行、Ethereum 行、M5.4、L5.1、L5.4、05b。本页是应用层「怎么用一条 URI 描述付款指示」，不是远程取单已经验证，也不是看见地址就已经有 UTXO。

## 官方三件事

规范把一条付款 URI 写成三件独立的应用事，不是「点了链接就已经付了」一件事：

1. **没有用户授权，不得按这条 URI 行事。**  
   官方写：本页给比特币付款指示写一种 URI。动机是让用户点网页或扫码就能付。官方还写：比特币客户端没有得到用户授权，不得按 URI 行事。应当要求用户一笔一笔手批；只有某些情况才可以让用户事先自动决定。看见一条付款 URI，不是已经授权，也不是已经付了，也不是已经广播。看见扫了码，不是已经点了发送。
2. **路径上的链上地址可以空；空了只要查询里至少有一条付款指示。**  
   官方写：路径部分是比特币地址，查询部分给额外付款选项。路径上的地址必须是规定的几种链上地址，或是空的。以后的地址格式应当改放查询键，好在升级时还能被旧发送方付。路径可以空，只要查询里至少有一条付款指示；收款方若不想给标准链上退路，可以这样写。看见路径没有链上地址，不是已经没有付款指示，也不是已经非法。看见路径上有地址，不是已经只有这一种付法，也不是已经付到链上。看见查询里另有付款指示，不是已经付过，也不是已经广播。
3. **不认识的必选参数让整条 URI 非法；回执回调不是已经确认，也不得打开浏览器方案。**  
   官方写：键前面加了必选前缀的，客户端若不实现，必须把整条 URI 当成非法。没加这个前缀、自己又不实现的，可以安全忽略。官方还写：可选回执参数让发起付款的应用在付完之后拿到证明。钱包必须先核回执方案不是浏览器会打开的那几类，才可以打开。若不会打开回执、而参数又是必选回执，钱包不得发起付款。看见不认识但不是必选的参数，不是已经非法。看见不认识的必选参数，不是已经能付。看见打开了回执，不是已经确认，也不是已经写进共识。看见必选回执却是浏览器方案，不是已经该付。

例地址、语法细则、金额写法是规范里的例子和格式，本页不抄。

## 官方为什么这样拆

- **看见 URI ≠ 已经授权：** 官方把「描述付款指示」和「用户批了」写成两件事。看见链接，不是已经点了发送。
- **路径空 ≠ 已经没有指示：** 官方允许路径空、查询里写别的付法。看见没有链上地址，不是已经不能付。
- **必选参数 ≠ 已经能付：** 官方把不认识的必选参数写成整条非法。看见回执，不是已经确认。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 付款 URI | 描述付款指示 | 不是已经授权 / 已经付了 |
| 路径可空 | 查询里至少有一条指示 | 不是已经没有指示 |
| 必选参数 / 回执 | 不认识则整条非法；回执不是确认 | 不是已经能付 / 已经确认 |

| 后继校验 ≠ 已是旧方案 | 另一对象 | 不变量 181 |
| 部分签名包 ≠ 已能广播 | 另一对象 | 不变量 179 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见付款 URI 就已经授权 / 就已经付了 / 路径空就已经没有指示」。若对照付款链接，必须分开用户授权、路径与查询里的指示、必选参数和回执。不要把本页写成已经覆盖远程取单。不要另写 BIP-21 当现行方案。

## 本页不抄

- 例地址、语法细则、金额写法、查询键取值、回执拼接步骤。
- 怎样造能骗过旧钱包的必选参数，怎样用回执把浏览器打开到收款方。

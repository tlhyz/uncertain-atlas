# 例：看见签过的消息不是已经证明能控制资金；看见签过不是已经证明发过上一笔；看见资金证明清单不是已经花光也不是已经齐

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-322](https://github.com/bitcoin/bips/blob/master/bip-0322.mediawiki)（Complete, Applications）。  
**对应课文**：[L0.7](../../courses/level-00-machine/L00-M07-one-payment-lifecycle.md)、[L1.2](../../courses/level-01-crypto/L01-M02-signatures.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、05b、M5.4、L5.4、03 共识。本页是「签过一条消息不是已经控制资金」，不是地址串已经有输出，也不是部分签名包已经能广播。

## 官方三件事

规范把通用签消息写成三件独立的应用事，不是「看见签过就已经能花」一件事：

1. **看见签过的消息不是已经证明能控制资金。**  
   官方写：归根结底，没有任何签消息协议真能证明控制资金。签名一做出来就已经过时。握着密钥的人可以愿意替别人签消息，却不肯签真正的交易。没有任何签消息协议能修掉这两条限制。看见验过一条签消息，不是已经能花，也不是已经肯签真正的交易，也不是已经控制那笔钱。
2. **本页只覆盖「能控制打到发票地址的钱」；证明签名人发过上一笔交易，本页做不到。**  
   官方写：本页只处理签名人表明自己将能控制打到发票地址的资金。用本页证明签名人发过上一笔交易，做不到。看见签过的消息，不是已经证明付过款，也不是已经证明广播过上一笔。
3. **资金证明清单不是已经齐，也不是已经没花。**  
   官方写：资金证明变体让签名人自选一组 UTXO 来展示控制。这份清单不声称齐（不是「这个地址上的 UTXO 就这些」），也不声称还没花（验证者必须去问链）。离线验证者只能核密码学是否成立，不能核链上状态。一份被证明过的清单，永远不能证明这个地址没有更多 UTXO。看见资金证明清单，不是已经齐，也不是已经没花，也不是已经是一笔付款。

编码前缀、虚拟交易怎么拼、测试向量是规范里的取值，本页不抄。

## 官方为什么这样拆

- **签过 ≠ 已经能花：** 官方把「没有任何签消息协议真能证明控制资金」写成限制，不是实现没做好。
- **签过 ≠ 已经付过：** 官方只覆盖打到发票地址的将来控制，明确写证明发过上一笔做不到。
- **清单 ≠ 已经齐 / 已经没花：** 官方把齐和未花都交给链，不交给这份清单。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 签过的消息 | 不是已经控制资金 | 不是已经肯签真正的交易 |
| 发票地址将来控制 | 本页能谈 | 不是已经证明发过上一笔 |
| 资金证明清单 | 自选、不齐、未花要问链 | 不是已经是付款 |
| 地址串 ≠ 已有输出 | 另一对象 | 不变量 174 |
| 部分签名包 ≠ 已能广播 | 另一对象 | 不变量 179 |
| 扩展公钥 ≠ 已经能花 | 另一对象 | 不变量 182 |
| 付款 URI ≠ 已经授权 | 另一对象 | 不变量 255 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机必须写清签消息、花费授权、链上未花是不是同一对象。可以跳过「看见签过就已经能花 / 已经付过」。若对照，必须分开签过、发票地址将来控制、清单齐不齐、链上还没花。不要另写怎样拼虚拟交易。

## 本页不抄

- 编码前缀、标签哈希、虚拟交易字段、PSBT 类型号、测试向量。
- 怎样拼能过验证器的签消息、怎样用资金证明假装齐或未花。

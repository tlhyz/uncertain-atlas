# 例：看见静默付款地址不是已经有一笔链上输出；看见扫过不是已经收到；看见同一条静默付款地址再用不是已经同一笔输出

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-352](https://github.com/bitcoin/bips/blob/master/bip-0352.mediawiki)（Complete, Applications）。  
**对应课文**：[L0.7](../../courses/level-00-machine/L00-M07-one-payment-lifecycle.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、05b、M5.4、L5.4、03 共识。本页是「静态收款码不是已经那笔链上输出」，不是地址串已经有 UTXO，也不是付款 URI 已经授权。

## 官方三件事

规范把静默付款写成三件独立的应用事，不是「看见一条收款码就已经付到链上」一件事：

1. **看见静默付款地址不是已经有一笔链上输出，也不是已经付过。**  
   官方写：本页给比特币写一种静态付款地址，链上不必把各次付款连在一起，也不必再发链上通知。外面的观察者不能把交易连回这条静默付款地址。每一次静默付款都走到一个新的地址，免得误复用。看见一条静默付款地址，不是已经有一笔链上输出，也不是已经付过，也不是已经能当普通见证地址去花。看见专用编码过了校验，不是已经是旧的见证地址方案。
2. **看见扫过不是已经收到，也不是已经能花。**  
   官方写：代价是钱包必须扫链才能发现付款。本页把扫描职责和花费职责分开：扫描可以在线，花费钥可以留在离线冷存。轻客户端怎么扫，官方写成仍在研究。看见扫过一遍，不是已经收到，也不是已经能从冷存花。看见没扫到，不是已经没人付。看见轻客户端过滤器对上，不是已经是本页这种发现。
3. **看见同一条静默付款地址再用不是已经同一笔输出，也不是已经把各次付款连上。**  
   官方写：多次付款不得链回同一个发送者。不必再发链上通知。官方还写：链下通知只是把隐私和代价挪到别处，还多了通知送不到就丢钱的风险。看见同一条静默付款地址再用，不是已经同一笔脚本，也不是已经把各次付款连上。看见没有通知，不是已经没有付款。

派生怎么算、编码字符、测试向量是规范里的取值，本页不抄。

## 官方为什么这样拆

- **静态码 ≠ 已经有输出：** 官方把「每次走到新地址、观察者连不回去」写成目标。看见码，不是已经付到链上。
- **扫过 ≠ 已经收到：** 官方把发现写成必须扫链，并把扫描和花费分开。
- **再用 ≠ 已经同一笔：** 官方把「避免误复用」和「不得链回同一发送者」写成两条独立目标。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 静默付款地址 | 静态码，不是链上输出 | 不是已经付过 |
| 扫链发现 | 必须扫才能发现 | 不是已经收到 / 已经能花 |
| 再用同一条码 | 每次仍应是新输出 | 不是已经连上各次付款 |
| 地址串 ≠ 已有输出 | 另一对象 | 不变量 174 |
| 后继校验 ≠ 已是旧方案 | 另一对象 | 不变量 181 |
| 扩展公钥 ≠ 已经能花 | 另一对象 | 不变量 182 |
| 付款 URI ≠ 已经授权 | 另一对象 | 不变量 255 |
| 签过 ≠ 已经控制资金 | 另一对象 | 不变量 258 |
| 过滤器对上 ≠ 已经有块 | 另一对象 | 不变量 243 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写静态收款码，必须分开码、链上输出、扫到、能花。可以跳过「看见收款码就已经付到链上」。若对照，必须分开静态码、每次新输出、扫链发现、花费钥。不要另写怎样派生输出。

## 本页不抄

- 派生公式、标签哈希、可读前缀字面量、例地址、测试向量。
- 怎样扫链、怎样从输入拼共享秘密、怎样用标签把付款连起来。

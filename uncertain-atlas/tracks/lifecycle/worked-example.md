# 实例：阿安付给阿比「1」

目的 A 的精读材料。不是考试。数字只为讲结构，不是某链主网参数。  
先修：L0.7、本目录 README 五列表。

同一意图：阿安授权把 1 个结算单位给阿比。五列都走完。

---

## 0. 共同的门（事实）

无论哪一列，都有：

1. 阿安的机器构造并签名  
2. 某台别人的机器（RPC）声称收下  
3. 尚未 canonical 的池或队列  
4. 排序  
5. `Apply`  
6. 磁盘  
7. 某种「可以放货吗」的政策  

第 2 步绿了，第 7 步可以仍是红的。

---

## 1. Bitcoin 列

阿安选中一枚价值 3 的 UTXO，输出：阿比 1，自己找零 2 减费。  
签名绑在「这枚输入 + 这些输出」上（具体 sighash 以规范为准）。

- RPC 显示「已广播」：只到门 2。  
- 进矿工 mempool：门 3。标准性可能拒一笔共识仍合法的交易（L3.2）。  
- 出现在高度 100 的块：门 4–5。阿比钱包若显示 1 确认，这是**政策**，不是协议最终。  
- 再长 5 个块：阿比的店若按「6 确认发货」，赌的是重组成本（L3.1）。日蚀可以让**他的节点**看见假 6 确认（L3.4）。

**仍能翻：** 更深的工作量、日蚀、实现通胀洞（博物馆）。  
**不要说：** 「6 确认所以不可逆。」

---

## 2. CometBFT 应用链列

阿安签一笔应用交易（账户或 UTXO 由应用定）。  
`CheckTx` 过只表示「此刻池想收」，不是执行。

- proposer 打进高度 50。  
- prevote / precommit 凑齐 +2/3（L4.1–L4.3）。  
- `DeliverTx` / `Apply`，应用哈希进 commit。  
- 高度 50 **commit**：协议对象「本高度已提交」成立（在实现守锁与 WAL 的前提下）。

**仍能翻：** 两客户端同高度不同应用哈希（实现）；`V(h)` 两套表（L4.5）；崩溃后丢 lock 投矛盾票（L4.4）。  
**不要说：** 「投票中了所以到了。」「CheckTx 过了所以到了。」

---

## 3. Ethereum L1 列

阿安 nonce=7，签给阿比的转账。  
构建者可能改序。执行成功：nonce→8，余额改。

- 钱包订 head：门 4 的一种，头可摆（L5.2）。  
- justified / finalized：更硬，仍有弱主观性与质押假设。  
- 若合约调用中途 revert：交易仍可能被包含，nonce 仍走，阿比没收到 1（L5.1）。

**仍能翻：** 跟错 head；客户端 gas 表分歧（L5.3）；只信 RPC。  
**不要说：** 「出块了所以 finalized。」「PoS 所以秒到。」

---

## 4. 乐观 L2 列

阿安签的是 **L2 域**的交易（必须与 L1 域分离，否则重放）。  
排序者 RPC 立刻显示成功：这是门 2 + 租户执行，**不是**房东结算。

- 批次把数据/承诺打到 L1：门 4 的锚。L1 头最终 ≠ 窗口结束。  
- 阿比若在 L2 UI 绿勾时发货：赌排序者诚实、数据可下、挑战期内有人能揭穿假根（L7.4）。  
- 提款 1 回 L1：还要过该桥的窗口/证明。数据扣留则乐观假设塌。

**仍能翻：** 假根 + 无人挑战；DA 扣留；升级钥改桥；排序者审查且无逃生舱。  
**不要说：** 「L2 出块了所以和 L1 一样最终。」

---

## 5. Zcash 完全屏蔽列

阿安有 note 承诺 C（链上看不见 v=1 与阿比）。  
钱包做证明：合法 note、金额守恒、授权；公布 nullifier N 与新承诺 C'。

- 全节点：π 过、N 未见过、树更新（L8.1）。  
- 「进块」的最终性仍是 Bitcoin 家族的概率最终，外加 **N 已在 canonical 历史上**。  
- 阿比用查看密钥认出 C'。链不知道阿比是谁。若查看密钥在 RPC 上，隐私对托管方作废（部署），协议仍可正确。

**仍能翻：** 重组吐出含 N 的块；电路漏守恒则通胀（此时零知识可以仍成立）；不完全屏蔽路径泄漏图。  
**不要说：** 「有 ZK 所以不可双花、不可通胀。」「链上什么都不知道。」

## 6. 同一笔钱上的五层（对照）

以「阿比已经放货」为失败观察。坏可以坏在不同层：

| 层 | Bitcoin 列怎么坏 | CometBFT 列怎么坏 | 乐观 L2 怎么坏 |
|---|---|---|---|
| 密码 | 无钥却能签（或电路/证明系统，屏蔽列） | 同左 | L2 签伪造；桥合约哈希错 |
| 协议 | 浅确认当最终 | 无锁的双 QC | 窗口未完当兑付 |
| 实现 | 溢出/重复输入 | 两客户端不同根 | 挑战游戏超时实现错 |
| 部署 | 日蚀、假 RPC | 假 RPC、WAL 没 fsync | 排序者 RPC、数据扣在硬盘 |
| 经济 | 重组划算 | 质押/集合被买 | 桥内资金 ≫ 揭穿成本 |

## 7. 对照句（建议写在产品里的形状）

| 链 | 可写的老实句 | 禁止句 |
|---|---|---|
| Bitcoin | 「我们看到 k 个确认；重组仍可能，政策是……」 | 「已经最终」 |
| CometBFT | 「高度 h 已 commit，应用哈希为 R」 | 「节点投过票了」 |
| Ethereum | 「头 / 已证明正当 / 已最终，我们用的是第几种」 | 「上链了」 |
| 乐观 L2 | 「L2 执行了；L1 锚了；窗口/DA/兑付条件是……」 | 「L2 确认 = L1 最终」 |
| 屏蔽 | 「N 已在历史上；最终性仍随底层共识；链仍看见 N 与 π」 | 「完全匿名且不可双花」 |

「不确定」选一种老实句，见 [`../../libraries/settlement-copy.md`](../../libraries/settlement-copy.md)。矩阵列仍空。

# 例：看见可读名字不是已经该走 DNS；看见 TXT 不是已经是合法付款指示；看见缓存或复制了名字不是已经是当前那条 URI

**层次**：应用 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-353](https://github.com/bitcoin/bips/blob/master/bip-0353.mediawiki)（Complete, Applications）。  
**对应课文**：[L0.7](../../courses/level-00-machine/L00-M07-one-payment-lifecycle.md)、[L3.6](../../courses/level-03-bitcoin/L03-M06-testing-and-culture.md)。  
**不要写进**：Ethereum 行、L5.1、05b、M5.4、L5.4、03 共识。本页是「DNS 里的可读名字不是已经该用、也不是已经核过」，不是付款 URI 已经授权，也不是远程取单已经验证。

## 官方三件事

规范把 DNS 付款指示写成三件独立的应用事，不是「看见 user@domain 就已经能付」一件事：

1. **看见可读名字不是已经该走 DNS，也不是已经比地址或 URI 更好。**  
   官方写：只要已经有明确的公钥或地址，钱包不得优先走 DNS。换句话说，若标准比特币地址或直接的付款 URI 已经够用，必须优先用那个。看见可读名字，不是已经该去解析。看见展示前缀，不是已经写进了要解析的标签。看见名字像邮箱，不是已经是本页。
2. **看见 TXT 不是已经是合法付款指示，也不是已经由远端解析器核过。**  
   官方写：必须以「bitcoin:」开头的 TXT 才看；同一标签上有多条这样的记录，整组非法，一条都不能用。必须把这一条 TXT 里的字段按顺序拼回一条 URI，中间不得另插分隔。不得跨多条 TXT 去拼。所有付款指示必须带 DNSSEC 签。必须自己把 DNSSEC 验到根，不得让远端解析器代验。看见解析器说绿，不是已经核过。看见一条 TXT，不是已经是一条能付的 URI。
3. **看见缓存或复制了名字不是已经是当前那条 URI。**  
   官方写：可以缓存，但不得超过解析器给的 TTL，也不得超过整条 DNSSEC 链上签过的最短初始 TTL。复制时应当直接复制底下的 URI，不要复制可读名字。带过期时间的指示（例如闪电报价）必须让 DNS 记录先过期，否则发送方手里可能还是过期指示。看见复制了可读名字，不是已经复制了 URI。看见 DNS 还没过期，不是里面的报价还有效。看见指示里有链上地址，不是已经不复用。

标签怎么拼、例名、PSBT 字段号是规范里的取值，本页不抄。不要另写 BIP-21 当现行用户方案。

## 官方为什么这样拆

- **名字 ≠ 已经该走 DNS：** 官方把「有地址或 URI 就必须优先用那个」写成硬规则。
- **TXT ≠ 已经合法：** 官方把拼装、多条非法、自己验到根写成三条独立谓词。
- **缓存 / 复制 ≠ 已经当前：** 官方把 TTL 和「复制 URI 而不是名字」写成独立对象。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 可读名字 | 不是已经该走 DNS | 不是已经比地址更好 |
| TXT / DNSSEC | 必须自己验到根 | 不是远端解析器已经核过 |
| 缓存 / 复制 | TTL 内才算当前 | 不是已经是 URI |
| 付款 URI ≠ 已经授权 | 另一对象 | 不变量 255 |
| 远程取单 ≠ 已经验证 | 另一对象 | 不变量 55 |
| 地址串 ≠ 已有输出 | 另一对象 | 不变量 174 |
| 静默付款地址 ≠ 已经有输出 | 另一对象 | 不变量 260 |
| 签过 ≠ 已经控制资金 | 另一对象 | 不变量 258 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写可读收款名，必须分开名字、DNS 记录、自己核过的指示、当前 URI。可以跳过「看见名字就已经能付」。若对照，必须分开优先用地址、自己验 DNSSEC、TTL 与复制。不要另写怎样枚举用户名。

## 本页不抄

- DNS 标签拼法、例名、解析器地址、PSBT 类型号、展示前缀当不确定默认。
- 怎样做同形字攻击、怎样枚举用户、怎样让远端解析器代验。
- 不要另写 BIP-21 当现行用户方案。

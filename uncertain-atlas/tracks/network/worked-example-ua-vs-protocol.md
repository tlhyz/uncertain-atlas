# 例：看见协议版本不是已经是客户端版本；看见 user agent 不是已经可以按实现改行为；看见同一协议版本不是已经是同一套实现

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-14](https://github.com/bitcoin/bips/blob/master/bip-0014.mediawiki)（Deployed, Peer Services）。  
**对应课文**：[L3.4](../../courses/level-03-bitcoin/L03-M04-network-and-eclipse.md)、[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：Ethereum 行、L5.1、05b、M5.4、L5.4、03 共识。本页是「协议版本不是客户端版本，user agent 不是已经可以按实现改行为」，不是功能协商已经启用，也不是带 nonce 的 pong 已经还活着。

## 官方三件事

规范把协议版本和 user agent 写成三件独立的对等事，不是「看见版本号就已经知道这是哪家客户端」一件事：

1. **看见协议版本不是已经是客户端版本，也不是已经是实现版本。**  
   官方写：本页要把协议版本从客户端版本里拆开。`version` 和 `getblocks` 里的版本字段变成协议版本。块里的版本反映的是造这块时的协议版本。以前这两套数字是同一个。看见协议版本，不是已经看见客户端版本。看见实现发了新版本，不是已经抬了协议。看见块上写了版本，不是已经是当时那家客户端的内部号。
2. **看见 user agent 不是已经可以按实现改行为。**  
   官方写：user agent 是一块「虚荣牌」，只是信息工具。协议不应当随 user agent 改。官方还写：它不提供按不同实现绕开、对人家表现不一样的方法；那样会把协议撕开。看见一条 user agent，不是已经可以按这家实现换规则。看见靠 user agent 认人，不是已经是本页允许的行为。官方把按 user agent 去排斥故障客户端写成极不推荐、极坏的形式。
3. **看见同一协议版本不是已经是同一套实现；看见 user agent 栈不是已经是协议能力。**  
   官方短句：协议版本用来区分节点，并据此表现不同；user agent 只是信息。官方还写：两家界面可以共用同一个协议版本，底下的代码库版本却不同。看见同一协议版本，不是已经是同一套实现。看见 user agent 里叠了几层名字，不是已经多了一项协议能力，也不是已经谈妥了某项功能。

栈怎么写、分隔符、例串是规范里的取值，本页不抄。

## 官方为什么这样拆

- **协议版本 ≠ 客户端版本：** 官方把「各实现被一家客户端的发版节奏绑死」写成要拆开的病。
- **user agent ≠ 已经可以改行为：** 官方把按实现换协议写成会撕开网络。
- **同一协议版本 ≠ 同一套实现：** 官方允许同一协议版本底下坐不同代码库。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 协议版本 | 从客户端版本拆开 | 不是已经是实现号 |
| user agent | 信息牌 | 不是已经可以按实现改行为 |
| 同一协议版本 | 可共用 | 不是已经是同一套实现 |
| 协议版本 ≠ 已经启用功能 | 另一对象 | 不变量 259 |
| 协议版本 ≠ 已经会回 pong | 另一对象 | 不变量 262 |
| 忽略多余字段 ≠ 已经是新协议 | 另一对象 | 不变量 235 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果写对等握手，必须分开协议版本、实现版本、user agent。可以跳过「看见 user agent 就已经按这家换规则」。若对照，必须分开协议能力、实现号、信息牌。不要另写怎样按 user agent 认人或排斥。

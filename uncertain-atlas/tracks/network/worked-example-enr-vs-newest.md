# 例：看见签过的节点记录不是已经是最新一份；看见能多写键不是已经换了身份方案

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Ethereum [EIP-778](https://eips.ethereum.org/EIPS/eip-778)（Final, Networking）。  
**对应课文**：[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：`index/03` 共识行、M5.4、L5.1、L5.4、05b。节点记录是连通身份，不是分叉标识，也不是 EVM 气页。

## 官方三件事

规范把一次开放格式写成三件独立的网络事，不是「发现里多一份名片」一件事：

1. **节点记录是灵活的连通信息格式，用来解开发现第 4 版当时只能传公钥、地址和两个端口的限制。**  
   官方写：其余部分是任意键值对；已有客户端应接受任何键值对，不论能不能解释内容。加新键不要求实现先达成共识。官方还写：除身份方案名以外都可选，包括地址和端口；没有端点信息的记录，只要签名合法，仍然有效。看见签过的记录，不是已经有了可连的地址。看见多出来的键被收下，不是这些键已经被解释。
2. **序号用来做权威更新。**  
   官方写：节点改端点并发布新记录时，别人应能判断哪一份更新。记录一变，节点应把序号加大并再发布。看见一份签过的记录，不是已经是最新一份。看见序号，不是全网已经换完。
3. **身份方案和多写键不是同一旋钮；记录也可以走发现以外的通道。**  
   官方写：签名按身份方案做，DHT 地址也由身份方案推导。加新身份方案需要实现共识，因为网络否则不认签名。本页只定义一种默认方案，兼容发现第 4 版那套密码，直到以后的 EIP 另定。看见默认方案名，不是已经换了发现协议，也不是新身份方案已经被网络接受。官方写：记录可以通过以后的发现版本转，也可以通过 DNS、ENS、线协议子协议等任意机制转。看见文本前缀记录，不是已经从发现里找到，也不是已经信任这个邻居。

编码上限、测试向量、例钥是规范里的常数，本页不抄。

## 官方为什么这样拆

- **灵活格式 ≠ 已经发现：** 官方说第 4 版发现转不了别的信息。看见能多写键，不是发现已经升级完，也不是端点已经齐。
- **签过 ≠ 已经最新：** 官方要的是权威更新，不是「验过签就永远这一份」。看见能验，不是已经比过序号。
- **多写键 ≠ 已经换身份方案：** 官方把「谁都能加键」和「换签名方案要实现共识」分开写。看见新键，不是签名方案已经换。看见能走 DNS 转发，不是已经写了发现第 4 版怎么要最新一份。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 签过的节点记录 | 连通信息格式 | 不是已经有端点 / 已经最新 |
| 任意键值对 | 应收下 | 不是已经解释 |
| 身份方案 | 签名 + DHT 地址 | 不是多写键已经换方案 |
| 发现以外转发 | 可以走 DNS / ENS / 子协议 | 不是已经从发现找到 / 已经信任 |
| 分叉标识 | 另一对象 | 不变量 239 |
| 忽略版本 / 多余字段 | 另一对象 | 不变量 235 |
| 对等历史窗 | 另一对象 | 不变量 207 |
| 握手请求有界 | 另一对象 | CVE-2020-5303 |
| 发现第 4 版要最新一份 | 另一对象 | 不另写 19 节 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见签过的节点记录就已经是最新一份 / 就已经发现 / 就已经换了身份方案」。若对照连通身份，必须分开记录格式、序号更新、身份方案、发现以外的转发。不要把文本前缀记录写成已经连上。

## 本页不抄

- 测试向量、例钥、节点标识、例地址、例端口、编码上限取值。
- 怎样造记录、怎样磨序号、怎样靠 DNS 冒充邻居。

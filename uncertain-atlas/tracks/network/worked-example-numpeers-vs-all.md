# 例：看见 NumPeers 不是已经数完所有邻居；看见能按名字拿到反应堆不是已经独立；看见 PeerState 不是已经验过高度

**层次**：网络 / 反应堆查询。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [API for Reactors](https://github.com/cometbft/cometbft/blob/main/spec/p2p/reactor-api/p2p-api.md)。  
**对应课文**：[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行。本页是「NumPeers 不是已经数完 / 按名字拿到反应堆不是已经独立 / PeerState 不是已经验过高度」，不是句柄已经是那个人，也不是 InitPeer 已经能交互。不要另写怎样数邻居或怎样切共识。

## 官方三件事

规范把反应堆能问 p2p 层的几件查询写成三件独立的网络事，不是「看见能问就已经数完、已经独立、已经验过高度」一件事：

1. **看见 NumPeers / 看见 outbound+inbound 不是已经数完所有邻居，也不是已经把正在拨的人算进已连接。**  
   官方写：`NumPeers()` 回已连接的出站和入站个数。**无条件邻居不在这里面。** 第三个数 `dialing` 是正在试着连、还没连上的人。官方还写：`dialing` **不该给协议层看**；除了可算 p2p 层一部分的 PEX，标准反应堆都不用这个数。看见回了三个数，不是已经数完。看见出站加进站，不是无条件名单已经算进去。看见正在拨，不是已经连上，也不是协议层该当现行用法。
2. **看见能按名字拿到另一个反应堆 / 看见 Block Sync 能切到 Consensus 不是已经该当推荐路径，也不是已经独立。**  
   官方写：`Switch.Reactor(name)` 能按登记名拿到另一个反应堆。眼下只有 Block Sync 用它去拿 Consensus，再叫导出的 `SwitchToConsensus()`。官方还写：这种反应堆互相拿的做法**不鼓励，应该避免**，因为它违反「反应堆彼此独立」这条假设。看见能拿到，不是已经该当现行用法。看见能切过去，不是已经独立。看见方法还在，不是已经推荐。
3. **看见 Peer 上有 KV / 看见 Consensus 写了 PeerState 不是已经 Evidence / Mempool 已经有了已验证的最后高度。**  
   官方写：每个 `Peer` 带一份同步键值店，给反应堆之间异步交换这个人的状态。现行用法是 Consensus 给每个已连接的人放一份 `PeerState`。Evidence 和 Mempool 会定期去拿，尤其是这个人报的最后高度。这份高度是共识反应堆写的，会影响那两家怎么跟人对说。看见能 `Get` 到高度，不是已经验过。看见 Consensus 写过，不是证据已经齐。看见 Mempool 读到了，不是已经是规范高度。

好邻居票数、发送超时、通道号是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **NumPeers ≠ 已经数完：** 官方把已连接、无条件邻居、正在拨分开，也把协议层不该看 `dialing` 写明。
- **按名字拿到反应堆 ≠ 已经独立：** 官方把能拿到和「应该避免、违反独立」分开。
- **PeerState ≠ 已经验过高度：** 官方把共识反应堆写下的高度，和证据 / 内存池已经验过分开。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「对等节点已经齐」，必须分开 NumPeers 是不是已经数完、按名字拿到反应堆是不是已经独立、PeerState 是不是已经验过高度。可以跳过「看见能问就已经数完」。不要另写怎样数邻居或怎样切共识。

# 例：看见对账素描不是已经有那些交易；看见发了 sendtxrcncl 不是已经在对账；看见对账失败退回洪水不是库存通告已经退役

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-330](https://github.com/bitcoin/bips/blob/master/bip-0330.mediawiki)（Draft, Peer Services）。  
**对应课文**：[L3.4](../../courses/level-03-bitcoin/L03-M04-network-and-eclipse.md)、[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)、[L9.2](../../courses/level-09-systems/L09-M02-mempool.md)。  
**不要写进**：`index/03` 共识行、Ethereum 行、M5.4、L5.1、L5.4、05b。本页是点对点层用集合对账代替每一次库存通告，不是已经有交易，也不是按 wtxid 通告已经谈妥。

## 官方三件事

规范把一次交易通告对账写成三件独立的传播事，不是「对账已经代替洪水」一件事：

1. **对账是两端对齐通告集合的积木，Erlay 仍然会向一小撮邻居发库存通告。**  
   官方写：本页规定的是两个节点之间对齐交易通告的协议扩展，是更省带宽的转发协议（例如 Erlay）的一块积木。今天每对邻居至少有一个方向要通告 32 字节交易标识，复杂度随节点数乘连接数涨。对账可以比按库存通告灌水更省。Erlay 同时用洪水（向邻居发库存通告）和对账。洪水贵，所以只在必须尽快传到一小撮连接时用。对账是把没靠洪水收到的交易补上，并确认其余连接两边已经对齐、没有东西可学。看见一次对账，不是已经有那些交易，也不是库存通告已经退役，也不是已经向每个邻居都通告过。看见只向一小撮邻居发洪水，不是全网已经齐。
2. **sendtxrcncl 是握手里的信号，必须带着 wtxidrelay、在应答之前发出。**  
   官方写：这条消息宣布支持对账。应当只发一次。应当在握手应答之前发出，并且同时带着 wtxidrelay（先后不论）。应答之后才发的，发送方应当被断开。应答之前发了、但到应答时还没收到 wtxidrelay 的，应当忽略对账信号，连接照常，只当不支持对账。对等节点在 version 里声明不转发交易的，不得发这条；否则应当断开。两端都发了之后，发起连接的一方发起对账请求，另一方应答。看见发了 sendtxrcncl，不是已经在对账，也不是已经有通告集合。看见发了 wtxidrelay，不是对账已经打开。看见协议两边都写了支持，不是已经对齐过一轮。
3. **素描是通告集合的校验和；解得开仍要再发库存通告；解不开退回洪水。**  
   官方写：对账主要是按请求传一份通告集合的素描并尝试解码。解不开可以再要一份加长素描，也可以直接标失败结束。标失败时，应当把该通告集合里的交易再按库存通告一遍，当作退回洪水。标成功时，对方缺的短标识走对账差额消息，己方缺的短标识再发库存通告。看见一份素描，不是已经有那些交易，也不是差额已经在手里。看见解码成功，不是已经下完，也不是已经验完。看见解码失败，不是集合已经空，也不是那些交易已经共识非法。看见短标识，不是已经有带见证的哈希，也不是已经收下。

短标识怎么算、素描有限域、容量公式是规范里的数字和算法，本页不抄。状态是草案，不是已经在主网默认打开。

## 官方为什么这样拆

- **对账 ≠ 已经代替洪水：** 官方把对账写成积木，并且写明 Erlay 仍向一小撮连接发库存通告。看见对账消息，不是库存通告已经消失。
- **握手信号 ≠ 已经在对账：** 官方把「能懂」钉在应答之前，并且必须同时有 wtxidrelay。看见发了信号，不是已经对齐过集合。
- **素描 ≠ 已经有交易：** 官方解完仍要再发库存通告；解不开还得退回洪水。看见素描到了，不是交易已经在手里。

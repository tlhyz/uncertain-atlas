# 例：看见 Peer 句柄不是已经是那个人；看见 Broadcast 回了通道不是已经送到每一家；看见 StopPeerForError 不是已经对持久邻居也断干净

**层次**：网络 / 对等句柄。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [API for Reactors](https://github.com/cometbft/cometbft/blob/main/spec/p2p/reactor-api/p2p-api.md)。  
**对应课文**：[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：Ethereum 行、L5.1、M5.4、L5.4、03 共识图谱、Bitcoin 行。本页是「句柄不是已经是那个人 / Broadcast 不是已经送到 / 踢持久邻居不是已经断干净」，不是 InitPeer 已经能交互，也不是入站配额已经认领 ID。不要另写怎样广播或怎样重连。

## 官方三件事

规范把反应堆能用的 p2p 接口写成三件独立的网络事，不是「看见句柄就已经是那个人、已经送到、已经踢走」一件事：

1. **看见 Peer 句柄 / 看见又一次 InitPeer 不是已经是同一个人。**  
   官方写：每次连上一个对等节点（包括断开再连），都会经 `InitPeer(Peer)` 再给反应堆一份新的、不一样的 `Peer` 句柄。这份句柄绑的是**这一次连接**，不是网上那个节点本身。要认人，得用 `p2p.ID`。看见又拿到句柄，不是已经是上一次那份。看见对象换了，不是网上那个人换了。看见 `InitPeer` 又来了，不是身份已经换了。
2. **看见 Broadcast 回了通道 / 看见通道里有 bool 不是已经送到每一家，也不是已经知道是谁。**  
   官方写：`Switch.Broadcast` 多半是历史兼容。它不阻塞，回一条 bool 通道。每个已连接的人各起一条后台去发。每条单播成败会丢进这条通道，发完才关。官方还写：标准反应堆都不看这个返回值。其中一个原因是，通道里每个 bool **对不上**是哪一个人。看见回了通道，不是已经送到。看见一串真假，不是已经能点名。看见方法还在，不是已经该当现行用法。
3. **看见 StopPeerForError / 看见反应堆要踢人 不是已经对持久邻居也断干净。**  
   官方写：反应堆可以让 p2p 层停掉一个人对等节点：收发例程停掉，再 `RemovePeer`，再从已连接集合拿走。但 `StopPeerForError` 有一条重要保留：若这个人配成**持久邻居**，Switch 还会试着重连同一个人。这对 p2p 层自己的通信错误说得通，反应堆来叫时说不通。看见叫了停，不是已经不会再来。看见理由进了，不是持久名单已经忘了。看见反应堆要踢，不是已经按「踢了就干净」执行。

通道号、好邻居计数、发送超时是规范里的取值或做法，本页不抄。

## 官方为什么这样拆

- **句柄 ≠ 已经是那个人：** 官方把连接对象和网上节点身份分开。
- **Broadcast 回通道 ≠ 已经送到：** 官方把发出去和「对得上是谁 / 标准反应堆会看」分开。
- **StopPeerForError ≠ 已经断干净：** 官方把反应堆要踢和持久邻居还会重连分开。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 又一次 InitPeer 的新句柄 | 不是已经是同一个人 | 不是 InitPeer 已经能交互（305） |
| Broadcast 回了通道 | 不是已经送到、也不是已经能点名 | 不是宣布已经收到（36） |
| 反应堆叫停持久邻居 | 不是已经断干净 | 不是入站配额已经认领 ID（67） |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机如果给人看「对等节点已经齐」，必须分开句柄是不是已经是那个人、Broadcast 是不是已经送到、踢持久邻居是不是已经断干净。可以跳过「看见句柄就已经是那个人」。不要另写怎样广播或怎样重连。

## 本页不抄

- 好邻居票数 / 块片段数、发送超时秒数、通道号、信封字段表。
- 怎样广播、怎样编 protobuf、怎样认好邻居、怎样配持久名单。
- 怎样在 `InitPeer` 里认领 ID。那是不变量 67。

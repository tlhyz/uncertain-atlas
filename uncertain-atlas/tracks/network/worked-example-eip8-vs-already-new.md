# 例：看见忽略版本 / 多余字段不是已经在说新协议

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Ethereum [EIP-8](https://eips.ethereum.org/EIPS/eip-8)（Final, Networking, Homestead 时期）。  
**对应课文**：[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：`index/03` 共识行、M5.4、L5.1、L5.4。本页不是 Homestead 那次共识四件事（不变量 234）。

## 官方三层，不是一层

规范把向前兼容写成三件独立的网络事，不是「握手松一点」一件事：

1. **devp2p 线协议的 hello：** 应忽略对方的版本号；发送时写自己支持的最高版本；忽略 hello 列表末尾多出来的元素。
2. **RLPx 发现：** 不应校验 ping 的版本号；任何包都忽略多出来的列表元素，以及第一个 RLP 值后面的数据；不认识的包类型应静默丢掉。发现包仍有最大长度，本页不抄数字。
3. **RLPx TCP 握手：** 应接受一种新的加密握手编码。解码时忽略版本对不上、多出来的列表元素、列表后面的尾巴。旧格式退役之前，新握手体要垫一段垃圾，好跟旧编码分开。

看见某一层能吞多余字段，不是三层都已经换完，也不是已经在说新协议。

## 官方为什么这样写

官方原文：旧客户端会因为版本号或结构对不上就拒通信，网络协议升级很难部署。把向前兼容要求绑进 Homestead 那次升级，是为了让当时还在网上的客户端都能扛住以后的**网络**协议升级（只要还保持向后兼容）。

看见「跟 Homestead 一起上」，不是已经改了共识规则，也不是已经写了交易创建 / 高 `s` / 空合约失败 / 难度均值（不变量 234）。本页类别是 Networking，不是 Core。

官方原文：版本更低的节点收到更高版本、可能多了列表元素的包，会盲目假定对端向后兼容，并用旧握手回应。看见对方没断开，不是两边已经谈成新功能。

官方原文：本页向后兼容，所有合法的旧版第 4 版包仍被接受。看见本页，不是旧握手已经退役。

官方还写过：明文长度前缀可能帮对手在网上认出这类连接。这是对手肯花多少力气的问题，不是本页已经抗审查，也不是长度前缀已经等于身份暴露。

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见能吞多余字段就已经在说新协议 / 就已经改了共识 / 就已经退役旧握手」。线协议版本、发现包、传输握手是三个旋钮。版本号对不上仍连着，是官方留下的旧假定，不是能力协商已经齐。235 eip8 vs already new bundled unbundling 完成（1283 item 1 / 1284 item 2 / 1285 item 3）；精读 [`worked-example-eip8-nothello-vs-bundled.md`](worked-example-eip8-nothello-vs-bundled.md)（不变量 1283 item 1）、[`worked-example-eip8-notdisc-vs-bundled.md`](worked-example-eip8-notdisc-vs-bundled.md)（不变量 1284 item 2）、[`worked-example-eip8-nothand-vs-bundled.md`](worked-example-eip8-nothand-vs-bundled.md)（不变量 1285 item 3）。

## 本页不抄

- hello / 发现 / 握手的测试向量、密钥、随机数。
- 版本号取值、发现包最大长度、填充长度区间、旧包固定长度。

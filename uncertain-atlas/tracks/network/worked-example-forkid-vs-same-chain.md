# 例：看见分叉标识对上不是已经同一条链；看见通告了下一分叉不是已经兼容

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Ethereum [EIP-2124](https://eips.ethereum.org/EIPS/eip-2124)（Final, Networking）。  
**对应课文**：[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：`index/03` 共识行、M5.4、L5.1、L5.4、05b。分叉标识是网络身份，不是共识难度，也不是 EVM 气页。

## 官方三件事

规范把一次身份方案写成三件独立的网络事，不是「握手里多一个哈希」一件事：

1. **分叉标识概括创世和已经应用的分叉。**  
   官方写：不同网络的节点根本不该考虑互连；创世相同、分叉不同（例如后来分出去的那条）应当互拒。看见分叉哈希对上，不是已经用朴素相等判定同一条链。官方还写：创世就带上非 Frontier 规则集，那不算一次分叉。看见创世规则已经不是 Frontier，不是本页已经把创世算进已应用分叉。
2. **校验是交叉核对，不是两边哈希相同就连。**  
   官方写：本地和远端分叉哈希相同，还要把本地头跟远端通告的下一分叉比。远端通告了一个自己还没过、本地已经过了的高度，断开——链已经不兼容。看见通告了下一分叉，不是已经兼容。官方写：远端哈希是本地已过分叉的子集、且远端下一分叉对上本地紧跟着的那一次，按远端还在同步来连。看见子集，不是已经陈旧、也不是已经不兼容。官方写：远端哈希是本地已过分叉的超集、且能用本地知道的未来分叉补齐，按本地还在同步来连。看见超集，不是本地已经该升级。官方写：硬分叉过去之后，升过级的应拒没升级的，但**不要提前拒**。看见分叉已经过，不是分叉前就已经该踢掉剩下来的节点。
3. **本页只定义身份方案和校验规则，不改功能，也不解决同一高度三向分叉。**  
   官方写：同一未来高度拆成「不分叉 / A / B」三路，要把分叉者彼此分开，需要个案特殊处理；本页故意不处理，以免太容易从主网拆出去。看见有了分叉标识，不是已经改了共识，也不是三向分叉已经能分开。官方写：只通告下一次分叉，不把所有已知未来分叉哈希进去，因为未来还不确定，可能推迟。看见只通告下一次，不是未来分叉清单已经齐。

CRC 取值、分叉高度、编码样例是规范里的常数，本页不抄。

## 官方为什么这样拆

- **概括 ≠ 已经同一条链：** 官方说发现协议本来分不清公网、私网、测试网；只靠连上再握手太贵，也分不清后来分出去的那条。看见能概括，不是已经用密码学哈希钉死身份。
- **通告下一分叉 ≠ 已经兼容：** 官方要区分「还在同步」和「软件陈旧」。只分享已经过的分叉，分不清落后和卡住。看见通告了下一高度，不是那次分叉已经过，也不是两边软件已经齐。
- **身份方案 ≠ 已经改共识：** 官方写本页不定义功能变化。看见握手或发现记录里能嵌这份摘要，不是已经写了发现记录格式本身，也不是已经改了出块规则。

# 例：看见拒收消息不是已经共识非法；看见调试理由不是已经该给用户看；看见没拒收不是已经是当前最好链

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Bitcoin [BIP-61](https://github.com/bitcoin/bips/blob/master/bip-0061.mediawiki)（Deployed, Peer Services）。  
**对应课文**：[L3.2](../../courses/level-03-bitcoin/L03-M02-fees-and-standardness.md)、[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)、[L9.2](../../courses/level-09-systems/L09-M02-mempool.md)。  
**不要写进**：`index/03` 共识行、Ethereum 行、M5.4、L5.1、L5.4、05b。本页是点对点层「这个对等节点回了一句拒」，不是策略大类已经等于共识，也不是已经全网拒绝。

## 官方三件事

规范把一条拒收消息写成三件独立的传播事，不是「邻居拒了就已经被链拒绝」一件事：

1. **拒收只是这个对等节点对版本、交易或块消息的直接反馈。**  
   官方写：本页新增一种消息，直接回给对等节点，用来回答版本、交易或块。动机是互操作：让对方知道为什么块或交易被拒，或为什么因没按协议走被踢。官方还写：否则合法、只是还不是这个节点心里当前最好链的块，不应当触发拒收。看见拒收，不是已经共识非法，也不是全网已经知道，也不是已经封禁。看见没拒收，不是已经收下，也不是已经是当前最好链。
2. **人读理由只给调试用；各实现可以写不同的句子，不得拿给用户看。**  
   官方写：人读字符串只打算用来调试。尤其是，不同实现可以用不同的句子。这条字符串不应当给用户看，也不应当拿去做互操作诊断以外的事。看见一条拒收理由，不是已经是官方原因，也不是已经写进共识，也不是已经该弹给用户。
3. **码分句法、语义和本节点策略三类；对手也可以对合法对象乱发拒收。**  
   官方写：码分成协议句法错误、协议语义错误、本节点策略规则三类。官方还写：实现必须考虑对手对合法交易或块发拒收、或乱发拒收；把每条拒收都通知用户，会变成骚扰；把每条都写进调试日志，会把盘写满。看见策略拒收，不是已经共识非法。看见语义非法码，不是已经全网非法。看见一条拒收，不是已经该弹窗或已经该写满日志。

拒收码取值、协议版本号、字段宽度是规范里的数字，本页不抄。

## 官方为什么这样拆

- **这个节点拒 ≠ 已经共识非法：** 官方只让这个对等节点回一句。看见拒，不是链已经判死刑。
- **调试句 ≠ 已经给用户看：** 官方把人读字符串写成调试专用。看见理由，不是已经该弹窗。
- **策略码 ≠ 已经共识码：** 官方把策略单独一类。看见策略拒，不是已经非法。没拒收也不是已经最好链。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| 拒收消息 | 这个对等节点回了一句拒 | 不是已经共识非法 / 已经全网知道 |
| 调试理由 | 只给互操作诊断 | 不是已经该给用户看 |
| 策略码 | 本节点策略 | 不是已经共识非法 |
| 策略拒绝 ≠ 共识非法 | 另一对象 | 不变量 144 |
| 跳过库存通告 ≠ 已经拒进池 | 另一对象 | 不变量 245 |
| 内存池查询 ≠ 已经有那些交易 | 另一对象 | 不变量 253 |
| 拒绝路径代价 | 另一对象 | 不变量 44 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见拒收消息就已经共识非法 / 就已经该弹给用户 / 就已经是全网拒绝」。若对照拒收反馈，必须分开这个节点回了一句、调试理由、策略码与共识码。不要把没拒收写成已经是最好链。不要写怎样用拒收骚扰或灌盘。

## 本页不抄

- 拒收码取值、协议版本号、字段宽度、哈希宽度。
- 怎样对合法对象乱发拒收、怎样骚扰用户、怎样把日志盘写满。

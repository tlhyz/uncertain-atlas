# 例：看见 ping 带了记录序号不是已经有当前记录；看见能请求不是已经解析完

**层次**：网络 / 规范对象。  
**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：Ethereum [EIP-868](https://eips.ethereum.org/EIPS/eip-868)（Final, Networking；依赖 8、778）。  
**对应课文**：[L9.1](../../courses/level-09-systems/L09-M01-p2p.md)。  
**不要写进**：`index/03` 共识行、M5.4、L5.1、L5.4、05b。本页是发现第 4 版怎么要最新一份，不是记录格式本身，也不是 EVM 气页。

## 官方三件事

规范把一次发现扩展写成三件独立的网络事，不是「握手里多一个序号」一件事：

1. **现有 ping / pong 加一个字段，带发送方当前记录的序号。**  
   官方写：其余字段含义不变。看见 ping 里有序号，不是已经拿到当前记录。看见两边序号对上，不是已经把记录取回来。
2. **新增一对请求 / 答复，用来要当前这一份记录。**  
   官方写：收到请求应回应当前版本；答复里带被答复的请求哈希和记录。收到答复的人应核：这份记录是由发出答复的那个节点签的。看见能发请求，不是已经解析完。看见回了记录，不是已经核过签名。
3. **请求有放大防护；解析路径是先查找、再要记录。**  
   官方写：发请求的人应当最近刚答过一次 ping，和 FindNode 同一条防护。过期的包不应答复。官方还写：要按公钥解析当前记录，先用 FindNode / Neighbors 做递归查找；找到节点后再发请求，返回答复里的记录。看见公钥，不是已经有当前记录。看见 FindNode 找到人，不是已经拿到记录。

包类型号、过期怎么算是规范里的常数，本页不抄。

## 官方为什么这样拆

- **序号在 ping 里 ≠ 已经有记录：** 官方要桥接当时的发现网和以后的发现网，并给 DNS 等转发一条「去要最新一份」的路。看见能通告序号，不是记录已经在手里。
- **请求 ≠ 已经解析：** 官方把「要」和「核签」写成两步。看见能要，不是已经验过是那个节点签的。
- **能请求 ≠ 已经没有放大：** 官方把防护写成和 FindNode 同一类。看见协议里有请求，不是放大面已经消失。看见查到邻居，不是记录格式已经换，也不是已经信任。

## 和相邻页的边界

| 对象 | 本页 | 那一页 |
|---|---|---|
| ping / pong 里的序号 | 通告当前序号 | 不是已经有记录 |
| 请求 / 答复 | 要当前一份并核签 | 不是已经解析 |
| FindNode 再请求 | 解析路径 | 不是已经有记录 / 已经信任 |
| 节点记录格式 | 另一对象 | 不变量 240 |
| 分叉标识 | 另一对象 | 不变量 239 |
| 忽略版本 / 多余字段 | 另一对象 | 不变量 235 |
| 对等历史窗 | 另一对象 | 不变量 207 |
| 握手请求有界 | 另一对象 | CVE-2020-5303 |
| DNS 转发本身 | 另一对象 | 不另写 19 节 |

## 产品

**建议（产品，不是事实）**：不确定第一条结算机可以跳过「看见 ping 带了序号就已经有当前记录 / 就能请求就已经解析 / 就已经没有放大」。若对照发现要记录，必须分开通告序号、请求答复、查找路径。不要把找到邻居写成已经信任。

## 本页不抄

- 包类型号、过期字段怎么填、查找跳数。
- 怎样造放大流量、怎样伪造答复、怎样用过期包试探。

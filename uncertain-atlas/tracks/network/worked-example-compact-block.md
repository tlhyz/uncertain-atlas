## 1. 核心问题

阿比看见「节点用 compact block 拼出了块」，以为：

1. 这就是共识验块；或
2. 拼失败 = 该块非法；或
3. 宣布者没立刻给齐 = 链停了。

三句都假。Compact block 是**少传字节、用自己的池去猜**。猜对是实现运气。共识仍要完整交易列表与 Merkle 承诺对齐。

---

## 2. 直觉（ELI15）

班长只念座号后几位。你对照自己书包里的作业，把整张座位表补齐。补不齐就向班长要缺的那几本。有人同号、或塞给你一本不在目录上的本子，目录对不上——这时该要全套讲义，不是把班长开除，也不是宣布这节课非法。

## 3. 正式对象（事实）

| 对象 | 它是 | 它不是 |
|------|------|--------|
| `cmpctblock` / 短 ID | 传播提示：这些交易可能你已经有 | 共识块本身 |
| 机会主义重建 | 用本节点池拼出候选列表 | 协议保证每次都能拼出 |
| Merkle 根核对 | 拼完必须对上宣布的根 | 「对上了就等于从创世验过脚本」 |
| `getblocktxn` / `blocktxn` | 补缺交易 | 第二次消息可以当断言过滤器 |
| 回退整块 | 碰撞/失败后的诚实路径 | 惩罚对等节点 |

**事实（CVE-2024-35202 公告）：** 短 ID 可能碰撞；碰撞时根会对不上。对等节点**不应**因此受罚，应回退整块。旧实现回退后没丢掉 `PartiallyDownloadedBlock`，第二条 `blocktxn` 断言崩节点。

**事实（CVE-2024-52922 公告）：** 宣布者不交付时，旧实现会长时间只等他。宣布 ≠ 已收到。

**事实（CVE-2012-2459）：** 两个不同叶列表不得承诺同一根；那是共识。Compact 拼错若根对不上，只是**这次没拼成**，不是那条不变式被改写。

## 4. 三案对照

| | 52922 | 35202 | 2012-2459 |
|--|-------|-------|-----------|
| 对象 | 块下载调度 | 部分下载实例生命周期 | Merkle 规范 |
| 失败样子 | 等不到新块 | 进程断言退出 | 变异块与合法块同根 |
| 层 | 实现 + 网络 | 实现 + 网络 | 协议 + 实现 |
| 不是 | 块非法 | 共识拒块 | 「实现自己约定一下就行」 |

## 5. 五层

| 层 | 本页能说的 | 不能说的 |
|----|------------|----------|
| 密码学 | 拼完仍要根对齐；短 ID 不是抗碰撞哈希 | 「6 字节短 ID 已经后量子」 |
| 协议 | 共识吃完整列表；compact 不在共识规则里 | 「用了 compact 所以更安全」 |
| 实现 | 部分对象必须一次终结；断言不当对等过滤 | 某版本默认短 ID 参数当永恒 |
| 部署 | 池越不像，机会主义重建越难 | 现行并行下载路数 |
| 经济 | 卡住传播会伤挖矿公平（52922 公告原句形状） | 未标注日期的孤块率 |

## 6. 对不确定的意义（建议）

- 第一版可以先传整块。压缩/短 ID 是传播优化，必须另写状态机：失败清实例、能换对等节点、碰撞不罚。
- 后量子大块会逼你做部分下载。先写 52922 + 35202 两句，再谈带宽广告。
- 不要把「拼出来了」写成结算文案。结算仍是完整对象 + 全节点规则。

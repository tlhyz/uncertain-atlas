# 实例：筐里有信，阿比已经放货

目的 A。不是考试。  
先修：L9.2、L0.7、L3.2、结算文案。

---

## 故事

阿安广播了付 1。阿比的钱包显示「已发送 / 在内存池」。货出门。  

三种常见后续：

| 后续 | 阿安的 1 | 阿比的货 |
|---|---|---|
| 被更高费同 nonce / 同输入替换 | 没进 canonical | 已出门 |
| 标准性拒（共识其实允许） | 永远进不了这台节点的筐 | 若阿比看的是另一台宽松池，两边故事不同 |
| 排序者/构建者审查 | 合法但不上块 | 已出门 |
| 验签炸弹把筐撑满 | 诚实交易被逐 | 已出门 |

**层：协议政策 + 部署 + 经济。** 池不是账本。L0.4 的「有效 ≠ 确认 ≠ 最终」在这里落地。

---

## 五层

| 层 | 本故事 |
|---|---|
| 密码 | 替换交易的签也可以是真的 |
| 协议 | 池规则常常**不是**共识 |
| 实现 | 驱逐/替换实现不一致 → 用户看见不同筐 |
| 部署 | 看谁的 RPC / 谁的池 |
| 经济 | 抢跑、替换、审查都是合法手续 |

## 「不确定」测试句（建议）

```text
产品「已发送」≠ 协议对象 Y
标准性拒绝必须显示为「本节点政策」，不得显示「链拒绝」
PQ 验签配额先于「更大的池」
```

# 例：看见提案收了交易不是已经从池里删掉；看见本块已 commit 不是已经不用再验剩下的；看见 CheckTx 过了不是已经永远有效

**分类**：事实（对象边界）+ 推断（产品）+ 建议（产品）。  
**来源**：CometBFT 官方 [Mempool](https://github.com/cometbft/cometbft/blob/main/spec/mempool/mempool.md)。  
**对应课文**：[L4.4](../../courses/level-04-bft/L04-M04-abci-and-wal.md)、[L9.2](../../courses/level-09-systems/L09-M02-mempool.md)。

## 官方三件事

规范把内存池和共识的交接写成三件独立的共识事，不是「看见提案收了就已经从池里拿走」一件事：

1. **看见共识从池里收了一串交易 / 看见这些交易进了提案 不是已经从池里删掉。**  
   官方写：共识向内存池要一串交易来造提案。这时这些交易**还不从池里删**。因为这块只是提案，还没决定。看见提案带了这些交易，不是池里已经没有它们。看见引擎按上限收了前缀，不是这些交易已经进块。看见收了，不是已经过了 Process。
2. **看见块已经 commit / 看见本块交易从池里去掉 不是已经不用再验剩下的。**  
   官方写：块决定之后，本块里的交易才从池里去掉。还留在池里的，要按应用的新状态再验一遍。看见 commit 了，不是剩下的已经不用再验。看见本块交易没了，不是池已经空了。看见再验开始了，不是剩下的已经永远有效。
3. **看见 CheckTx 过了 / 看见进了池 不是已经进块，也不是已经永远有效。**  
   官方写：进池前要先让应用验。有效性可以随应用状态变。某一状态绿了，后来可以变红。看见 CheckTx 过了，不是已经进块。看见进了池，不是已经结算。看见曾经绿过，不是已经永远有效。

实现名单、加锁、flush、再验次数是规范里的做法或取值，本页不抄。

## 官方为什么这样拆

- **提案收了 ≠ 已经从池里删掉：** 官方把「还没决定」写成还不能从池里拿走。
- **本块已 commit ≠ 已经不用再验剩下的：** 官方把去掉本块交易和按新状态再验剩下的分开。
- **CheckTx 过了 ≠ 已经永远有效：** 官方把进池前的验和状态变了之后还能变红分开。

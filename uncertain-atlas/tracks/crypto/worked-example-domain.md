# 实例：投票那一行字被当成转账

目的 A/B。不是考试。  
先修：L1.2、L1.6、模式 domain-separation、不变量第 6 条。

---

## 故事

验证者阿安用同一把钥，给高度 50 的 prevote 签了名。消息里如果只是「这块的哈希」，没有写 `type=vote`、`chain=Uncertain`。  
另一条链、或本链的用户交易路径，把同一串字节当成「阿安同意转 1」。

验签通过。印是真的。意图是假的。  
**层：协议工程（域分离），不是算法被破。**

后量子换库若不换域标签，旧票仍可能在新编码里被读错（接 L10.4 无标签裂链）。  
只用消息前缀、FIPS `ctx` 仍为空：算法层没有角色。第二层见 [`../post-quantum/fips-context.md`](../post-quantum/fips-context.md)、语料 C20。

---

## 五层

| 层 | 本故事 |
|---|---|
| 密码 | 算法可以仍安全 |
| 协议 | 消息类型 / chain id 是否进被签字节 |
| 实现 | 两客户端对缺标签各猜各的 |
| 部署 | 同一 sk 用在钱包和验证者进程 |
| 经济 | 被重放的是钱或是票 |

## 「不确定」测试句（建议）

```text
Verify(pk, m, σ) 的 m 必须含 chain | type | version
type=vote 的字节不得使 type=user-tx 为真
用户签与投票签分域，即使第一版算法相同
FIPS 204/205：ctx_vote ≠ ctx_tx，且都不得默认为空
```

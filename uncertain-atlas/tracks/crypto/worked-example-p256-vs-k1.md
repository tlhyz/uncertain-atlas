# 工作实例：看见 P256 验签预编译不是已经在验 k1

> **事实 / 推断 / 建议** 已分开。
> 对照：[L1.2](../../courses/level-01-crypto/L01-M02-signatures.md)、[L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)、[BLS12 算术 ≠ 已验 BLS](worked-example-bls-precompile-vs-verify.md)、[子群 ≠ 在曲线上](../failure-museum/cve-2025-30147.md)、[ECDSA 验得过 ≠ 严格 DER](../implementation/worked-example-valid-vs-der.md)。

## 1. 核心问题

阿比看见一条 secp256r1 验签预编译，以为合约已经在验 Ethereum 默认的 k1；或看见验绿，以为已经不可延展；或看见失败返回空输出，以为已经像别的预编译那样把剩余气烧光；或看见和某条 L2 接口兼容，以为 RIP-7212 那两个洞已经不存在；或看见规范编号 7951，以为就是 2537，或已经是 `ECRECOVER`，或已经是不变量 116 那次洞。

官方句（事实）：

- EIP-7951：加入一条预编译，用来在 secp256r1（也叫 P-256 / prime256v1）上做 ECDSA **验签**，并且带官方写成必须做的安全检查。
- 动机：给现代安全硬件（官方点名安全飞地、系统钥匙串、HSM / TEE、FIDO2 / WebAuthn）生成的签提供原生验。看见本页，不是已经是账户抽象，也不是已经是 WebAuthn。
- 本页**取代** RIP-7212：功能与接口相同，但没有那份漏洞。
- 针对 RIP-7212 的两处修补：必须检查恢复出来的点是不是无穷远；比较必须写成对阶取模的同余，不能写成坐标相等。
- 输入是定长拼接：消息哈希、签名两个分量、公钥两个坐标。长度不对、分量越界、点不在曲线上、点是无穷远，都必须失败。
- 对 secp256r1，`(0,0)` **不在曲线上**。一段全零字节按约定编码无穷远。公钥**不得**是无穷远。
- 成功输出一段定长、表示真的字节；失败输出空。任何情况下**不得 revert**。失败消耗的气，必须和成功时一样。
- 本页选的是**验签**，不是公钥恢复。官方对照：硬件和软件大多直接验；NIST 标准写的是验，不是恢复；对本曲线，验比恢复便宜；现有硬件接口也是验。
- secp256r1 的 ECDSA 签，按 NIST 标准**不要求**不可延展。需要不可延展的应用，必须自己在应用层再查。
- 本页**不要求**恒定时间算法。
- 与已部署在二层的 RIP-7212 接口兼容：同一地址、同一输入格式、同一输出格式、同一类返回值。气价不同。安全修补对正确实现的调用方透明，只影响本来就该失败的边角。
- 规范**没有**把本页写成已经在验 k1，也没有把验绿写成已经不可延展，也没有把空输出写成已经烧光，也没有把接口兼容写成 RIP-7212 那两个洞已经消失，也没有把本页写成 2537、`ECRECOVER` 或不变量 116。

验签预编译、k1 默认签、曲线算术预编译，是三件事。

## 2. 直觉（ELI15）

门口多了一台只认另一种门锁的验钥匙机器。  
这不是已经把原来那把门锁换了。  
绿灯亮了，不是这把钥匙已经不能被配一把还能开的。  
机器不发脾气、只摇头，不是已经把你剩下的力气罚光。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| P256 验签预编译 | secp256r1 上的 ECDSA 验 | 已经在验 k1 |
| 验绿 | 这份输入过了本页谓词 | 已经不可延展 |
| 空输出 | 失败且不 revert | 已经烧光剩余气 |
| 7951 | 带两处修补的验签接口 | 2537 算术；`ECRECOVER` 恢复；116 那次洞 |

## 4. 最小案例

一条 Ethereum 要对齐「这一口气 P256 预编译在验什么」。

1. 看见 P256 验签预编译。规范：secp256r1 上的 ECDSA 验。不是已经在验 k1。
2. 验绿。规范：过了本页检查。不是已经不可延展。
3. 失败返回空。规范：不得 revert，气和成功时一样。不是已经烧光剩余气。
4. 接口和 RIP-7212 兼容。规范：同地址、同输入输出形状。不是那两个洞已经没了。
5. 有人把这听成 2537（不变量 199）。那是 BLS12-381 算术和配对，不是验签指令。本页才是验签。2537 出错烧光本次调用气；本页失败不 revert。
6. 有人把这听成 `ECRECOVER`。那是 k1 上的公钥恢复。本页是 r1 上的验，官方故意不做成恢复。
7. 有人把这听成 116。那是子群过了不是已经在曲线上。本页要求点在曲线上，并且公钥不得是无穷远。
8. 有人把这听成 172。那是 Bitcoin 共识要严格 DER。本页是另一条曲线上的预编译验。
9. 有人把硬件动机听成已经是 WebAuthn / 已经是账户抽象。官方只写原生验让这些用法变得可能。

「看见 P256 = 已经在验 k1 / 验绿 = 不可延展 / 空输出 = 已烧光 / 兼容 = 7212 洞已没 / 7951 = 2537」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | secp256r1 验签；`(0,0)` 不在曲线上；无穷远按约定编码；不要求不可延展 |
| 协议 | 必须点名问的是验签、恢复、曲线算术，还是默认 k1 |
| 实现 | 失败不得 revert；必须查恢复点是不是无穷远；比较必须对阶取模 |
| 部署 | 不抄地址和气价当永恒；与某条 L2 接口兼容不是洞已经没了 |
| 经济 | 气价官方按实测比恢复预编译更贵；不当不确定常数 |

**推断：** 产品句若只写「链上能验硬件签了」，读者会把本页听成已经换了默认签，或把兼容听成 RIP-7212 的洞已经消失。  
**建议：** 第一版可以不做第二条曲线的验签预编译。若做，必须分开默认签、验签、恢复、曲线算术。不要发明「看见 7951 就已经在验 k1」。不要抄地址 / 气价。不要把 7951 写成 2537。

## 6. 和另外几句不是同一句

1. **预编译算术 ≠ 已验 BLS**（不变量 199）：2537 是曲线算术和配对。本页才是验签。2537 出错烧光本次气；本页失败不 revert。
2. **子群过了 ≠ 已经在曲线上**（不变量 116）：Besu 那次洞。本页要求在曲线上，并且公钥不得是无穷远。
3. **验得过 ≠ 已经是严格 DER**（不变量 172）：Bitcoin 编码谓词。本页是另一条曲线上的预编译。
4. **回滚 ≠ 烧光**（不变量 177）：带回剩余气的回滚。本页失败返回空，气和成功一样。
5. **JSON chainId ≠ 已经编进哈希**（不变量 161）：k1 用户交易的链绑定。本页不改默认签。

不要抄预编译地址 / 气价 / 域模数 / 曲线系数 / 生成元 / 阶 / 输入宽度 / 成功字面量。不要写怎样造可延展签、跳过无穷远检查，或用全零点当公钥。不编博物馆页。不另写 19 节。不转测试向量。EIP-2537 曲线算术、`ECRECOVER` 恢复、RIP-7212 原文、不变量 116 那次洞、BIP-66 DER 是另一对象。模幂输入帽（超帽烧光剩余气）不是已经是本页（206）。算术精读：[`worked-example-bls-precompile-vs-verify.md`](worked-example-bls-precompile-vs-verify.md)（不变量 199）。

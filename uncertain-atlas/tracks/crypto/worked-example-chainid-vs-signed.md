# 工作实例：看见 chainId 不是签名已经罩住这条链

> **事实 / 推断 / 建议** 已分开。
> 对照：[L1.2](../../courses/level-01-crypto/L01-M02-signatures.md)、[L2.2](../../courses/level-02-state/L02-M02-account.md)、[域分离](worked-example-domain.md)、[三层编码](worked-example-tagged-hash.md)、[基础费 ≠ 小费](../mempool/worked-example-basefee-vs-tip.md)。
> 主文献：[EIP-155](https://eips.ethereum.org/EIPS/eip-155) Simple replay attack protection。官方 EIP。不另写 19 节。
> 本页钉 **JSON 里的 chainId ≠ 已经编进签名哈希**、**旧的六字段签 ≠ 已经防跨链重放**、**EIP-155 ≠ EIP-1559**、**用户交易的链绑定 ≠ 投票域 / EIP-712 / FIPS ctx**。不抄分叉高度 / 链号表 / 例钥。不写怎样拿旧签去另一条链重放。

## 1. 核心问题

阿比看见钱包写了 `chainId`，以为签名已经罩住这条链；或看见规范编号 155，以为就是 1559 费用市场；或看见旧式 `v` 还能过，以为跨链重放已经没了。

官方句（事实）：

- EIP-155：一种**简单的重放防护**。
- 分叉之后、链号可用时：为了**签名**去算交易哈希，**应当**哈希九个 RLP 元素（原六字段再加 chainid、0、0），而不是只哈希六个。
- 若这样做，签名的 `v` **必须**按规范用链号编码，而不是旧的两种取值。
- 若选择仍只哈希六个值，`v` 继续用旧规则。
- 恢复公钥时：若 `v` 是链号编码的那两种，必须按九字段哈希恢复。旧的两种 `v` **仍然有效**，规则与以前相同。
- 动机：发出在本链能用、在另一条分叉链或测试网上**不能用**的交易。以后的测试网、联盟链、别的以太坊系链被鼓励采用本 EIP，并换成**自己的**链号。
- 规范**没有**把钱包 JSON 里写了 chainId 写成已经编进哈希，也没有把旧六字段签写成已经防跨链重放，也没有把本页写成费用市场。

看见链号、签进哈希、旧签仍能过，是三件事。

---

## 2. 直觉（ELI15）

信封上印了「寄往甲城」，不等于你在信纸上签的也是甲城。  
旧邮票还能用，不等于新规矩已经罩住所有旧信。  
门牌 155 不是门牌 1559。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 九字段签名哈希 | 原六字段再加 chainid 与两个零 | 钱包 JSON 已经写了 chainId |
| 旧六字段签 | 仍合法；`v` 走旧规则 | 已经防跨链重放 |
| EIP-155 | 用户交易的链绑定 | EIP-1559 费用市场；投票域；EIP-712 |
| 唯一链号 | 各链自己换一个值 | 已经分开投票 / typed data / FIPS ctx |

---

## 4. 最小案例

一条以太坊要对齐「这一口气签的是哪条链」。

1. 钱包 JSON 有 `chainId`。规范：只有按九字段去哈希，签名才罩住它。
2. 一笔仍走六字段、旧 `v`。规范：仍然有效，规则与以前相同。不是已经防跨链重放。
3. 有人把本页听成 1559（不变量 158）。那是基础费与小费。本页是签名预像里有没有链号。
4. 有人把本页听成投票字节不得当转账（不变量 6）。那是角色域。本页是同一类用户交易换一条链。
5. 有人把本页听成 EIP-712 / FIPS `ctx`（不变量 18）。那是钱包 typed data 或后量子包装。本页是共识交易哈希。
6. 有人把同链 nonce 听成本页。nonce 挡同链重放。本页挡跨链重放。
7. 有人把「链号表上有这个数」听成签名已经罩住。规范只鼓励各链换自己的号，不把登记表写成已经签过。

「看见 chainId 所以已经防重放 / 155 就是 1559」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 哈希罩住的字段才算绑住 |
| 协议 | 必须点名问的是九字段签、旧六字段签，还是钱包 JSON |
| 实现 | 恢复时按 `v` 选六字段还是九字段；两客户端必须同 |
| 部署 | 旧签仍能进块；不是已经全体换新 |
| 经济 | 能在本链过 ≠ 不能在分叉链过 |

**推断：** 产品句若只写「有 chainId」，读者会把 JSON 字段听成已经进哈希。  
**建议：** 用户交易的签名预像必须含链绑定。JSON 里有字段不够。不要留一条「旧六字段已经防跨链」的产品句。不要抄链号表。不要发明「155 = 1559」。

---

## 6. 和另外几句不是同一句

1. **投票字节 ≠ 用户交易**（不变量 6）：角色域。本页是用户交易换链。
2. **FIPS ctx 按角色**（不变量 18）：后量子包装。本页是 secp256k1 交易哈希。
3. **基础费 ≠ 小费**（不变量 158）：EIP-1559。编号相近，不是本页。
4. **三层编码**（tagged hash）：BIP-340 / EIP-712 / FIPS。本页不是 typed data。
5. **同链 nonce**：挡同链重放。本页挡跨链。

不要抄分叉高度 / 链号表 / 例钥 / 例哈希。不要写怎样拿旧签去另一条链重放。不编博物馆页。不另写 19 节。EIP-1559、EIP-712、CL `DomainType`、链号登记表、类型交易信封标成另一对象。

# 失败案：哨兵有效槽 0 不是卸载后再编译已经可见

层：**实现 + 协议**（旧加载器账户不保留部署槽；卸载条目挡在哨兵 0 前面，每次主循环都再编译；关闭部署入口不是缓存谓词已改完）

官方披露：

- Solana 官方转载 Anza 复盘：[02-06-24 Solana Mainnet Beta Outage Report](https://solana.com/news/02-06-24-solana-mainnet-beta-outage-report)。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 2024-02-06 **09:53 UTC**，Mainnet Beta **最终确认停住**。根因与前一周 **Devnet** 停机相同，补丁本已在路上。补丁略改，使集群**一重启就立刻生效**，打进 **v1.17.20**。验证者把 **246,464,040** 定为当时最高、仍能拿到的**乐观确认槽**，从那里做快照重启。约 **12:34 UTC** 发布二进制与重启指令。约 **14:55 UTC** 共识重新前进。整段约五小时。
- 客户端 JIT 编译被交易引用的程序，并缓存常用结果。v1.16 用 `LoadedPrograms` 替换 `ExecutorsCache`：缓存改成**全局、感知分叉**；执行线程**协作加载**，避免编译互相堵。感知分叉要记每个部署的**有效槽高**（程序从哪一槽开始生效），以便链上字节被替换时作废缓存。协作加载还为被引用过的程序记用量，包括因驱逐或作废而卸下 JIT 输出的那些。
- 现代加载器：能从链上账户读最近部署槽，再算有效槽高。**旧加载器账户不保留部署槽**，于是碰到旧加载器程序时，有效槽用哨兵 **0**。例外：亲眼看见一次**部署指令**（字节被替换），则不论哪种加载器，都按**真实有效槽**插入账本。这条刚插入的记录**从未被交易引用**，很容易被赶走。赶走后 JIT 丢掉，账本改成「已卸载」，但仍留着那个有效槽高。
- 下一笔交易再引用：状态是已卸载，必须再编译。编译完按该程序的有效槽高插入。下一轮主循环本应看见它。但旧加载器这条新 JIT 被插在哨兵 **0**，落在「已卸载」那条**后面**，主循环永远看见未加载，于是**同一程序无限再编译**。
- 若只有这一条：本可只卡住正在执行该交易的 **leader**，块发不出去，触发交易也不会传到全网。v1.16 **还没有协作加载**，不会走到这个退化情形，触发交易也就进不了块。v1.17 有了协作加载，触发交易被打进块、传到其余验证者，大家在**回放**里撞上死循环。当时超过 **95%** 质押跑 1.17，几乎所有人停在这块上，没人投票，共识**不可恢复地**停住。
- 两个能触发的旧加载器：v1 **已经禁止新部署**；v2 已弃用，原定 v1.18 周期再禁止部署。止血是把 v2 的禁止部署**回移到 v1.17**，并**去掉功能门**，集群一重启 v2 立刻不能再部署。这消除触发前提，比先改完 `LoadedPrograms` 简单。更完整的缓存修补随常规发布。

本页不写怎样走「部署—驱逐—再引用」，不抄 95% / 槽号进不确定常量。关闭旧加载器部署入口不是缓存谓词已经改完。

## 1. 发生了什么

一本旧程序没有写下「我从哪一页开始生效」。  
缓存用 0 页当缺省。  
有人换了字节。新页号写进去，很快被挤掉。  
再有人点这本程序。编译好了，却又塞回 0 页。  
0 页在「已卸下」后面。下一轮还当没编译。  
再编译。再看不见。  
leader 若只卡自己，块发不出去，别人没事。  
协作加载把这张单打进块。几乎全屋回放时一起转圈。  
没人投票。链不转。  
哨兵有效槽 0，不是卸载后再编译已经可见。

## 2. 根因

旧加载器账户不保留部署槽，缺省有效槽写成 0。  
驱逐之后，「已卸载」条目仍占着真实有效槽；新 JIT 插在 0，被挡在后面。  
主循环按「看得见的有效条目」判断是否要编译，于是同一程序无限再编译。  
协作加载让这张交易能进块、能广播；没有它，本可只卡 leader。  
Devnet 已经撞过，主网补丁还在路上——已识别不是已打上。  
重启时关掉 v2 部署，是拆掉前提，不是 `LoadedPrograms` 已经改完。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 43 | 并行验签作业寿命；本页是 JIT 缓存主循环 |
| 不变量 32 | 孤儿解析卡住事件循环；本页是回放里无限再编译 |
| 不变量 85 / 2022-06-01 | 失败 durable nonce 双路径 |
| 不变量 86 / 2022-09-30 | 已确认不能当父块 |
| 不变量 87 / 2023-02-25 | 恢复 shred 过滤 / vote-only |
| 不变量 69 | 非法提案 / 出块变少 ≠ 停 |
| 本页 | **哨兵有效槽 0 ≠ 卸载后再编译已可见；关掉旧加载器部署 ≠ 缓存谓词已改；只卡 leader ≠ 全网已停；Devnet 已识别 ≠ 主网已打补丁** |

## 3. 被破坏的 invariant

- 旧加载器若账户不保留部署槽，不得用会被挡在「已卸载」后面的哨兵 0 当再插入键（不变量 88）
- 编译完成并插入，不是主循环已经看得见
- 协作加载让触发交易进块，不是只有出块者会卡
- 重启时禁止再部署，不是缓存实现已经修完
- 95% 跑某版，不是该洞已经不在

## 4. 为什么测试没发现

幸福路径：现代加载器账户里有部署槽，插入位置与可见位置一致。  
只测「编译一次、下次命中缓存」会绿。  
边角要：旧加载器 + 亲眼看见部署 + 该条目被赶走 + 再引用 + 再插入落在哨兵 0。  
v1.16 没有协作加载，触发交易出不了块，单节点测试更看不见全网回放一起转圈。  
Devnet 已经出过，主网补丁尚未上——识别了不是已经挡住。

## 5. 修复

官方：从最高乐观确认槽重启，打 v1.17.20；v2 部署在重启当下禁用（去掉功能门）。  
这消除再制造前提。更完整的 `LoadedPrograms` 修补随常规发布。  
关掉部署入口 ≠ 哨兵 0 的插入规则已经改对。v1 早已禁止新部署，不等于 v2 已安全。

## 6. 「不确定」若同类

1. 第一版不要保留「账户里没有部署世代、缓存用哨兵槽」的旧加载器。要嘛账户写世代，要嘛禁止再部署。
2. 缓存若分「已卸载 / 已加载」，插入键必须与查找键是同一对象。哨兵 0 不得落在卸载条目后面还当命中。
3. 协作加载 / 并行预编译若让交易进块，必须测「leader 卡死」和「全网回放卡死」两句。只测出块者不够。
4. 实验网已撞见的洞，主网补丁未上之前，不得写成已缓解。
5. 重启时关功能门是止血，不是谓词已改。不要抄 95% 或乐观确认槽号。
6. 这和并行验签寿命（43）、孤儿扫描（32）、durable nonce（85）、重复槽（86）、恢复 shred（87）不是同一句。不要写怎样走部署—驱逐—再引用。

## 7. 回归测试

形状（不是利用包）：文案把哨兵有效槽 0 写成卸载后再编译已可见必须红。把关掉旧加载器部署写成缓存已修必须红。把「只卡 leader」写成全网不会停必须红。把 Devnet 已识别写成主网已打补丁必须红。与 2022-06-01 / 09-30 / 2023-02-25 糊成一句必须红。

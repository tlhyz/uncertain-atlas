# 失败案：失败的 durable nonce 不是已经不能再播

层：**协议 + 实现**（未推进的链上 nonce 不是已消费；缓存过期两边各执一词会停；不是 Tower / PoH 已经一致）

官方披露：

- Solana 官方复盘：[06-01-22 Solana Mainnet Beta Outage Report](https://solana.com/news/06-01-22-solana-mainnet-beta-outage-report-2)。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 2022-06-01 约 **16:30 UTC**，Mainnet Beta **停止出块**，共识卡住，根因是 **durable nonce 交易功能**里的运行时漏洞。
- 验证者一起重启；durable nonce **暂时关闭**。约 **21:00 UTC** 恢复出块。与 1.10 / 1.11 的改进**无关**。
- 失败的 durable nonce 交易在特定情形下可被**处理两次**，造成**非确定**：有的节点拒后续块，有的收。**超过 33%** 的验证者收下了那块，但**不够 66%**，无法对齐。
- 普通交易（官方写 **>99.99%**）：用 recent blockhash，再靠窗口内「已处理」记录防双处理。
- Durable nonce：设计为**不过期**，所以换机制；**串行**处理。链上每账户有一个值，**每次成功的 durable 处理**后轮换；轮换后同一笔 durable nonce 交易不应再被处理。
- 漏洞路径：这笔 durable 交易被处理时，它的 blockhash **仍够新**，看起来像普通交易 → 运行时**当成普通交易**，**没有推进**链上 nonce → 交易**失败**，但因为进了块，**手续费已付** → nonce **仍可用**。
- 用户**重提同一笔** → 出块者因 nonce 未推进而**错误收下** → 校验时：一部分验证者认为「已经处理过」（仍在近期缓存里），另一部分接受（缓存里已经没有上一笔）。超过 33%、不够 66%。
- 在 **v1.9.28 / v1.10.23** 关闭该功能，直到缓解落地并重新打开。

本页不写怎样让一笔交易同时走两条路径，不写怎样凑「仍够新」的 blockhash，不抄 33 / 66 进不确定法定人数。第一版可以不提供不过期 nonce。

## 1. 发生了什么

一笔该过期却被设计成不过期的票。  
第一次失败了。手续费付了。票根没撕。  
用户再递一次。  
一半屋子说「这张用过了」，一半说「没见过」。  
票数过了三分之一，没到三分之二。  
链不转。  
失败的 durable nonce，不是已经不能再播。

## 2. 根因

运行时看见还够新的 blockhash，就把 durable nonce 当成普通交易。  
普通路径不推进链上 nonce。  
失败进块 ≠ nonce 已被消费。  
重提时，近期缓存是主观的：有的节点还记得上一笔，有的已经忘了。  
诚实节点走出两个世界，高度停。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 3 / L1.6 | 一般确定性：Apply 不得读本地钟或 OS 随机数 |
| 不变量 77 / ISA-2025-001 | 跨链 ack JSON 反序列化必须确定 |
| 不变量 82 / Jackfruit | ValidateBasic 读节点本地钟 ≠ 已确定 |
| 不变量 69 / ASA-2024-002 | 非法提案 / 序号洞 ≠ 高度已经停 |
| 不变量 4 | 锁：诚实节点不得对两个冲突值违规承诺 |
| L6.1 | PoH 是顺序证明，不是单独的 BFT；本页不是「PoH 崩了」 |
| Bitcoin / Cosmos 序号 | 串行递增 nonce 本身；本页是「失败却没撕票根」再加缓存两边各执一词 |
| 本页 | **失败的 durable nonce ≠ 已不能再播；当普通 recent-blockhash 处理（nonce 未推进）再收下重提 ≠ nonce 已被消费；>33% 接受且不足 66% 对齐 ≠ Tower / PoH 已经一致** |

## 3. 被破坏的 invariant

- 失败的 durable nonce 交易不是已经不能再播（不变量 85）
- 运行时把它当普通 recent-blockhash 交易、不推进 nonce，不是 nonce 已被消费
- 近期已处理缓存不是全网同一对象；一边拒、一边收，超过 33%、不够 66%，是停链，不是 Tower / PoH 已经一致
- 能提交 durable nonce 的用户集合，在该功能打开时，就是能引入停链状态的集合

## 4. 为什么测试没发现

幸福路径：成功的 durable nonce 会轮换链上值，同一笔不能再走。  
只测「成功一次、再播被拒」会绿。  
失败路径看起来像普通交易：手续费付了，像已经结算，nonce 其实没动。  
单节点测试只有一份近期缓存，看不见「还记得」和「已经忘了」同时存在。

## 5. 修复

官方：在 v1.9.28 / v1.10.23 **关闭** durable nonce，直到缓解落地并重新打开。  
恢复出块靠验证者集体重启，找到最远进度。关闭功能 ≠ 谓词已改完。  
与 1.10 / 1.11 性能改进不是同一件事。

## 6. 「不确定」若同类

1. 第一版可以不提供不过期 / durable nonce。普通「近期哈希 + 全网同一已处理记录」就够结算。
2. 若提供不过期授权：失败路径必须与成功路径一样推进（或作废）同一链上对象。进块付费不是票根已撕。
3. 「已处理」缓存若影响收块，必须是全网能复算的对象，不得让诚实节点一边还记得、一边已经忘。
4. 非确定一旦让一部分人收、一部分人拒：写停链，不要写成 Tower / PoH / 锁已经对齐。不要把 33 / 66 抄进不确定法定人数。
5. 这和一般确定性（3）、ack JSON（77）、ValidateBasic 读钟（82）、非法提案（69）、锁（4）不是同一句。
6. 不要把「PoH 在转」写成共识还在出块。不要写怎样走双路径。

## 7. 回归测试

形状（不是利用包）：文案把失败的 durable nonce 写成已经不能再播必须红。把「当普通 recent-blockhash 处理、nonce 未推进」写成 nonce 已被消费必须红。把一边收一边拒、超过 33% 不够 66% 写成 Tower / PoH 已经一致必须红。把手续费已付写成票根已撕必须红。与 Jackfruit / ack JSON / 非法提案糊成一句必须红。

# 失败案：ASA-2024-001 扩展启用高度的治理变更必须先过合法转移谓词

层：**实现 + 协议**（`VoteExtensionsEnableHeight` 作为可治理的共识参数；块规则没有另发明一条）

官方披露：[ASA-2024-001 / GHSA-qr8r-m495-7hc4](https://github.com/cometbft/cometbft/security/advisories/GHSA-qr8r-m495-7hc4)。咨询标 **High**。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- CometBFT 对 `VoteExtensionsEnableHeight` 的**验证逻辑**有漏洞，可在 ABCI2 应用链上通过**治理参数变更提案**触发**停链**。
- 若包含修改 `VoteExtensionsEnableHeight` 的参数变更提案通过，受影响版本的节点**可能 panic**，网络停。
- 修法：改进该参数的验证，使其能正确处理针对它的治理提案。
- 可用「软补丁」：节点可在不同时间打补丁并重启，不必先协调停链升级。咨询写：超过 **66.7%** 投票权打上补丁后，利用风险被缓解；全部验证者更新后，本条停链风险才完全解除。
- 建议当时仍跑 0.38.x 的链应用升到 v0.38.3 或更新。

本页不写提案字节怎么拼、不发明「验证逻辑具体漏了哪一行」——咨询只写到「验证逻辑」和「正确处理治理提案」。66.7% 是官方缓解句，不是不确定法定人数常量。

## 1. 发生了什么

链上治理改了一个「从哪一高度开始要带 vote extension」的参数。实现验不好这次变更，节点不是拒掉非法参数，而是**进程崩**。多数节点一崩，共识停。

这不是「扩展没验过所以块非法」（不变量 34），也不是「扩展快路径跳过下标」（不变量 57）。这是**启用高度本身**作为共识参数，转移写错。

## 2. 根因

可治理的共识参数被当成「治理过了就一定能吃」。  
启用高度有合法/非法转移（现在关、以后开、已经开过不能乱改……）；咨询没有展开谓词表，但承认当时的验证处理不了治理提案。  
panic 把实现错误抬成全网活性故障。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 34 | Verify 拒扩展丢掉整张 Precommit |
| 不变量 57 / ASA-2024-011 | 扩展快路径跳过 `ValidatorIndex` |
| 不变量 35 | 验证者集合更新的 H+1/H+2/H+3 |
| 不变量 52 | 应用回的 post-commit 等待 |
| 本页 | **启用高度参数的治理转移未验完就 panic** |

## 3. 被破坏的 invariant

- 可治理的启用高度必须先过合法转移谓词；失败必须拒参数，不得让进程退出（不变量 58）
- 治理通过 ≠ 实现已经能吃这个值
- 软补丁超过 2/3 投票权只缓解本条利用，不是参数已合法

## 4. 为什么测试没发现

幸福路径：创世就写死启用高度，或从不走治理改这个键。  
只测「扩展开着时 Verify / 下标」（34 / 57）会绿。  
不测「运行中用治理提案改 `VoteExtensionsEnableHeight`」。

## 5. 修复

- v0.38.3：改进该参数在治理提案路径上的验证。
- 官方软补丁程序：先让超过 66.7% 投票权升级，再走治理；全部更新后本条才消。

升级 ≠ 以后每个新共识参数都自动有转移谓词。每加一个可治理键，都要单独写「哪些变更合法」。

## 6. 「不确定」若同类

1. 第一版可以不启用 vote extensions，也就不必暴露 `VoteExtensionsEnableHeight` 给治理。
2. 若暴露：必须写出合法转移（从未启用 → 未来某高度启用；已启用后能否改、能否关）。写不出就不要做成治理参数。
3. 非法转移必须在进入共识状态机之前被拒。panic 是实现事故，不得写成「治理否决」。
4. 不要把咨询里的 66.7% / 0.38.3 抄进第一版当法定人数或版本政策。
5. 这和集合更新延迟（不变量 35）是亲戚：都是「哪一高度哪个哈希生效」；这边多一句「验证失败不得崩进程」。

## 7. 回归测试

形状（不是利用包）：针对 `VoteExtensionsEnableHeight` 的治理变更，非法转移必须让节点拒参数并继续跑；合法转移必须被所有实现同样接受。文案把「治理通过」写成「节点已能吃」必须红。进程因该键退出不得标 PASS。

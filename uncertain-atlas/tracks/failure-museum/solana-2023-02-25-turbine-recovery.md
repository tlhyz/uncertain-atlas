# 失败案：恢复 shred 不是已经按父槽滤掉；投票专用模式不是已经停链

层：**协议 + 实现 + 部署**（数据 shred 能按父槽滤，恢复 shred 没有这份元数据；转发服务坐在 Turbine 过滤前面；出块变慢 / 只打包投票 ≠ 高度已停，也 ≠ 已最终的经济交易被回滚）

官方披露：

- Solana 官方复盘：[02-25-23 Solana Mainnet Beta Outage Report](https://solana.com/news/02-25-23-solana-mainnet-beta-outage-report)。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 2023-02-25 约 **05:46:16 UTC**，Mainnet Beta **最终确认变慢**。降级期间，leader **自动进入 vote-only**：只打包投票，不打包经济交易。根因是主传播协议 **Turbine 拥塞**，多数块数据改走更慢的后备 **Block Repair**。
- 验证者怀疑刚升的客户端，尝试**在线降级**无效。最后选择**手动重启并降到上一稳定版**。2023-02-26 约 **01:28 UTC** 恢复正常最终确认与吞吐。这次重启**没有回滚任何已最终的经济交易**。
- 不规则流量来自**块转发服务**碰到一块异常大的块后失灵。大块压垮验证者去重过滤，数据在验证者之间**连续再转发**，新块加重，直到协议饱和。
- 官方：Turbine **本身**应对这种尺寸有过滤、应能丢掉它们；但块转发服务**坐在这套逻辑前面**，削弱了过滤。
- 大块来自一台失灵验证者，父槽**远在过去**。过大最可能是为证明中间时间而填充的 **PoH 虚拟 tick**（父槽不是紧邻槽时必须带上）。验证者因配置、软件或硬件离开共识时会这样。
- **数据 shred** 带父槽元数据，能按「父槽早于最近最终槽」滤掉。**恢复 shred** 没有这份元数据，不能这样滤。恢复 shred 压垮去重；网上的 shred 转发服务再把它们送回 Turbine 树，形成环。去重过滤饱和后出现**假阴性**，重复 shred 不被丢、继续转。
- Turbine 被环流压满后，传播落到 Block Repair（本意是补丢的 shred / 追块）。最终确认变慢。乐观确认一度还能继续。当本节点最近投票槽距最近最终槽 ≥ **400**（官方写约 160 秒，并标任意选择）时进入 vote-only，避免尖继续无限往前、给可能永远进不了最终块的用户交易乐观确认。
- 社区早期把事故和升到 **v1.14.16**、刚过 **66%** 质押联系起来。官方：Testnet 用 v1.13.6 与 v1.14.16 连续灌大块，**单靠大块不够**复现；**没有转发服务时网络通常扛得住这种大块**。v1.14.16 曾提高一块里允许的恢复 shred 上限，为的是降低重传延迟、保持与 v1.13.6 相当的传输可靠。
- 修法方向（官方已写出）：转发服务的去重本应打断复制重传，却失败了；重传管道的去重本来也不是为防 Turbine 树成环设计的。客户端 **v1.13.7 / v1.14.17** 改了去重（逻辑曲线、更大容量、可并行）。另有补丁：出过大块的出块者会中止，提示运营检查。长期：用 QUIC 换 UDP，让节点能保证吃到的 shred 走了协议规定的路径。

本页不写怎样造远父槽大块、不写转发服务如何成环、不抄 400 / 160 秒 / 66% / 过滤容量进不确定常量。第一版不要在过滤前面再加一层不执行同一谓词的转发。

## 1. 发生了什么

一块建在很久以前的父槽上。中间的时间要用空白节拍填满。  
切成碎片时，有的碎片写着「我爸是谁」，有的只负责补洞。  
写着爸爸的被丢掉了。补洞的还在转。  
转发柜台在安检前面，把补洞碎片送回树里。  
树成了环。主路堵死，改走慢修车铺。  
尖还在往前，最终确认跟不上。  
屋子改成只收投票，不收客人的单。  
投票专用模式，不是已经停链。

## 2. 根因

数据 shred 与恢复 shred 不是同一对象：过滤谓词写在父槽元数据上，恢复 shred 没有这份字段。  
转发服务坐在 Turbine 过滤前面，等于另开一条不执行同一谓词的路。  
去重饱和后的假阴性，让重复碎片继续转，不是「已经去重所以安全」。  
Block Repair 是补丢与追块的后备，不是主路已通。  
vote-only 是尖与最终槽拉太远时的安全态，不是高度已停，也不是已最终的经济交易被回滚。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 85 / 2022-06-01 | 失败 durable nonce 双路径；一边收一边拒，高度停 |
| 不变量 86 / 2022-09-30 | 已确认的重复槽赢家不能当父块；票还在、根不前进 |
| 不变量 69 | 非法提案 / 出块变少 ≠ 高度已经停——本页是最终确认变慢 + vote-only，不是那条 |
| 不变量 36 | 宣布 ≠ 已收到；本页是收到了、再转成环 |
| 不变量 23 / 59 | Celestia 纠删 / 分片下标；本页是恢复 shred 缺父槽字段 |
| L6.1 | Turbine 切 shred 是五笔账里的网络账；本页是过滤对象与转发位置 |
| 本页 | **恢复 shred ≠ 已按父槽滤掉；转发服务在过滤前面 ≠ Turbine 已丢掉旧父块；落到 Block Repair ≠ 主路已通；vote-only ≠ 已停链 ≠ 已最终经济交易被回滚；连续灌大块 ≠ 没有转发服务时也会同样垮** |

## 3. 被破坏的 invariant

- 恢复 shred 不是已经按父槽滤掉（不变量 87）
- 坐在过滤前面的转发服务，不是 Turbine 自己的过滤已经生效
- 去重过滤饱和后的假阴性，不是重复碎片已被丢
- vote-only / 最终确认变慢 / 落到 Block Repair，不是高度已经停，也不是已最终的经济交易被回滚
- 刚过 66% 升上某版，不是该版已被证明是根因；官方 Testnet：单靠大块不够，转发服务才是复现条件

## 4. 为什么测试没发现

幸福路径：数据 shred 带父槽，旧父块被丢掉，恢复 shred 只补「还活着的」洞。  
只测「Turbine 能丢超大块」会绿——官方写 Turbine 本身应能滤。  
测试网连续灌大块、却不接转发服务，仍绿。  
边角要：恢复 shred 没有父槽字段 + 过滤前面还有一层会再广播的服务 + 去重饱和出假阴性。

## 5. 修复

官方：在线降级无效；手动重启并降到上一稳定版后，正常最终确认恢复。已最终的经济交易没有被回滚。  
客户端 v1.13.7 / v1.14.17 改去重；出过大块的出块者中止。与转发服务商改他们的去重。长期用 QUIC 约束路径。  
改过滤容量不是「环已经不可能」。没有转发服务时 Testnet 灌更大的块也复现不了——那是复现条件，不是主网已免疫。

## 6. 「不确定」若同类

1. 第一版不要在规范过滤前面再加一层不执行同一谓词的转发 / 中继。加了就必须写成另一信任对象，并测「过滤本应丢掉的东西被送回来」。
2. 纠删 / 恢复对象若与数据对象字段不同，必须各自写过滤谓词。缺父槽 / 缺下标不得当成「同一种碎片」。
3. 去重必须写出饱和之后做什么。假阴性必须当会成环审，不得写成「我们有去重」。
4. 产品句必须分开：主传播、后备补洞、乐观确认、最终确认、vote-only。落到后备不是主路已通。只打包投票不是已经停，也不是结算已回滚。
5. 不要把「刚过 ⅔ 升上某版」写成根因。官方自己用 Testnet 否定了「单靠大块 / 单靠该版」。
6. 不要抄 400 槽、约 160 秒、66%、过滤容量。不要写怎样造远父槽大块。不要把 PoH 虚拟 tick 写成攻击教程。

## 7. 回归测试

形状（不是利用包）：文案把恢复 shred 写成已按父槽滤掉必须红。把转发服务写成 Turbine 过滤已生效必须红。把 vote-only / 落到 Block Repair 写成高度已停或已最终经济交易被回滚必须红。把「刚过 66% 升上某版」或「连续灌大块」写成充分根因必须红。与 2022-06-01 / 2022-09-30 糊成一句必须红。

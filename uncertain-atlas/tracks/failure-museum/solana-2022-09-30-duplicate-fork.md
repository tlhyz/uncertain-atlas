# 失败案：已确认的重复槽赢家不是下一领导者会往上建的父块

层：**协议 + 实现 + 部署**（确认了正确版本 ≠ fork choice 会把它当父块；票还在走、根不前进 ≠ Tower / PoH 已经一致；同一身份两台出块不是高可用）

官方披露：

- Solana 官方复盘：[09-30-22 Solana Mainnet Beta Outage Report](https://solana.com/news/09-30-22-solana-mainnet-beta-outage-report)。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 2022-09-30 约 **22:41 UTC**，Mainnet Beta **停住**：网络无法从共识实现漏洞造成的**分叉**里恢复。约次日 **06:57 UTC** 协调重启后恢复出块。
- 根因入口：某验证者的**热备节点故障**。主节点与热备**同时活着**，用**同一节点身份**，却提出**成分不同的块**，出现在**同一槽高**。这种重复出块在停机前至少持续 **24 小时**；该验证者大多数 leader 槽的重复块，集群按预期处理。
- 槽 **153139220（220）**：出现重复块，集群对其中一块达成共识，再进 221——官方写这是重复块冲突**应有的**解决。
- 槽 **221**：再次出现重复块。**正确版本的 221 已被确认**，但 fork selection 的漏洞让出块者**无法在 221 上继续建**，集群因此无法达成共识。
- 时间线：21:46 已有验证者报共识失败——**投票还在发生，根不前进**。22:00 调查能否不重启恢复。22:41 集群停住。23:09 发现重复出块者，联系运营方，把这些验证者下线。次日 00:08 **不重启的恢复失败**。01:10 发重启指令。06:57 **80%** 质押权重上线，根重新前进。07:30 核心组锁定很可能的漏洞。09:30 提出补丁并加了复现该边角的测试。10-03 合入 master 并回移各发布线。10-04 通知升到 **v1.10.40** 与 **v1.13.2**。10-07 **90%** 质押权重打上补丁后，核心组认为该洞对网络的风险已被充分缓解。

本页不写怎样触发 221 那条边角、不写热备如何配成双活、不抄 80 / 90 进不确定法定人数。第一版不要把「同一身份两台机器」写成高可用。

## 1. 发生了什么

同一把钥匙，两台机器，同一个槽，两份不同的块。  
多数时候屋子会挑一份，往下走。  
220 挑对了。221 也确认了正确那份。  
下一班却不肯把 221 当地基。  
票还在飞，根不往前。  
把那两台机器关掉，屋子仍起不来。  
已确认的重复槽赢家，不是下一领导者会往上建的父块。

## 2. 根因

重复块冲突解决，和「确认之后别人会不会往上建」，不是同一谓词。  
220 走通了「挑一份再前进」。221 确认了正确版本，fork selection 仍不让出块者把它当父块。  
投票还在，只说明有人仍在签；根不前进，说明规范历史没锁住。  
热备与主节点同一身份同时出块，是两名提议者，不是一台验证者的备份。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 4 | 锁：诚实节点不得对两个冲突值违规承诺 |
| 不变量 85 / 2022-06-01 | 失败 durable nonce 当普通交易再重提；一边收一边拒 |
| 不变量 69 / ASA-2024-002 | 非法提案 / 序号洞 ≠ 高度已经停 |
| 不变量 12 | 同根不同列表；本页是同槽两份不同成分的块 |
| 不变量 36 | 宣布 ≠ 已收到；本页是收到了、确认了、仍不能当父块 |
| L6.1 | PoH 是顺序证明，不是单独的 BFT；本页不是「PoH 崩了」 |
| 本页 | **已确认的重复槽赢家 ≠ 下一领导者会往上建的父块；票还在走、根不前进 ≠ Tower / PoH 已经一致；关掉重复出块者 ≠ 边角已消失；24 小时里多数重复块被安全处理 ≠ 边角已被覆盖** |

## 3. 被破坏的 invariant

- 确认了正确版本，不是 fork choice 已经把它当作下一父块（不变量 86）
- 投票还在发生、根不前进，不是共识还在出规范历史，也不是 Tower / PoH 已经一致
- 同一节点身份、两台同时提议，不是高可用；是同槽两份不同块的来源
- 把重复出块者下线，不是不重启就能恢复；边角在实现里，不在那两台机器上

## 4. 为什么测试没发现

幸福路径：同槽两份块，集群挑一份，下一槽往上建。220 就是这条绿路径。  
只测「出现重复块后能确认其中一份」会绿。  
边角要：确认之后，出块者仍不肯建在那份上。  
热备双活可以连续很多槽都不踩中；官方写停机前至少 24 小时多数槽被安全处理。

## 5. 修复

官方：不重启恢复失败，协调重启后根重新前进。  
补丁加了复现该边角的测试，合入 master 并回移；通知升到 v1.10.40 与 v1.13.2。90% 质押权重打补丁后，官方写风险被充分缓解——那是运维覆盖率，不是谓词已抄进不确定法定人数。  
关掉重复出块者不是补丁。

## 6. 「不确定」若同类

1. 第一版不要把「同一身份两台机器」写成高可用。热备必须是另一身份，或严格互斥只活一台。
2. 同槽两份不同块：必须写出谁赢、赢了之后下一领导者**必须**能把它当父块。确认 ≠ 可建。
3. 产品句若写「还在投票」：必须同时写根 / 规范历史有没有前进。票还在飞不是链还在结算。
4. 关掉故障提议者之后，若边角仍在实现里，必须当停链审，不要写成「人已经拉下了所以安全」。
5. 这和锁（4）、durable nonce 双路径（85）、非法提案（69）、同根不同列表（12）、宣布≠收到（36）不是同一句。
6. 不要抄 80 / 90。不要写怎样踩 221 那条边角。不要把 PoH 在转写成根在前进。

## 7. 回归测试

形状（不是利用包）：文案把「正确版本已确认」写成下一领导者必会往上建必须红。把「投票还在」写成根已前进 / Tower 已一致必须红。把关掉重复出块者写成边角已消失必须红。把 24 小时多数重复块被安全处理写成该实现已覆盖必须红。与 2022-06-01 durable nonce 糊成一句必须红。

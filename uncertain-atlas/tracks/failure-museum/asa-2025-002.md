# 失败案：ASA-2025-002 分片外层下标必须与证明下标是同一对象

层：**实现 + 网络**（块分片流言；共识没有另发明一条块规则）

官方披露：[ASA-2025-002 / GHSA-r3r4-g7hq-pq4f](https://github.com/cometbft/cometbft/security/advisories/GHSA-r3r4-g7hq-pq4f)。咨询标 **High**（ACMv1.2：Catastrophic Impact, Possible Likelihood）。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- 提议者把下一块拆成许多 block part，经 p2p 流言。每个 part 带 `Index`、`Bytes`、以及一份 Merkle `Proof`（咨询写：用来快速确认「这是提案块的一片」）。
- `Proof` 自己也有 `Index`（咨询：被证明那一项的下标）。叶子总数等于该提案的分片数。
- 以前**不验证** `Part.Index` 必须等于 `Part.Proof.Index`。于是可以用**另一片**的证明，实现仍接受：证明证明的是提案里的另一片，不是对等节点刚送来的这一片。
- 官方写两条后果：1）本节点把这份无效分片再流言给邻居（因为它当成正确）；2）把它标成已收到，并让邻居以后不要再转发，于是**正确的那一片再也收不到**。
- 修法：验证 `Part.Index == Part.Proof.Index`。
- 官方：没有已知绕过。只能升级；升级后验证者最终会收敛到正确值。

本页不写怎样把一片的证明接到另一片上。咨询里的分片字节大小是实现数字，不是不确定常量。

## 1. 发生了什么

节点以为「证明过根，这片就是第 i 片」。其实证明说的是第 j 片，信封上写着 i。它把错片当对，再发给别人，并挡住正确的 i 再进来。传播层把自己锁死。块规则没改。

## 2. 根因

外层下标和证明下标被当成「反正都验过根，对得上就行」。  
验根只说明「某片属于这个提案」；它不自动说明「信封上的 i 就是被证明的那一片」。  
标成已收到 = 拒绝再收正确片。流言放大一次错标。

这不是：

| 案 | 对象 |
|----|------|
| CVE-2012-2459 / 不变量 12 | 奇数复制 ⇒ 同根不同列表 |
| CVE-2024-35202 / 不变量 37 | 部分块重建失败后断言崩 |
| CVE-2024-52921 / 不变量 39 | 变异块清掉别人的下载状态 |
| CVE-2024-52922 / 不变量 36 | 宣布新块 ≠ 已收到 |
| 本页 | **分片信封下标 ≠ 证明下标，仍当已收到并再流言** |

## 3. 被破坏的 invariant

- 部分对象的外层下标必须与证明下标是同一对象；对不上必须拒，不得标成已收到，不得再流言（不变量 59）
- 验根通过 ≠ 下标已对齐
- 没有绕过 ≠ 可以靠「对等节点诚实」当谓词

## 4. 为什么测试没发现

幸福路径：发送端上游，`Part.Index` 与 `Proof.Index` 碰巧相同。  
只测「证明能对上提案根」会绿。  
不测「根对、下标错」。

## 5. 修复

- v0.38.17 / v1.0.1：强制 `Part.Index == Part.Proof.Index`。
- 官方：无绕过，升级后最终收敛。

升级 ≠ 以后每个带证明的分片字段都自动对齐。每加一个外层下标，都要和证明下标写成同一谓词。

## 6. 「不确定」若同类

1. 若块/票/证据走「分片 + Merkle 证明」：外层下标与 `Proof.Index` 必须相等，否则拒。
2. 接受路径不得在对不上时标「已收到」或抑制邻居再传正确片。
3. 不要把「证明过根」写成「这就是第 i 片」。
4. 不要抄咨询里的分片字节大小进第一版。
5. 这和 compact 短 ID / 2012-2459 同根是亲戚，不是同一句：这边是**下标错配**，不是叶列表分叉，也不是断言当过滤器。

## 7. 回归测试

形状（不是利用包）：`Part.Index ≠ Part.Proof.Index`、证明对其它叶子仍能对根 → 必须拒；不得标已收到；不得再流言该对象。文案把「验根通过」写成「下标已对齐」必须红。只测同下标的幸福路径不得标 PASS。

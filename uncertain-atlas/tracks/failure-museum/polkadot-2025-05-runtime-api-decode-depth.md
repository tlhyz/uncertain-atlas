# 失败案：交易解码深度有界不是 runtime API 再解整块时计数器已重置；出块收下不是导入 check_inherents 已能解

层：**协议 + 实现**（解码深度套在所有 runtime API 参数上；check_inherents 再解整块时向量先加一层，同笔交易过不去；导入失败就封禁对等节点，出块者互踢）

官方披露：

- Parity / Polkadot-SDK 官方论坛：[Transaction Depth Limit](https://forum.polkadot.network/t/2025-05-23-polkadot-sdk-transaction-depth-limit/13248)（2025-05-23 通知，2025-06-06 公开）。无 CVE。本页只采用该页已写出的句子。官方写自 2020 年起影响所有 Polkadot-SDK 用户。Bittensor 上先踩到，随后复现。

**事实（官方原文能对上的句子）：**

- 一笔带**嵌套调用、用满交易解码深度**的 batch 会被收下并进块。任意节点导入含该交易的块时，`check_inherents` 失败。节点把块当非法，**封禁送来这块的对等节点**。交易已传开，每个出块者都把它打进自己的块，于是出块者互相封禁。禁令过一会儿解开，重连，再导，再封——循环。
- 拉黑一个哈希、删掉含它的块只是临时。对手可以再送**另一哈希的同类交易**。
- 出块者能收、导入者不能，是因为深度计数器的用法。`check_inherents` 由 runtime 提供，在 WASM 里跑。宿主把参数 SCALE 编码，runtime 再解。解码深度本意约束交易栈。计数器在类型解码时加减，到顶就报错。
- 该交易已经用满交易允许的深度。`check_inherents` 把**整块**当参数传入。块把交易放在向量里，解向量先给计数器 +1，再解那笔已满深度的交易 → 失败。
- 根因：解码深度**应当只约束交易**，实现却套在**每个 runtime API 参数**上。
- 修法：runtime API 参数解码去掉深度上限；**只有交易**保留深度上限。

本页不写怎样嵌套调用，不抄官方验证脚本，不抄深度数字进不确定常量。交易深度有界，不是再解整块时计数器已重置。

## 1. 发生了什么

门卫量交易：套娃不能超过这一层。  
刚好顶到这一层的交易进了门，也进了块。  
验块的人把整块再拆一次。  
盒子外面还有一只袋子，计数器先加一。  
同一笔套娃，第二次拆就超了。  
验块的人以为邻居在害他，把门关上。  
出块的人彼此关上门。  
过一会儿再开，再关。  
交易深度有界，不是再解整块时计数器已重置。

## 2. 根因

交易入池 / 出块走的解码，和导入时 `check_inherents` 再解整块，不是同一条路径，却共用一个深度计数器。  
整块是向量。解向量先占一层。已经用满交易深度的字节，第二次解必然失败。  
失败被当成块非法，再变成对等封禁。封禁是部署止血，不是谓词。  
拉黑一个哈希不是同类另一哈希不会来。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 70 / ASA-2024-0012 | 外层 `max_tx_bytes` 不是内层 UnpackAny 已有界；本页是深度套错对象 |
| 不变量 50 / CVE-2020-14198 | 自动封禁写入无界表 |
| 不变量 39 | 变异块清别人下载 |
| 不变量 96 / Sepolia | 出块通道尺寸分裂；本页是解码深度 |
| 不变量 71 | EndBlocker 出错会停 |
| 不变量 98 / 2025-08 | 组下标 ≠ 票向量下标；本页是解码深度套错对象 |
| 不变量 99 / 2024-02 | Active ≠ Confirmed；本页是导入再解整块 |
| 本页 | **交易解码深度有界 ≠ runtime API 再解整块已重置计数器；出块收下 ≠ 导入 check_inherents 已能解；封禁送来该块的对等节点 ≠ 块已非法；拉黑一个哈希 ≠ 同类另一哈希不会再来** |

## 3. 被破坏的 invariant

- 解码深度若只该约束交易，不得套在 runtime API 的整块参数上（不变量 97）
- 出块路径接受，不是导入路径已经能解同一对象
- 导入失败不得默认当成对等节点作恶
- 拉黑单一哈希不是同类输入已穷尽

## 4. 为什么测试没发现

幸福路径：浅层 batch，出块与导入都过。  
只测「交易解码深度到顶则拒」会绿——入池那条可以仍真。  
边角要：交易刚好用满深度，再作为块参数被解一次。  
官方写自 2020 年就在；到有链踩到才当漏洞收。

## 5. 修复

官方：runtime API 参数解码去掉深度上限；只留在交易上。回移多条发布线。  
公开页带了一段会停链的验证脚本——那是复现步骤，本馆不转。  
回移列表不是「没写到的线已经齐」。

## 6. 「不确定」若同类

1. 若有「交易解码深度」：必须写清计数器只在交易对象上走。runtime API / 整块 / 向量包装不得共用。
2. 出块接受与导入再验必须差分：同一对象两条路径都要过。
3. 导入失败先写成「本节点解不开」，不得先写成「邻居坏了所以踢」。
4. 第一版可以不做嵌套 batch。少一层，就少一次计数器错位。
5. 这和外层字节不是内层已有界（70）、自动封禁无界表（50）、Engine API 尺寸（96）不是同一句。
6. 不要写怎样套娃。不要抄深度数字。不要转官方停链脚本。

## 7. 回归测试

形状（不是利用包）：文案把交易解码深度有界写成 runtime API 再解整块已安全必须红。把出块收下写成导入 check_inherents 已能解必须红。把封禁送来该块的对等节点写成块已非法必须红。把拉黑一个哈希写成同类不会再来必须红。与 ASA-2024-0012 糊成一句必须红。

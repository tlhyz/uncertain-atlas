# 失败案：单笔低于入池上限不是拼出来的块已被所有客户端接受；各家 RPC 收到同一低值不是拼块已安全

层：**实现 + 协议 + 部署**（Engine API 沿用 HTTP RPC 尺寸；单笔入池上限与块 gas 上限盖不住拼块后的消息尺寸；多数拒、少数收会反复重组）

官方披露：

- Ethereum Foundation：[Sepolia Incident](https://blog.ethereum.org/2024/03/21/sepolia-incident)（2024-03-21）。无 CVE。本页只采用该页已写出的句子。威胁从 Merge 存在到 Dencun。

**事实（官方原文能对上的句子）：**

- 合并前，各客户端为防 HTTP RPC 拒绝服务设了不同消息尺寸上限。这些上限被带到 **Engine API**（执行层与共识层出块通道）。于是可以造出：对某些客户端超 RPC 上限、对另一些仍可接受的块。
- 攻击者若做出超过**最低那家**上限、仍满足 gas 限制的消息，等这块被提出，就会出现：有的客户端当合法，有的拒并回 HTTP `413 Content Too Large`。
- 官方：多数节点（= geth）拒、少数收 → 这些块被分叉掉，提议者拿不到奖励。
- 起初以为必须用 builder 或改过的客户端。Geth 入池单笔有上限，超大单笔进不了 geth 池；但**更高上限的客户端提出大块**后，CL 仍会要 EL 验这块。
- 曾提议把各家 RPC 暂时收到**最低那档**，让攻击块对大家都非法。2 月 7 日发现：用**一堆低于单笔入池上限**、且不超过当时块 gas 上限的交易，仍能拼出顶到该低档的块。高费交易会挤进每家（含 geth）的块，多数拒、少数收，**链反复重组**。
- 随后认定：各家**抬高** RPC 上限更安全。Geth 是当时唯一中招的客户端；别家也改了默认，以免以后 gas 上限再涨时再中。

本页不写怎样打磨交易或怎样拼出超限块，不抄单笔 / RPC / gas 数字进不确定常量。单笔没超入池上限，不是拼出来的块已被所有客户端接受。

## 1. 发生了什么

出块的电话线，沿用了网页接口的「包裹不能太大」。  
各家门口写的尺寸不一样。  
一笔交易可以小于入池上限。  
许多笔加在一起，对多数人太大，对少数人刚好。  
多数人拒，少数人收，头来回跳。  
把门口都改成最窄的那一档，窄门仍能被许多小包裹填满。  
单笔低于入池上限，不是拼出来的块已被所有客户端接受。

## 2. 根因

入池单笔上限、块 gas 上限、Engine API 消息尺寸，是三把尺。  
HTTP RPC 的防 DoS 数字被带到出块通道，各客户端默认不同，就变成「有的当合法、有的当太大」。  
把各家收到同一低值，只挡住「单笔已经很大」；许多低于入池上限的交易仍能顶满这条通道。  
多数拒、少数收，不是多客户端已经同根，是出块通道尺寸分裂。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 3 / CVE-2021-39137 | 执行别名错根；本页是消息尺寸 |
| 不变量 48 / CVE-2015-3641 | 最大序列化长度不是接收分配 |
| 不变量 45 | 库存三方向配额 |
| 不变量 63 | 默认 MaxBytes 不是第一轮 SLA |
| 不变量 12 | 同根不同列表 |
| 不变量 101 / 2021-05 | 块 gas 上限 ≠ 墙钟已有界；本页是出块通道尺寸 |
| 本页 | **单笔低于入池上限 ≠ 拼块已被所有客户端接受；gas 上限内 ≠ Engine API 尺寸已齐；各家 RPC 收到同一低值 ≠ 许多小交易不能顶满；多数拒少数收 ≠ 多客户端已经同根** |

## 3. 被破坏的 invariant

- 出块通道的消息尺寸必须与入池单笔上限、块 gas 上限分开写，且各实现同一对象同拒或同收（不变量 96）
- 单笔进得了池，不是拼出来的块能通过所有客户端的 Engine API
- 把 RPC 收到最低档，不是拼块已安全
- 只有一家中招不是「其他家默认已经够」——官方仍让别家改默认

## 4. 为什么测试没发现

幸福路径：普通交易、普通块，Engine API 回 200。  
只测「单笔超过入池上限进不了 geth 池」会绿。  
边角要：更高上限的客户端先提出大块；或许多低于入池上限的高费交易拼满通道。  
合并前的 HTTP 数字被带到出块通道，测试若只打普通 JSON-RPC，看不见。

## 5. 修复

官方：先试统一收到最低档，发现许多小交易仍能顶满，改为抬高上限。Geth 合入修复并发版；其他客户端也更新默认。  
Dencun 之后官方写该威胁窗口关掉——那是这条洞的时间范围，不是出块通道尺寸已永远齐。  
不要抄版本号当不确定常量。

## 6. 「不确定」若同类

1. 若执行与共识分开、用 RPC 出块：出块通道尺寸必须写成共识对象，不得沿用 HTTP 防 DoS 默认。
2. 必须同时测：单笔入池上限、块计量上限、通道消息上限。三句都绿才算。
3. 多客户端必须对「太大」同拒或同收。多数拒、少数收按分叉审。
4. 把各家收到同一低值，必须再测「许多低于入池上限的交易」。
5. 这和执行别名错根（3 / 39137）、接收分配（48）、库存配额（45）、默认 MaxBytes（63）不是同一句。
6. 不要写怎样打磨或怎样拼。不要抄 413 / 单笔 / 通道 / gas 数字。

## 7. 回归测试

形状（不是利用包）：文案把单笔低于入池上限写成拼块已被所有客户端接受必须红。把 gas 上限内写成 Engine API 尺寸已齐必须红。把各家 RPC 收到同一低值写成许多小交易不能顶满必须红。把多数拒少数收写成多客户端已经同根必须红。与 CVE-2021-39137 糊成一句必须红。

# 失败案：coinbase 正屏蔽余额不是供给已经对齐；ConnectBlock 对不上不是重启能起来

层：**实现 + 协议**（coinbase 带正的 Sapling 或 Orchard 价值余额，会让链供给记账与池余额在 `ConnectBlock` 对不上；节点中止；重启再崩。官方写影响活性，不改变哪些块/交易合法）

官方披露：

- Zcash 规范级 ZIP：[ZIP 256](https://zips.z.cash/zip-0256)，列在拒绝服务与崩溃加固。本页只采用 ZIP 已写出的句子。无独立 CVE 号写入本条。

**事实（官方原文能对上的句子）：**

- coinbase 若带**正的** Sapling 或 Orchard 价值余额，会让链供给记账与池余额在 `ConnectBlock` **失去同步**。
- 随后节点**中止**，重启再崩，形成崩溃循环。
- 官方把本条标成远程可触发的崩溃 / 资源问题：**影响活性，不改变哪些块或交易合法**。
- 同批另有「池增量超出货币范围」：不封发送对等节点，且每次重放把体再写盘。那是亲戚，主句仍是对不上就崩、重启还崩。

本页不写怎样给 coinbase 加正屏蔽余额、不抄发布线版本 / 规范金额上限进不确定常量。对不上，不是供给已经对齐；中止，不是重启能起来。

## 1. 发生了什么

出块奖励那一笔，屏蔽余额栏写成正的。  
左边的总供给账，右边的池账，对不上。  
对不上不是拒块，是进程退出。  
再开机，还是对不上，再退出。  
门卫死了，不是这块已经被规范判非法。  
官方说：合法集没变，活着的节点变少了。

## 2. 根因

`ConnectBlock` 把链供给与各池当成必须对齐的两本账。  
coinbase 正屏蔽余额让两本账分叉。实现选中止，而不是当共识拒绝并留下可重启的状态。  
重启再走同一条路径，再中止。活性洞，不是有效性已改。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 5 | 崩溃半块 / 原子高度；本页是对不上就循环崩 |
| 不变量 74 | 奖励池入金溢出停链；本页是 coinbase 正屏蔽余额，官方标活性 |
| 不变量 104 | 重复头复位跟踪、闸门关掉；本页是对账中止 |
| 不变量 90 | 估值为 0 assert；本页是供给与池两本账 |
| 不变量 73 | 停链消息不是已停；本页是真崩循环 |
| 本页 | **coinbase 正屏蔽余额 ≠ 供给已经对齐；ConnectBlock 对不上 ≠ 重启能起来；活性崩溃 ≠ 合法集已改** |

## 3. 被破坏的 invariant

- 两本账对不上必须拒块并留下可重启状态，不得中止成崩溃循环（不变量 109）
- 活性崩溃不得写成共识已经改合法集
- 重启必须能越过或拒绝该对象，不得再走同一条中止

## 4. 为什么测试没发现

幸福路径：coinbase 屏蔽余额为零或负向补偿按规范。  
绿测试只覆盖「两本账对得上就提交」。  
边角要：正屏蔽余额；中止之后重启是否再崩；是否被标成非法块而不是进程死。

## 5. 修复

官方列入 zcashd 崩溃加固。活性补丁，不是改哪些交易合法。  
同批「超出范围的池增量」另补封禁与不再重复写盘——亲戚，不是本条对账已齐。

## 6. 「不确定」若同类

1. 第一版可以不做 coinbase 进屏蔽池 / 双账跟踪。
2. 若供给与池是两本账：对不上必须共识拒绝，状态停在上一高度。
3. 中止进程不是已拒绝。重启再崩按停链面的崩溃循环审。
4. 官方写「不改变合法集」必须写进产品句，不得把活性补丁写成共识升级。
5. 这和原子高度（5）、奖励池溢出（74）、跟踪复位（104）、估值 0（90）不是同一句。
6. 不要写怎样给 coinbase 加正余额。不要抄版本 / 规范金额上限。

## 7. 回归测试

形状（不是利用包）：文案把 coinbase 正屏蔽余额写成供给已经对齐必须红。把 `ConnectBlock` 对不上写成重启能起来必须红。把活性崩溃写成合法集已改必须红。与 5 / 74 / 104 糊成「记账停链」一句必须红。

**事实来源：** [ZIP 256](https://zips.z.cash/zip-0256) 拒绝服务与崩溃加固节。

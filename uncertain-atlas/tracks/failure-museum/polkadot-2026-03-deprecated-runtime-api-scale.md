# 失败案：废弃 runtime API 还在不是返回编码已经兼容；出块者还能写块不是中继已经收到

层：**协议 + 实现 + 部署**（废弃 `backing_state` 仍可被旧整理者调用；清理把它指到多一个字段的新结构；SCALE 返回解不开；整理者本地还能出块，送不进中继）

官方披露：

- Polkadot 论坛官方复盘：[Partial Polkadot Parachains stall on runtime upgrade 2.1.1](https://forum.polkadot.network/t/partial-polkadot-parachains-stall-on-runtime-upgrade-2-1-1-postmortem/17387)（2026-03-26）。本页只采用该文已写出的句子。无 CVE。

**事实（官方原文能对上的句子）：**

- 中继 runtime 升级后，一小部分平行链出块停住或变慢。根因是废弃 runtime API 的返回值解码失败。
- 官方：整理者侧早已不再用该 API，并标了废弃。后来一次清理把废弃入口指到**多一个字段**的新结构，返回编码变了。仍调用旧名字的旧节点解不开 `Option::Some`。
- 官方：整理者**仍能写出块**，但因这次错误，块送不进中继验证者，平行链停。中继自己继续出块并最终。
- 同一清理还弄坏过另一条 runtime API，合并后、发布前修了；本条漏了。本该抓住它的向后兼容测试，和一批「不稳定」测试一起被关掉，实际藏的就是这次编码裂。测试网没报，因为那里的节点没那么老。
- 官方：支持窗只承诺给仍支持的稳定线打补丁与安全修，**不**承诺再老的发行线编码永远兼容。这次却让不受支持的旧整理者在中继升级后停平行链。
- 热修：整理者叉上不再调用该 API。全部整理者升完，块时间才按升上去的人数恢复。

本页不写怎样调用废弃 API、不抄版本 / 支持月数 / 平行链个数进不确定常量。废弃入口还在，不是返回编码已经兼容。

## 1. 发生了什么

门口的旧窗口还开着。  
里面的表格多了一栏。  
拿着旧说明书的人，读不懂新表格。  
他自己桌上还能写出下一块。  
送货的车开不进中继的门。  
中继的 bell 还在响。  
bell 还在响，不是平行链已经出块。  
窗口还开着，不是旧读者已经能读。

## 2. 根因

废弃不是删除。旧节点仍可能叫旧名字。  
返回结构多一个字段，SCALE 不是「多 Ignored」，是整段解失败。  
安全修引入新 API 时保持了旧编码；后来的清理把旧入口接到新结构，兼容断了。  
本地出块成功，不是已经交给中继。  
关掉「不稳定」兼容测试，不是这条编码裂已经覆盖。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 97 | 交易解码深度套在 runtime API 参数上；本页是**返回值**形状 |
| 不变量 3 | 两实现同根；本页是新旧节点对同一废弃入口 |
| 不变量 96 | Engine API 消息尺寸；本页是 SCALE 字段数 |
| 不变量 113 | XCM origin 指令缺失；本页是整理者查询中继 |
| 不变量 110 | 选举地板；本页是平行链送块 |
| 本页 | **废弃 API 还在 ≠ 返回编码已经兼容；整理者还能写块 ≠ 中继已经收到** |

## 3. 被破坏的 invariant

- 仍可调用的废弃 runtime API，返回编码必须与仍在外的调用方兼容，或入口必须失败关闭且不得卡住送块（不变量 114）
- 本地出块成功不得写成中继已经收到
- 支持窗只打补丁，不是更老节点的编码已经保证

## 4. 为什么测试没发现

幸福路径：新整理者走新 API，旧结构已删。  
绿测试与评审覆盖安全修引入新 API 的那次（当时旧编码还在）。  
边角要：废弃入口仍被极老整理者调用；返回多一个字段后旧端能否解；解失败后块还送不送。  
官方：本该抓住的兼容测试被标成不稳定关掉；测试网节点不够老。

## 5. 修复

官方：整理者不再调用该 API。升到仍支持的稳定线。  
过程：恢复兼容测试、写清废弃与兼容政策、告警不要因误报长期关掉。那些是过程，不是谓词已齐。

## 6. 「不确定」若同类

1. 第一版可以不做平行链 / 双代 backing API / 废弃仍可调用的入口。
2. 若废弃一条仍可能被旧节点调用的 API：要么锁死返回编码，要么删入口并让送块走另一条不依赖它的路。
3. 产品句若写「中继还在最终」，必须点名平行链是否还在出、块是否已送进中继。
4. 关掉不稳定测试必须逐条写清藏了什么兼容句。支持窗不是「更老的也永远能连」。
5. 这和解码深度（97）、确定性（3）、Engine API 尺寸（96）、XCM origin（113）不是同一句。
6. 不要写怎样调用废弃入口。不要抄版本 / 个数 / 月数。

## 7. 回归测试

形状（不是利用包）：文案把废弃 API 还在写成返回编码已经兼容必须红。把整理者还能写块写成中继已经收到必须红。把支持窗写成更老节点编码已保证必须红。把关掉不稳定测试写成兼容已覆盖必须红。与 97 糊成「runtime API 解码」一句必须红。

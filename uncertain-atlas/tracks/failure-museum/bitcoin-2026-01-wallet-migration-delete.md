# 失败案：迁移失败不是目录里其它钱包已经安全；现有用户不受影响不是迁移路径已经安全

层：**实现 + 部署**（legacy `wallet.dat` 迁到 descriptor 钱包失败时，实现可能删掉钱包目录里的全部文件，而不只是这次迁不动的那一份）

官方披露：

- Bitcoin Core 官方页：[Wallet Migration Failure May Delete Unrelated Wallet Files In Bitcoin Core 30.0 and 30.1](https://bitcoincore.org/en/2026/01/05/wallet-migration-bug/)（2026-01-05）。无 CVE 写入该页。

**事实（官方原文能对上的句子）：**

- 某条发行线引入迁移洞：`wallet.dat` 迁移失败时，钱包目录里的**全部文件**都可能被删掉，官方写可能丢资金。
- 官方从站点下架受影响发行的二进制，修法随下一小版本。在修好之前，不要用 GUI 或 RPC 做钱包迁移。
- 现有钱包用户、不跑迁移的安装，官方写不受影响，可以继续用已装副本。
- 触发条件合取：目录里要有默认（未命名）的 `wallet.dat`。该默认文件从 0.21 起不再默认创建。官方点名的一种情况：开了修剪，且钱包在修剪发生时处于卸下状态，之后这次迁移或加载失败。
- 本页不把版本号抄进不确定常量。下架二进制不是已安装副本已经打补丁。

本页不写怎样踩失败路径，不转成复现步骤。

## 1. 发生了什么

搬家失败，本该只退回这一箱。  
实现把整间库房清空。  
隔壁箱子不是这次要搬的。  
隔壁也被倒空。  
官方说：没搬家的人没事。  
没搬家没事，不是搬家这条路已经安全。  
站点下架安装包，不是家里已经装上的那份已经改过。

## 2. 根因

失败路径的清理范围必须等于这次失败的对象。  
迁一份 `wallet.dat` 失败，不得按「整目录都是这次迁移」去删。  
默认未命名钱包文件不再默认创建，不是这条失败路径已经消失。  
修剪与卸下是官方写明的一种合取，不是修剪本身非法。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 111 | 加载钱包泄出站 TXID；本页是删文件 |
| 不变量 55 | 付款 URI 远程取单；本页是本地迁移 |
| 不变量 112 | 隐私广播降级露 IP；本页是磁盘上的钱包目录 |
| 不变量 42 | 拒绝路径灌日志占盘；本页是实现主动删文件 |
| 本页 | **迁移失败 ≠ 目录里其它钱包已经安全；现有用户不受影响 ≠ 迁移路径已经安全** |

## 3. 被破坏的 invariant

- 迁移失败的清理必须只覆盖这次失败的对象，不得扫掉同目录其它钱包（不变量 120）
- 现有用户不受影响不是失败路径已经安全
- 下架二进制不是已安装副本已经修

## 4. 为什么测试没发现

幸福路径：迁移成功，或目录里只有这一份钱包。  
绿测试不在「默认未命名 `wallet.dat` + 迁移失败」上断言邻居文件仍在。  
官方写罕见，且默认文件多年不自动创建。罕见不是谓词已齐。

## 5. 修复

官方：下一小版本修；修好前不要跑 GUI / RPC 迁移；受影响发行的二进制从官网撤下。  
热修是「先别迁」，不是失败清理已经收窄。

## 6. 「不确定」若同类

1. 第一版可以不提供钱包格式迁移器。
2. 若提供迁移：失败必须只动这次的对象；同目录其它文件必须还能打开。
3. 「现有用户不受影响」不得写成迁移路径已经安全。
4. 这和加载泄 TXID（111）、付款 URI（55）、隐私广播（112）不是同一句。
5. 不要写怎样踩失败。不要抄版本。不要把修剪本身写成非法。

## 7. 回归测试

形状（不是利用包）：文案把迁移失败写成目录里其它钱包已经安全必须红。把现有用户不受影响写成迁移路径已经安全必须红。把下架二进制写成已安装副本已经修必须红。与 111 / 55 糊成「钱包事故」一句必须红。

**事实来源：** [bitcoincore.org/en/2026/01/05/wallet-migration-bug](https://bitcoincore.org/en/2026/01/05/wallet-migration-bug/)。

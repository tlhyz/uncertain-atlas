# 失败案：检查点隔离拒证不是已经分叉；超过 ⅓ 签了另一摘要所以停是为了安全

层：**协议 + 实现**（共识提交在垃圾回收优化下分叉；隔离区不让未认证效果最终；RPC 仍读上一份已认证状态 ≠ 链还在结算）

官方披露：

- Sui 官方复盘：[Sui Mainnet Network Stall Resolution](https://www.sui.io/blog/sui-mainnet-network-stall-resolution)（2026-01-14）。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 2026-01-14 Mainnet **长时间中断**：验证者共识处理**内部分叉**，无法认证新检查点，交易提交超时。与拥堵、交易量、外部威胁**无关**。
- 官方：没有已认证状态分叉，没有已认证交易被回滚，资金从未受险，安全/一致性保证未被打破。检查点**认证与隔离**挡住了用户可见分叉，代价是进度停住。
- RPC 读请求继续提供**上一份已认证状态**（除非节点被配成「太久没更新就不服务」）。
- 用户可见中断约 **6 小时**：提交超时，窗口内不执行交易，读仍一致，无回滚或双花。
- 根因：共识提交逻辑在特定**垃圾回收**条件下处理冲突交易的边角；一条**优化路径**让不同验证者算出**不同的共识提交**。时间凑巧，不是用量。
- 四层（官方原文）：① 共识产出有序提交流；② 确定性执行把提交变成检查点；③ **隔离区**保证认证成功前效果不最终（短暂执行层，尚未结算）；④ 检查点认证要求质押法定人数签**同一检查点摘要**。
- 事故路径：共识漏洞 → 不同验证者得到不同提交 → 执行出不同候选检查点 → 交换签名后看见**超过 ⅓ 质押**在签另一摘要 → 无法认证 → **停住以免最终不一致状态**。官方：这是此类问题的**预定失败模式**——安全停，而不是冒险最终不一致。
- 恢复：从分叉点清掉错误共识数据、打开改正逻辑；Mysten Labs 验证者先金丝雀；其余升级、安全回放、恢复签名。同一检查点摘要凑齐法定人数后，认证与状态同步恢复。

本页不写怎样踩垃圾回收冲突，不抄 ⅓ / 6 小时进不确定法定人数。读到上一份已认证状态不是链还在结算。

## 1. 发生了什么

两台诚实机器，同一段冲突交易，算出两份不同的提交。  
各自往下执行，检查点摘要对不上。  
超过三分之一的人签了另一份。  
认证凑不齐。  
隔离区不放行。  
柜台停开，告示栏还挂着上一份已盖章的账。  
检查点隔离拒证，不是已经分叉。

## 2. 根因

共识提交必须全员同一输出。垃圾回收优化路径让冲突交易走出两个提交，破坏这句。  
执行是确定的——输入已经分叉，检查点就会分叉。  
隔离区 + 认证：摘要对不上就不最终。这挡住用户可见分叉，也把活性换成停。  
RPC 读上一份已认证状态，是读，不是新交易已结算。  
不是共享对象拥塞，也不是用量。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 3 | 一般确定性：同一已排序输入必须同根。本页是提交层先分叉 |
| 不变量 4 | 锁；本页不是两张冲突票 |
| 不变量 9 | 提交 ≠ 兑付；本页是检查点认证 ≠ 已最终 |
| 不变量 85 / 2022-06-01 | 一边收一边拒同一块 |
| 不变量 86 / 2022-09-30 | 已确认不能当父块 |
| 不变量 90 / 2024-11-21 | 拥塞控制 assert 全员崩溃；本页是活着但不认证 |
| L6.2 | owned/shared；本页官方写与拥堵无关 |
| 本页 | **检查点隔离拒证 ≠ 用户已看见分叉；超过 ⅓ 签另一摘要所以停 ≠ 状态已不一致；RPC 仍读上一份已认证 ≠ 链还在结算；垃圾回收优化路径 ≠ 提交已确定** |

## 3. 被破坏的 invariant

- 共识提交输出必须全员同一；优化路径不得让冲突交易走出两份提交（不变量 91）
- 隔离区拒证、进度停住，不是已经最终不一致，也不是用户已看见分叉
- 超过 ⅓ 签另一摘要，是无法认证，不是已经有两份最终状态
- RPC 读上一份已认证状态，不是新交易已执行

## 4. 为什么测试没发现

幸福路径：无冲突或垃圾回收不走进优化路径，提交同一，检查点同一。  
只测「检查点能认证」会绿。  
边角要：冲突交易 + 特定 GC + 优化路径。官方事后扩大共识随机测试，并写 Antithesis 已能稳定复现——说明当时没有这句。

## 5. 修复

官方：从分叉点清错误共识数据，改正逻辑，金丝雀后全员升级回放。  
清数据 + 换二进制是恢复，不是「隔离区已经保证不会再停」。  
官方改进方向：更早暂停共识、自动清理分叉内部状态、扩大随机测试。那是运维与测试，不是本条谓词已抄进不确定。

## 6. 「不确定」若同类

1. 第一版必须写清：未认证的执行效果不得当最终。隔离 / quarantine 是活性换安全，产品句不得写成「不会停」。
2. 共识提交若有优化路径，必须与慢路径对同一冲突输入测同输出。垃圾回收不得改变提交。
3. 读上一份已认证状态，必须标「读，不是结算」。钱包绿勾不得挂在还能读上。
4. 不要把「超过 ⅓ 签了另一摘要」抄进不确定法定人数。那是 Sui 这次无法认证的观察，不是你们的阈值。
5. 这和一般确定性（3）、锁（4）、拥塞控制 assert（90）、durable nonce 双路径（85）不是同一句。不要写怎样踩 GC 冲突。
6. 不要把「资金安全 / 没有用户可见分叉」写成链还在出检查点。

## 7. 回归测试

形状（不是利用包）：文案把隔离区拒证写成已经分叉 / 已经最终不一致必须红。把 RPC 仍可读写成链还在结算必须红。把超过 ⅓ 签另一摘要抄进不确定法定人数必须红。把「与拥堵无关」的提交分叉写成共享对象拥塞必须红。与 2024-11-21 assert 崩溃糊成一句必须红。

# 失败案：因余额不足被取消不是已经不再扣款；临时只认一种取消理由不是下溢已经消失

层：**协议 + 实现**（混合气费在取消路径上仍会砸币；结算把负增量加到零余额上崩溃；一种取消理由盖住另一种，临时补丁被绕过）

官方披露：

- Sui 官方复盘：[Sui Mainnet Halts Resolved After Major Upgrade](https://www.sui.io/blog/sui-mainnet-halts-resolved-after-major-upgrade)（2026-05-28 / 05-29，第一、二次停机）。无 CVE。本页只采用该页已写出的句子。同页第三次停机（DKG 失败未落盘）另立。

**事实（官方原文能对上的句子）：**

- 2026-05-28 / 05-29 Mainnet 三次停机。前两次来自 **气费逻辑** 与 **1.72 地址余额** 的交互崩溃。周四临时补丁为尽快复电，**已知有低概率再停**；周五早上撞上该已知变体，第二次停。官方：资金未受险，恢复时**没有回滚已提交交易**。
- 1.72 引入地址余额：可用空输入币列表付气费，可用币对象，或**混合**（输入币 + 从地址余额划出的合成预留）。后两种在扣气费前做 **gas smashing**：把输入币合成一枚再扣。成功执行与**被取消**的交易都会砸。
- 边角：混合气费里，预留在判断够不够预算时试图透支地址余额 → 交易标为取消，错误 `InsufficientFundsForWithdraw`。随后砸币时，**同一预留再透支一次**。交易因余额不够被取消，砸币却把那些钱花掉。
- 崩溃不发生在砸币当时。地址余额用**余额增量**支持并发存取，由系统结算交易加总。负增量加到零余额上，结算崩溃。
- `InsufficientFundsForWithdraw` 不是「花 X、余额 < X」那种进共识前就会失败的路径。只有两笔同时进调度器、抢同一笔不够分的地址余额时才会出现。调度器用这种取消防透支，**若被取消的交易仍因砸币扣款，就防不住**。
- 周四修法：`InsufficientFundsForWithdraw` 取消时**不要砸币**。验证者采纳后复电。气费改动必须保住旧行为或做版本门，否则回放旧交易会分叉；守恒检查保证交易不能无中生有或毁掉 SUI，忘了把扣下的气费记到该记的地方也会崩。
- 一笔交易可以有**多种取消理由**，一种会盖住另一种。例如等热点共享对象被更高优先级挤掉，同时又因另一笔花掉同一地址余额而 `InsufficientFundsForWithdraw`。后者被盖住，周四补丁不生效，同一下溢再崩。这是周五早上第二次停。更完整的补丁随后上线。

本页不写怎样让两笔混合气费同时进调度器，不写怎样用另一种取消盖住余额不足，不抄 1.72 / 钟点进不确定常量。因余额不足被取消，不是已经不再扣款。

## 1. 发生了什么

新钱包里的钱和旧硬币可以混着付气费。  
两个人同时伸手，钱不够两份。  
调度器说：你这单取消。  
取消之后，门口仍把硬币砸成一枚再扣。  
账本结算看见负数加到零上，进程倒下。  
临时补丁只认「余额不足」这一张取消条。  
另一张条盖住它，同一条坑再踩一次。  
因余额不足被取消，不是已经不再扣款。

## 2. 根因

取消路径与成功路径不是同一套扣款谓词。砸币写在两条路上。  
调度器的「取消以防透支」假定取消后不再扣。砸币打破这句。  
结算把负增量加到零余额，守恒检查 / 下溢变成崩溃，不是拒交易。  
临时补丁只看一种取消理由。理由被盖住，谓词当没写过。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 2 / 7 | 供给守恒 / 溢出拒；本页是取消后仍扣、结算下溢崩 |
| 不变量 90 / 2024-11-21 | 估值为 0 的 assert；本页是气费砸币 |
| 不变量 91 / 2026-01-14 | 检查点隔离拒证；本页是执行崩溃 |
| 不变量 93 / 同周第三次 | DKG 失败未落盘；不是气费 |
| 不变量 71 | EndBlocker 出错会停 |
| 本页 | **因 InsufficientFundsForWithdraw 取消 ≠ 已经不再扣款；砸币走取消路径 ≠ 守恒已成立；只认一种取消理由的临时补丁 ≠ 下溢已消失；被盖住的余额不足 ≠ 已经按该理由取消** |

## 3. 被破坏的 invariant

- 因余额不足取消的交易，不得再走砸币扣款（不变量 92）
- 取消理由若可被另一种盖住，补丁必须覆盖所有会走进同一扣款路径的取消，不得只认一个错误码
- 结算增量不得把负值加到零余额上变成崩溃；应拒或按规范记账
- 临时复电补丁已知会再停，不是谓词已齐

## 4. 为什么测试没发现

幸福路径：单笔混合气费，余额够，砸币与结算同号。  
只测「余额不够、进共识前失败」会绿——官方写那种路径到不了链上。  
边角要：两笔同时抢同一地址余额 + 取消后仍砸 + 结算加总。  
第二种取消盖住第一种，只测「错误码是 InsufficientFundsForWithdraw」会绿。

## 5. 修复

官方：周四不要在该错误码上砸币；周五补上被盖住的变体。没有回滚已提交交易。  
气费改动必须版本门，否则回放分叉。守恒检查仍要，但不能用崩溃当唯一阀门。  
临时补丁换时间，不是边角已穷尽。

## 6. 「不确定」若同类

1. 第一版不要上地址余额 + 币对象混合气费。一种付费对象够结算。
2. 取消路径禁止再改余额。取消就是不扣，或只扣规范写明的固定费，且不得下溢崩进程。
3. 若取消理由可叠加，补丁必须按「是否走进扣款」写，不得只匹配一个错误码。
4. 临时复电若已知会再停，产品句必须写成未齐，不得写成已修。
5. 气费逻辑按与状态机同一测试条审。不要抄 1.72。不要写怎样竞态。
6. 这和估值 0 assert（90）、检查点隔离（91）、DKG 未落盘（93）、供给守恒口号（2）不是同一句。

## 7. 回归测试

形状（不是利用包）：文案把「因余额不足取消」写成已经不再扣款必须红。把砸币写成只走成功路径必须红。把只认一种取消理由的补丁写成下溢已消失必须红。把守恒检查写成不会崩必须红。与第三次 DKG 停机糊成一句必须红。

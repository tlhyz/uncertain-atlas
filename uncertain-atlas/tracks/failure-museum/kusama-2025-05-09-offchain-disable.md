# 失败案：链下内存禁用不是已确认争议已经不参与；训练轮触发不是最终性还在走

层：**协议 + 实现 + 部署**（版本差会引发争议是预期；链下禁用只挡未确认；名单在内存、只活一个 session；重启清空；训练轮在 GRANDPA 已停之后才转）

官方披露：

- Parity 官方论坛：[Kusama dispute storm postmortem](https://forum.polkadot.network/t/2025-05-09-kusama-dispute-storm-postmortem/12947)（标题 2025-05-09）。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 运行时升到新版后，打开了 **v2 候选收据**。一小撮验证者仍跑不支持 v2 的旧节点。新收据去掉了收集人签名字段。旧节点在审批时对所有 v2 收据的该字段验失败，**不断发起争议**。
- 官方**预期**旧节点会争议；也**预期**链下禁用能挡掉这些垃圾、忽略旧验证者发起的争议。链下禁用**没有完全挡住**。
- 链下禁用**只对未确认争议有效**（官方：参与不超过确认门槛）。争议一旦确认，节点**仍会参与**，哪怕官方把它叫垃圾。
- 禁用名单存在**内存**里：输了「有效候选」争议的验证者，当 session **只禁用这一期**。旧节点每个新 session 再发起。验证者**重启后名单空了**。官方相信重启削弱了链下禁用。
- 负载够高时，**已升级**的验证者也开始争议有效候选：PVF 执行超时。
- **训练轮**：争议或审批让最终性停够官方写明的块数后，未最终链上的候选一律标通过。这次争议落后和审批落后都超过该窗，训练轮**触发了**。它什么也没做——**GRANDPA 在训练轮触发之前就已经停最终**。
- 应急：节点侧关掉争议逻辑（忽略争议协议消息）；两周后按高度再开；节点侧覆盖运行时标志、不再 backing v2。常备修法：启动时把链下禁用表填回去；争议很多时仍要处理已 backing 的声明。
- 为何测不到：官方自己写要更大规模、更长争议压测，才看得见失败模式。

本页不写怎样让旧节点留下、怎样灌争议、怎样打超时。不抄确认门槛 / 训练轮块数 / 落后小时 / 版本号 / 块号进不确定常量。链下内存禁用不是已确认争议已经不参与。

## 1. 发生了什么

链升了级。新收据少了一个旧节点还在验的字段。  
少数人还没跟上。他们把合法候选当假的，一遍遍喊。  
设计者以为：喊输了的人，名单上记一笔，别人就不理他。  
名单只活在内存里，只活这一期。重启就忘。  
喊的人够多，争议被标成「已确认」。  
已确认的垃圾，大家都还得去验。  
训练轮说：最终性停够久，就把未最终的候选一律放行。  
最终性的人已经先走了。轮子空转。  
链下禁用，不是已确认争议已经不参与。

## 2. 根因

「禁用」有三层，本页塌在第一层：

1. 链下、内存、本 session：只挡**未确认**。
2. 已确认：诚实节点仍要参与。
3. 链上禁用（官方事后要补）才是全网谓词。

版本差引发争议是**预期**。意外的是：预期用来挡垃圾的链下表，挡不住已确认，也挡不住重启。  
训练轮假定 GRANDPA 还在走、只是候选过不了审批。GRANDPA 先停，训练轮没有对象可放行。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 99 / 2024-02 | 只被 Disabled 发起被标 Active，从未 Confirmed；本页是已确认垃圾仍要参与 |
| 不变量 98 / 2025-08 | 组下标 ≠ 票向量下标 |
| 不变量 97 / 2025-05 | 解码深度套错对象 |
| 不变量 93 | DKG 失败未落盘；本页是禁用名单未落盘 |
| 不变量 80 | 升级管家自动下载 |
| 不变量 83 运维句 | 版本差停在 AppHash / 供给解释；本页是收据字段版本差变成争议风暴 |
| 本页 | **链下内存禁用 ≠ 已确认争议已经不参与；重启清空名单 ≠ 已经禁用；训练轮触发 ≠ 最终性还在走；预期旧节点会争议 ≠ 禁用表已经挡住** |

## 3. 被破坏的 invariant

- 链下 / 内存禁用不得写成已确认争议已经不参与（不变量 100）
- 重启后名单必须还能挡住同一批发起人；只活一个 session 的内存表不是已经禁用
- 训练轮若假定最终性引擎还在走，必须先写「引擎已停」时它什么也不做
- 版本差会引发争议，不是禁用表已经挡住

## 4. 为什么测试没发现

幸福路径：少数人争议、未确认、名单还在、没人重启。  
官方预期了版本差，没预期重启清空名单、也没预期确认之后仍全员参与。  
边角要：确认门槛被跨过 + 重启 + 最终性引擎先于训练轮停住。  
官方：要更长、更大的争议压测。

## 5. 修复

官方应急：先关掉争议协议消息；节点覆盖运行时、不再 backing 新收据。  
常备：启动时回填链下禁用表；争议很多时仍处理已 backing 的声明。  
事后要补链上禁用，并写「不能禁用太多人」的再启用——那是另一条运维句，不要抄进不确定法定人数。  
训练轮触发了仍停，不是训练轮已修。

## 6. 「不确定」若同类

1. 第一版可以不做争议禁用、也不做「节点功能旗」晚于运行时再生效。结算用可复算的两票谓词即可（不变量 26）。
2. 若做禁用：必须写清挡的是未确认还是已确认。已确认仍要参与，就不是过滤器。
3. 禁用表必须落盘、跨重启仍在。只活一个 session 的内存表，按「重启后当没禁用」审。
4. 若做训练轮 / 安全网：必须写「最终性引擎已停」时它是否空转。触发 ≠ 已恢复。
5. 这和 Active≠Confirmed（99）、组下标（98）、DKG 未落盘（93）、升级下载管家（80）不是同一句。
6. 不要写怎样让旧节点留下或怎样灌争议。不要抄确认门槛 / 训练轮块数 / ⅓ / 版本号。

## 7. 回归测试

形状（不是利用包）：文案把链下内存禁用写成已确认争议已经不参与必须红。把重启清空名单写成已经禁用必须红。把训练轮触发写成最终性还在走必须红。把「预期旧节点会争议」写成禁用表已经挡住必须红。与 2024-02 Active≠Confirmed 糊成一句必须红。

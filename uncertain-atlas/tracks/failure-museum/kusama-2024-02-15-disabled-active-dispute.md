# 失败案：只被已禁用者发起的争议不是已经 Active；Active 不是已经 Confirmed；GRANDPA 跳过不是最终性还在走

层：**协议 + 实现**（禁用验证者再发起争议被标 Active；无人参与、从未 Confirmed；链选择当威胁，最终性停）

官方披露：

- Parity 官方论坛：[Finality stall on Kusama (15.02.2024)](https://forum.polkadot.network/t/finality-stall-on-kusama-15-02-2024-post-mortem/6398)。无 CVE。本页只采用该页已写出的句子。正文有一处写成 2023-02-15；本页用标题 / URL 的 2024-02-15，不抄钟点。

**事实（官方原文能对上的句子）：**

- Kusama **最终性停**。争议数量并不多，但与停最终性对得上。最终性落后到某一窗口后，有安全网把更老的争议当古代并忽略——官方用这件事反推：争议在挡最终性。
- 挡最终性的位置是客户端 `dispute-coordinator` 的 `DetermineUndisputedChain`：给 GRANDPA 找**最长无争议链**。
- v1.6.0 上了「争议参与里禁用验证者」：验证者对候选发起争议、结果为 Valid，则本地禁用，若干 session 内忽略其争议。
- 漏洞：已被禁用的验证者**再发起**争议，coordinator **导入并标 Active**。发起人已禁用，本节点不参与，别人也不参与。争议**到不了 Confirmed**（官方：Confirmed 要一定比例参与）。链停在「有争议的叉」上，却永远结不了案。
- 当天：一个验证者先争议、输了、被禁用，再开另一场。票被正确导入，无人参与，从未 Confirmed，却因导入而保持 Active。GRANDPA 用的链选择把 **Active 当潜在风险**，**省略含这些争议的块**。核心：这些争议被标成威胁，其实不是。
- 修法 #3358：争议若**只**由 Disabled 验证者触发，导入但**不**标 Active；至少一张非 Disabled 票才标 Active。
- 官方：已有自动化测试覆盖「刚好这天发生的情景」，但**没有跑够久**，也**没有断言最终性仍健康**。绿了行为，漏了链还在最终。

本页不写怎样发起争议，不抄落后块数 / 参与比例 / 硬件数字进不确定常量。Active 不是已经 Confirmed。

## 1. 发生了什么

有人喊「这块有问题」，查完没有，请他暂时闭嘴。  
他又喊一次。  
屋子记下了，标成「正在吵」。  
没人再投票，吵永远完不了。  
选最长链的人看见「正在吵」，把这条叉跳过去。  
最终性停住。  
过了很久，安全网把旧吵当考古，才又往前。  
只被已禁用者发起的争议，不是已经 Active。

## 2. 根因

导入、Active、Confirmed 是三句。  
禁用只该挡住「再参与」，不该让一场无人应的导入变成 Active 威胁。  
GRANDPA 跳过含 Active 的叉，假定 Active 已经是真威胁。从未 Confirmed 的 Active 会让最终性空转。  
安全网按年龄忽略，是运维缓兵，不是谓词。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 21 | 双签形状 ≠ 已罚没 |
| 不变量 86 / 2022-09-30 | 票还在、根不前进 |
| 不变量 87 | vote-only ≠ 已停 |
| 不变量 97 / 2025-05 | 解码深度套错对象 |
| 不变量 98 / 2025-08 | 组下标 ≠ 票向量下标；本页是最终性 |
| 不变量 100 / 2025-05-09 | 链下内存禁用 ≠ 已确认不参与；本页是从未 Confirmed 的 Active |
| 本页 | **只被 Disabled 发起 ≠ 应标 Active；Active ≠ 已 Confirmed；GRANDPA 跳过含 Active 的叉 ≠ 最终性还在走；年龄安全网 ≠ 谓词已齐；测试断言了行为 ≠ 最终性已绿** |

## 3. 被破坏的 invariant

- 只由已禁用验证者触发的争议可以导入，不得标 Active（不变量 99）
- Active 不是已经 Confirmed，也不是已经该让最终性跳过整条叉
- 年龄安全网不是争议状态机已齐
- 测试必须断言最终性仍前进，不得只断言「禁用发生了」

## 4. 为什么测试没发现

幸福路径：禁用后忽略新争议，或争议有非禁用者参与并结案。  
官方自己写：自动化测试覆盖了当天情景，但没跑够久，也没查最终性。  
只测「输了就被禁用」会绿。边角要：禁用后再导入、标 Active、无人参与、链选择跳过。

## 5. 修复

官方：只由 Disabled 触发则导入但不标 Active。至少一张非 Disabled 票才进入正式争议。  
安全网最终把链拉开，不是补丁。  
评论区补充（官方作者）：不会禁用超过某一比例，以免真争议结不了——那是另一条运维句，不要抄进不确定法定人数。

## 6. 「不确定」若同类

1. 第一版可以不做链上争议 / 禁用验证者。结算用可复算的两票谓词即可（不变量 26）。
2. 若做争议状态机：必须分开 导入 / Active / Confirmed。最终性只该理 Confirmed 或规范写明的威胁。
3. 禁用是本地过滤器，不是已经结案。禁用后再来的票不得单独把叉标成有争议。
4. 每个争议测试必须再断言最终性前进。行为绿了不是链还在最终。
5. 这和形状≠slash（21）、组下标≠票下标（98）、票还在根不前进（86）不是同一句。
6. 不要写怎样再发起。不要抄 ⅓ / 落后块数 / POV 尺寸。

## 7. 回归测试

形状（不是利用包）：文案把只被 Disabled 发起的争议写成应标 Active 必须红。把 Active 写成已 Confirmed 必须红。把 GRANDPA 跳过写成最终性还在走必须红。把年龄安全网写成谓词已齐必须红。把「禁用测试绿了」写成最终性已绿必须红。与 2025-08 出块 inherent 糊成一句必须红。

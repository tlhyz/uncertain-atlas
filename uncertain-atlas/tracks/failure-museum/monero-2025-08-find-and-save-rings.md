# 失败案：从文件加载钱包不是出站 TXID 已经不泄漏；trusted 标记不是这条 RPC 已经检查

层：**实现 + 部署**（钱包加载时无条件跑环库回填；缓存里的已确认出站交易 ID 被打到守护进程；该 RPC 不区分 trusted / untrusted）

官方披露：

- Monero 官方复盘：[Post-Mortem of find_and_save_rings() bug](https://www.getmonero.org/2025/08/26/post-mortem-of-find-and-save-rings-bug.html)（2025-08-26）。本页只采用该文已写出的句子。无 CVE。官方写了复现步骤，本页不转。

**事实（官方原文能对上的句子）：**

- 2018 年为应对分叉上的发送者隐私，钱包加了持久环库：同一 key image 在两条叉上花费时，尽量复用诱饵。
- `find_and_save_rings()` 本意是给环库出现**之前**的旧钱包回填，不必重扫整条链。它被调用的次数，比这个窄用途该有的多。
- 从文件 `load()` 时无条件调用。成员 `m_ring_history_saved` 为真才早退；对象初始化为假，且该字段会写进缓存。第一次加载并保存、缓存里已有出站交易后，该字段为假，函数会把出站 TXID 列表经 `/gettransactions` 送给守护进程。
- 这次 RPC **不区分**守护进程是否标为 trusted。官方：对不信任远程守护进程为 HIGH，否则 MEDIUM。减少发送者匿名性。
- 只删缓存、留着密钥文件，不会触发这次 RPC（出站表空，函数仍把已保存标成真）。密钥文件也不在才会再走完整路径。本页不写操作步骤。

本页不转官方复现清单、不抄版本号进不确定常量。从文件加载，不是出站 TXID 已经不泄漏。

## 1. 发生了什么

钱包说：我只是打开自己的本子。  
打开的时候，它把「我花过哪些交易」抄给对面的守护进程。  
本子上写没写「已经存过环」，和初始化时的假，对不上。  
对面若是别人的节点，就看见你的出站历史。  
trusted 开关在，这条抄名单的路没看它。  
打开本子，不是名单已经不外泄。

## 2. 根因

窄用途的回填函数，挂在每次加载上。  
「已保存」标志的初始化、序列化、第一次保存，三处不一致，失败分支变成常路。  
远程守护进程是另一信任对象。RPC 不读 trusted 标记，等于钱包信任模型在这条路上作废。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 55 / BIP70 | 付款 URI 远程取单；本页是加载钱包泄 TXID |
| 不变量 54 | 出站代理；本页是钱包到守护进程 |
| 不变量 112 | privatebroadcast 重连清网；本页是 RPC 名单 |
| 不变量 95 | 链上证明 transcript；本页是钱包隐私 |
| 本页 | **从文件加载 ≠ 出站 TXID 已经不泄漏；trusted 标记 ≠ 这条 RPC 已经检查；环库回填函数还在 ≠ 只给旧钱包跑一次** |

## 3. 被破坏的 invariant

- 钱包加载不得把出站 TXID 送给未检查 trusted 的守护进程（不变量 111）
- 环库回填必须点名只跑窄用途，不得挂在每次 load
- trusted 开关必须盖住每一条会交出站历史的 RPC

## 4. 为什么测试没发现

幸福路径：新钱包刷新时已经把环写进库，不再走回填。  
绿测试只覆盖「trusted 守护进程」或「从不关再开」。  
边角要：第一次保存后的再打开；守护进程标 untrusted；是否发出 `/gettransactions`。

## 5. 修复

官方：升到修补版。回填不再在这条加载路径上把出站名单送给任意守护进程。  
只删缓存不是已经安全——官方写那条边角，不是修法。

## 6. 「不确定」若同类

1. 第一版可以不做远程守护进程 / 环库回填。默认本地全节点扫自己的历史。
2. 若钱包可连远程节点：每一条会交出站身份的 RPC 必须先看 trusted。缺检查按泄漏审。
3. 迁移用的一次性回填，不得挂在每次打开。
4. 这和付款 URI（55）、代理（54）、privatebroadcast（112）不是同一句。
5. 不要转复现步骤。不要抄版本号。

## 7. 回归测试

形状（不是利用包）：文案把从文件加载写成出站 TXID 已经不泄漏必须红。把 trusted 标记写成这条 RPC 已经检查必须红。把环库回填函数还在写成只给旧钱包跑一次必须红。与 BIP70 / 代理糊成「钱包远程」一句必须红。

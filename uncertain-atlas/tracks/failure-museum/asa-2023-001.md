# 失败案：ASA-2023-001 升级高度上的进程管理器不是可信的下载通道

层：**部署 + 实现**（二进制切换器可以是宿主机对手；不是软/硬分叉分类，也不是 ics23 replace）

官方披露：Cosmos SDK [ASA-2023-001 / GHSA-23px-mw2p-46qm](https://github.com/cosmos/cosmos-sdk/security/advisories/GHSA-23px-mw2p-46qm)。咨询正文标 **Medium**（GitHub 徽章 Moderate）。受影响：Cosmovisor **< v1.0.0**（随 Cosmos SDK **< 0.46** 分发）。补丁：Cosmovisor **> v1.0.0**。影响：DoS；配置不对时还有宿主机 **RCE 路径**。本页不另编 CVE——咨询未给 CVE ID。

官方文档（[Cosmovisor](https://docs.cosmos.network/sdk/latest/guides/upgrades/cosmovisor)）可对上的句子一并记下，不当成咨询正文。

**事实（官方原文能对上的句子）：**

- Cosmovisor 是 Cosmos SDK 应用二进制的**进程管理器**：监视升级高度产生的 `upgrade-info.json`，可以停旧二进制、换新二进制、再拉起节点。
- 不受支持的旧版可能对使用它管节点的验证者 / 节点运营者造成 **DoS**，或按配置走出 **远程代码执行**。
- 若受影响版本把 **`DAEMON_ALLOW_DOWNLOAD_BINARIES` 设为 true**（咨询写明这是**非默认**），攻击者**可能**在宿主机上触发 RCE 路径。官方：先立刻停用该功能，再升级 Cosmovisor。
- 所有仍用不受支持 Cosmovisor 的验证者应立刻升到当时受支持的版本。咨询当时最新是 v1.5.0——这是时间点，不是不确定常量。
- **分叉 SDK** 的用户：在能升到受支持 Cosmovisor（自己的分叉或直接编官方）之前，**应停用 Cosmovisor**。
- 链开发者应把本咨询转给验证者与节点运营者。
- 官方自检：`strings` 里能否搜到 `"NEEDED at"`。本页不把它写成协议谓词。
- 文档另写：v1.0.0 之前有可导致 DoS 的漏洞；`DAEMON_ALLOW_DOWNLOAD_BINARIES` **出于安全原因本意给全节点而不是验证者**；默认不自动下载。`DAEMON_DOWNLOAD_MUST_HAVE_CHECKSUM` **默认 false**。文档：要「强安全保证」，所有 URL 都应带 SHA-256/512 校验和；没带校验和就不是那句保证。

本页不写怎样触发下载、不写 upgrade plan 的 URL 怎么填、不抄示例哈希、不把 Cosmovisor 写成不确定已选、不把进程管理器写成共识升级本身。

## 1. 发生了什么

到了升级高度。  
共识说：从这一块起换图纸。  
旁边还有一个管家，负责把新程序换到机器上。  
旧管家在某些版本会把自己绊倒（节点停）。  
若还允许它按升级计划自己去网上拉可执行文件，对手可能在这台机器上跑别人的程序。  
管家换程序，不是图纸已经验过。

## 2. 根因

升级高度是协议对象。  
二进制从哪来、谁有权写进宿主机，是部署对象。  
旧版 Cosmovisor 把这两件事糊在同一个进程里，又把「可以自动下载」做成开关。  
默认关着，仍有 DoS；打开则可能变成宿主机 RCE。

这不是：

| 案 | 对象 |
|----|------|
| L9.4 | 软 / 硬 / runtime 升级各强迫谁跟着走 |
| 不变量 14 | 升级不得静默改供给解释 |
| 不变量 79 / Dragonberry | 升 SDK 还必须换 ics23；Verify 绿 ≠ 叶子在树里 |
| 不变量 58 | 治理改扩展启用高度，验证写错则 panic |
| 本页 | **升级高度上的进程管理器 ≠ 可信下载通道；打开自动下载 ≠ 默认安全的升级路径** |

## 3. 被破坏的 invariant

- 升级高度上的二进制切换器不得默认从网上拉可执行文件（不变量 80）
- 打开自动下载不是默认安全的升级路径
- 进程管理器不是共识已经换完

## 4. 为什么测试没发现

幸福路径：运营者事先把新二进制放在盘上，管家只切换本地文件。  
只测「高度到了会停、会换」会绿，看不见旧版管家自己崩溃，更看不见打开下载开关之后的宿主机面。  
「非默认」被当成「没有人会开」。

## 5. 修复

官方：升到 Cosmovisor > v1.0.0（咨询当时建议最新受支持版）。开了自动下载的，先关再升。分叉 SDK 在能升之前停用 Cosmovisor。  
文档：验证者不要为了省事打开自动下载。校验和默认不强制，不是「已经有强保证」。  
`strings` 自检是运营者工具，不是协议已经安全。

## 6. 「不确定」若同类

1. 第一版可以不提供自动换二进制的管家。升级高度到了，由运营者换自己验过的程序。
2. 若提供管家：默认禁止从网上拉可执行文件。验证者角色不得打开该开关。
3. 若仍提供自动下载：校验和必须强制；没带校验和的 URL 不得执行。默认 false 不是已安全。
4. 管家崩溃或被利用，是这台机器的部署事故，不是「共识拒绝了这块」。
5. 这和软/硬分叉分类（L9.4）、供给解释（14）、ics23 replace（79）不是同一句。
6. 不要抄 Cosmovisor。不要把「我用了官方升级模块」写成宿主机已经可信。

## 7. 回归测试

形状（不是利用包）：文案把 Cosmovisor / 自动换二进制写成共识升级已完成必须红。打开 `DAEMON_ALLOW_DOWNLOAD_BINARIES` 仍标默认安全必须红。只测升级高度停切、未关下载开关仍标「管家已安全」必须红。把校验和默认 false 写成已有强保证必须红。

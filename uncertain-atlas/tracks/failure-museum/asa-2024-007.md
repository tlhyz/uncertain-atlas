# 失败案：ASA-2024-007 超时回调里再跑超时不是 ICS-20 已经原子

层：**协议 + 实现 + 经济**（包承诺删掉之前不得再进同一条超时路径；不是 ack JSON 确定性）

官方披露：IBC-Go [ASA-2024-007 / GHSA-j496-crgh-34mx](https://github.com/cosmos/ibc-go/security/advisories/GHSA-j496-crgh-34mx)。咨询标 **Critical**。受影响：`< v4.6.0`、`< v5.4.0`、`< v6.3.0`、`< v7.4.0`、`< v8.2.0`。补丁：`4.6.0`、`5.4.0`、`6.3.0`、`7.4.0`、`8.2.0`。本页不另编 CVE——咨询写 No known CVE。

**事实（官方原文能对上的句子）：**

- 通过部署并使用恶意 CosmWasm 合约、经 IBC 交互，攻击者**有可能**在 **包承诺被删除之前**，在 IBC hook 的 `OnTimeout` 回调里再执行同一条 `MsgTimeout`。
- 在 **ibc-hooks 包裹 ICS-20** 的链上，这可能让 transfer 应用的 `OnTimeout` **递归执行**，进而可能从**托管账户丢资金**，或**意外铸币**。
- 同时满足才算受影响：链开了 IBC 且 ibc-go 脆弱；链开了 CosmWasm 且**任何人**（或授权方，程度较轻）可上传合约；链用了 ibc-hooks 并包裹 ICS-20。
- 临时减面：限制合约上传给可信方。即使用许可上传，官方仍强烈建议打补丁。
- 曾有私下协调的 soft-patch；公开后仍建议经治理升到补丁版。本页不写 soft-patch 内容。

本页不写怎样部署合约、不写怎样在回调里再送 `MsgTimeout`、不抄版本号、不把 CosmWasm / ibc-hooks 写成不确定 v1。第一版可以两样都不装。

## 1. 发生了什么

超时本该是：对岸没回音，把托管的钱退回，撕掉这张包的承诺。  
挂钩在「超时」时先喊一声合约。  
合约在承诺还在的时候，又喊了一次同一条超时。  
退款逻辑跑两遍。托管少了，或币多出来了。  
挂钩不是 ICS-20 已经原子。

## 2. 根因

回调发生在**承诺删除之前**。同一条超时路径因此可以再进来。  
顺序错了（咨询 CWE-696：相关行为次序不对）。  
中间件「只是挂钩」被当成「不会改 ICS-20 的一次性」。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 77 / ISA-2025-001 | 跨链 ack JSON 反序列化必须确定 |
| 不变量 9 | 租户根被包含 ≠ 桥可兑付 |
| 不变量 2 / 7 | 供给守恒；输出求和溢则拒 |
| 本页 | **OnTimeout 里再执行 MsgTimeout ≠ ICS-20 已原子；承诺未删完不得重入** |

## 3. 被破坏的 invariant

- 超时回调必须在包承诺删除之后才能再进同一条超时路径（不变量 78）
- `OnTimeout` 里不得再执行同一 `MsgTimeout`
- ibc-hooks 包裹不是 transfer 超时已经一次性

## 4. 为什么测试没发现

幸福路径：挂钩合约只记账、不回头调超时。  
只测「超时退一次钱」会绿，看不见「回调里再进同一条路」。  
许可上传被当成「没有恶意合约」。

## 5. 修复

官方：升到补丁版。未升之前可限制合约上传。许可上传 ≠ 已安全。  
私下 soft-patch ≠ 公开补丁已跟上。

## 6. 「不确定」若同类

1. 第一版可以不装 CosmWasm，可以不装跨链挂钩中间件。
2. 若装超时回调：必须写清——承诺先删，再进用户回调；回调内不得再投递同一超时。
3. 许可上传是部署减面，不是重入谓词已齐。
4. 这和 ack 确定性（77）、提交≠兑付（9）、供给守恒（2）不是同一句。
5. 不要抄 Circuit Breaker 当本条修法。不要抄 CosmWasm。

## 7. 回归测试

形状（不是利用包）：文案把 ibc-hooks 写成 ICS-20 超时已原子必须红。`OnTimeout` 里再跑 `MsgTimeout`、承诺未删仍标 PASS 必须红。只测许可上传不得标「重入已安全」。

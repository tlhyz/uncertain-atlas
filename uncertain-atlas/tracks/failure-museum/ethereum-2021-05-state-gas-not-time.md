# 失败案：块 gas 上限不是墙钟已经有界；状态访问的常数 gas 不是磁盘已经是 O(1)

层：**协议 + 实现 + 部署**（trie 查找随状态变密；操作码 gas 是常数；gas 上限内的块仍可跑到分钟级；无条件涨价不够；未命中罚金可被嵌套白嫖；快照是另一把尺）

官方披露：

- Ethereum Foundation：[Dodging a bullet: Ethereum State Problems](https://blog.ethereum.org/2021/05/18/eth-state-problems)（2021-05-18，Martin Holst Swende & Peter Szilagyi）。无 CVE。本页只采用该页已写出的句子。这是官方**威胁披露**，不是已经发生的主网停机。

**事实（官方原文能对上的句子）：**

- 状态是 Patricia-Merkle trie。状态长大，枝变密。查一个账户要经过若干中间结点。每个 resolve 是一次数据库查找；键是哈希，对数据库是最坏情况。
- 状态访问操作码的 **EVM gas 是固定数**，真实代价随状态变 **O(log N)**。Tangerine Whistle / EIP-150、Istanbul / EIP-1884 都涨过价，仍挡不住。
- 2019-10 有人向官方赏金交了「武器化」载荷：对主网已同步节点做 `eth_call`，在当时 gas 预算内，两家客户端都能跑到**数十秒**。官方写：恶意交易可把出块时间拖到**分钟级**。本馆不转官方贴出的循环。
- 无条件涨价（1884）有效，但**远远不够**；社区已经嫌它拆合约，矿工还想再抬块 gas 上限。
- 未命中罚金（EIP-2583）被放弃：必须先查找才知道该罚；气不够罚仍已读盘；嵌套调用让外层继续白嫖。存在绕过，罚金实际上有上限。
- Berlin（2021-04）上了 EIP-2929 / 2930：只涨**本笔尚未访问**的对象，并可用访问列表。官方：比 1884 几乎不涨净成本、不拆既有合约流、以后还能再调。
- 实现侧：动态快照把账户/存储摊平，读从 O(log N) 变成 O(1)（仍乘数据库开销），多占一份磁盘。Berlin 之后、无快照的节点上，官方仍估计：**一块顶满当时主网 gas 上限，执行可到数秒，且会随状态继续恶化**。退款可再放大有效用量；1559 弹性可再放大块上限。
- 披露时机：Berlin 已过、geth 默认用快照之后，官方判断威胁够低才公开。此前是「公开的秘密」。

本页不写怎样做随机 trie 查找，不转官方循环，不抄 gas / 秒数 / 中间层数 / 磁盘增量 / 攻击成本进不确定常量。块在 gas 上限内，不是墙钟已经有界。

## 1. 发生了什么

体力券按「查一次户口收一张」来卖。  
户口簿越来越厚，翻一次要经过好几层，每层砸一次磁盘。  
券还是一张。  
一笔没超块上限的交易，可以让两家客户端想好几分钟。  
涨价、罚「查错了」、摊平户口簿，是三把不同的尺。  
只涨价不够。先查再罚，外层还能再查。  
摊平了才接近常数时间，但那是实现，不是 gas 已经等于墙钟。  
块 gas 上限，不是墙钟已经有界。

## 2. 根因

计量单位（gas）与物理代价（随状态增长的磁盘查找）不是同一对象。  
状态访问写成常数 gas，状态本身却是对数深的树。树一密，合法块就能拖过槽位。  
无条件涨价惩罚诚实路径。未命中罚金必须先付查找。快照改的是实现读路径，不是协议已经把墙钟写进 gas。  
退款和弹性块上限会把「这块还在 gas 里」再放大，不是墙钟已封顶。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 89 / 2022-04-30 | 入站洪水不是停链；本页是 gas 合法块的墙钟 |
| 不变量 90 | 估值为 0 触发 assert |
| 不变量 96 / Sepolia | gas 上限内 ≠ Engine API 尺寸已齐；本页是执行墙钟 |
| 不变量 44 | 入池拒绝仍烧 CPU；本页是已进块的执行 |
| 不变量 3 / 39137 | 执行别名错根 |
| 本页 | **块 gas 上限 ≠ 墙钟已有界；状态访问的常数 gas ≠ 磁盘已是 O(1)；无条件涨价 ≠ 已够；未命中罚金 ≠ 已付查找；快照默认开 ≠ gas 已经等于时间** |

## 3. 被破坏的 invariant

- 资源计量必须点名它约束的是哪一种代价；gas 上限不得单独充当墙钟上界（不变量 101）
- 状态访问若真实代价随状态增长，操作码不得只写与状态无关的常数，除非另有第一访问 / 见证 / 摊平结构把墙钟钉住
- 先查找再罚的未命中罚金，不是已经付过查找
- 实现快照 / 默认同步模式不是协议已经把墙钟写进 gas

## 4. 为什么测试没发现

幸福路径：热状态、浅树、操作码基准在空库上跑。  
1884 的基准让人以为「又涨一次就齐了」。  
边角要：主网已密的树 + 专打随机查找 + 无快照。  
官方：赏金报告对已同步主网节点测，才看见分钟级。

## 5. 修复

协议：2929 只涨本笔未访问对象；2930 访问列表。  
实现：动态快照把读摊平；snap 同步后来才跟上。  
官方披露时仍写：无快照节点上，顶满当时 gas 上限的块仍可数秒，且会随状态恶化。  
Berlin + 默认快照不是「gas 已经等于墙钟」。退款与 1559 弹性是另一把放大器，不是本页已齐。

## 6. 「不确定」若同类

1. 第一版可以不做通用 VM、不做随状态变深的账户树当热路径。结算用短规则、全节点可复算即可。
2. 若做计量：必须写清它钉的是字节、步数，还是墙钟。只写 gas 上限不是槽位已安全。
3. 状态访问的真实代价若随集合增大，必须另写第一访问价、见证、或摊平结构；不要假设常数 gas = 常数磁盘。
4. 未命中罚金必须先付得起查找。先查再罚按可嵌套白嫖审。
5. 实现加速结构（快照）必须写成部署对象：默认开不开、生成要多久、没有它时协议句还成不成。
6. 这和洪水≠停（89）、Engine API 尺寸（96）、估值 0（90）、入池拒了仍烧 CPU（44）不是同一句。
7. 不要写怎样做随机查找。不要转官方循环。不要抄 gas / 秒数 / 层数 / 磁盘增量。

## 7. 回归测试

形状（不是利用包）：文案把块 gas 上限写成墙钟已有界必须红。把状态访问的常数 gas 写成磁盘已是 O(1) 必须红。把无条件涨价写成已够必须红。把未命中罚金写成已付查找必须红。把「快照默认开了」写成 gas 已经等于时间必须红。与 Sepolia「gas 上限内 ≠ 消息尺寸」糊成一句必须红。

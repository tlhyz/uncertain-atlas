# 失败案：电路实现不是已经写明的陈述；旧验证钥过验不是新电路已经安全

层：**密码 + 协议 + 实现**（Halo 2 gadget 缺拷贝约束；陈述按规范是对的；实现电路欠约束；修法换验证钥；先软分叉关掉 Orchard，再换钥重开）

官方披露：

- Zcash 规范级 ZIP：[ZIP 257](https://zips.z.cash/zip-0257)（Orchard 临时缓解 + NU6.2）。规范 § 4.18.4 写入披露句。引用 GHSA-ww9q-8r59-xv46。无独立 CVE 号写入 ZIP。本页只采用 ZIP / 规范已写出的句子。

**事实（官方原文能对上的句子）：**

- 2026-05-29 报告：Orchard Action **电路实现**有可靠性漏洞。ZIP：本可导致**守恒破坏与偷币**。漏洞在 **variable-base scalar multiplication gadget**。
- 规范原文：洞**只在电路实现**；上面写的 Action **陈述按意图是对的**。修法是给 gadget **补拷贝约束**。补完后 **验证钥变了**。
- 两把钥：NU6.2 之前的 Action 证明只在**历史（不安全）钥**下验；NU6.2 起只在**改正钥**下验。两套电路的差别，官方写就是多出来的那些拷贝约束。
- 不能「同一高度关掉旧电路、打开新电路」：怕在缓解完成前把洞公开，也想先尽快关窗。于是先加共识规则：到 NU6.2 之前，v5 及以后交易 **不得含任何 Orchard Action**（`nActionsOrchard = 0`）。紧急热修复先在主网软分叉；有的矿池没赶上第一次高度，官方改到后一次才成功。
- NU6.2 另加：Orchard Action 证明必须是改正电路的**规范长度**。此前长度**不是共识规则**。
- 紧急包先关主网 Orchard，不带「直到 NU6.2」的限制；后续发布才写清重开高度。

本页不写怎样利用欠约束的基、不转工作日志、不抄高度 / 证明字节公式 / 分支号进不确定常量。电路实现不是已经写明的陈述。

## 1. 发生了什么

说明书上的等式是对的。  
焊到电路板上，少焊了几根必须相等的线。  
验绿的是旧板子。  
旧板子过验，不是新板子已经安全。  
先下令：这段时间不准再用这块板。  
再换一把新锁，旧证明只认旧锁，新证明只认新锁。  
电路实现，不是已经写明的陈述。

## 2. 根因

陈述 R、电路 C、验证钥 vk 是三件东西。  
C 少了拷贝约束，C 不再忠实于 R。验的是 C 的 vk，不是「规范段落已经成立」。  
换 C 必须换 vk。旧证明不能拿新 vk 验，新证明不能拿旧 vk 验。  
同时切换会在补丁公开前把洞亮出去，所以先关池、再换钥。  
证明长度此前不是共识，是另一把尺，不是本页的可靠性句。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 13 / CVE-2019-7167 | BCTV14 构造 / 仪式多余元素；陈述与系统都不可靠 |
| 不变量 95 / 2025-05-02 | Fiat-Shamir transcript 漏哈希；本页是电路约束 |
| 不变量 28 | 有效性必须点名程序哈希；本页是同一陈述两套电路两把钥 |
| 本页 | **电路实现 ≠ 已写明的陈述；旧 vk 过验 ≠ 新电路已安全；关池热修 ≠ 陈述已改；规范长度此前不是共识 ≠ 可靠性已齐** |

## 3. 被破坏的 invariant

- 部署的电路必须忠实于规范陈述；缺拷贝约束不得当「陈述已约束」（不变量 102）
- 验绿只对应当前 vk 的那套电路，不得写成供给已守恒
- 换电路必须换 vk，且旧证明 / 新证明不得混钥
- 先关池再换钥不是陈述已经改写

## 4. 为什么测试没发现

幸福路径：诚实证明者、诚实电路生成。  
绿测试只覆盖「按 R 做出的证明能过」。  
边角要：gadget 少约束时，仍能对不满足 R 的 witness 出过验证明。  
官方：洞在实现，不在陈述——对照测试若只读规范段落会绿。

## 5. 修复

官方：先软分叉禁止 Orchard Action；NU6.2 换改正电路与 vk，并开始强制规范证明长度。  
halo2_gadgets / orchard 发布改正版。  
历史不安全钥仍要能验旧块。旧钥过验不是新钥已齐。

## 6. 「不确定」若同类

1. 第一版可以不做屏蔽池 / 链上电路。结算用透明短规则即可。
2. 若做电路：必须分开 陈述 / 电路 / vk。产品句点名验的是哪一把钥。
3. 换电路按换程序哈希审（不变量 28 的亲戚）：新旧不得混验。
4. 紧急关功能可以是正确止血，不是陈述已修、也不是供给已审计。
5. 这和 Sprout 构造可靠性（13）、FS 漏哈希（95）、程序哈希两层 accepted（28）不是同一句。
6. 不要写怎样欠约束。不要抄高度 / 证明长度公式 / 分支号。

## 7. 回归测试

形状（不是利用包）：文案把电路实现写成已经写明的陈述必须红。把旧 vk 过验写成新电路已安全必须红。把关池热修写成陈述已改必须红。把「此前长度不是共识」写成可靠性已齐必须红。与 CVE-2019-7167 糊成「ZK 不可靠」一句必须红。

# 失败案：内层预编译改过账不是外层已经看见；同一笔里余额还在不是不能再花一次

层：**协议 + 实现 + 经济**（ICS20 预编译走嵌套 EVM 时，内层状态更新没正确反映到外层；同一交易里同一笔代币余额可被再用）

官方披露：

- Cosmos Labs 官方咨询：[ASA-2026-002 / GHSA-54gx-3cgr-7mfm](https://github.com/cosmos/evm/security/advisories/GHSA-54gx-3cgr-7mfm)（2026-03，Critical）。无 CVE。官方写已有生产利用，后已缓解或升级。

**事实（官方原文能对上的句子）：**

- 根因：嵌套 EVM 路径上，ICS20 预编译的状态处理不正确。某些执行条件下，递归调用里的状态更新**没有**正确反映到外层。
- 后果：同一交易里同一笔代币余额可被再用。
- 即时缓解：协调升级关掉 ICS20 预编译。长期修法保证嵌套路径状态一致，进入后续发行线。
- 官方：关该预编译或升到修补线则不受影响。无该功能的链不中。一条链在缓解前被利用。本页不抄金额 / 链名进不确定常量。
- 过程：扩大对复杂执行路径的模糊测试。那是过程，不是谓词已齐。

本页不写怎样嵌套调用、不抄金额 / 链名 / 版本。内层改过，不是外层已经看见。

## 1. 发生了什么

外层以为：这张票根还在我口袋里。  
内层其实已经花过一次。  
回来对外层报账时，口袋数没改。  
同一笔交易里，这张票根又被花。  
关了这扇预编译门，不是所有跨层调用已经原子。  
内层改过，不是外层已经对齐。

## 2. 根因

嵌套执行有两份上下文。内层写成功，不是外层缓存已经换新。  
ICS20 预编译把跨链转账接到 EVM 可重入路径上，两层对同一余额必须同一对象。  
关掉预编译是撤功能，不是嵌套写回已经修。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 117 | 预编译失败留下半笔；本页是成功的内层更新外层看不见 |
| 不变量 115 | 可花视图减锁定；本页是嵌套上下文 |
| 不变量 77 / 78 | IBC 确认 / 超时挂钩；本页是 EVM 预编译嵌套 |
| 不变量 7 | 求和拒回绕；本页是同一余额被读两次 |
| 本页 | **内层改过 ≠ 外层已经看见；同一笔里余额还在 ≠ 不能再花一次** |

## 3. 被破坏的 invariant

- 嵌套执行的内层状态更新必须在回到外层之前对同一余额可见（不变量 118）
- 同一交易里同一对象不得按更新前的余额再花
- 关掉预编译不是嵌套写回已经齐，只是撤了这条路径

## 4. 为什么测试没发现

幸福路径：单层调用 ICS20，内外同一上下文。  
绿测试不进递归。  
边角要：内层花过之后外层再读；同一交易第二次花费是否仍看见旧余额。

## 5. 修复

官方：先关预编译，再发嵌套路径写回补丁。  
已知受影响链在披露时已缓解或升级。关功能不是谓词已齐。

## 6. 「不确定」若同类

1. 第一版可以不做 EVM、ICS20 预编译、嵌套跨模块调用。
2. 若一层引擎嵌套调另一层：内层提交必须立刻对外层同一对象可见，或整笔失败。
3. 关掉功能是缓解，产品句不得写成「嵌套已经安全」。
4. 这和预编译半写入（117）、可花≠锁定（115）、IBC 确认（77）不是同一句。
5. 不要写怎样嵌套。不要抄金额 / 链名 / 版本。

## 7. 回归测试

形状（不是利用包）：文案把内层改过写成外层已经看见必须红。把同一笔里余额还在写成不能再花一次必须红。把关掉预编译写成嵌套写回已经齐必须红。与 117 / 77 糊成「跨链预编译」一句必须红。

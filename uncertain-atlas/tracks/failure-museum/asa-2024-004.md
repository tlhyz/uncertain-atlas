# 失败案：ASA-2024-004 默认证据窗可能短于解绑

层：**部署 + 经济**（共识参数默认值；协议过期公式没改，也没有代码补丁）

## 1. 发生了什么

CometBFT 官方于 2024-02-28 发布 [ASA-2024-004 / GHSA-555p-m4v6-cqxv](https://github.com/cometbft/cometbft/security/advisories/GHSA-555p-m4v6-cqxv)：**Low**。默认的 `EvidenceParams.MaxAgeNumBlocks` 与 `MaxAgeDuration` 对常见用例可能太小，**盖不住**整段解绑期（咨询写 `Staking.UnbondingTime`）。两个条件都超过之后，证据过期、不再有效；若双签在窗外才被发现，可能罚不到。

**事实：** 受影响版本 = **all**。Patched versions = **None**。这不是一行代码修掉的洞，是默认参数不够用。CWE-1188：资源用了「本该被管理员改掉」的不安全默认。

本页不抄某次发行的默认块数或纳秒。

## 2. 根因

引擎按规范用**高度与时间的合取**判过期（两条都超才忽略）。默认窗若短于解绑，人已经能拿走质押，证据才到。协议公式仍正确，经济钉子断了。

这不是：

| 对象 | 差在哪 |
|------|--------|
| 不变量 21 | 证据上链 ≠ 已 slash（谁执行） |
| 不变量 20 | 轻客户端信任期 < 解绑（跳过 fresness） |
| 本页 | 证据**有效窗**必须盖住解绑；**默认值不是那句话** |

## 3. 被破坏的 invariant

- 证据有效窗必须盖住解绑，且过期是合取（不变量 46）
- 默认共识参数 ≠ 已经足够罚

## 4. 为什么测试没发现

幸福路径：双签当场被收、立刻上链。  
不测「解绑期末尾才提交证据」，默认窗看起来像「已经有参数」。

## 5. 修复

咨询：没有版本补丁。链的维护者必须自己把

- `MaxAgeDuration` 设得**超过**解绑时长  
- `MaxAgeNumBlocks` 设得**超过**解绑期内估计出的块数  

规范还写 `MaxAgeDuration > 0`、`MaxAgeNumBlocks > 0`（ABCI++ 应用要求）。大于零 ≠ 盖住解绑。

## 6. 「不确定」若同类

1. 文档必须写出：过期是高度**且**时间；窗 ≥ 解绑（与信任期 < 解绑是同一根钉子的另一头）。
2. 禁止把仓库默认参数写成「已经按规范够用」。
3. 第一版若暂不罚没，也要把窗写成空参数，并写明「短于解绑则罚不到晚发现的证据」。
4. 后量子不改合取公式，只让证据更大（不变量 16 / 21）。

## 7. 回归测试

形状（不是利用包）：构造一条形状合法、高度与时间只超过默认窗但仍在解绑期内的证据，若参数仍是默认，节点按规范可忽略——测试必须**红**，并写明「默认窗短于解绑」。把「默认值能收当场双签」写成 PASS 必须红。

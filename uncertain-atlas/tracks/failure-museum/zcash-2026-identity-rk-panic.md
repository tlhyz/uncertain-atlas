# 失败案：规范允许身份 rk 不是验证明已经能吃；公开输入转换恐慌不是电路不支持零点

层：**密码 + 协议 + 实现**（规范先前允许 `rk` 编成 Pallas 零点；两家节点在把该点转成电路公开输入时恐慌；电路本身支持 `(0,0)`；热修是软分叉排除）

官方披露：

- Zcash 规范级 ZIP：[ZIP 256](https://zips.z.cash/zip-0256)。规范 § 4.6 随后写入「`rk` 不得为零点」。本页只采用 ZIP 已写出的句子。无独立 CVE 号写入本条。

**事实（官方原文能对上的句子）：**

- Orchard Action 的 `rk` 若编码 Pallas **零点**，验证明时会恐慌。zcashd 与 zebra **都**会。
- 洞发生在把 `rk` 曲线点**转换成电路公开输入**，不是陈述缺约束。
- 底层电路实现当时和现在都**支持** `rk` 为零点，坐标写成 `(0,0)`；若转换写对，该情形本无害。排除它是当时更简单、更安全的热修。
- 规范**先前允许** `rk` 编零点。两家后来都拒。这是**收紧**共识：从合法集里拿掉，不是恢复旧规则。
- 官方：诚实证明者按规范均匀抽 `α` 时，`rk` 为零点的概率可忽略；升级节点不会因此拒诚实矿工的块。

本页不写怎样造身份 `rk`、不抄发布线版本 / 曲线方程进不确定常量。规范允许，不是验证明已经能吃。

## 1. 发生了什么

说明书说：这把钥匙可以是零点。  
验的时候，把钥匙抄进电路门口的那一步崩了。  
两家门卫都崩。  
电路板上其实画得下 `(0,0)`。  
崩的是抄写，不是板子不认。  
后来下令：不准再送零点钥匙。  
下令，不是说明书本来就不许，也不是板子已经坏了。

## 2. 根因

陈述允许的点、电路支持的点、验证明路径能转换的点，是三件东西。  
公开输入转换漏了零点，进程退出。  
规范当时允许，所以这不是「实现没跟上已有拒绝规则」，而是「允许集里有一个实现吃不了的点」。  
热修选排除，因为改转换要更小心；排除是收紧，不是陈述已经禁止过。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 102 / ZIP 257 | gadget 缺拷贝约束；陈述按意图是对的。本页是转换恐慌，电路支持零点 |
| 不变量 108 | `ephemeralKey` 无效编码；规范已经要求拒。本页是 `rk`，规范先前允许 |
| 不变量 90 | 估值为 0 assert；本页是曲线点转公开输入 |
| 不变量 76 | Dec 进 Int panic；本页是点编码 |
| 本页 | **规范允许身份 rk ≠ 验证明已经能吃；公开输入转换恐慌 ≠ 电路不支持零点；排除零点 ≠ 陈述本来就禁止** |

## 3. 被破坏的 invariant

- 规范允许的点，验证明路径必须能转换或在入口显式拒，不得恐慌（不变量 107）
- 电路支持 `(0,0)` 不是转换已经写对
- 软分叉排除是新规则，不得写成「本来就不合法」

## 4. 为什么测试没发现

幸福路径：诚实 `α` 几乎碰不到零点。  
绿测试只覆盖随机合法 `rk`。  
边角要：身份点进公开输入转换；两家是否同崩；电路向量是否本可以吃。

## 5. 修复

官方：两家拒绝编码零点的 `rk`。规范补「不得为零点」。  
官方写电路支持该情形，排除是更安全的热修。  
收紧不是恢复与规范的旧一致——旧规范允许。

## 6. 「不确定」若同类

1. 第一版可以不做屏蔽授权随机化点 / 电路公开输入。
2. 若规范允许某编码：验证明与公开输入转换必须覆盖，或规范先改成禁止。
3. 恐慌不是已拒绝。电路支持向量不是实现门口已经能吃。
4. 排除可以是正确止血，必须标成收紧，不得写成「本来就不合法」。
5. 这和电路≠陈述（102）、`ephemeralKey` 编码（108）、估值 0 assert（90）不是同一句。
6. 不要写怎样造身份 `rk`。不要抄版本 / 曲线方程。

## 7. 回归测试

形状（不是利用包）：文案把规范允许身份 `rk` 写成验证明已经能吃必须红。把公开输入转换恐慌写成电路不支持零点必须红。把排除零点写成陈述本来就禁止必须红。与 ZIP 257 / `ephemeralKey` 糊成「点编码」一句必须红。

**事实来源：** [ZIP 256](https://zips.z.cash/zip-0256)；规范 § 4.6 随后补的禁止句。

# 失败案：入站洪水不是已经停链；票不够落地导致分叉清不掉才是内存把节点打死

层：**实现 + 协议 + 经济 + 部署**（固定地板价竞速制造入站洪水；共识停是因为票不够最终更早的块，废弃分叉清不掉，节点 OOM；重启后分叉仍超能力）

官方披露：

- Solana 官方复盘：[04-30-22 Solana Mainnet Beta Outage Report](https://solana.com/news/04-30-22-solana-mainnet-beta-outage-report-mitigation)。无 CVE。本页只采用该页已写出的句子。2022-06-16 编辑注：把一种缓解改称为 stake-weighted quality of service。

**事实（官方原文能对上的句子）：**

- 2022-04-30 约 **20:30 UTC**，Mainnet Beta **停止出块**，共识卡住。约七小时后协调重启。2022-05-01 约 **03:30 UTC** 恢复出块。
- 入站交易约 **每秒 600 万**，个别节点超过 **100 Gbps**。官方写**没有拒绝服务攻击的证据**；证据指向机器人用 Candy Machine **程序化抢新 NFT**。铸造价是**固定地板**，不是动态荷兰拍，先调用的人拿走，于是有经济动机海量发交易。
- 共识卡住的**具体原因**是验证者**内存耗尽并崩溃**。高内存的根因是**落地的票不够，更早的块最终不了，废弃分叉清不掉**。要评估的分叉数量超过能力，**重启之后仍然如此**，必须人手介入。
- 当年 1 月起就有针对 NFT 铸造的机器人拥堵。上一回 Mainnet Beta 停机是 **2021-09**，17 小时。这次与那次有共同点，但请求量到了那次的 **10,000%** 仍能先撑一段时间——官方把它写成后续更新的结果，不是清理谓词已经够。
- 当时在 Testnet 稳住的 **v1.10** 含内存改进，拉长节点在共识变慢或卡住时能撑的时间。Mainnet Beta 上跑 v1.10 的测试节点，比同规格 v1.9 多撑约 **2000** 个槽。
- 三件当时在做的缓解（不是本页谓词已齐）：把 RPC→leader 的自定义 **UDP** 换成 **QUIC**（UDP 无连接、无流控、无回执，难以约束滥用）；**按质押加权的 QoS**（结束先到先得、不问来源；官方举例 0.5% 质押至少能占 0.5% 进 leader 的包）；**按附加费 / 计算单元比**做执行优先级（争用的是写同一片状态，不是整块空间；stake-weight 不适合这层）。费优先瞄准 v1.11。官方对照：这不是以太坊那种全局费市场。

本页不写怎样灌包、不抄 600 万 / 100 Gbps / 10,000% / 2000 槽 / 0.5% 进不确定容量或法定人数。入站洪水不是已经停链。QUIC / 加权 QoS / 本地费不是本条已经修完。

## 1. 发生了什么

门口挤满了抢同一件东西的单。  
地板价，先到先得，机器人比谁手快。  
票飞得不够密，更早的块锁不住。  
废弃的岔路清不掉，屋子被岔路填满。  
机器内存打满，进程倒下。  
重启，岔路还在，还是数不过来。  
要人手把链拉起来。  
入站洪水，不是已经停链。  
票不够落地、分叉清不掉，才把节点打死。

## 2. 根因

入站量和抢 NFT 的经济动机，是压力来源，不是停链谓词。  
停链谓词是：票不够让更早的块最终 → 废弃分叉不能回收 → 要评估的分叉超过内存 → 崩溃；重启后集合仍太大。  
UDP 先到先得、不问来源，放大入站。固定地板价让「再多发一笔」有期望值。  
本节点 OOM 不是共识已经拒绝合法块；这次是**足够多的节点**一起倒，共识才停。  
v1.10 多撑 2000 槽，是耐久，不是清理谓词已成立。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 67 / Lavender | 本节点崩溃 / 握手配额；不是全网因分叉表 OOM 停 |
| 不变量 44 / 45 | 拒了仍烧 CPU / 库存配额；本页是分叉清不掉占内存 |
| 不变量 87 / 2023-02-25 | Turbine 环流、vote-only；本页是票不够最终 → 分叉不回收 |
| 不变量 85 / 86 / 88 | durable nonce / 重复槽 / 旧加载器死循环 |
| 不变量 69 | 非法提案导致出块变少 |
| L6.1 本地费 | 官方当时还在做附加费；不是 2022-04-30 已经有本地费市场 |
| 本页 | **入站洪水 ≠ 已停链；票不够落地、废弃分叉清不掉 ≠ 因为 TPS 高所以内存满；重启后分叉仍超能力 ≠ 自动恢复；固定地板价竞速 ≠ 协议层 DoS；QUIC / 加权 QoS / 本地费 ≠ 本条已齐** |

## 3. 被破坏的 invariant

- 入站洪水不是已经停链；停必须点名「票不够最终更早的块 → 废弃分叉清不掉 → OOM」（不变量 89）
- 重启之后分叉集合仍超能力，不是自动恢复
- 固定地板价、先到先得的应用激励，不是协议已经在做 DoS
- UDP 无流控、先到先得入站，不是已有来源配额
- v1.10 多撑若干槽，不是清理谓词已经够

## 4. 为什么测试没发现

幸福路径：票密、块能最终、废弃分叉被回收，内存回落。  
只测「大 TPS 还能出块一会儿」会绿——官方自己写这次请求量远高于 2021-09，仍先撑了一段。  
边角要：落地的票不够，最终停住，分叉表只增不减，重启也减不下来。  
单节点灌包测吞吐，看不见「全网票不够 → 分叉不回收」。

## 5. 修复

官方：人手找最远进度，协调重启。v1.10 改内存耐久。当时在做 QUIC、质押加权 QoS、按费/计算比的执行优先。  
这些是后续缓解，不是 2022-04-30 当天谓词已改完。  
编辑注把一种缓解改名为 stake-weighted QoS，不另立事故。

## 6. 「不确定」若同类

1. 产品句若写「洪水 / 拥堵」：必须再写清停在票不够、分叉不回收、还是单节点 OOM。入站数字不是停链谓词。
2. 废弃分叉 / 未最终历史必须有回收不等式。重启后仍超能力，按会停审。
3. 第一版入站不要用无流控、先到先得的裸 UDP。来源配额与执行优先级是两层：谁能把包送到 leader，和谁先写热点状态。
4. 应用若用固定地板价 + 先到先得分配稀缺状态，必须写成经济对手会灌包。不要写成「那是 NFT，不是结算」。
5. 不要抄每秒 600 万、100 Gbps、10,000%、2000 槽、0.5% 例子。不要把 QUIC / 加权 QoS / 本地费抄进不确定当已完成。
6. 这和握手 OOM（67）、库存配额（45）、Turbine 环流（87）、旧加载器死循环（88）不是同一句。不要写怎样灌包。

## 7. 回归测试

形状（不是利用包）：文案把入站洪水 / 官网 TPS 写成已经停链必须红。把 OOM 写成「因为 TPS 高」而不写票不够、分叉不回收必须红。把重启写成分叉表已清空必须红。把固定地板价竞速写成协议层 DoS 必须红。把 QUIC / 加权 QoS / 本地费写成 2022-04-30 已齐必须红。

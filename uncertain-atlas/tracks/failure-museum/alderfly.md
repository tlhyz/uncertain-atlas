# 失败案：Alderfly 朝前的 lunatic 不能只等「同一高度再出一块」

层：**协议 + 经济**（轻客户端证据何时能形成；不是跳过时重叠旧集合那一句）

官方披露：Tendermint [Security Advisory Alderfly / GHSA-f3w5-v9xx-rp8p](https://github.com/tendermint/tendermint/security/advisories/GHSA-f3w5-v9xx-rp8p)。咨询标 **Moderate**。受影响：v0.34.0–v0.34.8。补丁：v0.34.9。无绕过。咨询写根因在规范，并点名与 spec 侧 [GHSA-jqfc-687g-59pw](https://github.com/tendermint/spec/security/advisories/GHSA-jqfc-687g-59pw) 重复——本页只采用本咨询已写出的句子，不发明 spec 页正文。咨询未给 CVE。

**事实（官方原文能对上的句子）：**

- 轻客户端当时无法检测并惩罚一种新攻击，官方命名 **forward lunatic attack / FLA**。
- FLA **不能成功执行**，除非已经有 **⅓+** 拜占庭验证者，因此**在 Tendermint 安全模型之外**。咨询仍写：必须能检测并惩罚，才能给正确行为激励。
- FLA：攻击验证者（带 ⅓+ 投票权）为**尚未出现的高度**签 commit，内容是任意应用状态。「朝前」= 目标高度高于当前链高。
- 常见证据只在**同一高度出现冲突块**时才形成。目标若远在前方，链可能来不及在该高度及时出一块冲突块，证据就做不出来。
- 补丁前：轻客户端可以从 primary 收下坏头，即使所有 secondary 都正确，也**形不成**这次欺骗的证据。
- 轻客户端负责 IBC 跨链状态验证；成功的 FLA **可能导致丢资金**。咨询再次强调：只在安全模型外才可能成功。
- 所有 FLA（未遂与既遂）都在链上留下可证明的不端痕迹。坏头带故障者签名。未打补丁的网仍可用社会共识（链下）恢复。v0.34.9 起自动、在链上处理证据。
- 补丁还让停链之后仍能自动上报：给 `FetchBlock` 加了时间，轻客户端多一把尺判断「停着的链本该继续」，链恢复后就能交证据。

本页不写怎样签朝前高度，不把 ⅓ 抄进不确定法定人数，不编 CVE。

## 1. 发生了什么

轻客户端从主证人收下一条坏头，旁边的证人其实都对。  
以前的证据公式在等「同一高度再出一块冲突块」。攻击者签的是**还没轮到的高度**。那一块迟迟不来，证据做不出来。  
验过头了，罚不到人。IBC 若信这条头，钱可能先走。

## 2. 根因

证据形状被写成「同高两块」。  
朝前的 lunatic 不给你同高的第二块，只给你一张对未来高度的坏 commit。  
验头通过 ≠ 已经能提交证据。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 20 | 跳过必须重叠旧 `NextValidators`；新集合自嗨的 2/3 不是信任 |
| 不变量 21 | 证据形状成立 ≠ 已 slash |
| 不变量 64 / Mulberry | 飞行中 last commit ≠ 证据身份 |
| 规范 lunatic / equivocation / amnesia | 三种分类；本页是**朝前**、同高冲突来不及形成 |
| 本页 | **验过头 ≠ 能交证据；证据不得只等同高再出一块** |

## 3. 被破坏的 invariant

- 收下冲突头必须能形成证据；不得只依赖「同一高度已经出了另一块」（不变量 66）
- 对尚未出现的高度签任意状态，仍须能问责
- 主证人骗过头、次证人全对，仍须能交证据
- 停链不得抹掉交证据的能力（官方：`FetchBlock` 带时间）

## 4. 为什么测试没发现

幸福路径：冲突出在同一高度，立刻能拼 `LightClientAttackEvidence`。  
只测「新集合自己的 2/3 必须拒」会绿，看不见「目标高度还没出块」。  
不测停链后再上报。  
「已在安全模型外」常被当成「不必测」。

## 5. 修复

官方：v0.34.9，规范与实现一起改。无绕过。  
未打补丁：咨询写仍可用社会共识链下恢复。社会共识 ≠ 协议已经能交证据。  
`FetchBlock` 加时间是停链后的备份尺，不是第三条最终性。

## 6. 「不确定」若同类

1. 第一版默认结算角色仍是全节点。若提供 BFT 轻客户端：收下坏头必须能形成证据，不得只等同高再出一块。
2. 朝前高度的坏 commit 必须仍能问责。不要把「安全模型外」写成「不用写检测」。
3. 主证人骗过头、次证人全对，仍须能交。验过头 ≠ 已经能提交。
4. 若允许在停链后补交：取块必须带时间，停着不等于证据窗口已关。不要抄 `FetchBlock` 当产品字段名而不写语义。
5. IBC / 跨链若信轻客户端头，必须把「能交证据」写成和「能验头」分开的两句。不要写「有轻客户端所以桥安全」。
6. 这和重叠旧集合（20）、上链≠slash（21）、证据身份（64）不是同一句。不要抄 ⅓ 当不确定门槛。

## 7. 回归测试

形状（不是利用包）：文案把「已经 ValidAndVerified」写成已经能交证据必须红。只测同高两块、不测朝前高度仍标 PASS 必须红。主证人坏头、次证人全对、形不成证据仍标 PASS 必须红。把「在安全模型外」写成不必检测必须红。

# 失败案：ISA-2025-005 奖励池溢出不是只是金额算错

层：**实现 + 协议 + 经济**（模块池入金溢出可以停链；不是输出求和拒块，也不是停链交易被恢复）

官方披露：Cosmos SDK [ISA-2025-005 / GHSA-p22h-3m2v-cmgh](https://github.com/cosmos/cosmos-sdk/security/advisories/GHSA-p22h-3m2v-cmgh)。咨询标 **High**。受影响：使用 `x/distribution` 的未打补丁链；描述写 `<= v0.50.13`、`<= v0.53.2`。补丁：`v0.50.14`、`v0.53.3`。咨询写无已知绕过。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- 分配模块里，向 **Validator Rewards pool** 做一笔**恶意存款**会导致**整数溢出**，并因此**停链**。
- **恶意验证者**可以与 distribution 模块交互，引入这种状态。
- 受影响的是使用 `x/distribution` 的未打补丁链。

本页不写怎样存款、不写溢出的是哪一个整型、不抄版本号当不确定常量。

## 1. 发生了什么

奖励池是验证者领报酬的桶。  
有人往桶里倒一笔能把计数器撑破的数。  
计数器一回绕或一炸，高度走不下去。  
这不是「这笔转账金额写错、拒掉就好」。它停的是整条链。

## 2. 根因

溢出有两种产品句：

- **拒：** 对象非法，块或交易不收（例如输出求和溢出）。
- **停：** 实现在提交路径上算爆，节点起不来。

奖励池入金被当成普通加总，没有写成「溢则拒」。能往这个池存款的验证者，因此是活性对手。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 7 / CVE-2010-5139 | 输出求和溢出必须拒绝，不得模回绕后当合法 |
| 不变量 51 / CVE-2025-46597 | 尺寸检查必须用固定宽度 |
| 不变量 71 / ISA-2025-002 | 可选模块 EndBlocker 出错会停链 |
| 不变量 73 / x/crisis | 停链交易被恢复，不是已经停 |
| 本页 | **奖励池入金溢出必须拒，不得变成停链** |

## 3. 被破坏的 invariant

- 模块奖励池入金溢出必须拒绝，不得变成停链（不变量 74）
- 能向该池存款的验证者是活性对手
- 金额算错 ≠ 只是经济层；溢出落在提交路径上就是活性

## 4. 为什么测试没发现

幸福路径：存款是小正数，加总到不了上界。  
只测「合法佣金能发」会绿，看不见「恶意入金把高度卡住」。  
分配模块被当成「只是发钱」。

## 5. 修复

官方：升级到补丁版本。咨询写无已知绕过。  
把入金改小 ≠ 溢出已经会拒。自己写奖励池仍要测「溢则拒、不停链」。

## 6. 「不确定」若同类

1. 第一版可以不做验证者奖励池。若做：入金、累加、发放每一步溢则拒。
2. 能向该池存款的主体必须写成活性对手，不是「只是领工资的验证者」。
3. 这和输出求和拒块（7）、固定宽度（51）、可选模块 EndBlocker（71）、停链交易被恢复（73）不是同一句。
4. 后量子对象更大时，更不能把「加总」写成不会爆。
5. 不要抄 `x/distribution`。不要把 High 写成「溢出只是金额」。

## 7. 回归测试

形状（不是利用包）：文案把奖励池入金溢出写成「只是金额错、拒掉即可」且链继续、但实现会停仍标 PASS 必须红。能存款的验证者引入溢出、高度停仍标 PASS 必须红。只测小额发放不得标「池已安全」。

# 失败案：ASA-2024-009 轻验集合对上了，不等于提议者选择已对齐

层：**协议 + 实现 + 部署**（state sync 装上的共识 `State`；应用快照哈希是另一句话）

官方披露：[ASA-2024-009 / GHSA-g5xx-c4hv-9ccc](https://github.com/cometbft/cometbft/security/advisories/GHSA-g5xx-c4hv-9ccc)。咨询正文标 **Medium**（ACMv1.2）；GitHub 页标 Moderate。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- state sync 装应用快照之后，还要装一份共识 `State`，新生节点才从该高度验新块。
- 这份 `State` 用轻客户端协议、至少两个 RPC 端点算出来。轻客户端会比不同端点、查不一致。
- `State.Validators` 除地址、公钥、投票权外，还带着每个验证者的 `ProposerPriority`（咨询写：历史原因，保存提议者选择算法的状态）。
- 轻客户端能验 `ValidatorSet`，但**当时不包含**各人的 `ProposerPriority`。
- 若 RPC 给出无效的提议者选择状态，本节点对「这一轮谁提议」的看法会和正确验证者不一致：它会拒掉多数别人的提案，自己的提案也会被别人拒。越来越多验证者这么同步，网络最终停。
- 补丁：轻客户端比较各 RPC 拿来的 `ProposerPriority`；不同则这份 `State` 非法，state sync 报错失败。
- 咨询写：跑上游代码的非恶意节点**不应**报出无效提议者状态；出现过，可能来自改过的代码或手工改本地库。公开 RPC 若已坏，新验证者不要用 state sync 引导，或先确认端点的提议者状态有效。
- 手工核对：`/validators?height=_` 的输出必须完全一致，**包括**每人的 `ProposerPriority`。

本页不写怎样改本地库、不写怎样伪造 priority。受影响版本区间是官方事实，不是不确定常量。

## 1. 发生了什么

新生验证者走 state sync。应用根可以对上轻验 `AppHash`（不变量 38），节点仍可能带着一份**错的提议者日程**进入共识。它不是在和别人争另一条历史，而是在同一高度上认错了「该谁出块」。

## 2. 根因

轻客户端把「验证者是谁、权重大小」当成集合已对齐，漏掉集合里保存的提议者选择状态。  
`ProposerPriority` 不是装饰字段。咨询自己写：它就是提议者选择算法的状态。  
RPC 端点是部署对象；轻验过投票权 ≠ 这些端点的 priority 彼此一致。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 38 / state sync 精读 | 只有轻验 `AppHash` 可信；`Snapshot.hash` 可伪造 |
| ASA-2024-004 | 证据窗默认可能短于解绑 |
| 不变量 20 | 跳过高度时重叠旧集合 |
| 本页 | **装上的共识 State 里，提议者选择字段未交叉核对** |

## 3. 被破坏的 invariant

- 状态同步装上的共识 `State` 必须含提议者选择字段，且该字段必须被交叉核对（不变量 56）
- 轻验 AppHash ≠ 提议者日程已对齐
- 对不上的 priority 必须让 state sync 失败，不得带着错日程进共识

## 4. 为什么测试没发现

幸福路径：两个 RPC 都来自未改过的上游节点，priority 碰巧一致。  
只测「AppHash 对上 / 快照装完」会绿。  
不测「同一集合、不同 priority」。

## 5. 修复

- 0.34.34 / 0.37.11 / 0.38.12：轻客户端比较 `ProposerPriority`；不同则 `State` 非法。
- 绕过（官方）：不要从提议者状态已坏的 RPC 做 state sync；或手工对 `/validators` 全字段。

补丁让不一致失败。它**没有**把 priority 变成链上头承诺的新对象——那是另一项设计，本页不发明。

## 6. 「不确定」若同类

1. 若提供 state sync：除轻验 AppHash 与信任期（不变量 38）外，必须写清共识 `State` 里哪些字段参与提议者选择，以及这些字段如何被交叉核对。
2. 不要把「集合哈希对上」写成「下一轮谁提议已一致」。
3. 第一版默认可从创世。state sync 是另一条信任路径，RPC 端点是部署对象。
4. 公开 RPC 已坏时，正确动作是拒绝同步，不是「先跟上再慢慢修日程」。
5. 不要把咨询里的版本号、CVSS 分数抄进产品句。

## 7. 回归测试

形状（不是利用包）：两份 RPC 验证者列表地址与投票权相同、`ProposerPriority` 不同 → state sync 必须失败。文案把「轻验 AppHash 对上」写成「提议者日程已对齐」必须红。只测快照哈希、不测 priority 不得标 PASS。

# 失败案：ASA-2024-006 提议者注入的扩展不是投票权预言机

层：**协议 + 实现**（ProcessProposal 从哪读投票权；不是扩展被拒丢掉票，也不是快路径下标）

官方披露：Cosmos SDK [ASA-2024-006 / GHSA-95rx-m9m5-m94v](https://github.com/cosmos/cosmos-sdk/security/advisories/GHSA-95rx-m9m5-m94v)。咨询标 **High**，影响写成 Elevation of Privilege。受影响：0.50 线 `<= 0.50.4`。补丁：`0.50.5`。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- 默认助手 `ValidateVoteExtensions` 按**提议者注入的** `VoteExtension` **推断**总投票权。
- 链若在 `ProcessProposal` 里用这个助手，不诚实的提议者**有可能改掉**它写进注入扩展里的每个验证者投票权。
- 咨询原文：可能对**被修改的状态**造成意外或负面后果。
- 修法：对注入的扩展数据加验证，**对照状态机核对投票权**。

本页不写怎样改注入字段，不抄 CVSS，不抄版本号当不确定常量。

## 1. 发生了什么

引擎把上一轮的扩展交给提议者，提议者再把它们塞进本轮提案。  
应用助手看见这份注入物，就用它算「全网有多少投票权、每人多少」。  
提议者自己填数字。ProcessProposal 若信这份数字，状态会按假权重量写。  
扩展验过签 ≠ 权重已对齐状态机。

## 2. 根因

投票权被当成「扩展里自带的元数据」，而不是「已提交集合上的字段」。  
提议者是注入人，不是投票权预言机。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 34 | Verify 拒扩展 → 丢掉整张 precommit，不是块非法 |
| 不变量 57 / ASA-2024-011 | 扩展快路径仍须复用旧票字段检查 |
| 不变量 58 / ASA-2024-001 | 治理改启用高度必须先过转移谓词 |
| 不变量 65 / Syringa | +2/3 不是其余 Commit 槽位已签 |
| 不变量 56 | 轻验 AppHash ≠ 提议者日程 |
| 本页 | **注入的扩展 ≠ 状态机上的投票权** |

## 3. 被破坏的 invariant

- ProcessProposal 用的投票权必须来自已提交状态机，不得从提议者注入的 VoteExtension 推断（不变量 68）
- 提议者带来的扩展不是投票权预言机
- 扩展签名为真 ≠ 权重字段已对齐

## 4. 为什么测试没发现

幸福路径：提议者原样转发，权重碰巧和状态机一样。  
只测「扩展签名对」会绿，看不见「权数字段被改」。  
默认助手被当成「规范已经验完」。

## 5. 修复

官方：对照状态机核对注入扩展里的投票权。  
升级助手 ≠ 所有自写的 ProcessProposal 都已经改。自己抄推断逻辑的链仍要重审。

## 6. 「不确定」若同类

1. 第一版可以不启用 vote extensions。
2. 若启用：ProcessProposal / 任何按「谁有多少权」改状态的路径，权重必须读已提交集合。不要从提议者注入物推断总值或每人值。
3. 默认 SDK 助手不是规范保证。抄助手必须能指出权重对照的是哪份状态。
4. 这和拒扩展丢票（34）、快路径下标（57）、启用高度治理（58）、Commit 槽位（65）不是同一句。
5. 后量子票更大时，更不能让提议者顺便带来「权重表」。

## 7. 回归测试

形状（不是利用包）：文案把「ValidateVoteExtensions 绿了」写成投票权已对齐状态机必须红。注入扩展里的权数与状态机不一致仍标 PASS 必须红。只测扩展签名不得标「权重已安全」。

# 失败案：ASA-2025-003 结构不变量必须在流言之前验

层：**实现 + 网络**（对等消息里的 `BitArray`；共识没有另发明一条块规则）

官方披露：[ASA-2025-003 / GHSA-hrhf-2vcr-ghch](https://github.com/cometbft/cometbft/security/advisories/GHSA-hrhf-2vcr-ghch)。咨询标 **High**（ACMv1.2：Considerable Impact, Possible Likelihood）。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- 实现处理 `BitArray` 时，若 `Bits` 所要求的 `Elems` 数量与实际 `Elems` **对不上**，以前验证不够。
- 修法：增加验证，阻止处理这种非法状态；并对 `BitArray` 方法加防护，避免再处理时 panic。
- `BitArray` 出现在多种从对等节点收到的消息里。
- 最坏情况（官方）：节点会先把**仍处于非法状态**的消息流言给邻居，**然后**自己才处理 → 网络停，而不是只有收到恶意消息的那一个节点崩。
- 修复版：v0.38.19、v0.37.16。
- 绕过（官方）：若能认出发送这些载荷的恶意对等节点，可用 `iptables` 一类工具 ban IP。这是部署止血，不是结构谓词已成立。

本页不写怎样拼一份 `Bits` / `Elems` 对不上的数组。

## 1. 发生了什么

对等消息里带着一份「有多少位 / 实际装了几格」对不上的位图。节点还没验完，就先转发出去。邻居同样先转。全网吃同一份坏结构，活性停。

## 2. 根因

流言被当成「先传、后验」。  
结构不变量（位数与底层格数一致）是接收谓词，不是处理到一半才想起的断言。  
先流言再处理，把单点崩溃抬成全网停。

这不是：

| 案 | 对象 |
|----|------|
| ASA-2025-002 / 不变量 59 | 分片外层下标 ≠ 证明下标 |
| ASA-2024-011 / 不变量 57 | 扩展快路径跳过发送者下标 |
| 不变量 45 | 库存三方向配额 |
| 本页 | **位图结构未验完就先流言** |

## 3. 被破坏的 invariant

- 带内部长度的结构必须在流言之前验完；对不上必须丢，不得先转发出去（不变量 60）
- 单点 panic ≠ 已经比「先流言再崩」更安全——官方最坏句是全网停
- iptables ban 是部署止血，不是谓词

## 4. 为什么测试没发现

幸福路径：对等节点上游，`Bits` 与 `Elems` 一致。  
只测「自己处理时 panic」会漏掉「先流言」这条。  
不测非法位图的转发顺序。

## 5. 修复

- v0.38.19 / v0.37.16：接收时挡住非法 `BitArray`；方法上加防护避免 panic。
- 官方绕过：认出发送者后 ban IP。绕过 ≠ 结构已验。

升级补的是接收顺序。以后每个「带自己长度」的结构，都要单独写「先验再传」。

## 6. 「不确定」若同类

1. 对等消息里凡是「声明长度 + 实际容器」的对象，必须在进入流言之前验完。对不上丢弃。
2. 不要先转后验。官方最坏句已经写明：先流言会把单点事故变成停网。
3. 防火墙 ban 不能代替接收谓词。
4. 不要发明 `Bits` / `Elems` 的具体编码当不确定常量。
5. 这和分片下标错配（59）是亲戚：都是「结构字段彼此要对上」；这边多一句**验完才能传**。

## 7. 回归测试

形状（不是利用包）：`Bits` 与 `Elems` 数量对不上的位图 → 本节点必须拒；不得再发给任何对等节点。文案把「自己稍后会处理」写成「可以先转发」必须红。只测本地 panic、不测转发顺序，不得标 PASS。

# 失败案：ASA-2024-011 扩展处理路径不得跳过普通票字段检查

层：**实现**（vote extension 启用后的 Precommit 快路径；共识没有改块规则）

官方披露：[ASA-2024-011 / GHSA-p7mv-53f2-4cwj](https://github.com/cometbft/cometbft/security/advisories/GHSA-p7mv-53f2-4cwj)。咨询标 **High**（ACMv1.2：Considerable Impact, Possible Likelihood）。本页不另编 CVE——咨询未给 CVE ID。

**事实（官方原文能对上的句子）：**

- 网络**启用了 vote extensions** 时，一个节点可能发出无效 `Vote`，让接收节点在处理时 panic。
- 无效字段是 `ValidatorIndex`：它标明发送者在该高度 `ValidatorSet` 里的位置。
- 普通 `Vote` 处理会验这个字段。但 **Precommit 且 `BlockID` 非空** 时，0.38.x 为处理挂上的扩展，在普通验证**之前**插了一段逻辑；这段逻辑**不再复查** `ValidatorIndex`。
- 结果：接收并处理该消息的节点执行 panic。
- 资格限定（官方）：发送端必须引入**恶意代码**。跑上游代码的节点发不出「不存在的 `ValidatorIndex`」。**默认不启用扩展**的网络不受影响。
- 修复：`v0.38.15`（以及当时的 `main` / `v1.x` / experimental 线）。
- 临时绕过（官方）：从日志认出发送该票的对等节点，在 p2p 层 ban。这是部署止血，不是字段检查已补上。
- 咨询归类 CWE-129（未验证的数组下标）。本页不把该编号写成不确定常量。

本页不写怎样造一条无效 `ValidatorIndex`，不写怎样让接收端 panic。

## 1. 发生了什么

扩展挂在非空 Precommit 上。实现为了先处理纸条，把「发送者是集合里第几个」这条旧检查让到后面——然后没补上。接收节点用未检查的下标走进集合，进程崩。块规则没变。

## 2. 根因

新功能路径被当成可以跳过旧票的字段检查。  
`ValidatorIndex` 不是装饰：咨询写它标识该高度集合里的发送者。未检查就当数组下标，是实现倒挂。  
「上游发不出」不是谓词。默认关着只是本条打不进，开关仍在。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 34 / 扩展精读 | `VerifyVoteExtension` REJECT 丢掉整张 Precommit，不是块非法 |
| 不变量 37 / CVE-2024-35202 | 部分块断言当对等过滤器 |
| 不变量 43 / CVE-2024-52911 | 非法块提前 return，后台读已释放预计算 |
| 本页 | **扩展快路径跳过普通票的发送者下标检查** |

## 3. 被破坏的 invariant

- 新票路径必须复用旧票的字段检查，不得在处理扩展之前用未检查的发送者索引（不变量 57）
- 默认关扩展 ≠ 启用后字段检查可以少做
- 对等节点 panic ≠ 共识已拒绝该票

## 4. 为什么测试没发现

幸福路径：扩展关着，或发送端是上游、`ValidatorIndex` 合法。  
只测「Verify 拒扩展丢掉票」（不变量 34）会绿。  
不测「扩展开着、Precommit 非空、下标越界」。

## 5. 修复

- `v0.38.15`：补上扩展路径上的字段检查。
- 官方绕过：ban 发送对等节点。绕过 ≠ 谓词已成立。

升级到当时的修复版。没开扩展 ≠ 开了以后可以少验。

## 6. 「不确定」若同类

1. 第一版可以不启用 vote extensions（不变量 34 已写）。启用则**每条**旧票字段检查必须在新路径上复用，尤其是会当数组下标的字段。
2. 不要把「诚实上游发不出」写成安全证明。实现必须拒，不得 panic。
3. p2p ban 是部署止血，不能代替接收路径上的检查。
4. 这和「Verify 拒扩展丢掉票」是亲戚，不是同一句：那边是应用验收；这边是引擎还没走到验收就崩了。
5. 不要抄咨询版本号或 CWE 编号进第一版。

## 7. 回归测试

形状（不是利用包）：扩展启用时，Precommit 非空、`ValidatorIndex` 不在本高度集合内 → 接收路径必须拒这条票，不得进程退出。文案把「默认关着所以安全」写成启用后已检查必须红。只测 Verify REJECT、不测下标，不得标 PASS。

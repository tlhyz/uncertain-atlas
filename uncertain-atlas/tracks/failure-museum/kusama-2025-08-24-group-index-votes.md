# 失败案：组下标不是票向量下标；create_inherent 回 None 不是客户端已经报错

层：**协议 + 实现 + 部署**（剔除已禁用验证者时用组下标去票向量；票比组少就删错签；API 回 None 被客户端当成合法；生产 runtime 关日志）

官方披露：

- Parity 官方论坛：[Kusama stall postmortem](https://forum.polkadot.network/t/2025-08-24-kusama-stall-postmortem/14729)（标题 2025-08-24；票页一处写成 2024）。无 CVE。本页只采用该页已写出的句子。

**事实（官方原文能对上的句子）：**

- 新 session 开始后，链上争议结案：投反对**有效**平行块的验证者被 runtime **禁用**。随后一段时间**没有出块**。出块者在 `finalize_block` 里 panic：每个中继块必须带 `parainherent.enter`；官方原文 *Bitfields and heads must be included every block*。
- `parainherent.create_inherent` 供出块者拼 `enter` 的参数。节点把已 backing 的候选、bitfield、争议票送进去，API 过滤后交回。漏洞在过滤：**要把已禁用验证者的有效性票去掉**，但 `indices_to_drop` 是**组内下标**，实现却拿它当 **validity_votes 向量下标**。某候选的票数**少于** backing 组人数，于是删错一张票，后面的签错位，验签失败。
- 验签失败 → inherent 数据缺失。`create_inherent` 对调用方回 **`None`**。官方：从**客户端看这是合法返回**，**没有打错误日志**。runtime 里有警告，但**生产 runtime 为性能关掉日志**，客户端看不见。
- 后来出现一块 **空 InherentData**（无候选、无 bitfield、无争议票）的块。官方推断该出块者在停机期间**重启**，内存里没有这些对象，所以能出。完整恢复发生在被禁用者 backing 的那份候选**过期**之后。官方：backing 候选在中继父块超过某一窗口后过期；这次出空块的人「运气好」，从没见过那份候选。
- 修法：按 `validity_votes` 向量正确映射下标（PR #9564），回移发布线并走公投升 runtime。
- 为何测不到：私有测试网条件太干净，**有效性票数总等于组大小**，边角不出现。官方要改测试环境、fuzz 平行共识、改善 runtime 报错。

本页不写怎样让票比组少，不抄验证者下标 / 块号 / 过期窗进不确定常量。组下标不是票向量下标。

## 1. 发生了什么

有人投了反对票，投错了，被请出组。  
下次拼块，要把他的票划掉。  
名册上的座位号，不是信封里的第几张。  
组里本来就缺一张，划错了，后面的签名全错位。  
拼块函数回了一句「没有」。  
客户端当没事。生产环境不说话。  
收尾钩子发现块里少了必须有的那一笔，进程倒下。  
组下标不是票向量下标。

## 2. 根因

组内下标与票向量下标不是同一对象。票可以比组少。按组下标去删，删的是别人的签。  
`create_inherent` 失败回 `None` 被客户端当成「这次没有可放的」，不是已经报错。  
生产 runtime 关日志，警告到不了运维。  
`on_finalize` 断言「每块必须有 parachain inherent」，缺了就 panic——这是停，不是局部跳过。

这不是：

| 案 | 对象 |
|----|------|
| 不变量 59 / ASA-2025-002 | 分片外层下标 ≠ 证明下标 |
| 不变量 97 / 2025-05 | 交易深度套在整块 API 参数上 |
| 不变量 71 | EndBlocker 出错会停 |
| 不变量 73 | 停链消息不是已停 |
| 不变量 99 / 2024-02 | Active 争议不是已 Confirmed；本页是出块 inherent |
| 本页 | **组下标 ≠ 票向量下标；票比组少 ≠ 已按组下标可删；create_inherent 回 None ≠ 客户端已报错；生产关日志 ≠ 错误已可见；空 inherent 能出块 ≠ 谓词已齐** |

## 3. 被破坏的 invariant

- 从集合删人，必须映射到票所在向量的下标，不得拿组座位号当信封序号（不变量 98）
- 票数可以少于组人数；缺席必须显式，不得按稠密下标删
- runtime API 回 None 必须让客户端当失败或打日志，不得静默出缺 inherent 的块
- 生产关日志不是错误已到运维

## 4. 为什么测试没发现

幸福路径：组里每人一张票，下标碰巧对齐。  
只测「禁用某人再出块」且票数=组大小会绿。  
边角要：组里有人没投票 + 另一人被禁用。  
官方：完美测试网永远票数=组大小。

## 5. 修复

官方：映射到 `validity_votes` 下标。回移并公投升 runtime。  
空 inherent 那块能出、候选过期后恢复，是这次运气，不是补丁。  
私有测试网太干净，官方自己写要改。

## 6. 「不确定」若同类

1. 第一版可以不做平行链 backing / 禁用验证者过滤。结算不必在出块路径上筛一组人的票。
2. 若要从集合剔除签名：必须写清「集合下标」和「票向量下标」是不是同一对象。缺席必须占位或显式映射。
3. 出块 API 失败必须失败，不得回空当成功。生产关日志必须另有可见错误。
4. 测试必须造「票比组少」。票数总等于组大小的网测不到。
5. 这和分片下标（59）、解码深度（97）、EndBlocker（71）、Active≠Confirmed（99）不是同一句。
6. 不要写怎样让票缺席。不要抄下标 / 块号 / 过期窗。

## 7. 回归测试

形状（不是利用包）：文案把组下标写成票向量下标必须红。把票比组少写成已按组下标可删必须红。把 create_inherent 回 None 写成客户端已报错必须红。把生产关日志写成错误已可见必须红。与 2025-05 深度套错对象糊成一句必须红。

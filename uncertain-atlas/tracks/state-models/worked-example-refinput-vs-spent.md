## 1. 核心问题

阿比看见交易列了某枚输出，或看见脚本读到了 datum，以为那枚输出已经被花掉；或以为引用等于已经通过花费条件；或以为同一枚输出可以在本笔既当花费输入又当引用输入。

官方句（事实）：

- CIP-31：引入一种新输入，**引用输入**。作者把输入标成普通花费输入或引用输入。引用输入链到某枚输出，但是**引用**它，不是花费它。
- 被引用的输出必须还在 UTXO 集合里。它上面的值**不**参与本笔平衡。它的花费条件**不被检查**，也不要求出示见证：校验器不必通过（脚本与赎回物都可以不在），公钥输出也不要求签名。
- 交易若通过，被引用的输出**不**从 UTXO 集合里删掉。引用输入对脚本可见。
- 两件旧行为不变：交易必须至少花费一枚输出；花费一枚输出仍然要检查花费条件。
- Conway 正式账本 UTXO 前提：`txins ≢ ∅`；`txins ∪ refInputs ⊆ dom utxo`；**`txins ∩ refInputs ≡ ∅`**。花费集合与引用集合必须不相交。
- 旧版语言接口不改。带引用输入的交易里，不得再花旧版脚本；试图这样做是 phase 1 失败。
- CIP-31 **没有**给输出创建者「谁可以引用」的门。规范写：单靠引用输入做不到这件事。
- 规范**没有**把「脚本看见了这枚输出」写成已经花掉，也没有把引用写成已经验过花费条件，也没有允许同一枚输出在本笔既花又引用。

看、花、验花费条件，是三件事。

---

## 2. 直觉（ELI15）

图书馆允许你隔着玻璃看一本书（引用），不是已经把书借走（花费）。  
隔着玻璃看见封面和页数，不是已经出示借书证、也不是书已经从架上消失。  
同一本书不能在这一笔里又看又借走。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 花费输入 | 消耗一枚输出；要过花费条件 | 只看一眼；本笔还可以再引用同一枚 |
| 引用输入 | 看一枚仍在集合里的输出 | 已经花掉；已经验过锁；已经参与平衡 |
| 被引用输出上的值 / datum | 脚本可以看见 | 已经算进本笔输入值；已经通过校验器 |
| `txins ∩ refInputs ≡ ∅` | 同一枚不得既花又引用 | 「看过所以已经花」或「花了还可以再看」 |

---

## 4. 最小案例

一条 eUTXO 链要对齐「这枚柜台状态支票我看过了」。

1. 交易 R 引用输出 O，不把 O 放进花费集合。规范：O 必须仍在 UTXO；O 的值不参与平衡；O 的锁不被检查；R 通过后 O 还在。
2. 另一笔 S 花费 O。规范：必须过 O 的花费条件。S 通过后 O 才消失。不是 R 已经把 O 花掉。
3. 有人把 R 和 S 写进同一笔，同一枚 O 既在 `txins` 又在 `refInputs`。Conway：相交必须空，这笔过不了。
4. 有人把这听成 Fuel 只读重叠可并行（不变量 143）。那是访问集与写冲突。本页是：看 ≠ 花，且同一枚不得既看又花。
5. 有人把这听成「eUTXO 所以已经解决并发」（L2.5 假学习）。引用让多人同时看 O，不把「大家都要改 O」变成可以并行成功。

「看见所以已经花掉」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 引用不要求出示被引用输出的签名 / 脚本 |
| 协议 | 必须点名问的是看、花，还是验花费条件 |
| 实现 | 旧版脚本遇引用输入是 phase 1 失败，不是已经静默省略 |
| 部署 | 被引用的输出仍占全节点 UTXO |
| 经济 | 值不参与本笔平衡；min UTXO 仍由真正花费回收，本页不抄数字 |

**推断：** 产品句若只写「交易用到了这枚输出」，读者会把看听成已经借走。  
**建议：** 第一版可以不做 eUTXO / 引用输入。若做，必须写清看不是花。不要抄字段号。不要发明「引用已经过锁」。

## 6. 和另外几句不是同一句

1. **谓词 ≠ 脚本 / 只读重叠 ≠ 写冲突**（不变量 143）：Fuel 访问集与并行。本页是 Cardano 看 ≠ 花。
2. **owned ≠ 快路径**（不变量 128）：对象所有权。本页不是 Sui。
3. **占用**（不变量 15）：谁为磁盘付钱。本页是引用不删输出，不是 Nervos 容量公式。
4. **策略 ≠ 共识**（不变量 144）：节点本地规则。本页是账本谓词。
5. **Bitcoin UTXO**（L2.1）：花了才从集合消失。本页多了一种「看了还不消失」。

不要抄 CDDL 字段号 / min UTXO / 硬分叉名当产品常量。不要写怎样构造引用–花费竞态。不编博物馆页。不另写 19 节。CIP-32 内联 datum、CIP-33 引用脚本、check-input、Hydra 引用–花费冲突标成另一对象。

## 精密检查

**边界：** 不讲 Plutus 语法。不抄字段号。不另写 19 节。不写怎样构造竞态。CIP-32 / CIP-33 / check-input / Hydra 冲突另标。

# 工作实例：nonce 顶到规范上限不是已经还能加一

> **事实 / 推断 / 建议** 已分开。
> 对照：[L2.2](../../courses/level-02-state/L02-M02-account.md)、[L5.1](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)、[有代码 ≠ 能发](worked-example-code-sender-vs-eoa.md)、[chainId ≠ 已签](../crypto/worked-example-chainid-vs-signed.md)。
> 主文献：[EIP-2681](https://eips.ethereum.org/EIPS/eip-2681) Limit account nonce to 2^64-1。官方 EIP。核心层。不另写 19 节。
> 本页钉 **nonce 顶到规范上限 ≠ 已经还能加一**、**交易 nonce 达到或超过上限 ≠ 已经合法**、**CREATE / CREATE2 碰到上限 ≠ 已经创建**、**客户端已经用窄整数存 nonce ≠ 共识已经写了这道上限**、**EIP-2681 ≠ EIP-155 用起始 nonce 防重放**。不抄上限取值 / 气价公式 / 例账户 / 旧测试网起始值。不写怎样把 nonce 推到上限，也不写怎样靠创建指令在上限上省气。

## 1. 核心问题

阿比看见账户 nonce 很大，以为还能永远加一；或看见客户端已经用窄整数存 nonce，以为共识早就写了这道上限；或看见规范编号 2681，以为就是 EIP-155 那种用起始 nonce 防重放。

官方句（事实）：

- EIP-2681：把账户 nonce 限制在规范写死的有限区间。以前可以是任意长的无符号整数。
- 从创世起补上两条。一：交易的 nonce **达到或超过**上限，整笔非法。二：账户 nonce 已经在上限上，`CREATE` / `CREATE2` 结束时栈上推 0；初始化代码那笔气不扣。
- 为什么交易 nonce 等于上限也非法：收进去之后，发送者 nonce 会超过上限。
- 动机三句：任意长 nonce 对状态见证不合适；交易编码以后可能用得上有界字段；客户端不必再按更宽的整数存 nonce。
- 旧测试网曾用一个很大的起始 nonce 和主网交易区分。这种防重放已经过时：EIP-155 用链标识更干净。那不是本页已经在讲 155。
- 规范自称破坏性变更，但写明当时看不到实际可见效果。那不是「上限已经不可能碰到」可以当产品保证。
- 规范**没有**把「nonce 很大」写成已经还能加一，也没有把客户端窄整数写成共识已经写了上限，也没有把本页写成 EIP-155。

序号、上限灯、还能发下一笔，是三件事。

## 2. 直觉（ELI15）

门票印到最后一张，窗口就关了，不是还能再撕一张。  
售票机屏幕只显示四位数，不等于票规已经写死四位数。  
旧园用不同起始号区分两场，不是这道「印到头就不能再印」的新规矩。

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 账户 nonce | 该账户下一笔该用的序号 | 已经没有上限；已经是签名随机数 |
| 上限灯 | 达到或超过则交易非法 | 很大所以还能加一 |
| 创建指令在上限 | 栈上推 0，不跑初始化代码 | 已经创建；已经扣了初始化气 |
| 客户端窄整数 | 实现存储习惯 | 共识已经写了这道上限 |

---

## 4. 最小案例

一条 Ethereum 要对齐「这一口气 nonce 停在哪」。

1. 账户 nonce 顶到规范上限。规范：再发一笔会让发送者超过上限。不是已经还能加一。
2. 交易把自己的 nonce 写成上限或更大。规范：整笔非法。不是「只是钱包不让点」。
3. 合约账户 nonce 已在上限，跑 `CREATE` / `CREATE2`。规范：栈上推 0，初始化气不扣。不是已经创建。
4. 客户端早就用窄整数存 nonce。规范：实现习惯。不是共识已经写了这道上限。
5. 有人把这听成 EIP-155（不变量 161）。155 是签名里的链标识。旧测试网起始 nonce 防重放已经过时。本页是上限本身。
6. 有人把这听成发送者有代码（不变量 162）。那是能不能当 EOA 发。本页是序号还能不能加。
7. 有人把这听成类型信封（不变量 167）。信封是怎么装交易。本页是账户序号的界。

「nonce 很大所以还能加 / 客户端已经窄所以共识已写 / 2681 = 155」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 无新原语；nonce 不是签名随机数 k |
| 协议 | 必须点名问的是当前序号、上限灯，还是下一笔还能不能发 |
| 实现 | 窄整数存储不是共识已经写了上限 |
| 部署 | 从创世补上；当时写明看不到实际可见效果，不是产品保证撞不到 |
| 经济 | 不抄把 nonce 推到上限要多少气 |

**推断：** 产品句若只写「账户有 nonce」，读者会把很大听成还能加，或把客户端宽度听成共识已经有界。  
**建议：** 第一版若用账户序号，必须写死上限，并分开交易非法和创建指令失败。不要发明「很大 = 还能加一」。不要抄上限取值。不要把 2681 写成 155。

---

## 6. 和另外几句不是同一句

1. **chainId ≠ 已签**（不变量 161）：跨链重放。本页是同链序号上限。
2. **有代码 ≠ 能发**（不变量 162）：发送者种类。本页是序号还能不能加。
3. **信封 ≠ 内层**（不变量 167）：交易怎么装。本页是账户字段的界。
4. **后来自毁 ≠ 已删**（不变量 160）：账户还在不在。本页不是删户。
5. **initcode ≠ 运行时代码**（不变量 176）：构造代码有多长。本页是序号还能不能加。
6. **空 ≠ 已消失**（不变量 180）：账户空不空。本页是序号还能不能加。规范 EIP-161 不是不变量 161。

不要抄上限取值 / 气价公式 / 例账户 / 旧测试网起始值 / 客户端内部类型名。不要写怎样把 nonce 推到上限，或怎样靠创建指令在上限上省气。不编博物馆页。不另写 19 节。EIP-155 链标识、交易格式提案、见证编码宽度表是另一对象。

## 精密检查

**禁止假学习：** 「nonce 很大 = 还能加一。」「客户端已经窄 = 共识已写上限。」「等于上限 = 收进去再加。」「创建碰到上限 = 已经创建。」「2681 = 155。」  
**边界：** 不抄上限取值。不另写 19 节。不写怎样推到上限。跨链见 **C165**。有代码见 **C166**。

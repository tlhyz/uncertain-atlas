## 1. 核心问题

阿比看见类型写了 `has store`，以为已经是账户下的顶层资源；或看见结构体声明了 `has copy`，以为装进去的每一种实例都能复制；或看见字段是 `u64`，以为外层「钱」也能复制。

官方句（事实）：

- Move Book：能力控制某类型的值允许做什么。四项是 `copy`、`drop`、`store`、`key`。
- `copy`：允许从局部复制、允许解引用复制。有 `copy` 则里面装的值也都有 `copy`。
- `drop`：允许丢掉（不转走、相当于执行中销毁）。有 `drop` 则里面装的值也都有 `drop`。
- `store`：允许存在**全局存储里某个结构体的字段中**，**不必**自己就是顶层资源。这是唯一不直接挡住某条操作的能力；它和 `key` 一起才挡住「能不能进全局存储」。
- `key`：挡住全部全局存储操作。要用 `move_to` / `borrow_global` / `move_from` 等，类型必须有 `key`。这些操作仍必须写在**定义该 `key` 类型的模块里**（对定义模块私有）。
- 有 `key` 则里面装的值都有 `store`。这是唯一这种不对称。
- 内建：`bool` / 各宽整数 / `address` 有 `copy`、`drop`、`store`。`signer` 只有 `drop`，不能复制、不能进全局存储。引用有 `copy`/`drop`，复制的是引用不是所指对象，且没有 `store`。**没有任何内建类型有 `key`。**
- 结构体写 `has copy`：所有字段必须有 `copy`。写 `has key`：所有字段必须有 `store`。`key` 是目前唯一不要求自己的能力。
- 泛型：类型参数被悲观地当成用在结构体里面。`Cup<T>` 就算声明了 `has copy`，只有 `T` 有 `copy` 时这个实例才有 `copy`；`key` 则要求 `T` 有 `store`。官方例句：**即便 `Cup` 声明了 `copy`，`Cup<signer>` 仍然没有 `copy`。**
- 规范**没有**把 `store` 写成已经是顶层资源，也没有把声明了 `has copy` 写成每一种实例都能复制，也没有把字段是整数写成外层资源已经能复制，也没有把有 `key` 写成模块外谁都能 `move_to`。

`copy`、`drop`、`store`、`key`，是四扇门。

## 2. 直觉（ELI15）

仓库规章写四种章：

- 能复印（`copy`）
- 能扔掉（`drop`）
- 能塞进别人的箱子（`store`）
- 能当箱子本身上架（`key`）

「能塞进别人的箱子」不是自己已经上架。  
箱子上印了「可复印」，里面若装的是不能复印的东西，这一只箱子仍不能复印。  
整数能复印，不等于装着整数的「钱」能复印。  
上架钥匙只在做这个箱子的车间里，不是谁进仓库都能搬。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| `copy` | 这个值能复制 | 外层没声明 `copy` 也能复制；声明了则每种实例都能复制 |
| `drop` | 这个值能丢掉 | 已经转走；钱已经安全 |
| `store` | 能作为字段待在全局存储的结构体里 | 已经是顶层资源；已经能 `move_to` |
| `key` | 能当全局存储操作的钥匙 | 模块外谁都能搬；字段是整数所以已经有 `key` |
| 条件能力 | 声明 + 类型参数一起决定 | 写了 `has copy` 就永远有 `copy` |

---

## 4. 最小案例

一条 Move 链要对齐「这是资源所以不能复制」。

1. 类型 `Coin` 只写了 `has key`，字段是 `u64`。规范：字段有 `store`，外层没有 `copy`。不能因为里面是整数就复制外层。
2. 类型 `Cup<T>` 声明了 `has copy`。`Cup<u64>` 能复制；`Cup<signer>` 不能。声明不是实例。
3. 类型 `Inner` 只有 `store`。规范：它可以待在某个 `key` 资源的字段里，自己不是顶层资源。
4. 有人把这听成 Sui owned ≠ 快路径（不变量 128）。那是版本走哪条共识路。本页是语言能力四扇门。
5. 有人把这听成 STM 跑完 ≠ 最终（不变量 122）。那是并行提交。本页不是执行器。

「写了 store 所以已经上架」是假学习。

## 5. 五层

| 层 | 本页 |
|---|---|
| 密码学 | 能力不替代验签；`signer` 不能复制、不能进全局存储 |
| 协议 | 必须点名问的是 `copy` / `drop` / `store` / `key` |
| 实现 | 字节码按能力挡指令；声明与实例可以不一致 |
| 部署 | 模块外不能替别人做 `move_to` |
| 经济 | 整数能复制不是钱能复制 |

**推断：** 产品句若只写「Move 所以钱不能复制」，读者会把声明听成已经盖住每一种实例。  
**建议：** 第一版可以不上 Move。若上，必须写清四扇门。不要发明「有整数字段所以能复制」。不要把 `store` 写成已经上架。

---

## 6. 和另外几句不是同一句

1. **owned ≠ 快路径**（不变量 128）：Sui 所有权决定版本走哪条路。本页是 Move 能力。
2. **STM 跑完 ≠ 最终**（不变量 122）：并行提交。本页不是执行器。
3. **占用**（不变量 15）：谁为磁盘付钱。本页是类型能不能进存储，不是容量公式。
4. **谓词 ≠ 脚本**（不变量 143）：Fuel 访问集。本页不是 UTXO。
5. **引用 ≠ 花费**（不变量 150）：eUTXO 看≠花。本页不是 Cardano。

不要抄官方例句当产品模块。不要写怎样做出可复制的钱。不编博物馆页。不另写 19 节。Sui 对象 `UID` / 包裹对象、Aptos `0x1::object` 标成另一对象。

## 精密检查

**禁止假学习：** 「`store` = 已经上架。」「写了 `has copy` = 每种实例都能复制。」「字段是 `u64` = 钱能复制。」「有 `key` = 谁都能搬。」  
**边界：** 不讲某一版 Move 的对象模型扩展。不另写 19 节。不写怎样做可复制资产。Sui `UID` / Aptos Object 另标。

# 看见授权名单不是已经委托成功

> 类型：worked example（账户种类 / 委托指示 / 类型交易）  
> 范围：只写 [EIP-7702](https://eips.ethereum.org/EIPS/eip-7702) 官方页已经写明的对象。不写怎么构造授权元组、怎么抢先初始化、怎么把 `tx.origin` 当成可设代码的发送方、怎么代付、怎么让委托存储撞车。  
> 五层：协议（新类型交易、授权名单、委托指示） / 实现（代码执行操作必须加载并执行所指代码；失败元组跳过继续） / 钱包（不得暴露「签这个授权」界面） / 应用（名单里有一项不是已经委托成功） / 威胁（把看见名单写成已经委托，或把本笔失败写成已经撤回委托）。  
> 分类标签：事实 / 推断 / 建议 已分开。  
> 对读：[`../../libraries/invariants/README.md`](../../libraries/invariants/README.md) 不变量 190；[`../../libraries/adversarial-corpus/README.md`](../../libraries/adversarial-corpus/README.md) C194；[`../../libraries/anti-patterns/auth-sold-as-delegated.md`](../../libraries/anti-patterns/auth-sold-as-delegated.md)；[`../../libraries/design-patterns/name-the-delegation.md`](../../libraries/design-patterns/name-the-delegation.md)；课 [`../../courses/level-02-state/L02-M02-account.md`](../../courses/level-02-state/L02-M02-account.md)、[`../../courses/level-05-ethereum/L05-M01-evm-and-gas.md`](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)；档案 [`../../protocols/ethereum/README.md`](../../protocols/ethereum/README.md)。

## 事实（官方页能指回去）

1. [EIP-7702](https://eips.ethereum.org/EIPS/eip-7702) 题目是 Set Code for EOAs。官方页写：增加一种新交易类型，永久设置外部拥有账户的代码。
2. 官方页写：该类型交易必须带 `authorization_list`；名单是形如 `[chain_id, address, nonce, y_parity, r, s]` 的元组列表。空名单则该笔交易无效。
3. 官方页写：对每个通过校验的元组，向授权账户写入**委托指示**。代码执行类操作必须加载并执行指示所指向的代码。
4. 官方页写：授权名单在执行之前处理，且在发送方 nonce 递增之后。某个元组失败则跳过该元组、继续处理其余元组。名单里有一项不是已经委托成功。
5. 官方页写：本笔执行失败或回滚**不会撤回**已经处理完的委托指示。失败不是已经撤销委托。
6. 官方页写：委托到零地址会清掉代码（空代码哈希）。这不是已经走了 160 的自毁删除。
7. 官方页写：对授权账户做 EXTCODESIZE 读到的是指示本身；在委托执行中做 CODESIZE 读到的是目标代码。指示不是已经是目标合约代码。
8. 官方页写：目标是预编译则视为空代码，调用成功且不执行。委托链只跟**第一跳**。
9. 官方页写：没有 initcode；创建靠模板（地址指针）。委托是持久的，不是只活一笔的临时代码。
10. 官方页写：EIP-3607 被修改为：代码是**有效委托指示**的发起者可以发交易；任意其它代码仍不得发起。委托指示不是已经把 3607 整条解除。
11. 官方页写：`msg.sender == tx.origin` 不再只出现在顶层帧。钱包不得暴露「签这个授权」一类界面。
12. 官方页写 Requires：EIP-2、EIP-161、EIP-1052、EIP-2718、EIP-2929、EIP-2930、EIP-3541、EIP-3607、EIP-4844。
13. 因此：EIP-7702 ≠ EIP-3607 ≠ EIP-3541 ≠ EIP-2718。看见授权名单不是已经委托成功。代码里是委托指示不是已经是目标代码。本笔失败不是已经撤回委托。

## 推断（从官方句推出，不是另一条共识规则）

- 把「账户里有代码」一句用完，会把 162 的代码发送方、188 的保留首字节、160 的自毁、167 的信封和本页糊成同一对象。
- 把「3607 已被修改」读成「任意代码账户都能发起」，会把官方只放开有效委托指示的那一句丢掉。
- 把本笔回滚读成委托也被撤回，会把「指示在执行前写入、失败不回滚指示」那一句丢掉。

## 建议（对「不确定」）

第一版结算机若出现「一次交易改账户代码」或「授权名单」，先问四句：看见名单了吗，还是已经委托成功？代码槽里是指示，还是已经是目标代码？3607 是只对有效指示放开，还是已经整条解除？本笔失败了，委托指示还在不在？四句各指各的对象。不要发明授权元组、代付或存储撞车配方。

## 五层（只展开本对象）

| 层 | 本对象要看见的 |
| --- | --- |
| 协议 | 新类型交易；非空授权名单；通过校验才写委托指示。 |
| 实现 | 先处理名单再执行；失败元组跳过；执行失败不撤回已写指示；只跟第一跳。 |
| 钱包 | 不得把「签这个授权」做成普通签名按钮。 |
| 应用 | 名单里有一项不是已经委托；指示不是目标代码；预编译目标视为空代码。 |
| 威胁 | 文案把看见名单写成已经委托，或把失败写成已经撤回。 |

## 禁句

- 「看见授权名单就是已经委托成功。」
- 「委托指示已经是目标合约代码。」
- 「EIP-7702 已经解除 EIP-3607。」
- 「本笔执行失败，委托指示也撤回了。」
- 「EIP-7702 就是 EIP-3607 / EIP-3541 / EIP-2718。」
- 「账户有代码就是 162、188、160、167 里的同一种代码。」

## 边界（本页不写）

- 不写授权元组怎么构造、怎么抢先初始化、怎么代付、怎么让委托存储撞车。
- 不写类型字节、指示魔数、gas 常数、空代码哈希字面量。
- 不写 162 代码发送方、167 信封、188 保留首字节、160 自毁本身（只说本页不是它们）。
- 不写怎么把 `tx.origin` 当成可设代码的发送方。

## 和相邻对象的唯一性

1. **不是 162 / EIP-3607 原文** — 3607 禁止带代码的发送方；7702 只把「有效委托指示」加进可发起集合。指示不是已经解除 3607。
2. **不是 167 / EIP-2718** — 2718 是类型信封；7702 是其中一种新类型，外加授权名单与委托指示。信封不是已经是名单，名单不是已经委托。
3. **不是 188 / EIP-3541** — 3541 拒收以保留首字节开头的新返回代码；7702 的指示格式不是已经等于 EOF，也不是已经等于 3541 放行。
4. **不是 160 / EIP-6780** — 委托到零地址清代码不是已经走了自毁删除。
5. **不是 180 / EIP-161** — 空、不存在、死账户不是委托指示，也不是目标代码。

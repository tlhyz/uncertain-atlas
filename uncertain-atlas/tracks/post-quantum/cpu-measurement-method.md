## 事实：必须先钉死的实验对象

一次实验只回答一句可复现的话：

> 在机器 M、库 L 版本 V、参数集 P、算法角色 R 上，对输入形状 I 做单核验签，得到吞吐 T 与延迟分布 D。

| 字段 | 必须写出 | 禁止写成 |
|---|---|---|
| 机器 M | CPU 型号、核数、频率策略（固定 / turbo）、OS、governor | 「云主机」「很快的机器」 |
| 库 L + 版本 V | crate / 发行包名 + 精确版本 + 是否 asm / AVX2 / 硬件加速 | 「用了官方库」 |
| 参数集 P | FIPS 204/205 参数名（如 ML-DSA-65、SLH-DSA-SHA2-128s）+ FIPS 版本年号 | 「Dilithium」「SPHINCS+」口语名当唯一标识 |
| 角色 R | 用户交易签 / 验证者投票签；`ctx` 是否空；pure vs pre-hash | 两种角色混成一列 |
| 输入形状 I | 消息长度、是否预哈希、批大小=1（单核单签）还是批 API | 把批量吞吐写成单核单签 |
| 结果 T / D | 签/秒中位数、p50/p95 延迟、样本数、暖机是否丢掉 | 只报峰值 |

**事实**：第 1–3 行（体积）可以先引用 [`nist-size-card.md`](nist-size-card.md) 的 FIPS 表，那不是 CPU。  
**事实**：第 4 行在本仓库没有实测记录之前必须保持「方法已写，数字仍空」。

## 事实：最小可复现步骤（不写实现代码）

1. 固定机器：关 turbo 或写明未关；绑单核；记 `lscpu` / 等价输出。
2. 固定库：锁版本；写编译特征（asm on/off）。同一参数集换实现算另一次实验。
3. 固定密钥与消息：写随机种子；消息长度单独成列（投票 SignBytes 与用户 tx 不得共用一行）。
4. 暖机后取样：至少丢掉前 N 次；报告样本数与中位数，不报告「最好一次」。
5. 只测 Verify（第 4 行是验签）。Sign 另开一行，不得把签+验加总当验签。
6. 若存在批量 Verify API：第 5 行另记「是否存在」；批量数字不得回填第 4 行。
7. 留下反例：同一机器换参数集或关 asm 后数字应变；不变则实验无效。

每条实验落一行附录或独立笔记，字段齐才能引用进账本第 4 行。

## 推断（产品，不是事实）

- 单核 Verify 若低于「每高度票数 × 验证者人数」所需预算，不能靠官网 TPS 把第 4 行涂绿。
- 投票签与用户签的 `ctx` / 域分离不同（不变量 18），测完一个不得自动填另一个。
- 有状态 HBS（XMSS/LMS）的 CPU 还受 index I/O 约束；不得只报纯 CPU 当第 4 行完成（见 [`stateful-hbs.md`](stateful-hbs.md)）。

## 建议（产品，不是事实）

不确定第一条结算机在填决策矩阵「签名」列之前：

1. 先完成第 1–3 行尺寸卡引用（已有路径）。
2. 再按本页跑第 4 行；数字进账本时必须带机器型号与库版本。
3. 未测前保持空，并显式写「方法见本页」。
4. 不得把本页方法本身写成「已经测过」。

# 实例：同一轮票，签名从 64 字节变成 3309

目的 B。不是考试。N 是结构，不是委员会决策。  
先修：L1.5、L4.1、L10.2、[`nist-size-card.md`](nist-size-card.md)。

---

## 故事

CometBFT 风格：高度 50，一轮，21 个验证者（示意）。每人投 prevote 和 precommit。  
旧世界：每票 64 字节（BIP-340 量级）。  
若每票换成 FIPS 204 Table 2 的 ML-DSA-65（3309 B），只算签名、不算证书其它字段：

```text
2 × 21 × 64    = 2688 B
2 × 21 × 3309  = 138978 B
```

若有人「为了安全」把投票签设成 SLH-DSA-*-256f（49856 B）：

```text
2 × 21 × 49856 = 2093952 B   // 约 2 MiB 纯签名
```

锁的算术没变。`+2/3` 没变。变的是网卡与 mempool。  
用户看见：槽时间变长、节点在验签上排队——容易被说成「共识不稳」。  
**层：密码体积变成部署/经济。** 协议 lock 可以仍对。

---

## 五层

| 层 | 本故事 |
|---|---|
| 密码 | 名义长度来自 FIPS；安全性是另一张假设表 |
| 协议 | 票数公式未改 |
| 实现 | 验签是否批量、是否有配额 |
| 部署 | 带宽、CPU、超时是否仍按旧值 |
| 经济 | 委员会越大，PQ 税越像门槛 |

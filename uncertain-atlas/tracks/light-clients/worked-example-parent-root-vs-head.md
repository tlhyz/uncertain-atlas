## 1. 核心问题

阿比看见执行头多了一个信标根，以为那就是当前信标头；或合约读到一个根，以为已经 finalized；或把环缓冲听成永存档案室。

官方句（事实）：

- EIP-4788：每个执行载荷头承诺对应的信标块的 hash tree root，并把这些根存进一份合约。
- 高层句：每个执行块含**父**信标块的根。漏槽时父根不变，所以每个执行块只要常数空间。
- 为了好用，合约里再存一小段根的历史。为了卡住存储，用环缓冲，镜像共识层的块根累加器。
- 这份父根的有效性由共识层担保，很像提款怎么处理。
- 验块时，执行客户端必须让头里的根等于共识客户端给的那一份。
- 创世没有已有父根时，用 32 个零当占位。
- 处理任何执行块一开始（任何用户交易之前），系统把 `parent_beacon_block_root` 写入合约。这是系统操作：必须跑完；不计入本块 gas 上限。
- 查询按时间戳。输入长度不对、时间为 0、或存着的时间戳对不上，合约必须 revert。
- 官方解释：故意不改 `BLOCKHASH`。选块根不选状态根，是为了漏槽时每个新执行块的工作量仍是常数。
- 环会覆盖旧槽。对不上时间戳就 revert，不是「还能读到很久以前那一颗」。
- 规范**没有**把头里的父根写成当前信标头，也没有把合约读到的根写成已经 finalized，也没有把环缓冲写成永存。

父根、当前头、finalized，是三件事。合约能读到根，不是轻客户端已经验过当前共识。

## 2. 直觉（ELI15）

班长把**昨天**教室门牌的拓片钉在今天的车间墙上。  
拓片能证明昨天那间教室长什么样，不是今天门口已经换了哪一张课表。  
墙上只留最近几天的拓片。前天的被盖住了，不是档案室还在。

---

## 3. 对象

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| 父信标根 | 本执行块头里、对应父信标块的 hash tree root | 当前信标头；本块对应的那一颗；已经 finalized |
| 合约历史 | 系统在交易之前写入的一小段 (时间戳, 根) | 永存档案；当前头预言机 |
| `BLOCKHASH` | 执行层旧操作码，规范故意不改 | 已经等于信标根 |
| 环缓冲过期 | 时间戳对不上则 revert | 根已经永久可查 |

---

## 4. 最小案例

一条以太坊要对齐「合约怎么读共识」。

1. 执行头带上父信标根。规范：这是父块，不是当前头。
2. 块一开始、交易还没跑，系统写入合约。规范：交易列表绿了不是根已经可查。
3. 有人按时间戳来读。时间戳对不上：规范要求 revert，不是读到一张旧根还假装是这一刻。
4. 有人把这听成 head ≠ justified ≠ finalized（不变量 127）。那是三等确认。本页是 EVM 里到底钉了哪一颗根。
5. 有人把这听成处理完一块已经改规范头（不变量 149）。那是哪一次调用才改头。本页是头上多了一个字段。
6. 有人把这听成提款操作（不变量 154）。那是系统加余额。本页是系统写根。

「看见链上有信标根所以已经是当前头 / 已经 finalized」是假学习。

## 6. 和另外几句不是同一句

1. **head ≠ justified ≠ finalized**（不变量 127）：三等确认。本页是 EVM 里钉的是父根。
2. **处理 ≠ 改头**（不变量 149）：哪一次调用才改规范头。本页是头上多了字段。
3. **提款 ≠ 交易**（不变量 154）：同一条 CL→EL 系统操作，但是加余额。本页是写根。
4. **弱主观检查点**（不变量 24）：从检查点起步的安全。本页不是同步假设。
5. **blob 承诺 ≠ 字节**（不变量 145）：EVM 能读 hash 不是已经读到袋。本页是另一份承诺。

不要抄分叉时间戳 / 环长 / 系统地址 / 调用气限。不要写怎样塞假父根或怎样打环碰撞。不编博物馆页。不另写 19 节。EIP-2935 历史执行哈希、从根做 SSZ 证明、状态根缓存合约标成另一对象。

```text
头里的父信标根 ≠ 当前信标头
合约里读到的根 ≠ 已经 finalized
环缓冲过期 ≠ 根已经永久可查
```

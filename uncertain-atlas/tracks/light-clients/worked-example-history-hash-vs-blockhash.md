# 看见状态里的历史执行哈希不是已经是 BLOCKHASH

> 类型：worked example（从状态供应历史执行块哈希）  
> 范围：只写 [EIP-2935](https://eips.ethereum.org/EIPS/eip-2935) 官方页已经写明的对象。不写怎样构造系统调用、怎样填环、怎样打见证。  
> 五层：协议（历史哈希写进系统合约存储，BLOCKHASH 语义不动） / 实现（开块系统写入父哈希；系统写入不预热） / 钱包（合约能查更长窗口不是已经改了操作码） / 应用（激活后要等窗口填满） / 威胁（把看见状态槽写成已经是 BLOCKHASH 或已经是 4788）。  
> 分类标签：事实 / 推断 / 建议 已分开。  
> 对读：[`../../libraries/invariants/README.md`](../../libraries/invariants/README.md) 不变量 195；[`../../libraries/adversarial-corpus/README.md`](../../libraries/adversarial-corpus/README.md) C199；[`../../libraries/anti-patterns/history-sold-as-blockhash.md`](../../libraries/anti-patterns/history-sold-as-blockhash.md)；[`../../libraries/design-patterns/name-the-history-hash.md`](../../libraries/design-patterns/name-the-history-hash.md)；课 [`../../courses/level-05-ethereum/L05-M01-evm-and-gas.md`](../../courses/level-05-ethereum/L05-M01-evm-and-gas.md)；档案 [`../../protocols/ethereum/README.md`](../../protocols/ethereum/README.md)。

## 事实（官方页能指回去）

1. [EIP-2935](https://eips.ethereum.org/EIPS/eip-2935) 题目是 Serve historical block hashes from state。官方 EIP。不另写 19 节。
2. 官方页写：作为处理一块的一部分，把最近一段历史执行块哈希写进一份系统合约的存储。本页对 `BLOCKHASH` 的解析机制没有影响（窗口和代价都不改）。
3. 官方页写：EVM 暗含客户端手里已经有最近几块哈希。无状态客户端会让这句假设不再站得住。把哈希放进状态，才能打进见证。
4. 官方页写：若去拉长 `BLOCKHASH` 能服务的窗口，那是语义变更。改走本页这份合约存储，才是软过渡。卷可以查这份合约拿更长窗口。
5. 官方页写：哈希放在环缓冲里。本页窗口大于 `BLOCKHASH` 窗口；后者保持原样。看见合约能查更长，不是已经改了操作码。
6. 官方页写：本页生效后，处理任何一块一开始、在任何用户交易之前，用系统调用把 `block.parent.hash` 交给历史合约。这是系统操作，跟 4788 同一套约定：必须跑完；不计入本块 gas 上限；不走 1559 燃烧；合约没有代码则静默失败。客户端也可以直接写存储，但官方仍建议走 EVM 调用。
7. 官方页写：激活后要等一整窗块才会填满环。合约里只有分叉块的父哈希，没有更早的。系统刚写入不是已经填满窗口。
8. 官方页写：`BLOCKHASH` 操作码语义保持原样。
9. 官方页写：合约有读和写。只有调用者是系统地址才走写；否则走读。读的人交出块号。呼叫数据不是规定宽度则回滚。超出 [本块号−窗口, 本块号−1] 则回滚。写的是父哈希，落到环槽。
10. 官方页写：这份账户有代码、序号为 1，免除 161 清理。
11. 官方页写：开块这次系统更新不按 2929 预热该地址或槽。第一次用户调用仍要付预热。对这份合约的普通调用走普通 EVM 语义。`BLOCKHASH` 机制和代价不受影响。
12. 官方页写：他们选择等窗口自然填满，而不是在分叉块一次写入整窗。这简化逻辑；官方认为没有旧合约依赖这条新路径。
13. 因此：EIP-2935 ≠ EIP-4788 ≠ EIP-4399。看见状态里的历史执行哈希不是已经是 `BLOCKHASH`。系统写入父哈希不是已经填满窗口。合约能查更长窗口不是已经改了操作码语义。

## 推断（从官方句推出，不是另一条共识规则）

- 把「能查历史哈希」一句用完，会把操作码窗口、合约窗口和信标父根糊成同一对象。
- 把「开块写进了父哈希」读成「窗口已经齐」，会把官方「要等一整窗」丢掉。
- 把本页和 4788 糊成「系统合约」，会把执行块哈希和信标块根听成一句。

## 建议（对「不确定」）

第一版结算机若把最近哈希放进状态，先问四句：看见的是 `BLOCKHASH` 操作码，还是这份合约存储？系统刚写入父哈希，还是窗口已经填满？能查更长，还是已经改了操作码语义？这是执行块哈希，还是已经是 4788 那种信标根？四句各指各的对象。不要发明环槽配方或见证构造法。

## 五层（只展开本对象）

| 层 | 本对象要看见的 |
| --- | --- |
| 协议 | 历史执行哈希写进系统合约存储；`BLOCKHASH` 语义不动。 |
| 实现 | 开块系统写入父哈希；这次写入不预热；无代码则静默失败。 |
| 钱包 | 合约能查更长窗口不是已经改了操作码。 |

## 禁句

- 「状态里能读哈希，就是已经改了 BLOCKHASH。」
- 「系统写入了父哈希，窗口就已经齐。」
- 「合约窗口更长，操作码就已经更长。」
- 「这就是 4788 / 4399。」
- 「开块写入已经按 2929 预热过。」
- 「没有代码，这块就已经非法。」

## 和相邻对象的唯一性

1. **不是 156 / EIP-4788** — 4788 是父信标根进执行。本页是历史执行块哈希进状态。看见系统合约不是已经是那一页。
2. **不是 `BLOCKHASH` 操作码** — 官方写本页对解析机制没有影响。合约窗口更长不是已经改了操作码。
3. **不是 157 / EIP-4399** — 4399 是 `PREVRANDAO`。本页不是随机，是执行块哈希。
4. **不是 169 / EIP-2929** — 开块这次系统更新故意不预热。第一次用户调用才付预热。
5. **不是 180 / EIP-161** — 这份账户免除 161 清理。空账户句不是本页。

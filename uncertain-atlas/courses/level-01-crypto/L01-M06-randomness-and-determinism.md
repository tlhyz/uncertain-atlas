# L1.6 三种「随机」与一种确定性

优先级：重要  
先修：L0.2，L0.6，L1.2  
覆盖知识树：M1.5

---

## A. 先修知识

复制状态机要求：同一输入字节，同一 `S'`。  
签名要求：没有私钥的人不能对**新消息**造印。  
这两句里都出现「不该乱来的数」，但不是同一种数。

---

## B. 核心问题

**签名随机数、账户序号、共识超时，为什么不能互相借用名字？哪一种进了 `Apply` 就会把诚实节点劈开？**

---

## C. 直觉（ELI15）

三种东西都被人叫过「nonce」或「随便来一下」：

1. **签名里的一次性秘密。** ECDSA 每次签字还要一个只有自己知道的 `k`。`k` 漏了或重复用，私钥可以被解出来。这是**密码层**。
2. **账户上的序号。** 「这是我的第 8 张支票。」用来防同一张已签字条被兑两次。这是**协议层的重放保护**，见 L2.2。它不是密码学随机数。
3. **共识里的等待。** 「这轮提议太慢，进入下一轮。」这是**活性**用的钟，不是安全用的锁。锁在 L4.3。把超时写成 `sleep(随机毫秒)`，各节点醒来的世界会错位。

还有第四句，必须单独钉死：

> `Apply(S, 块)` 里不许掷骰子。本地时钟、`/dev/urandom`、map 遍历顺序，都不是块里的输入。

骰子一旦进状态转移，两台诚实机器不必被黑，也会算出两个根。这是**实现保证**先死，密码学可以仍成立。

---

## D. 正式定义（本科计算机）

### D.1 签名随机数（ECDSA 的 `k`）

ECDSA 签名大致依赖一个每次签字都应新鲜、保密、均匀的标量 `k`。  
**事实（数学）：** 同一私钥下，两个签名若共用同一个 `k`（或 `k` 泄漏），可以从公开的 `(r,s)` 解出私钥。  
**事实（工程对策）：** RFC 6979 用私钥和消息**确定性地**派生 `k`，避免「机器上的坏 RNG」直接变成丢钥。EdDSA 族从设计上走确定性路径。  
**推断：** 确定性派生消除的是「实现随手 `rand()`」这一类口子，不消除侧信道、也不消除算法本身被破。

### D.2 账户 nonce（重放序号）

协议对象，通常是「该账户下一笔必须等于 `n`，成功后变 `n+1`」。  
它不需要保密，常常还公开在链上。  
它防的是**同一张已授权请求被执行两次**，不防偷钥，不防跨链（跨链要 domain / chain id，见 L1.2）。

### D.3 共识超时

BFT 的 `timeoutPropose` / `timeoutPrevote` 一类**本地**等待决定：**还没凑齐票时，何时放弃本轮。**  
**事实（结构）：** 锁保护安全；超时推动活性。超时再乱，只要锁和 WAL 还在，不应投出与旧 lock 矛盾的票（L4.3、L4.4）。  
**事实（结构）：** 超时不是「协议允许各节点自己发明一个随机睡眠」。规范要写清从哪一刻开始计、超时后进入哪一步；**等几毫秒**是本地配置，不是共识常数。见 [`../../tracks/consensus/worked-example-timeouts.md`](../../tracks/consensus/worked-example-timeouts.md)。

### D.4 `Apply` 的确定性禁令

设 `B` 是已经规范化的块字节。

```text
∀ 诚实实现 A, A'.  A.Apply(S, B) = A'.Apply(S, B)
```

禁止作为 `Apply` 输入（除非已经写进 `B` 并被共识承认）：

| 来源 | 为什么会裂 |
|---|---|
| 节点本地时钟 | 两机「现在」不同 |
| OS 随机数 | 两机抽到不同字节 |
| 无序哈希表遍历 | 两机构造不同收据/根 |
| 浮点、未定义溢出 | 两机语言/CPU 不同 |
| 错误字符串拼进状态 | 两机文案不同（L1.4） |

**建议：** 需要「链上随机」时，把它变成**块内已承诺的输入**（例如被投票覆盖的种子），而不是执行器自己掷。本课不选具体信标方案。

## E. 最小案例

同一把 ECDSA 钥，两笔不同消息，实现用了同一个 `k`：

1. 观察者收集两个签名。  
2. 代数上解出 `sk`。  
3. 之后任意伪造「阿安同意」。  

层：密码 + 实现（坏 RNG 或复制了 `k`）。协议可以说「必须验签」——验签仍会通过，因为印是真的。  
用户看见：钱走了，浏览器仍显示「签名有效」。

第二个案例：`Apply` 里写了 `if now() > T { 多扣一点费 }`。  
节点甲与乙的墙钟差 2 秒，同一块两个根。  
层：实现。这不是「共识投票错了」。

第三个案例：验证者把 `timeoutPropose` 写成 `sleep(rand())`。  
有人永远先醒、有人永远后醒。活性变差，甚至活锁。  
若同时 WAL 丢了 lock，才升级成**安全**事故（见实现轨崩溃实例）。

## F. 真实项目

- **Bitcoin / Ethereum（事实）：** 外部账户路径长期是 secp256k1 ECDSA；实现必须处理 `k`。Bitcoin 后来大量路径转向 BIP-340 Schnorr；Ethereum EOA 默认仍是 ECDSA。  
- **RFC 6979（事实）：** 用确定性 `k` 降低「主机 RNG」事故面。  
- **CometBFT（事实）：** 超时是状态机参数，和 prevote/precommit 锁分开；崩溃恢复靠 WAL，不是靠再睡一次。见 L4.2–L4.4。  
- **Ethereum 执行（事实）：** 共识输入不得含节点本地时间与本地随机；需要随机性时走信标等**已被承诺**的值。失败交易的 nonce/费语义必须两客户端一致（L5.1、L5.3）。  
- **「不确定」（建议）：** 第一天就把三个词写进词典，禁止混用；`Apply` 的确定性用差分测试看守；签名路径禁止自写 RNG。

## G. 源码入口（预告）

1. 签名库：`k` 是 RFC6979 / 库内部确定性，还是调用方传入？  
2. `Apply`：搜 `time.Now`、`rand`、`HashMap` 迭代是否漏进收据或根。  
3. 共识：超时从哪一个时钟源读、超时后进入哪一个 step。  
4. 测试：同一块在两个进程、两种语言绑定下根是否相同。

路径以各仓库当时的树为准，本课不把某次 commit 写成规范。

---

## H. 攻击者视角

1. 收集坏 RNG 签出的两枚 ECDSA，解钥。侧信道测 `k`。  
2. 把「账户 nonce」和「签名 k」在文档里故意写混，让实现者把序号当秘密、或把 `k` 当可公开计数器。  
3. 诱使 `Apply` 读本地时间（「限时拍卖」），专打时钟不同的节点对。  
4. 把超时当成可以不写 WAL 的借口：「反正要重投」。  
5. 后量子签名若引入盐/随机化编码，把盐漏进两套不一致的规范化规则（接 L1.4）。

## I. Trade-off

| 选择 | 得到 | 失去 |
|---|---|---|
| 确定性签名（RFC6979 / EdDSA） | 少一类丢钥 | 侧信道模型不同；实现仍能写错 |
| 真随机 `k` + 高质量 RNG | 理论新鲜性 | 主机 RNG、虚拟机、嵌入式最容易烂 |
| 账户公开 nonce | 重放好查 | 热点、空洞、替换交易（L2.2） |
| 规范写死超时 | 活性可推理 | 慢网会空转轮次 |
| 执行器自己掷骰 | 合约「像真随机」 | 诚实节点裂根 |

## J. 对「不确定」的意义

后量子算法往往带更长的盐、种子、编码长度字段。  
**建议：**

1. 词典先分开：`sig_nonce` / `account_nonce` / `timeout` / `block_seed`。  
2. `Apply` 零本地熵；要随机就进块并被投票覆盖。  
3. 签名实现禁止自写 CSPRNG；换算法时连同确定性/盐的规范化一起换。  
4. 超时**何时触发、超时后进哪一步**写在规范；等几毫秒测过再填，不要抄文档示例秒数，也不要写成第三条最终性。

## 精密检查

**五层**

| 层 | 本课钉在哪 |
|---|---|
| 密码 | `k` 泄漏/重用 ⇒ 私钥可解；算法假设另账 |
| 协议 | 账户序号；超时与锁分工；块内种子才是合法熵 |
| 实现 | RFC6979 是否真用了；`Apply` 是否偷偷读钟 |
| 部署 | 坏主机 RNG、NTP、容器时间冻结 |
| 经济 | 解钥之后的盗币；裂根之后的「跟错根放货」 |

**禁止假学习：** 「有 nonce 所以安全。」「超时就是 sleep。」「确定性签名所以没有侧信道。」「链上随机 = 节点 `rand()`。」  
**边界：** 不讲 VRF 数学（见模式 vrf-sortition）；不选信标方案；不填未测超时毫秒；账户空洞细节在 L2.2。ValidateBasic 读本地钟 ≠ 已确定：博物馆 [Jackfruit](../../tracks/failure-museum/jackfruit.md)。授权代发漏检查是另一句：[Elderflower](../../tracks/failure-museum/elderflower.md)。  
**事实 / 推断 / 建议** 已分标。ECDSA 具体历史事故的七问，只收有 CVE / 官方披露的条目，不在本课点名未核新闻。

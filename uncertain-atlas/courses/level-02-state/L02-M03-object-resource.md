# L2.3 对象与资源

优先级：重要  
先修：L2.1，L2.2

---

## A. 先修知识

UTXO：支票。账户：存折格子。  
对象/资源：东西有身份、有主人、有版本。像仓库里的编号货物，不像银行里的一个数字。

---

## B. 核心问题

**为什么「谁拥有这个对象」能让很多交易绕过全网抢一把大锁？共享对象又如何把锁请回来？**

---

## C. 直觉（ELI15）

阿安有一把编号伞。他把伞转给阿比。  
只要没人跟他抢**同一把伞**，这件事不必和全城的转账排一条长队。

如果有一把「城市广场」这种大家都能摸的东西（共享对象），摸它的人又必须排队。  
对象模型把世界分成：

- 我的东西：依赖简单，可能走快路径
- 大家的东西：仍要共识排序

Move 的 resource 还多一句：资源不能被复制或扔掉（除非模块允许）。钱是资源，不是随便复制的整数。

---

## D. 正式定义（本科计算机）

**对象：** 有全局 ID、版本、所有者（地址 / 共享 / 不可变）。  
交易声明读哪些、写哪些。调度器看所有权与版本做冲突检测。

**owned object：** 单一所有者。许多系统设计成：所有者签名即可，不必和所有共享对象交易一起全序。  
**shared object：** 多交易可争用，必须进入共识排序（或等价的全局协议）。

**resource（Move）：** 线性类型味道。不能随意 copy/drop。模块定义资源的产生与销毁。  
`store` 不是已经是顶层资源。结构体写了 `has copy` 不是这个实例能复制。精读：[`../../tracks/state-models/worked-example-ability-vs-resource.md`](../../tracks/state-models/worked-example-ability-vs-resource.md)（不变量 151）。

**事实：** Sui 以对象为中心；Aptos 以账户+Move 资源为主，并行靠 Block-STM 乐观执行，不是同一条路。  
**推断：** 「对象模型更容易并行」只对 owned 路径结构性地成立；shared 一多，故事退回账户热点。

---

## E. 最小案例

```text
Obj_umbrella: owner=A, version=3
Obj_plaza:    shared, version=10

T1: A 把 umbrella 转给 B     // 只碰 owned
T2: C 把 C 的帽子转给 D     // 另一 owned
T3: A 和 C 都要改 plaza     // 共享，必须排
```

T1 与 T2 无共享依赖，可并行甚至可能不进同一条全序。  
T3 与任何其他改 plaza 的交易冲突。

版本：T1 必须带着「我看见 umbrella v3」。若已变成 v4，T1 过期。

---

## F. 真实项目

- **Sui（事实）**：对象所有权 + 版本；共享对象走共识。  
- **Aptos（事实）**：Move 资源；Block-STM 先并行再检测冲突。  
- **Solana（对照）**：不是对象链，但是「交易列出账户」在工程上接近「提前声明依赖」。

---

## G. 源码入口

预告：对象版本检查、所有权转移、shared 进共识的分叉点。具体路径 Level 6 核仓库。

---

## H. 攻击者视角

1. 把本可 owned 的东西设计成 shared，制造假热点。  
2. 故意让版本飞速上涨，让诚实交易过期。  
3. 共享对象上的抢跑与 MEV。  
4. 资源模块写错，允许复制「钱」。这是实现/语言不变量被破坏。

---

## I. Trade-off

| 得到 | 失去 |
|---|---|
| owned 路径的结构性并行 | 钱包与编程模型要理解对象/版本 |
| 资源线性，少一类复制 bug | 语言与工具更陡 |
| 快路径少共识 | 安全论证和实现更绕；shared 仍痛 |

---

## J. 对「不确定」的意义

若「不确定」第一版是结算：每笔都是「明确的券从 A 到 B」，owned/UTXO 都比「全球一个热账户」干净。  
若以后有 AMM 式共享盘子，对象模型不会魔法消除争用。  
**建议：** 决策矩阵里写清「第一版有没有共享对象」。没有，就不要抄整套 Sui。

## 精密检查

| 层 | 本课钉在哪 |
|---|---|
| 密码学 | 能力 / 所有权不替代验签 |
| 协议 | owned 可局部序；shared 回到全局序；`store` ≠ 已经是顶层资源 |
| 实现 | 版本号 / 锁必须两客户端相同 |
| 部署 | 共享对象争用先打执行器 |
| 经济 | AMM 式共享盘会把并行广告打回原形 |

**禁止假学习：** 「对象模型所以所有交易绕过共识。」「`store` = 已经上架。」「写了 `has copy` = 每种实例都能复制。」「字段是整数 = 钱能复制。」
**边界：** owned/shared 深挖在 L6.2。Move 四能力精读：[`../../tracks/state-models/worked-example-ability-vs-resource.md`](../../tracks/state-models/worked-example-ability-vs-resource.md)（不变量 151）。不另写 19 节。Sui `UID` / Aptos Object 另标。

## D. 对比表（第一版）

标记：F=事实（该族典型设计），I=推断，S=对「不确定」的建议。

| 维度 | UTXO | Account | Object / Resource |
|---|---|---|---|
| 状态原子 | 未花费输出 | 账户 + 存储槽 | 对象 / 资源 |
| 重放 | 花掉就没了 (F) | nonce / chain id (F) | 版本 + 所有权 (F) |
| 默认并行 | 输入不交则可并行 (F) | 同账户默认串行 (F) | owned 易并行，shared 否 (F) |
| 钱包体验 | 找币、找零 (F) | 人较熟，nonce 坑 (F) | 要理解对象/版本 (F) |
| 可编程 | 脚本陡；eUTXO 见 L2.5 (F) | 通用 VM 成熟 (F) | Move 能力强，生态较新 (F) |
| 隐私 | 图谱分析难躲 (F) | 更差的复用地址习惯 (I) | 视设计 (I) |
| 证明复杂度 | 单笔包含证明简单 (F) | 状态证明靠树 (F) | 对象证明，视实现 (I) |
| 存储 | UTXO 集膨胀 (F) | 状态树膨胀 (F) | 对象存活性/版本 (F) |
| 无状态方向 | 输入自带见证较自然 (I) | 正在做 Verkle 等 (F) | 对象可随交易携带 (I) |
| 后量子成本 | 每输入可能一堆签名 (I) | 每笔一签，但热账户验签挤爆 (I) | owned 分散验签；shared 仍挤 (I) |
| 结算适配 | 高 (S) | 中，除非只要简单余额 (S) | 高，若没有 shared (S) |
| 通用世界计算机 | 低到中 (S) | 高 (S) | 中到高 (S) |

混合模型存在（例如账户外表 + UTXO 内核）。第一版地图先不展开。

## H. 攻击者视角（按模型）

- UTXO：未确认双花、粉尘膨胀。  
- Account：nonce 空洞、热合约。  
- Object：假 shared、版本抢跑。  

---

## I. Trade-off 总句

> 更好写的全局可变状态，通常更难并行、更难证明、更怕热点。  
> 更易并行的所有权模型，通常更难做「大家一起改的一盘汤」。

---

## J. 对「不确定」的意义

第一版地图只禁止一件事：用 TPS 广告选状态模型。  
真正选型在 Level 4–6 和决策矩阵之后。

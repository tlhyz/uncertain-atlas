## A. 先修知识

---

## B. 核心问题

**一条区块链到底在计算什么？**

---

## C. 直觉（ELI15）

不要先想「区块」「矿工」「质押」。

想一台非常固执的计算器：

1. 它心里有一个当前数字（或一张表），叫**状态**。
2. 有人递进一张合法申请，叫**交易**。
3. 它用同一套规则算出新数字，叫**状态转移**。
4. 世界上很多台机器都跑这套规则。
5. 如果它们吃进的申请**顺序一样**，又**不会随便发挥**，它们心里的数字就会一样。

这就是复制状态机：

> 很多副本，同一份规则，同一串输入，得到同一份状态。

区块链难的不是「会加法」，而是：**在有人说谎、有人掉线、网络乱序时，仍然让诚实副本吃进同一串输入。**

---

## D. 正式定义（本科计算机）

**状态（state）**：协议规定的、在某一时刻所有诚实节点都应同意的数据。  
例如：谁有多少币；哪个合约存储是什么。

**交易（transaction）**：对状态转移的一次请求。是否被接受，由规则决定，不由发送者的心情决定。

**状态转移函数（state transition function）**：

```text
Apply(S, T) → S'   或   Reject
```

**确定性（determinism）**：对相同的 `S` 和相同的 `T`，所有诚实实现必须得到相同的 `S'` 或相同的拒绝。  
如果某台机器因为「现在几点」「随机数」「遍历 map 的顺序」得出不同结果，副本会悄悄分裂。

**复制状态机（replicated state machine, RSM）**：一组副本对同一输入序列执行同一确定性函数。  
经典出处（研究预告，本课不必读）：Schneider, *Implementing Fault-Tolerant Services Using the State Machine Approach*, 1990。

**事实：** 「共识」在这套语言里，主要是在选**输入序列**；「执行」是在算 `Apply`。

## E. 最小案例

三个节点 N1 N2 N3。初始状态：

```text
S0 = { A: 10, B: 0, C: 0 }
```

两笔都合法、但互相争同一笔钱：

```text
T1 = A→B 6
T2 = A→C 6
```

若全网按同一顺序 `T1 然后 T2`（余额不足则拒绝）：

```text
S1 = { A: 4, B: 6, C: 0 }
S2 = { A: 4, B: 6, C: 0 }   // T2 被拒绝，状态不变
```

现在打乱：

| 情况 | 结果 |
|---|---|
| N2 先执行 T2 再执行 T1 | 最终是 C=6、B=0。和 N1 的 B=6、C=0 冲突。这不是「算错加法」，是**输入顺序不同** |
| N3 把本应拒绝的 T2 当成成功（实现写错） | 可能出现 A 的钱被花两次。这是实现保证失败，不是用户不会用钱包 |
| 某节点用「当前时间」决定手续费 | 不确定性。同一交易在不同机器结果不同 |

本课最小结论：

> 顺序 + 确定性 = 可复制。缺一个，就不是同一条链。

## F. 真实项目

- **Bitcoin（事实）**：状态可以看成「哪些 UTXO 还没被花」。转移 = 销毁一些 UTXO、创造一些 UTXO。
- **Ethereum（事实）**：状态是账户树。转移 = 对账户余额、nonce、存储做 `Apply`。Yellow Paper 把这写成形式对象。
- **Cosmos SDK / CometBFT（事实）**：共识负责为高度 `h` 选一个交易列表；应用通过 ABCI 执行 `Apply`。共识引擎不需要懂「余额」。
- **「不确定」（建议）**：先把 `Apply` 写到「两个独立实现也不能算歪」，再谈功能多少。

## H. 攻击者视角

攻击者喜欢不确定性：

1. 利用未定义的字节序、非规范编码，让客户端 A 接受、客户端 B 拒绝。
2. 利用「错误字符串」进入共识关键状态，两个实现解析不同。
3. 利用浮动手续费、系统时间、map 迭代顺序制造分裂。

这类攻击不需要偷私钥。它攻击的是：**复制**。

---

## I. Trade-off

| 选择 | 得到 | 失去 |
|---|---|---|
| 状态很小、规则很少 | 容易复制、容易验证 | 应用不好写 |
| 状态很大、规则很强 | 能跑复杂程序 | 更难确定、更难吃进同一序列、状态膨胀 |
| 允许多个独立实现 | 降低「一个客户端写错全网跟着错」 | 规范必须极其硬，否则分裂 |

---

## J. 对「不确定」的意义

后量子签名会改变「什么叫合法交易」，但不应改变这句话：

```text
诚实节点对同一已排序输入，必须得到同一状态。
```

如果「不确定」将来有两个客户端，这是第一不变式。

## 精密检查

| 层 | 本课 |
|---|---|
| 协议 | 同一 S、同一已排序 T 必须同 S' |
| 实现 | 非确定性输入会裂 |
| 部署 | 副本没收到同一 T |

**禁止假学习：** 「分布式数据库 = 区块链。」
**边界：** 不选状态模型。

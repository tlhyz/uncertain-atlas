# TASK-0008: DATA_QUALITY_REPORT Pre-Experiment Gate

## Why
User spec §8: experiments must not run on garbage data. ETH manifest rows=0 proves gap.

## Hypothesis
Automated quality report can block runs when missing rate, gaps, duplicates, or manifest mismatch exceed thresholds.

## Dependencies
TASK-0005 (GAP_ANALYSIS), DATA-010 partial

## Implementation
1. Create `src/data/quality_gate.py` with `generate_data_quality_report(manifest_paths) -> DataQualityReport`
2. Check: missing rate, gap count, duplicate rows, time disorder, symbol mismatch, rows>0
3. Integrate into `qtb/dual/run.py` and `qtb/ab/run.py` — abort if FAIL
4. Output: `DATA_QUALITY_REPORT.json` per run
5. Unit tests in `tests/test_data_quality_gate.py`

## Validation
- Run blocked when ETH rows=0 manifest used
- Run allowed when SOXL manifest valid
- Report written before backtest starts

## Failure Conditions
- Experiments still run on corrupt cache
- Gate always passes (useless)

## Expected Output
`src/data/quality_gate.py`, tests, sample report in outputs/

## Reviewer Checklist
- [ ] Thresholds configurable in configs/
- [ ] Report includes sha256 + row counts
- [ ] Red team: can corrupt data still pass?
